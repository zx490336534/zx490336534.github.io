📦 Redux Toolkit 基础入门

理解 React 状态管理的核心工具

Redux Toolkit 是 Redux 的官方推荐工具包，它大大简化了 Redux 的使用。本课程将从 "什么是状态管理" 开始，带你理解 Redux Toolkit 的核心概念。

📖 一、什么是状态管理？

在 React 应用中，状态（State）就是驱动界面显示的数据。比如：

  • 用户是否已登录
  • 购物车里有哪些商品
  • 当前选中的主题是深色还是浅色
  • 聊天消息列表

状态管理就是如何组织、存储和更新这些数据。

💡 类比理解

想象一个餐厅：状态就是厨房里 "当前有哪些订单"。状态管理就是一套流程 —— 谁负责下单、谁负责做菜、谁负责通知顾客。

React 自带的状态管理

React 自带了 useState 和 useContext 来管理状态。对于小型应用，这就够了。但当应用变复杂时，问题就来了：

  • 状态需要跨很多组件共享：比如用户登录信息，几乎每个页面都要用
  • 状态更新逻辑复杂：比如购物车的增删改查，逻辑散落在各处
  • 调试困难：状态变了不知道是谁改的、什么时候改的

🤔 二、为什么需要 Redux？

Redux 是一个可预测的状态容器，它有三个核心原则：

  1. 单一数据源：整个应用的状态存储在一个地方（Store），而不是散落在各个组件里
  2. 状态只读：不能直接修改状态，只能通过发送 "Action" 来触发更新
  3. 纯函数更新：状态的更新逻辑写在 "Reducer" 里，它是一个纯函数 —— 输入相同，输出一定相同
  ┌──────────┐    dispatch action    ┌──────────┐    新状态    ┌──────────┐
  │  组件     │ ──────────────────>  │ Reducer  │ ──────────> │  Store   │
  │ (View)   │                       │ (纯函数)  │             │ (状态树)  │
  └──────────┘ <──────────────────  └──────────┘             └──────────┘
        │          订阅状态更新                                     │
        │                                                          │
        └──────────── 读取状态 <────────────────────────────────────┘

⚠️ 传统 Redux 的痛点

原生 Redux 写起来很繁琐 —— 要定义 Action Types、Action Creators、Reducer，还要配置 Store，写大量模板代码。这就是 Redux Toolkit 诞生的原因！

🛠️ 三、Redux Toolkit 核心 API

Redux Toolkit（简称 RTK）是 Redux 官方推荐的工具包，它把 Redux 的最佳实践打包成了简洁的 API。

1. createSlice — 创建状态切片

createSlice 是 RTK 最核心的 API。它帮你同时定义 初始状态、reducers（更新逻辑）和 actions（触发更新的方式）。

// features/counter/counterSlice.js
import { createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',        // slice 的名字
  initialState: {         // 初始状态
    value: 0,
  },
  reducers: {             // 更新逻辑（自动生成 actions）
    increment(state) {
      state.value += 1;   // 看起来像直接修改，其实是 Immer 在背后处理
    },
    decrement(state) {
      state.value -= 1;
    },
    incrementByAmount(state, action) {
      state.value += action.payload;
    },
  },
});

// 自动生成了 actions
export const { increment, decrement, incrementByAmount } = counterSlice.actions;
// 导出 reducer
export default counterSlice.reducer;

✅ 为什么可以直接修改 state？

RTK 内部使用了 Immer 库。你写的 state.value += 1 实际上会被 Immer 转换为不可变更新。这让代码写起来简单，但底层仍然是安全的不可变操作。

2. configureStore — 创建 Store

configureStore 帮你创建 Redux Store，自动配置了中间件（包括 thunk 异步处理）和开发工具。

// store.js
import { configureStore } from '@reduxjs/toolkit';
import counterReducer from './features/counter/counterSlice';
import userReducer from './features/user/userSlice';

const store = configureStore({
  reducer: {
    counter: counterReducer,  // counter 状态由 counterReducer 管理
    user: userReducer,        // user 状态由 userReducer 管理
  },
});

export default store;

3. useSelector — 读取状态

useSelector 是一个 React Hook，用来从 Store 中读取状态。

import { useSelector } from 'react-redux';

function Counter() {
  // 从 Store 中读取 counter.value
  const count = useSelector((state) => state.counter.value);

  return <div>当前计数：{count}</div>;
}

4. useDispatch — 触发状态更新

useDispatch 是一个 React Hook，用来发送 actions 触发状态更新。

import { useDispatch, useSelector } from 'react-redux';
import { increment, decrement } from './counterSlice';

function Counter() {
  const count = useSelector((state) => state.counter.value);
  const dispatch = useDispatch();

  return (
    <div>
      <span>{count}</span>
      <button onClick={() => dispatch(increment())}>+1</button>
      <button onClick={() => dispatch(decrement())}>-1</button>
    </div>
  );
}

数据流总结

  组件点击按钮
       │
       ▼
  dispatch(increment())     ← useDispatch 发送 action
       │
       ▼
  Reducer 处理 action       ← createSlice 定义的 reducers
       │
       ▼
  Store 状态更新            ← configureStore 创建的 Store
       │
       ▼
  useSelector 感知变化      ← 组件自动重新渲染

⚖️ 四、Redux Toolkit vs React Context

很多同学会问："React 自带的 Context 不就能共享状态吗？为什么还要 Redux？"

对比维度React ContextRedux Toolkit
适用场景简单的全局状态（主题、语言）复杂的应用状态（购物车、聊天）
性能Context 值变化时，所有消费者都会重新渲染精确订阅，只有相关组件重新渲染
调试没有内置工具Redux DevTools，可追踪每次状态变化
中间件不支持支持异步（thunk）、日志、持久化等
状态更新追踪困难完整的 action 日志，时间旅行调试
代码量少比原生 Redux 少很多，但比 Context 多
学习曲线低中等

💡 什么时候用哪个？

  • 用 Context：只有少数组件需要共享的简单状态（如主题色、语言设置）
  • 用 Redux Toolkit：多个页面/组件需要共享的复杂状态，需要异步操作，需要调试能力

⚠️ 常见误区

"用 Redux 就不用 Context 了" —— 不对！它们可以共存。Redux 管理业务状态，Context 管理一些简单的配置（如主题）。关键是选择合适的工具。

🧠 Quiz — 检验你的理解

📝 选择题

1. createSlice 中，为什么可以直接写 state.value += 1？
  • Redux 允许直接修改状态
  • RTK 内部使用了 Immer 库，会自动转换为不可变更新
  • 这只在开发环境有效
  • 这是一个 bug，不应该这样写
答案：B — Redux Toolkit 内部集成了 Immer 库。你写的 "直接修改" 代码会被 Immer 转换为正确的不可变更新操作，所以底层仍然是安全的。
2. useSelector 的作用是什么？
  • 发送 action 触发状态更新
  • 从 Store 中读取状态
  • 创建一个新的 Slice
  • 配置 Redux Store
答案：B — useSelector 是一个 React Hook，用于从 Redux Store 中读取（选择）状态。dispatch 用于发送 action，configureStore 用于创建 Store。
3. 以下哪种场景更适合使用 Redux Toolkit 而不是 React Context？
  • 存储当前主题色（深色/浅色）
  • 存储当前语言设置
  • 管理购物车商品列表，需要增删改查和异步同步
  • 存储一个模态框的开关状态
答案：C — 购物车涉及多个组件共享的复杂状态、异步操作、复杂更新逻辑，这些正是 Redux Toolkit 的优势场景。简单的主题/语言/模态框状态用 Context 就够了。
