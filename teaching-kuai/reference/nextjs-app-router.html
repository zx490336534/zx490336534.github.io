Next.js App Router 基础入门

概念 面向零基础小白的 Next.js App Router 教程

本教程将带你了解 Next.js 这个 React 框架，重点讲解 App Router 的核心概念。学完后你将理解文件系统路由、布局系统以及 Server/Client Components 的区别。

⚡ 什么是 Next.js

Next.js 是一个基于 React 的全栈框架，由 Vercel 公司开发和维护。

一句话理解：如果 React 是一个"引擎"，那 Next.js 就是一辆"完整的汽车"——它在 React 的基础上，帮你搞定了路由、服务器渲染、打包构建等所有工程化的事情。

Next.js 解决了什么问题？

纯 React 项目（用 Create React App 创建的）有一些痛点：

  • 没有内置路由 — 需要自己装 react-router
  • 只有客户端渲染 — 首屏加载慢，SEO 不友好
  • 没有 API 路由 — 后端接口需要另外搭服务器
  • 配置复杂 — Webpack、Babel 等需要自己折腾

Next.js 把这些都内置好了，开箱即用：

  • ✅ 内置文件系统路由（不用写路由配置）
  • ✅ 支持 SSR（服务器渲染）和 SSG（静态生成）
  • ✅ 内置 API Routes（前后端一体）
  • ✅ 零配置，自动优化

🔄 App Router vs Pages Router

Next.js 有两套路由系统，这是因为框架在不断演进：

对比Pages Router（旧）App Router（新）
引入版本Next.js 9（2019）Next.js 13（2022）
目录名pages/app/

布局系统需要手动实现内置 layout.js
数据获取getServerSideProps直接在组件中 async/await
流式渲染不支持支持 loading.js
我们的项目用的是哪个？kuai-service-front 使用的是 App Router（Next.js 16），这是 Next.js 推荐的新方案。

📁 文件系统路由

App Router 最大的特点是：文件夹结构就是 URL 路由。你不需要写任何路由配置文件，创建文件夹就是在创建页面。

app/ ├── page.js              → /（首页） ├── about/ │ └── page.js          → /about ├── users/ │ ├── page.js          → /users │ └── [id]/ │ └── page.js      → /users/123（动态路由） ├── dashboard/ │ ├── page.js          → /dashboard │ ├── settings/ │ │ └── page.js      → /dashboard/settings │ └── [...slug]/ │ └── page.js      → /dashboard/任何/路径（Catch-all） └── api/ └── hello/ └── route.js    → GET /api/hello（API 路由）
规则很简单：
- 每个文件夹是一个路由段
- 文件夹里的 page.js 是这个路由的页面内容
- [参数名] 是动态路由参数
- [...参数名] 是 Catch-all 路由

📄 layout.js / page.js / loading.js

App Router 中有几个特殊的文件名，它们各自有不同的职责：

page.js — 页面内容

每个路由的实际页面内容。访问对应 URL 时渲染的就是这个文件。

// app/dashboard/page.js
export default function DashboardPage() {
  return <h1>仪表盘页面</h1>;
}

layout.js — 布局包装

布局组件会包裹其子路由的页面。最典型的用途是导航栏、侧边栏等公共部分。

// app/layout.js（根布局，所有页面都会被它包裹）
export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <nav>导航栏</nav>
        <main>{children}</main>  {/* 子页面渲染在这里 */}
        <footer>页脚</footer>
      </body>
    </html>
  );
}
布局的特点：当页面切换时，布局不会重新渲染（状态会保留）。这意味着导航栏不会闪烁，用户输入的内容不会丢失。

loading.js — 加载状态

当页面数据正在加载时显示的内容，类似"骨架屏"效果。

// app/dashboard/loading.js
export default function Loading() {
  return <div className="spinner">加载中...</div>;
}

它的工作原理是利用了 React 的 Suspense。当 page.js 中有异步操作（比如请求 API）时，Next.js 会自动显示同级的 loading.js。

其他特殊文件

文件名作用
error.js错误边界，捕获子组件的错误
not-found.js404 页面
template.js类似 layout，但每次导航都重新渲染
route.jsAPI 路由端点（替代 page.js）

🖥️ Server Components vs Client Components

这是 App Router 最重要的概念之一。在 Next.js 中，组件分为两种：

Server Components（服务端组件）

  • 默认所有组件都是 Server Components
  • 在服务器上渲染，HTML 直接发送给浏览器
  • 可以直接访问数据库、读文件、调用内部 API
  • 不能使用 useState、useEffect、onClick 等浏览器功能
// 这是 Server Component（默认）
// 可以直接 fetch 数据，不需要 useEffect
async function UserList() {
  const users = await db.query('SELECT * FROM users');
  return (
    <ul>
      {users.map(u => <li key={u.id}>{u.name}</li>)}
    </ul>
  );
}

Client Components（客户端组件）

  • 需要在文件顶部加 "use client" 指令
  • 在浏览器中渲染（像传统 React 一样）
  • 可以使用 useState、useEffect、onClick 等
  • 不能直接访问数据库等服务端资源
"use client";  // 加上这行就是 Client Component

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(c => c + 1)}>
      点击了 {count} 次
    </button>
  );
}
对比Server ComponentClient Component
渲染位置服务器浏览器
声明方式默认（不用加任何东西）文件头加 "use client"
useState/useEffect❌ 不能用✅ 可以用
访问数据库✅ 可以❌ 不能
事件处理（onClick）❌ 不能用✅ 可以用
发送给浏览器的 JS更少（性能好）更多
最佳实践：尽量用 Server Component，只在需要交互（点击、输入、动画）时才用 Client Component。把 Client Component 放在组件树的"叶子节点"，而不是整个页面。
