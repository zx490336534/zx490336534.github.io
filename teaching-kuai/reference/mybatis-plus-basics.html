🗃️ MyBatis-Plus 基础入门

概念 理解 ORM 思想，掌握 MyBatis-Plus 的注解和 CRUD 操作

🤔 什么是 ORM？

ORM（Object-Relational Mapping，对象关系映射）的核心思想很简单：

🔄 一句话理解 ORM

用 Java 对象来代替 SQL 语句操作数据库。
一张数据库表 → 一个 Java 类
表中一行数据 → 一个 Java 对象
表中的字段 → 对象的属性

没有 ORM 时，你需要这样查数据库：

// 传统 JDBC：手写 SQL，手动映射字段
String sql = "SELECT * FROM user WHERE id = ?";
PreparedStatement ps = conn.prepareStatement(sql);
ps.setLong(1, 1L);
ResultSet rs = ps.executeQuery();
while (rs.next()) {
    String name = rs.getString("name");  // 手动取值
    // ...
}

有了 ORM 之后：

// MyBatis-Plus：一行代码搞定
User user = userMapper.selectById(1L);

⚖️ MyBatis vs MyBatis-Plus

MyBatis 是一个半自动的 ORM 框架 —— 你需要自己写 SQL 语句，MyBatis 帮你执行并映射结果。

MyBatis-Plus 是 MyBatis 的增强版 —— 简单的 CRUD 操作不需要写 SQL，框架自动生成。

对比项MyBatisMyBatis-Plus
CRUD 操作每个都要写 SQL单表 CRUD 零 SQL
分页手写分页 SQL 或用插件内置分页插件
条件查询拼接 XML 或注解 SQLWrapper 链式构建
代码生成无内置代码生成器
学习成本需要会写 SQL会调方法就行
简单说：MyBatis-Plus = MyBatis + 自动 CRUD + 分页 + 条件构造器 + 代码生成器。它不会替代 MyBatis，而是在 MyBatis 基础上做加法。

🏷️ 核心注解：@TableName 和 @TableId

3.1 @TableName —— 表名映射

告诉 MyBatis-Plus 这个类对应数据库的哪张表：

@TableName("user")  // 对应数据库的 user 表
public class User {
    private Long id;
    private String name;
    private String email;
}

如果你的类名和表名遵循命名规则（类名 User → 表名 user），可以不加这个注解。

3.2 @TableId —— 主键映射

标记哪个字段是主键，以及主键的生成策略：

@TableName("user")
public class User {
    @TableId(type = IdType.AUTO)  // 数据库自增
    private Long id;
    private String name;
}

常用 IdType 策略

  • AUTO —— 数据库自增（最常用）
  • ASSIGN_ID —— 雪花算法生成 Long 类型 ID
  • ASSIGN_UUID —— 生成 UUID 字符串
  • NONE —— 不做任何处理

🔧 BaseMapper 常用方法

MyBatis-Plus 最核心的类就是 BaseMapper<T>。你只需要写一个 Mapper 接口继承它，就能获得大量现成的 CRUD 方法：

@Mapper
public interface UserMapper extends BaseMapper<User> {
    // 什么都不用写！已经自动拥有了增删改查方法
}

4.1 selectById —— 根据 ID 查询

User user = userMapper.selectById(1L);
// 生成的 SQL: SELECT * FROM user WHERE id = 1

4.2 insert —— 插入数据

User user = new User();
user.setName("张三");
user.setEmail("zhangsan@example.com");
int rows = userMapper.insert(user);
// 生成的 SQL: INSERT INTO user (name, email) VALUES ('张三', 'zhangsan@example.com')

4.3 updateById —— 根据 ID 更新

User user = new User();
user.setId(1L);
user.setName("李四");  // 只更新 name，其他字段不动
userMapper.updateById(user);
// 生成的 SQL: UPDATE user SET name='李四' WHERE id = 1

注意：updateById 只更新非 null 的字段，null 字段不会被更新。

4.4 deleteById —— 根据 ID 删除

userMapper.deleteById(1L);
// 生成的 SQL: DELETE FROM user WHERE id = 1

4.5 常用方法速查

方法作用示例
selectById(id)按 ID 查一条selectById(1L)
selectList(wrapper)条件查多条selectList(null) 查全部
selectCount(wrapper)统计条数selectCount(null)
insert(entity)插入一条insert(user)
updateById(entity)按 ID 更新updateById(user)
deleteById(id)按 ID 删除deleteById(1L)
deleteBatchIds(ids)批量删除deleteBatchIds(Arrays.asList(1,2,3))

✍️ @Select 自定义 SQL

当 BaseMapper 的方法不够用时（比如多表联查），你可以用 @Select 注解写自定义 SQL：

@Mapper
public interface UserMapper extends BaseMapper<User> {

    // 自定义查询：查某个部门的所有用户
    @Select("SELECT u.* FROM user u " +
            "JOIN department d ON u.dept_id = d.id " +
            "WHERE d.name = #{deptName}")
    List<User> selectByDeptName(@Param("deptName") String deptName);
}

这就是 MyBatis 的"半自动"体现 —— 简单操作用 Plus 自动生成，复杂操作你手写 SQL。

三种写 SQL 的方式

  • @Select 注解 —— 简单 SQL 直接写在方法上
  • XML 文件 —— 复杂 SQL 写在 *Mapper.xml 里
  • Wrapper 条件构造器 —— 链式调用，不用写 SQL 字符串
