🗄️ TDDL 数据库中间件入门

概念 了解 TDDL 是什么、为什么需要它，以及如何在项目中使用

🤔 什么是 TDDL？

TDDL（Taobao Distributed Data Layer）是阿里巴巴开源的数据库中间件。它在你的 Java 应用和数据库之间加了一层，帮你处理数据库访问的各种复杂问题。

🎯 一句话理解

TDDL 是一个"智能代理"，站在你的应用和数据库中间，帮你自动完成数据源选择、读写分离、分库分表等操作。你的代码不需要关心底层有几个数据库、数据存在哪个库。

TDDL 的核心能力：

  • 数据源路由：自动选择访问哪个数据库
  • 读写分离：写操作走主库，读操作走从库
  • 分库分表：数据量大时自动拆分到多个库/表
  • 故障转移：某个库挂了自动切到备用库

💡 为什么不用普通 JDBC？

当你的系统只有一个数据库、数据量不大时，普通 JDBC（或 MyBatis 直连）完全够用。

但当业务增长到一定程度，你会遇到这些问题：

场景普通 JDBC 的问题TDDL 的解决方案
读多写少所有请求打到一个库，主库压力大自动读写分离，读走从库
数据量巨大单表几亿行，查询慢到爆分库分表，数据分散存储
多个数据源代码里写死连接地址，切换麻烦统一配置，动态路由
数据库故障应用直接报错，无法自动恢复健康检查 + 自动故障转移

🏢 酷家乐为什么用 TDDL？

酷家乐作为大型 SaaS 平台，用户数据量大、访问量高。使用 TDDL 可以在不改变业务代码的情况下，通过配置实现数据库的水平扩展，保障系统性能和稳定性。

📦 tddl-min 依赖

在项目中使用 TDDL，需要引入 tddl-min 依赖。这是一个精简版的 TDDL，只包含核心功能：

<!-- pom.xml -->
<dependency>
    <groupId>com.taobao.tddl</groupId>
    <artifactId>tddl-min</artifactId>
    <version>5.1.4</version>
</dependency>

tddl-min vs 完整版 TDDL：

  • tddl-min：轻量级，只包含数据源路由和基本功能，适合大多数项目
  • 完整版 TDDL：包含分库分表、分布式事务等高级功能，配置更复杂

⚙️ 数据源配置

TDDL 的核心是数据源（DataSource）配置。它替代了你之前直接配置的 JDBC 数据源。

4.1 Spring 配置方式

在 Spring Boot 中，通常通过 Java Config 类配置 TDDL 数据源：

@Configuration
public class DataSourceConfig {

    @Bean
    public DataSource dataSource() {
        // TDDL 数据源配置
        TGroupDataSource dataSource = new TGroupDataSource();

        // 配置数据库连接信息
        Properties props = new Properties();
        props.setProperty("ip", "your-db-host");
        props.setProperty("port", "3306");
        props.setProperty("dbName", "kuai_db");
        props.setProperty("dbType", "mysql");
        props.setProperty("userName", "root");
        props.setProperty("password", "your-password");

        dataSource.setDataSourceProperties(props);
        return dataSource;
    }
}

4.2 application.yml 配置

也可以在配置文件中统一管理：

spring:
  tddl:
    datasource:
      ip: your-db-host
      port: 3306
      dbName: kuai_db
      dbType: mysql
      userName: root
      password: your-password
注意：在实际的酷家乐项目中，数据库地址、密码等敏感信息不会写在代码里，而是通过配置中心（如 Diamond/Nacos）动态获取。

🔗 与 MyBatis / MyBatis-Plus 的集成

TDDL 最大的优势是：它对上层框架完全透明。你的 MyBatis-Plus 代码不需要做任何改动。

集成原理

你的代码 (Mapper/Service)
        ↓ 调用
MyBatis-Plus (ORM 框架)
        ↓ 使用 DataSource
TDDL 数据源 (智能代理)  ← 这层帮你做路由、读写分离
        ↓ 连接
实际数据库 (MySQL)

只要把 Spring 的 DataSource Bean 替换为 TDDL 的数据源，MyBatis-Plus 的所有操作（selectById、insert 等）都会自动经过 TDDL 路由。

集成步骤

  1. 引入 tddl-min 依赖
  2. 配置 TDDL 数据源 Bean（替代原来的 JDBC 数据源）
  3. MyBatis-Plus 的 Mapper 和 Service 代码不需要改任何一行
// 这段代码和用不用 TDDL 完全一样，无需修改
@Service
public class UserService {
    @Autowired
    private UserMapper userMapper;

    public User getUser(Long id) {
        return userMapper.selectById(id);  // TDDL 自动帮你路由到正确的库
    }
}

总结：TDDL 的使用姿势

  1. 加 tddl-min Maven 依赖
  2. 把 DataSource Bean 换成 TDDL 的实现
  3. 业务代码零改动，框架透明
  4. 通过配置中心管理数据库连接信息
