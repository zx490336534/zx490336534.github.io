🔌 MCP 协议基础入门

理解 Model Context Protocol 的核心概念与工作原理

MCP（Model Context Protocol）是 AI 领域的一个重要协议标准，它让 AI 模型能够安全、标准化地调用外部工具和访问外部数据。本课程将从零开始，带你理解 MCP 的核心概念。

📖 一、什么是 MCP？

MCP 的全称是 Model Context Protocol（模型上下文协议），由 Anthropic 公司在 2024 年底提出并开源。

简单来说，MCP 是一个开放标准，它定义了 AI 模型（如 Claude、GPT 等）如何与外部世界进行交互。你可以把它想象成 AI 世界的 "USB 接口" —— 任何符合 MCP 标准的工具，都可以被任何支持 MCP 的 AI 模型使用。

💡 一句话理解 MCP

MCP 就是 AI 的 "万能插头"：不管是什么工具（查数据库、读文件、调 API），只要按 MCP 标准包装一下，AI 就能直接使用。

🤔 二、为什么需要 MCP？

在 MCP 出现之前，让 AI 使用外部工具是一件很麻烦的事情：

没有 MCP 之前的问题

  • 每个 AI 平台各搞一套：OpenAI 有自己的 Function Calling，Claude 有自己的 Tool Use，格式完全不同
  • 每个工具要适配每个平台：如果你开发了一个 "查天气" 的工具，要分别写 OpenAI 版、Claude 版、Gemini 版……
  • 没有统一标准：工具的描述方式、调用方式、返回格式都不一样
  • 安全性难以保障：AI 直接访问系统资源，缺乏统一的权限控制

MCP 解决了什么

问题MCP 的解决方案
工具开发重复一次开发，所有 AI 平台通用
接口不统一统一的协议标准（JSON-RPC 2.0）
安全性差标准化的权限控制和沙箱机制
难以发现工具内置工具发现机制（tools/list）

⚠️ 类比理解

想象一下，如果每个品牌的手机都要用不同的充电器（Micro-USB、Lightning、USB-C……），那多麻烦！MCP 就像 USB-C 标准 —— 统一了接口，一插就能用。

🏗️ 三、MCP 的三大核心概念

MCP 架构中有三个核心角色：

1. MCP Host（宿主）

Host 是发起连接的一方，通常是 AI 应用或 AI 模型的运行环境。比如：

  • Claude Desktop 应用
  • Cursor、VS Code 等 IDE
  • 你自己开发的 AI 应用

2. MCP Client（客户端）

Client 是 Host 内部用来与 MCP Server 通信的组件。每个 Client 与一个 Server 建立一对一的连接。

3. MCP Server（服务器）

Server 是提供工具和数据的一方。它把自己拥有的能力（比如读文件、查数据库、调 API）通过 MCP 协议暴露出来，供 AI 使用。

MCP Server 能提供什么？

🔌 四、三种传输方式

MCP 定义了三种通信传输方式，适用于不同的场景：

1. Stdio（标准输入输出）

💡 最简单的方式

通过进程的标准输入（stdin）和标准输出（stdout）通信，就像两个程序通过管道连接。

  • 工作方式：Host 启动一个子进程（Server），通过 stdin/stdout 交换 JSON-RPC 消息
  • 适用场景：本地工具、CLI 工具、桌面应用
  • 优点：简单、无需网络、安全性高（进程隔离）
  • 缺点：只能本地使用，不支持远程
# 示例：Host 通过 stdio 启动 MCP Server
npx @modelcontextprotocol/server-filesystem /path/to/dir

2. SSE（Server-Sent Events）

💡 HTTP 长连接

基于 HTTP 的单向流式通信，Server 可以持续向 Client 推送消息。

  • 工作方式：Client 通过 HTTP POST 发送请求，Server 通过 SSE 流返回响应
  • 适用场景：远程服务、Web 应用、云端部署
  • 优点：支持远程、基于标准 HTTP
  • 缺点：需要维护长连接，部署相对复杂
# SSE 端点示例
POST http://localhost:8000/messages    # Client 发送请求
GET  http://localhost:8000/sse         # Client 接收事件流

3. StreamableHTTP（可流式 HTTP）

⚠️ 最新标准

这是 MCP 协议最新推荐的远程传输方式，是对 SSE 的改进和替代。

  • 工作方式：所有通信通过一个 HTTP 端点完成，支持流式和非流式响应
  • 适用场景：现代 Web 应用、生产环境部署
  • 优点：更简洁、兼容性更好、支持无状态部署
  • 缺点：较新，部分旧客户端可能不支持

⚖️ 五、MCP vs REST API

你可能会问："我已经有 REST API 了，为什么还需要 MCP？" 这是个好问题！

对比维度REST APIMCP
设计目标人/程序之间的通信AI 模型与工具之间的通信
发现机制无（需要文档）内置（tools/list）
工具描述靠 Swagger/OpenAPI 文档协议内置 schema 描述
调用方式HTTP 方法 + URLJSON-RPC 2.0 统一调用
上下文感知无有（Resources、Prompts）
AI 友好度需要额外适配专为 AI 设计

✅ 核心区别

REST API 是为人类和程序设计的，AI 要使用它需要额外的适配层。MCP 是专为 AI 设计的，AI 可以自动发现、理解和调用 MCP 工具，无需额外适配。

简单来说：

  • REST API 像是 "给程序员看的说明书" —— 人读了文档才知道怎么调用
  • MCP 像是 "给 AI 用的遥控器" —— AI 按一下按钮就知道有什么功能、怎么用
