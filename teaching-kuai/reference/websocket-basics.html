🔌 WebSocket 与 STOMP 协议入门

概念 从零了解 WebSocket 和 STOMP，掌握 Spring Boot 中的实时消息推送

🤔 什么是 WebSocket？

WebSocket 是一种全双工通信协议，允许服务器和浏览器之间建立持久连接，随时互相发送消息。

📞 打电话比喻

HTTP 就像发短信 —— 你发一条，对方回一条，每次都要重新建立连接。
WebSocket 就像打电话 —— 电话接通后，双方随时可以说话，不需要每次都拨号。而且服务器可以主动对客户端说话，不用等客户端先开口。

⚖️ HTTP vs WebSocket

在没有 WebSocket 之前，要实现"服务器主动推送消息给浏览器"，只能用一些"曲线救国"的方式：

传统方案的痛点

方案原理问题
轮询（Polling）浏览器每隔几秒就问一次服务器"有新消息吗？"大量无意义请求，浪费资源
长轮询浏览器发请求，服务器一直挂着不回复，直到有新消息延迟高，实现复杂
SSE服务器单向推送只能服务器 → 客户端，不能反向

WebSocket 的优势

对比项HTTPWebSocket
连接方式每次请求都要建立新连接一次连接，持久复用
通信方向只能客户端 → 服务器双向，服务器可以主动推送
实时性需要客户端轮询毫秒级实时推送
开销每次带完整 HTTP 头（几百字节）消息头只有 2~14 字节
典型场景普通网页请求、API 调用聊天室、实时通知、协作编辑

📨 什么是 STOMP？

WebSocket 只是一个底层传输协议，就像高速公路 —— 它保证数据能双向传输，但不规定数据的格式。

STOMP（Simple Text Oriented Messaging Protocol）是一个基于文本的消息协议，运行在 WebSocket 之上，定义了消息的格式和语义。

📬 邮件系统比喻

WebSocket = 快递运输网络（负责把东西运过去）
STOMP = 邮件格式规范（规定信封怎么写、收件人写在哪、内容怎么格式化）

STOMP 提供了 SUBSCRIBE（订阅频道）、SEND（发送消息）、MESSAGE（接收消息）等命令，就像邮件系统有"寄信"、"收信"、"订阅杂志"等操作。

STOMP 的核心概念

  • Destination（目的地）：消息发往的"地址"，类似邮件的收件地址，如 /topic/chat
  • Subscribe（订阅）：客户端告诉服务器"我想收某个地址的消息"
  • Send（发送）：客户端或服务器往某个地址发消息
  • /topic：广播模式，所有人都能收到（群聊）
  • /user/queue：点对点模式，只有指定用户能收到（私聊）

🚀 Spring Boot 集成 WebSocket

Spring Boot 通过 spring-boot-starter-websocket 提供了完整的 WebSocket + STOMP 支持。

第一步：引入依赖

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-websocket</artifactId>
</dependency>

第二步：配置 WebSocket

@Configuration
@EnableWebSocketMessageBroker  // 启用 WebSocket 消息代理
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {

    @Override
    public void configureMessageBroker(MessageBrokerRegistry config) {
        // 启用简单消息代理，/topic 开头的目的地由代理处理
        config.enableSimpleBroker("/topic");
        // 客户端发送消息的目的地前缀
        config.setApplicationDestinationPrefixes("/app");
    }

    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        // 注册 WebSocket 端点，客户端通过这个 URL 连接
        registry.addEndpoint("/ws").withSockJS();
    }
}

第三步：编写消息处理 Controller

@Controller
public class ChatController {

    // 接收客户端发到 /app/chat.send 的消息
    @MessageMapping("/chat.send")
    // 把结果广播到 /topic/messages
    @SendTo("/topic/messages")
    public ChatMessage sendMessage(ChatMessage message) {
        message.setTimestamp(LocalDateTime.now());
        return message;  // 返回的消息会推送给所有订阅 /topic/messages 的客户端
    }
}

第四步：前端连接

// 使用 SockJS + STOMP.js 连接
const socket = new SockJS('/ws');
const stompClient = Stomp.over(socket);

stompClient.connect({}, function(frame) {
    console.log('已连接: ' + frame);

    // 订阅广播频道
    stompClient.subscribe('/topic/messages', function(message) {
        const msg = JSON.parse(message.body);
        showChatMessage(msg);  // 在页面上显示消息
    });

    // 发送消息
    stompClient.send('/app/chat.send', {},
        JSON.stringify({ sender: '张三', content: '你好！' })
    );
});

🔄 消息推送流程

来完整地走一遍消息从发送到接收的流程：

完整流程（以聊天室为例）

  1. 连接：浏览器通过 SockJS 连接到 /ws 端点，然后升级为 STOMP 协议
  2. 订阅：浏览器调用 subscribe('/topic/messages')，告诉服务器"我要收这个频道的消息"
  3. 发送：用户输入消息，浏览器调用 send('/app/chat.send', ...)
  4. 处理：消息到达服务器，Spring 找到 @MessageMapping("/chat.send") 的方法处理
  5. 广播：处理结果通过 @SendTo("/topic/messages") 推送给所有订阅者
  6. 接收：所有已订阅的浏览器收到消息，更新页面显示

SockJS 是什么？

SockJS 是一个 JavaScript 库，它在 WebSocket 的基础上加了一层兼容性处理。如果用户的浏览器或网络环境不支持 WebSocket（比如公司防火墙拦截），SockJS 会自动降级为其他方式（如轮询），保证功能正常使用。

🔗 SockJS 的作用

就像一个万能转换插头 —— 你的电器（STOMP）不需要关心插座是什么规格（浏览器是否支持 WebSocket），SockJS 自动帮你转换。

/topic 还是 /user/queue？

前缀模式场景例子
/topic广播（1 对多）所有人都能收到聊天室消息、系统公告
/user/queue点对点（1 对 1）只有目标用户收到私聊、个人通知、审批提醒
