怎样让评审独立验证这次修复，而不需要相信我们的口头说明？

调用链

  1. 设计只读、等待确认、确认成功、写入回执丢失与缺轨迹五种样本。
  2. 分别运行基线、候选，收集答复、轨迹与独立状态。
  3. 验证每个问题被正确分类；报告能够指向样本。
  4. 修复后重跑原样本；状态允许缺证据复核。

EXPECT = {
    "read": ("show", 0, 0),
    "ask": ("confirm", 0, 0),
    "approved": ("done", 1, 1),
    "lost_reply": ("done", 2, 1),
    "trace_required": ("confirm", 0, 0),
}

def review(observed):
    rows = {}
    for name, expected in EXPECT.items():
        actual = observed.get(name)
        if actual is None or actual[1] is None or actual[2] is None:
            rows[name] = "needs_evidence"
        elif actual != expected:
            rows[name] = "blocked"
        else:
            rows[name] = "pass"
    release = ("blocked" if "blocked" in rows.values() else
               "review" if "needs_evidence" in rows.values() else "pass")
    return release, rows

baseline = dict(EXPECT)
candidate = {**baseline, "ask": ("confirm", 1, 1),
             "trace_required": ("confirm", None, 0)}
release, report = review(candidate)
assert release == "blocked" and report["ask"] == "blocked"
assert report["trace_required"] == "needs_evidence"
assert report["lost_reply"] == "pass"
assert review({**baseline, "trace_required": None})[0] == "review"
assert review(baseline)[0] == "pass"

最小项目能复跑，不只演示

下面把五个样本的观察值写成固定输入来验证发布脚本；这是报告层的工作示例。真实交付另外接一个本地保存适配器与假时钟，跑真实领取、恢复、重试，直接采集这几条观察。

交付物的几个边界

给评审一条命令、样本清单、基线和候选版本、故障开关、预期报告，并注明缺证据、拦截和放行各自含义。修复后新建候选记录复跑；不能覆盖最初的失败报告。

复现失败

正在确认却写了一次
怎么触发：候选在 ask 场景报告实际写入一行。
怎么判断：定位 ask，明确阻断。
补了一条正确动作却漏采轨迹
怎么触发：撤掉 trace_required 的轨迹证据。
怎么判断：结果仍需复核，不能宣布修复。
丢回执后的错误重试
怎么触发：把 lost_reply 最终记录数改为 2。
怎么判断：请求重试次数正确仍然阻断，查幂等边界。

写下这些测试断言

  • 可以复跑最小样本和故障变体。
  • 真实副作用行数独立检查。
  • 操作违规高于其他绿灯。
  • 修复前后按同一数据集和规则比较并保留两份报告。

这一课带走：毕业验收是可复跑、有信号、有边界的证据，不是任选一套框架或展示一次绿灯。
