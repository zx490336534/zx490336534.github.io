🔍 kuai-service 架构深度追踪

深度 从 Controller 到 Mapper，追踪完整的请求处理链路

🏗️ 三层架构总览

kuai-service 遵循经典的 Controller → Service → Mapper 三层架构：

HTTP 请求 → Controller → Service → Mapper (MySQL) Service → MongoTemplate (MongoDB) Service → 外部 API (FastGPT/企微)
层级职责所在包
Controller接收 HTTP 请求，参数校验，调用 Service，返回统一 Resultcom.qunhe.kuai.controller
Service核心业务逻辑，事务管理，异步任务编排com.qunhe.kuai.Service
Mapper数据访问，SQL/查询定义com.qunhe.kuai.mapper + mapper.fastGpt

📝 调用链 1：Prompt 管理

以"创建提示词"为例，追踪完整的请求流程：

PromptController.createPrompt()
  │ POST /api/sso/prompts
  │ SsoSessionUtil.getUserInfo() → 获取当前用户
  │
  ├→ PromptService.createPrompt(request, currentUser)
  │   构建 Prompt 实体，设置创建人/时间
  │  
  │   ├→ PromptMapper.insert(prompt) // MySQL 插入
  │   └→ 返回 Prompt 对象（含自增 ID）
  │
  └→ Result.ok({id, title, version}) → HTTP 200

其他 Prompt 相关接口遵循相同模式：

HTTP 方法路径Controller 方法说明
GET/api/promptsgetPromptList()列表查询（支持分类/关键词/状态筛选）
GET/api/prompts/{id}getPromptById()详情查询
PUT/api/sso/prompts/{id}updatePrompt()更新（需 SSO 登录）
DELETE/api/sso/prompts/{id}deletePrompt()删除（需 SSO 登录）
PUT/api/sso/prompts/{id}/publishpublishPrompt()发布

🤖 调用链 2：LLM 批量评估

这是项目中最复杂的链路，涉及异步并发和外部 API 调用：

LLMEvaluationController.batchLLMEvaluate()
  │ POST /kuai/evaluation-app/llmEvaluate/batch
  │
  ├→ LLMEvaluationService.batchLLMEvaluation(requests)
  │   1. 计算 totalCount，验证 appId
  │   2. LlmTaskMapper.insertTask() → 创建任务记录
  │   3. CompletableFuture.runAsync() → 异步执行
  │   4. 返回 taskId
  │
  │   [异步线程] executeBatchLLMEvaluationAsync()
  │     for each answer:
  │       ├→ evaluateSingleAnswer()
  │       │   ApplicationInfoMapper.findByAppId()
  │       │   EvaluationResultMapper.selectManualSatisfaction...()
  │       │   buildLLMEvaluationPrompt() → 构建评估 Prompt
  │       │   ChatService.chat() // 调用 FastGPT API
  │       │   parseScoreFromResponse() → 解析分数
  │       │   LlmEvaluationRecordMapper.insert()
  │       └→ SharedAppService.saveOrUpdateEvaluationResult()
  │
  └→ Result.ok({taskId, chatCount, message})
关键设计点
  • 异步执行：使用 @Async("llmTaskExecutor") + CompletableFuture 并发评估多个答案
  • 进度追踪：BatchTaskProgressTracker 实时更新 doneCount，前端可轮询任务状态
  • 取消机制：shouldStopTask() 检查任务状态，支持中途取消
  • 分布式锁：通过 LlmEvalLockMapper 防止同一 chatId 重复评估

💬 调用链 3：微信机器人对话

WeChatRobotController.wechatNew()
  │ POST /gpt/wechat/message
  │ @Async("myAsync") → 异步处理
  │
  ├→ RobotChatService.fastWxWechat(data)
  │   解析消息类型（文本/图片/事件）
  │  
  │   ├→ NewRobotService.getToken(messageObj)
  │   │   根据 roomId/userId + botId 查找 Token
  │   │   NewRobotMapper.list(robot) → MySQL 查询
  │   │   回退: TxBotUtil.getDefaultFastToken()
  │   │
  │   ├→ ChatService.chat(chatIns) // 调用 FastGPT
  │   │   HTTP POST → fastqa-new.example.com
  │   │
  │   └→ WeChatSendService.sendMessage() // 回复企微
  │
  └→ void（异步，无需返回值）

🔄 数据流模式

模式 1：同步请求-响应

适用于轻量查询，如获取提示词列表、分类统计。

HTTP GET → Controller → Service → Mapper.findByCondition() → Result.ok(list)
模式 2：异步任务 + 轮询

适用于耗时操作，如批量 LLM 评估。前端提交后获得 taskId，通过轮询查询进度。

POST /batch → 创建任务 → 返回 taskId → 异步执行
GET /task/{taskId} → 查询进度 {status, doneCount, totalCount, avgScore}
模式 3：Webhook 回调

适用于企业微信消息推送。企微服务器主动 POST 到 kuai-service，异步处理后回复。

企微 POST /gpt/wechat/message → @Async → 解析消息 → 调用 FastGPT → 回复企微
