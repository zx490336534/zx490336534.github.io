🏗️ 1. Prompt 管理系统架构总览

Prompt 管理系统是 kuai-service 的核心功能之一，负责管理 AI 对话的「提示词」。你可以把它理解为一个「提示词的 Git」——每个提示词有多个版本，可以创建、发布、回滚。

核心数据模型

系统由 3 张核心表组成，形成一对多的关系：

prompt（提示词主表）
  ├── id, title, description, content, category, tags
  ├── status: 1=草稿, 2=已发布, 3=已下线
  ├── currentVersion: 当前生效版本号
  └── averageRating: 平均评分

prompt_version（版本表，一个 prompt 有多个版本）
  ├── promptId → 关联 prompt.id
  ├── version: 版本号（如 "1.0.0"）
  ├── content: 该版本的 Prompt 内容
  ├── changeLog: 变更说明
  └── status: 1=开发中, 2=测试中, 3=已发布, 4=已废弃

prompt_evaluation（评估表，记录每次评估结果）
  ├── promptId, version
  ├── testScenario, inputData, outputData
  ├── evaluationMetrics (JSON), score, feedback
  └── evaluator, evaluationTime
prompt 表 → 一对多 → prompt_version 表 → 一对多 → prompt_evaluation 表

📦 2. 关键实体类详解

2.1 Prompt 实体

位于 com.qunhe.kuai.entity.Prompt，映射数据库 prompt 表：

@Data
@Table(name = "prompt")
public class Prompt extends BaseDo {
    private String title;           // 提示词标题
    private String description;     // 描述
    private String content;         // 提示词内容
    private String category;        // 分类
    private String tags;            // 标签（逗号分隔）
    private Integer status;         // 1=草稿, 2=发布, 3=下线
    private String currentVersion;  // 当前版本号
    private BigDecimal averageRating; // 平均评分
    private String createUser;      // 创建人
    private String updateUser;      // 更新人
}

2.2 PromptVersion 实体

位于 com.qunhe.kuai.entity.PromptVersion，映射 prompt_version 表：

@Data
@Table(name = "prompt_version")
public class PromptVersion extends BaseDo {
    private Integer promptId;   // 关联的 Prompt ID
    private String version;     // 版本号
    private String content;     // 该版本的 Prompt 内容
    private String changeLog;   // 变更日志
    private Integer status;     // 1=开发中, 2=测试中, 3=已发布, 4=已废弃
    private String createUser;  // 创建人
    private String updateUser;  // 更新人
}

2.3 PromptEvaluation 实体

记录每次对 Prompt 的评估结果，包含测试场景、输入输出、评分和反馈。

@Data
@Table(name = "prompt_evaluation")
public class PromptEvaluation extends BaseDo {
    private Integer promptId;          // 关联的 Prompt ID
    private String version;            // 被评估的版本号
    private String testScenario;       // 测试场景
    private String inputData;          // 输入数据
    private String outputData;         // 输出数据
    private String evaluationMetrics;  // 评估指标（JSON）
    private BigDecimal score;          // 评分
    private String feedback;           // 反馈意见
    private String evaluator;          // 评估人
    private Date evaluationTime;       // 评估时间
}

🔄 3. Prompt CRUD 流程

3.1 创建 Prompt

当用户在前端填写 Prompt 标题、描述、内容后，调用创建接口：

前端 → PromptService.createPrompt() → PromptMapper.insert() → MySQL

创建时的关键逻辑：

  • 初始状态设为 status=1（草稿）
  • 初始版本号设为 "1.0.0"
  • 平均评分初始化为 BigDecimal.ZERO
  • 自动记录 createUser 和 updateUser（从 SSO 会话获取）

3.2 读取 Prompt

通过 PromptMapper.findById(id) 查询单个提示词详情。列表查询和分类查询也通过 Mapper 完成。

3.3 更新 Prompt

更新时先查询确认存在，再逐字段设置新值，最后调用 promptMapper.update()。注意更新会修改 updateUser 字段。

3.4 删除 Prompt

系统使用逻辑删除——将 isDeleted 设为 true，而非真正从数据库删除。这是生产环境的最佳实践：

// 逻辑删除，不是物理删除
prompt.setIsDeleted(true);
prompt.setUpdateUser(currentUser);
promptMapper.update(prompt);

3.5 发布与下线

提示词有完整的生命周期：草稿 → 已发布 → 已下线。通过 status 字段控制：

  • publishPrompt()：status 从 1 改为 2
  • offlinePrompt()：status 从 2 改为 3

📋 4. 版本管理机制

4.1 版本创建

版本管理是 Prompt 系统的核心亮点。每次修改 Prompt 内容时，不直接覆盖，而是创建一个新版本：

PromptVersionController.createVersion() → PromptVersionService.createVersion() → PromptVersionMapper.insert()

创建版本的流程：

  1. 验证 Prompt 是否存在（promptMapper.findById()）
  2. 检查版本号是否重复（findByPromptIdAndVersion()）
  3. 构建 PromptVersion 实体，状态设为 1（开发中）
  4. 插入数据库并返回

4.2 版本发布

发布一个版本时，系统会做两件事：

  1. 将该版本的 status 更新为 3（已发布）
  2. 更新 Prompt 主表的 currentVersion 为该版本号，同时将 Prompt 的 status 改为 2（已发布）
// 更新版本状态为已发布
promptVersionMapper.updateStatus(versionId, 3, currentUser);
// 更新提示词的当前版本
prompt.setCurrentVersion(version.getVersion());
prompt.setStatus(2);
promptMapper.update(prompt);

4.3 版本回滚

回滚操作非常简单——只需要将 Prompt 主表的 currentVersion 指向目标版本号即可。旧版本数据都保留着，所以回滚是安全的。

// 回滚 = 把 currentVersion 指回旧版本
prompt.setCurrentVersion(version.getVersion());
prompt.setUpdateUser(currentUser);
promptMapper.update(prompt);

4.4 版本对比与 A/B 测试支持

系统的设计天然支持版本对比：

  • 版本对比：通过 getVersionList() 获取所有版本，前端可以并排展示不同版本的 content 和 changeLog
  • A/B 测试：通过 prompt_evaluation 表，可以对同一 Prompt 的不同版本进行评估，比较 score 差异。前端可以筛选 version 参数来查看特定版本的评估结果

⭐ 5. 评估与评论集成

5.1 Prompt 评估流程

PromptEvaluationController 提供了评估的完整 API：

接口方法说明
POST /sso/prompts/{promptId}/evaluations创建评估记录一次评估结果
GET /prompts/{promptId}/evaluations查询评估列表支持按 version 筛选
GET /evaluations/{id}查询评估详情获取单条评估记录

评估记录包含：测试场景、输入数据、输出数据、评估指标（JSON）、评分、反馈。这些数据可以用于：

  • 比较不同版本的效果
  • 追踪 Prompt 质量随时间的变化
  • 为 A/B 测试提供数据支撑

5.2 用户评论系统

PromptUserCommentController 提供评论功能：

接口方法说明
POST /sso/prompts/{promptId}/comments发表评论需要 SSO 登录
GET /prompts/{promptId}/comments查询评论列表返回全部评论
DELETE /comments/{commentId}删除评论仅评论人可删除

5.3 SSO 认证机制

所有写操作（创建、发布、回滚、评论）都通过 SsoSessionUtil.getUserInfo(httpRequest) 获取当前登录用户：

final UserInfo userInfo = SsoSessionUtil.getUserInfo(httpRequest);
if (userInfo == null) {
    return Result.error("用户未登录");
}
String currentUser = userInfo.getLdapId();

🌐 6. API 接口全景

Controller前缀功能
PromptVersionController/api版本的创建、列表、发布、回滚
PromptEvaluationController/api评估记录的创建、查询
PromptUserCommentController/api评论的创建、查询、删除

注意路径中的 /sso/ 前缀表示需要 SSO 登录认证的接口，而没有 /sso/ 的是公开查询接口。
