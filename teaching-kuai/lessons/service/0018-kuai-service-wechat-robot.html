🤖 微信机器人集成详解

深度 企业微信消息接收、路由、AI 对话与存储全链路

本课深入讲解 kuai-service 中企业微信机器人的完整工作流程：从接收加密消息、解密路由、调用 AI Agent 生成回复，到消息存储和流式输出。你会理解 WeChatRobotController 和 WeChatMessageController 两个核心控制器的分工与协作。

📋 前置知识

  • 依赖注入（DI） — 知道 Spring 会自动把 Bean 注入到 Controller 的成员变量中
  • JSON 处理 — 了解 JSONObject（Fastjson）的 getString/getJSONObject 用法
  • HTTP 请求/响应 — 知道 POST 请求体、请求参数（query param）、响应加密的基本概念
  • 异步编程 — 了解 @Async 和 CompletableFuture 的基本用法

🗂️ 一、两个 Controller 的分工

微信机器人功能由两个 Controller 共同完成，它们分别对接不同的企业微信应用：

Controller路径职责对接的应用
WeChatRobotController/gpt/wechat、/gpt/wechat/message接收旧版/通用微信回调，转发给 RobotChatService通用微信机器人
WeChatMessageController/kuai/wechat/message企业微信 AI 机器人的完整消息处理：校验、解密、路由、AI 对话、流式输出企业微信 AI 机器人（酷小发）

📨 二、消息接收与回复流程

2.1 整体流程

企业微信向你的服务器发送加密消息，你需要解密、处理、再加密回复。整个流程如下：

企业微信发送加密消息 → 解密消息 (WXBizMsgCrypt) → 解析消息类型 → 路由到对应处理器 → 调用 AI Agent → 加密响应返回

2.2 URL 验证（GET 请求）

企业微信首次配置回调 URL 时，会发一个 GET 请求验证你的服务器。代码位于 WeChatMessageController：

@GetMapping("/kuai/wechat/message")
public String verifyUrl(HttpServletRequest request) throws Exception {
    String decryptedMsg = decryptMessageTest(request.getParameter("echostr"));
    log.info("return is {}", decryptedMsg);
    return decryptedMsg;  // 返回解密后的 echostr 即可通过验证
}

简单来说：收到 echostr 参数 → 解密 → 原样返回，企业微信就知道你的服务器是可信的。

2.3 接收消息（POST 请求）

用户在企业微信里发消息后，企业微信会 POST 加密数据到你的服务器：

@PostMapping("/kuai/wechat/message")
public JSONObject receiveMessage(HttpServletRequest request, @RequestBody String encryptedMsg) {
    // 1. 提取签名参数
    RequestParams params = extractRequestParams(request);
    // 2. 解密消息
    String decryptedMsg = decryptMessage(encryptedMsg);
    // 3. 解析为 JSON
    JSONObject messageObj = JSONObject.parseObject(decryptedMsg);
    // 4. 根据消息类型路由到不同处理器
    // ...
}

2.4 加密与解密工具

所有消息的加解密都通过 WXBizMsgCrypt 类完成，它需要三个配置参数：

// 企业微信后台配置的三个参数
public static final String token = "gFaj7oGoeSegyiyez7gYcPHzDyD";
public static final String encodingAesKey = "xyjfgKlIi1cKGr17eB5WPOGTNRdUTLpjsoJwppeb7sD";
public static final String corpId = "wxe838eaf3a3855809";
这三个参数是企业微信应用的"钥匙"，泄露了别人就能伪造消息。生产环境应该放在配置文件或环境变量中，不要硬编码。

🔀 三、消息路由机制

解密后的消息会经过一系列"分流"判断，不同类型的消息走不同路径：

// receiveMessage 方法的核心路由逻辑
if (TxBotUtil.isStream(messageObj)) {
    // 流状态查询 — 企业微信轮询 AI 回复进度
    return handleStreamStatusRequest(messageObj, params);
}
if (handleWorkaiFeedbackEvent(messageObj, params) != null) {
    // WorkAI 反馈卡片事件（好评/差评）
    return ...;
}
if (handleChoiceCardEvent(messageObj, params) != null) {
    // 注册选择卡片事件
    return ...;
}
if (TxBotUtil.isText(messageObj)) {
    // 文本消息 — 进一步判断是注册还是普通对话
    if (content.contains("我要注册") && ...) {
        return sendChoiceCardForRegisterPrompt(messageObj, params);
    }
    // 检查是否是数字员工（WorkAI）
    if (workaiRobotConfig.isPresent()) {
        return handleDigitalEmployeeMessage(...);
    }
    // 普通 AI 对话
    return handleNewMessageRequest(messageObj, content, params);
}
if (TxBotUtil.isImage(messageObj) || TxBotUtil.isMixed(messageObj)) {
    // 图片或混合消息
    return handleImageMessageAsync(messageObj, params);
}

用表格总结消息路由：

消息类型处理方法说明
流状态查询handleStreamStatusRequest企业微信轮询 AI 回复是否完成
反馈卡片事件handleWorkaiFeedbackEvent用户点击好评/差评按钮
选择卡片事件handleChoiceCardEvent用户在注册卡片中选择选项
文本（注册）sendChoiceCardForRegisterPrompt用户发送"我要注册"
文本（数字员工）handleDigitalEmployeeMessage走 WorkAI 数字员工通道
文本（普通对话）handleNewMessageRequest调用 FastGPT Agent
图片/混合handleImageMessageAsync异步解析图片后调用 Agent

🧠 四、AI 对话集成

4.1 普通对话流程

用户发一条文本消息后，系统调用 AI Agent 生成回复。但因为 AI 生成需要时间，企业微信采用流式轮询机制：

Step 1：立即返回"思考中"

收到消息后，生成一个唯一的 appId，立即返回 {"stream": {"id": appId, "finish": false, "content": "正在思考中……"}}。企业微信收到后会开始轮询。

Step 2：异步调用 AI Agent

通过 sendToAgent() 方法，将用户消息转发给 FastGPT 或 Kuai Test Agent：

private void sendToAgent(JSONObject messageObj, String question, String appId) {
    NewRobot binding = newRobotService.getRobotBinding(messageObj);
    String userId = TxBotUtil.getUserId(messageObj);
    Map<String, String> headers = createAuthHeaders(messageObj, binding, userId);
    String requestUrl = createAgentUrl(binding);
    JSONObject requestBody = createAgentRequestBody(messageObj, question, userId, binding);

    httpUtils.sendStreamPostRequest(question, requestUrl, headers, requestBody, appId, ...);
}
Step 3：企业微信轮询获取结果

企业微信会不断调用 handleStreamStatusRequest() 查询 appId 的状态。当 AI 回复生成完毕，ConversationManager 标记为 finished，返回完整内容。

4.2 两种 AI 后端

系统支持两种 AI 后端，根据机器人的绑定配置自动选择：

AI 后端标识请求方式
FastGPT非 Kuai Test Agent发送 messages 数组到 fastgptUrl
Kuai Test AgentisKuaiTestAgent() 为 true发送 message 字符串到 binding.getFastUrl()

4.3 图片消息处理

图片消息比较特殊，因为企业微信的图片 URL 是加密的。处理流程：

  1. 先创建占位会话（确保企业微信拿到可轮询的 stream id）
  2. 异步解析图片：如果是企业微信加密图片（URL 包含 ww-aibot-img-），先解密再上传 CDN
  3. 将 CDN 链接拼接后发给 AI Agent
// 判断是否是企业微信加密图片
private boolean isWechatEncryptedImageUrl(String imageUrl) {
    return imageUrl.contains("ww-aibot-img-");
}

💾 五、消息存储与查询

5.1 消息存储

当 AI 回复完成后，系统会将消息存入数据库，并在回复末尾追加"好评/差评"链接：

// handleStreamStatusRequest 中的存储逻辑
WeChatMessage weChatMessage = chatHistoryService.insertWechatMessage(
    userId, status.getQuestion(), streamContent, robotNick, "");
if (weChatMessage != null) {
    streamContent = append(weChatMessage.getId(), streamContent);
}

append() 方法会在回复末尾拼上好评和差评的评分链接：

public String append(Integer messageId, String res) {
    String good = "[😀好评](https://kuai.example.com/gpt/chat/wechat/score?chatId=...&score=3)";
    String bad  = "[🙁差评](https://kuai.example.com/gpt/chat/wechat/score?chatId=...&score=1)";
    return res + "\n" + good + "       " + bad;
}

5.2 故障复盘文档的消息查询

当用户发送"生成故障复盘文档"关键词时，系统会查询该用户的历史消息作为上下文：

// 通过用户 ID 和消息内容查找房间 ID
String roomId = weChatMessageHistoryMapper.findRoomIdByUserAndContent(userId, question);
// 查询该房间的历史消息
List<WeChatMessageEntity> messageList = weChatMessageHistoryMapper.selectByRoomId(roomId);
这种设计让用户可以直接在微信中触发故障复盘，系统自动拉取历史对话作为上下文，非常方便。

📝 七、Quiz

Q1：当企业微信首次配置回调 URL 时，服务器需要怎么回应？
  1. A. 直接返回 200 状态码
  2. B. 将收到的 echostr 解密后原样返回
  3. C. 返回一个 JSON 对象 {"ok": true}
  4. D. 返回 HTML 页面
✅ 答案：B。企业微信会发送一个 GET 请求，携带 echostr 参数，服务器需要解密后原样返回。
Q2：为什么 AI 回复采用"流式轮询"而不是直接返回？
  1. A. 因为企业微信不支持直接返回长文本
  2. B. 因为 AI 生成需要时间，直接等待会导致企业微信超时重试
  3. C. 因为流式轮询更省带宽
  4. D. 因为这是企业微信强制要求的方式
✅ 答案：B。AI 生成可能需要几秒到几十秒，企业微信有超时限制。采用流式轮询可以先返回"思考中"，然后企业微信不断查询进度，避免超时。
Q3：handleImageMessageAsync 方法中为什么要先创建"占位会话"？
  1. A. 为了在数据库中记录图片消息
  2. B. 为了确保企业微信马上拿到可轮询的 stream id，避免超时重试
  3. C. 为了压缩图片大小
  4. D. 为了验证用户权限
✅ 答案：B。图片解析（解密、上传 CDN）是耗时操作。先创建占位会话返回 stream id，企业微信就可以开始轮询，等图片处理完成后再更新会话内容。
