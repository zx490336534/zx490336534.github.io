🏗️ 1. LLM 评估系统架构总览

LLM 评估系统是 kuai-service 的「AI 质检中心」。它的核心任务是：用 AI 来评估 AI 的回答质量。

系统提供两套评估引擎：

  • LLM 评估（LLMEvaluationService）：调用自定义 LLM 模型对 QA 对进行打分
  • DeepEval 评估（DeepEvalEvaluationService）：集成开源 DeepEval 框架，支持更丰富的评估指标

核心数据模型

application_info（应用信息表）
  ├── appId, appName, appType
  ├── owner（负责人）
  └── customLlmModel（自定义评估模型）

llm_task（LLM 批量评估任务表）
  ├── id, taskId, appId
  ├── totalCount（总评估条数）
  ├── doneCount（已完成条数）
  ├── status: 0=待开始, 1=运行中, 2=成功, 3=失败, 4=已取消
  ├── avgScore（平均分）
  └── startTime, endTime

deep_eval_task（DeepEval 批量评估任务表，结构类似 llm_task）

llm_evaluation_record（评估记录表）
  ├── taskId, appId, chatId
  ├── question, answer（问题和答案）
  ├── llmAnswer（LLM 的评估回答原文）
  ├── llmScore（LLM 打分）
  ├── deepEvalScore（DeepEval 打分）
  ├── satisfaction（人工满意度）
  └── category1, category2（分类标签）

evaluation_result（评估结果汇总表，MySQL）
application_info → 关联 → llm_task / deep_eval_task → 一对多 → llm_evaluation_record

🚀 2. 评估任务创建流程

2.1 单次评估

单次评估适用于快速测试，同步执行：

LLMEvaluationController.evaluateApplicationDialog() → LLMEvaluationService.getLLMEvaluation() → evaluateSingleAnswer()（并发评估每条 QA）

单次评估使用数据库锁防止同一 chatId 被重复评估：

// 释放超时锁（超过60分钟的锁自动释放）
llmEvalLockMapper.releaseTimeoutLockByChatId(chatId, 60);
// 检查是否已锁定
if (llmEvalLockMapper.isLocked(chatId) > 0) {
    throw new RuntimeException("该对话的 LLM 评估任务正在执行中");
}
// 新建锁
llmEvalLockMapper.insertLock(chatId, new Date(), totalCount, 1);

2.2 批量评估

批量评估是系统的核心功能，流程如下：

  1. 创建任务：计算总评估条数，插入 llm_task 记录，获取自增 ID 作为 taskId
  2. 异步执行：通过 CompletableFuture.runAsync() 提交到 taskExecutor 线程池
  3. 并发评估：为每条 QA 创建独立的 CompletableFuture，提交到 workerExecutor 线程池
  4. 进度追踪：通过 BatchTaskProgressTracker 实时更新 doneCount
  5. 结果汇总：所有任务完成后计算平均分，更新任务状态
// 创建任务记录
LlmTask task = LlmTask.builder()
        .appId(appId)
        .totalCount(totalCount)
        .doneCount(0)
        .status(0) // 待开始
        .build();
llmTaskMapper.insertTask(task);
String taskId = String.valueOf(task.getId());

// 异步执行
CompletableFuture.runAsync(
    () -> executeBatchLLMEvaluationAsync(taskId, requests),
    taskExecutor
);

2.3 按筛选条件批量评估

除了手动指定 QA 列表，系统还支持通过筛选条件自动拉取 QA 并评估：

POST /kuai/evaluation-app/llmEvaluate/batch-by-filter
// 请求体：BatchEvaluationFilterRequest 包含 appId、分类、满意度等筛选条件

⚡ 3. 异步任务处理机制

3.1 双层线程池架构

系统使用两层线程池来控制并发：

线程池Bean 名称用途
任务执行器llmTaskExecutor / deepEvalTaskExecutor执行整个批量任务（只运行 1 个任务）
工作执行器llmEvalWorkerExecutor / deepEvalWorkerExecutor执行单条 QA 评估（并发多个）

这种设计的好处：外层线程池控制任务级别并发（避免同时跑太多批量任务），内层线程池控制单条评估的并发（避免打爆 LLM API）。

3.2 任务状态机

0: 待开始 → 1: 运行中 → 2: 成功

1: 运行中 → 3: 失败

0 或 1 → cancel → 4: 已取消

3.3 任务取消机制

系统通过 shouldStopTask() 方法检查任务是否被取消。在每个评估步骤前后都会检查：

// 在遍历请求和评估单个答案前都检查
if (shouldStopTask(taskId)) {
    return; // 跳过执行
}

📊 4. 进度追踪 — BatchTaskProgressTracker

BatchTaskProgressTracker 是一个精巧的进度追踪工具，核心设计：

public class BatchTaskProgressTracker {
    private static final int FLUSH_INTERVAL = 5;  // 每完成5条刷一次数据库
    private static final int MAX_DB_RETRY = 5;     // 最多重试5次

    public void onItemComplete() {
        int done = doneCounter.incrementAndGet();
        // 每完成5条 或 全部完成时，才写数据库
        if (done - lastFlushed >= FLUSH_INTERVAL || done >= totalCount) {
            flushProgress(done);
        }
    }
}

设计亮点：

  • 批量刷盘：不是每完成 1 条就写数据库，而是每 5 条刷一次，大幅减少数据库压力
  • 重试机制：数据库写入失败时自动重试（最多 5 次），识别瞬态错误（连接超时、连接池不可用等）
  • 线程安全：使用 AtomicInteger 计数，synchronized 刷盘

🔬 5. DeepEval 集成详解

5.1 什么是 DeepEval？

DeepEval 是一个开源的 LLM 评估框架，提供多种评估指标（如 AnswerRelevancyMetric、GEval_Coherence）。kuai-service 通过 HTTP 调用 kuai-service-py（Python MCP 服务）来执行 DeepEval 评估。

5.2 同步 vs 异步模式

DeepEval 支持两种调用模式，通过 kuai.deepeval.async-enabled 配置切换：

模式调用方式适用场景
同步模式直接 POST 到 /evaluation/evaluate/direct单条评估、快速响应
异步模式先提交到 /evaluation/evaluate/async，再轮询任务状态批量评估、耗时较长

5.3 异步轮询机制

异步模式下，Java 端通过轮询检查 Python 服务的任务状态：

while (System.currentTimeMillis() < deadline) {
    // 1. 检查是否需要取消
    if (taskId != null && shouldStopTask(taskId)) {
        cancelDeepEvalTask(pyTaskId);
        return null;
    }
    // 2. 等待 pollInterval（默认 2 秒）
    TimeUnit.MILLISECONDS.sleep(deepEvalPollIntervalMs);
    // 3. 查询状态
    HttpClientResult statusResult = getDeepEvalStatus(statusUrl);
    // 4. 解析状态：completed/failed/canceled/running
}

5.4 评估请求体构建

DeepEval 请求体包含问题、答案、上下文、人工标注等信息：

{
  "q": "用户问题",
  "a": "AI回答",
  "context": "上下文信息",
  "humanWeight": 2.0,
  "alignmentWeight": 1.0,
  "humanAnnotations": [
    {"answer": "历史标准答案", "score": 8.0}
  ],
  "scenario": "rag",
  "metrics": ["AnswerRelevancyMetric", "GEval_Coherence"]
}

✍️ 6. LLM 评估提示词构建

LLM 评估的核心是 buildLLMEvaluationPrompt() 方法，它构建了一个详细的评估提示词：

# 任务说明
你是 AI 回答质量评估专家。请结合人工标注信息，判断待评估答案是否满足用户预期。

# 待评估问答
**问题**: {question}
**答案**: {answer}

# 当前条目人工标注（优先参考）
- 人工满意度: 非常满意/满意/一般/不满意
- 人工标准答案: ...
- 人工备注: ...

# 同类问题历史人工标注（参考）
**历史样本 1**: ...

# 评分标准
- 非常满意/满意：7-10 分
- 一般：4-6 分
- 不满意：0-4 分

# 输出要求
仅输出一个 0-10 的数字分数

这个提示词的设计非常精妙：

  • 结合人工标注来校准 AI 评分
  • 参考同类问题的历史标注（最多 5 条）
  • 明确的评分区间约束
  • 要求只输出数字，方便解析

📋 7. 评估结果查询与导出

7.1 API 接口一览

接口说明
GET /llmEvaluate/tasks获取任务列表（分页）
GET /llmEvaluate/task/{taskId}查询单个任务状态和统计
GET /llmEvaluate/task/{taskId}/details获取任务下所有评估记录
POST /llmEvaluate/task/{taskId}/details/page分页查询评分明细（支持筛选排序）
POST /llmEvaluate/task/{taskId}/exportCsv导出评分明细为 CSV 文件
POST /llmEvaluate/task/{taskId}/cancel取消正在运行的任务
POST /llmEvaluate/task/{taskId}/delete删除任务及其评估记录

7.2 CSV 导出

CSV 导出功能会生成包含以下字段的文件：

  • 会话链接、会话 ID、应用 ID
  • 一级分类、二级分类、人工满意度
  • 问题、AI 回答、LLM 得分、DeepEval 得分

注意 CSV 文件使用 UTF-8 BOM 编码（\uFEFF），确保 Excel 正确识别中文。
