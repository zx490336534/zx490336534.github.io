🛠️ kuai-service 开发实战指南

实战 从零上手 kuai-service 后端开发

本课聚焦实战：如何新增 Controller 接口、如何新增 Service 层、本地运行命令、调试技巧和常见排查路径。学完即可动手开发小功能。

📡 一、新增 Controller 接口

kuai-service 使用 Spring Boot + MyBatis-Plus，Controller 层负责接收 HTTP 请求并调用 Service。

Step 1：创建 Controller 类

在 src/main/java/.../controller/ 目录下新建文件：

@RestController
@RequestMapping("/api/example")
public class ExampleController {

    @Autowired
    private ExampleService exampleService;

    /**
     * GET /api/example/list
     * 获取示例列表
     */
    @GetMapping("/list")
    public Result<List<ExampleDTO>> list(
            @RequestParam(required = false) String keyword,
            @RequestParam(defaultValue = "1") Integer page,
            @RequestParam(defaultValue = "10") Integer size
    ) {
        return Result.success(exampleService.listByKeyword(keyword, page, size));
    }

    /**
     * POST /api/example/create
     * 创建新记录
     */
    @PostMapping("/create")
    public Result<ExampleDTO> create(@RequestBody @Valid ExampleCreateReq req) {
        return Result.success(exampleService.create(req));
    }
}
Step 2：定义请求体 DTO
@Data
public class ExampleCreateReq {
    @NotBlank(message = "名称不能为空")
    private String name;
    private String description;
    private Integer status;
}
Step 3：统一返回格式

所有接口使用 Result<T> 包装返回值：

// 成功
Result.success(data)

// 失败
Result.error(ErrorCode.PARAM_ERROR, "参数错误")
注意：新增的接口路径不要与已有路径冲突。使用 @Valid 注解启用参数校验。

⚙️ 二、新增 Service

Service 层封装业务逻辑，调用 Mapper（MyBatis-Plus）操作数据库。

Step 1：定义 Service 接口
public interface ExampleService extends IService<ExampleEntity> {
    List<ExampleDTO> listByKeyword(String keyword, Integer page, Integer size);
    ExampleDTO create(ExampleCreateReq req);
}
Step 2：实现 Service
@Service
public class ExampleServiceImpl extends ServiceImpl<ExampleMapper, ExampleEntity>
        implements ExampleService {

    @Override
    public List<ExampleDTO> listByKeyword(String keyword, Integer page, Integer size) {
        LambdaQueryWrapper<ExampleEntity> wrapper = new LambdaQueryWrapper<>();
        if (StringUtils.isNotBlank(keyword)) {
            wrapper.like(ExampleEntity::getName, keyword);
        }
        wrapper.orderByDesc(ExampleEntity::getCreateTime);
        Page<ExampleEntity> pageResult = page(new Page<>(page, size), wrapper);
        return pageResult.getRecords().stream()
                .map(this::toDTO)
                .collect(Collectors.toList());
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public ExampleDTO create(ExampleCreateReq req) {
        ExampleEntity entity = new ExampleEntity();
        BeanUtils.copyProperties(req, entity);
        entity.setCreateTime(new Date());
        save(entity);
        return toDTO(entity);
    }

    private ExampleDTO toDTO(ExampleEntity entity) {
        ExampleDTO dto = new ExampleDTO();
        BeanUtils.copyProperties(entity, dto);
        return dto;
    }
}
Step 3：定义 Mapper
@Mapper
public interface ExampleMapper extends BaseMapper<ExampleEntity> {
    // MyBatis-Plus 自动提供 CRUD 方法
    // 如需自定义 SQL，在 resources/mapper/ 下编写 XML
}
约定：Mapper XML 文件放在 src/main/resources/mapper/ 目录，与 Mapper 接口同名。

🚀 三、本地运行命令

命令说明
mvn spring-boot:run启动开发服务器（默认端口 8080）
mvn clean package -DskipTests跳过测试打包
mvn test运行单元测试
mvn compile仅编译，检查语法错误

环境配置

  • 配置文件：src/main/resources/application.yml（或 application-local.yml）
  • 数据库连接：修改 spring.datasource 配置项
  • 端口配置：server.port=8080
  • 日志级别：logging.level.root=INFO，开发时可改为 DEBUG

🔍 四、调试技巧

1. 日志调试

// 在 Service/Controller 中使用 Slf4j 日志
@Slf4j
@Service
public class ExampleServiceImpl {
    public void doSomething() {
        log.info("开始处理请求, param={}", param);
        log.debug("详细调试信息: {}", detail);
        log.error("处理失败: {}", e.getMessage(), e);
    }
}

2. 接口测试工具

  • Swagger/Knife4j：访问 /doc.html 在线调试接口
  • Postman：导入接口集合进行测试
  • curl：快速命令行测试
# 测试 GET 请求
curl http://localhost:8080/api/example/list?keyword=test

# 测试 POST 请求
curl -X POST http://localhost:8080/api/example/create \
  -H "Content-Type: application/json" \
  -d '{"name":"test","description":"desc"}'

3. 断点调试

  • IDEA 中在行号左侧点击设置断点
  • 使用 Debug 模式启动（而非 Run）
  • Step Over (F8)：跳过当前行
  • Step Into (F7)：进入方法内部
  • Evaluate Expression (Alt+F8)：查看/修改变量值

4. 热部署

添加 spring-boot-devtools 依赖，修改代码后自动重启（需在 IDEA 中开启自动编译）。

🧩 五、常见排查路径

问题排查路径
接口返回 404 1. 检查 @RequestMapping 路径是否正确
2. 检查 Controller 是否在 @ComponentScan 扫描范围内
3. 检查方法注解（@GetMapping / @PostMapping）
接口返回 500 1. 查看控制台异常堆栈
2. 检查 Service 层是否有 NPE
3. 检查数据库连接和 SQL
参数校验不生效 1. 确认 DTO 上有 @Valid 注解
2. 确认字段上有校验注解（@NotBlank 等）
3. 确认 Controller 参数有 @RequestBody
MyBatis SQL 异常 1. 开启 SQL 日志：logging.level.mapper包名=DEBUG
2. 检查实体类字段与数据库列映射
3. 检查 XML 中 SQL 语法
启动报 Bean 注入失败 1. 检查 @Service / @Mapper 注解是否遗漏
2. 检查包路径是否在启动类所在包的子包下
3. 检查循环依赖
遇到不懂的地方？直接问 Agent。比如："帮我排查 MyBatis-Plus 查询返回空列表的问题" 或 "Spring Boot 启动报 BeanCreationException 怎么解决"。

📝 Quiz

Q1：在 kuai-service 中，新增 Controller 接口时，统一的返回值包装类是什么？

  • A. ResponseEntity
  • B. Result<T>
  • C. ApiResponse
  • D. JsonResult

✅ 答案：B. Result<T> — 项目使用统一的 Result 类包装所有接口返回值。

Q2：MyBatis-Plus 的 ServiceImpl 已经内置了哪些常用方法？

  • A. 只有 save 和 remove
  • B. save、removeById、updateById、getById、list、page 等
  • C. 需要自己写所有 SQL
  • D. 只有查询方法

✅ 答案：B — ServiceImpl 提供了完整的 CRUD 方法，无需额外编写。

Q3：Spring Boot 中如何开启 SQL 日志以便调试 MyBatis 查询？

  • A. 在代码中使用 System.out.println 打印 SQL
  • B. 配置 logging.level.你的Mapper包路径=DEBUG
  • C. 修改 MyBatis 源码
  • D. 无法查看 SQL 日志

✅ 答案：B — 在 application.yml 中设置 Mapper 包的日志级别为 DEBUG 即可。
