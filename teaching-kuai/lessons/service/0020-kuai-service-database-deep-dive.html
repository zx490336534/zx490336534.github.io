🏛️ 1. 双数据库架构总览

kuai-service 同时使用 MySQL 和 MongoDB 两种数据库，各有分工：

MySQL — 结构化数据 + MongoDB — 文档型数据 = kuai-service 数据层
数据库存储内容访问方式典型表/集合
MySQL 评估结果、任务状态、机器人配置等结构化业务数据 MyBatis-Plus（BaseMapper）+ XML/注解 SQL evaluation_result、llm_task、workaiwechatrobot
MongoDB 应用信息、会话记录、用户数据等来自 FastGPT 平台的数据 Spring Data MongoDB（MongoTemplate + MongoRepository） apps、chats、chatitems、teams、users
设计思路

MongoDB 中的数据大多来自 FastGPT 平台（共享同一个 MongoDB 实例），kuai-service 通过 TDDL（阿里的分布式数据库中间件）直连读取。MySQL 中的数据是 kuai-service 自己产生的业务数据（评估记录、任务管理等）。

🐬 2. MySQL 表设计详解

2.1 evaluation_result 表（评估结果表）

这是系统最核心的 MySQL 表，存储每条 QA 对的评估数据：

-- evaluation_result 表结构
CREATE TABLE evaluation_result (
    id              INT AUTO_INCREMENT PRIMARY KEY,  -- 自增主键
    app_id          VARCHAR(64),      -- 应用ID
    chat_id         VARCHAR(64),      -- 会话ID
    _id             VARCHAR(64),      -- 关联 MongoDB chatitems 的 _id
    q               TEXT,             -- 用户问题（Question）
    a               TEXT,             -- AI 回答（Answer）
    satisfaction    VARCHAR(32),      -- 人工满意度：very_satisfied/satisfied/neutral/unsatisfied/invalid
    standard_answer TEXT,             -- 标准答案
    llm_score       DOUBLE,           -- LLM 自动评分
    deepEval_result TEXT,             -- DeepEval 评估结果详情
    deepEval_score  DOUBLE,           -- DeepEval 评分
    comment         TEXT,             -- 人工评论
    created         DATETIME,         -- 创建时间
    lastmodified    DATETIME          -- 最后修改时间
);

对应实体类与 Mapper

// Entity: 使用 @Table 注解映射 MySQL 表
@Table(name = "evaluation_result")
public class EvaluationResult extends BaseDo {
    private Integer id;
    private String appId;
    private String chatId;
    private String _id;
    private String q;
    private String a;
    private String satisfaction;
    private String standardAnswer;
    private Double llmScore;
    private String deepEvalResult;
    private Double deepEvalScore;
    private String comment;
}

// Mapper: 使用 @Select 注解写 SQL
@Mapper
public interface EvaluationResultMapper extends BaseMapper<EvaluationResult> {

    @Select("SELECT id, app_id AS appId, chat_id AS chatId, _id, q, a, "
          + "satisfaction, standard_answer AS standardAnswer, ... "
          + "FROM evaluation_result "
          + "WHERE app_id = #{appId} AND chat_id = #{chatId}")
    List<EvaluationResult> selectByAppIdAndChatId(
        @Param("appId") String appId,
        @Param("chatId") String chatId);
}

2.4 Mapper 中的高级 SQL 技巧

EvaluationResultMapper 中有一些值得学习的 SQL 模式：

// 动态 SQL（MyBatis XML 语法嵌入注解）
@Select({
    "<script>",
    "SELECT",
    "  IFNULL(AVG(llm_score), 0) AS avgLlmScore,",
    "  SUM(IF(satisfaction = 'very_satisfied', 1, 0)) AS verySatisfiedCount,",
    "  SUM(IF(satisfaction = 'satisfied', 1, 0)) AS satisfiedCount,",
    "  ...",
    "FROM evaluation_result",
    "WHERE 1 = 1",
    "<if test='appId != null and appId != \"\"'>",
    "  AND app_id = #{appId}",
    "</if>",
    "<if test='chatId != null and chatId != \"\"'>",
    "  AND chat_id = #{chatId}",
    "</if>",
    "</script>"
})
EvaluationStats selectEvaluationStats(@Param("appId") String appId,
                                      @Param("chatId") String chatId);

这段 SQL 用了几个高级技巧：

  • IFNULL(AVG(...), 0)：如果没数据返回 0 而不是 NULL
  • IF(condition, 1, 0)：条件计数，统计各满意度等级的数量
  • <if> 动态 SQL：根据参数是否为空动态拼接 WHERE 条件
  • <foreach> 集合遍历：将 List 参数转为 SQL 的 IN 子句

// Spring Data MongoDB 的 Repository 接口
public interface AppsSetRepository extends MongoRepository<Apps, String> {

    List<Apps> findByObjectIdIn(List<ObjectId> ids);

public interface ChatRepository extends MongoRepository<Chats, String> {

3.4 ObjectId 类型处理

一个需要注意的细节：MongoDB 的 _id 是 ObjectId 类型，但在 Java 中经常用 String 接收。代码中经常需要互相转换：

// String → ObjectId（查询时）
ObjectId appObjectId = new ObjectId(query.getAppId());

// ObjectId → String（DTO 输出时）
List<ObjectId> objectIds = sharedAppIds.stream()
    .map(ObjectId::new)      // String → ObjectId
    .collect(Collectors.toList());

List<Apps> apps = appsSetRepository.findByObjectIdIn(objectIds);

⚙️ 4. TDDL 配置与数据源

TDDL（Taobao Distributed Data Layer）是阿里巴巴开源的分布式数据库中间件，在 kuai-service 中负责管理数据库连接。

4.1 数据源架构

kuai-service → TDDL → MySQL 主库 / MySQL 从库

TDDL 提供了以下核心能力：

  • 读写分离：写操作走主库，读操作走从库
  • 分库分表：数据量大时自动路由到不同的库/表
  • 连接池管理：复用数据库连接，避免频繁建连
  • 故障转移：主库故障时自动切换到从库

软删除设计

所有表都有 isDeleted 字段。删除数据时并不真正删除，而是将 isDeleted 设为 1。查询时需要加 WHERE isDeleted = 0 条件，如：

@Select("SELECT ... FROM workaiwechatrobot WHERE isDeleted = 0 ORDER BY updateTime DESC")
List<WorkaiWechatRobot> findActive();
