🗄️ 1. 知识库数据模型

知识库是 Kuai 平台的核心功能之一，底层对接 FastGPT 知识库系统。KnowledgeBase.java 是一个工具类，负责构造创建知识库和文件夹的 JSON 请求体。

1.1 KnowledgeBase 类结构

// 文件：com.qunhe.kuai.Service.KnowledgeBase
public class KnowledgeBase {

  // 创建知识库
  public static JSONObject createKnowledgeBase(String name, String parentId) {
    JSONObject knowledgeBase = new JSONObject();
    knowledgeBase.put("avatar", "/icon/logo.svg");       // 头像
    knowledgeBase.put("name", name);                      // 知识库名称
    knowledgeBase.put("tags", new String[] {});           // 标签数组（初始为空）
    knowledgeBase.put("vectorModel", "text-embedding-3-small"); // 向量模型
    knowledgeBase.put("type", "dataset");                 // 类型：数据集
    knowledgeBase.put("parentId", parentId);              // 父目录ID
    return knowledgeBase;
  }

  // 创建文件夹
  public static JSONObject createFolder(String name, String parentId) {
    JSONObject folder = new JSONObject();
    folder.put("parentId", parentId);
    folder.put("name", name);
    folder.put("type", "folder");                         // 类型：文件夹
    folder.put("avatar", "/imgs/files/folder.svg");
    folder.put("tags", new String[] {});
    return folder;
  }
}

1.2 数据模型字段说明

字段类型说明
nameString知识库或文件夹的名称
avatarString图标路径（数据集用 logo.svg，文件夹用 folder.svg）
tagsString[]标签数组，用于分类标记，创建时默认为空
vectorModelString向量化模型名，如 text-embedding-3-small（仅数据集需要）
typeString"dataset"（知识库）或 "folder"（文件夹）
parentIdString父目录 ID，空字符串表示根目录

1.3 设计要点

  • 静态工厂模式：所有方法都是 static，不需要实例化，直接调用即可构造 JSON
  • parentId 机制：支持树形目录结构。根目录创建时 parentId 传空字符串 ""
  • 向量模型绑定：每个知识库在创建时就绑定了 embedding 模型，后续文档切片都会用此模型向量化

🔗 2. 分享应用管理

SharedAppService 是系统中最大的 Service 类之一（超过 2700 行），负责管理所有分享应用的查询、统计和导出。

2.1 分享类型

每个应用可以有两种分享方式：

应用（App） → API 分享（OpenApis） + 页面分享（Outlinks） 
// SharedAppDto —— 分享应用的数据传输对象
public class SharedAppDto {
  private String appId;           // 应用ID
  private String appName;         // 应用名称
  private String version;         // 版本号（如 v1.0.0）
  private LocalDateTime versionPublishTime;  // 版本发布时间
  private String userId;          // 用户ID
  private String username;        // 用户名
  private List<String> shareTypes;      // ["API"] 或 ["PAGE"] 或 ["API", "PAGE"]
  private ApiShareInfo apiShareInfo;    // API 分享信息
  private PageShareInfo pageShareInfo;  // 页面分享信息

  public static class ApiShareInfo {
    private String apiKey;        // API 密钥
    private String openApiId;     // OpenApi 记录ID
  }

  public static class PageShareInfo {
    private String shareId;       // 分享链接ID
    private String outlinkId;     // Outlink 记录ID
  }
}

2.2 查询流程

获取分享应用列表的核心方法 getSharedApps() 的执行流程：

Step 1: getSharedAppIds()
        ├── 查询 OpenApis 集合 → 获取有 API 分享的 appId
        └── 查询 Outlinks 集合 → 获取有页面分享的 appId
        → 合并去重得到 sharedAppIds

Step 2: appsSetRepository.findByObjectIdIn(objectIds)
        → 根据 appId 列表查询 MongoDB apps 集合的应用信息

Step 3: filterAppsWithValidTmb(allSharedApps)
        → 过滤掉 TMB（团队成员）已不存在的应用

Step 4: filterAppsByKeyword(validApps, keyword)
        → 按应用名称关键字过滤（不区分大小写）

Step 5: 手动分页 + 转换为 SharedAppDto

2.3 数据关联关系

Apps → teamId → Teams → ownerId → Users

获取用户信息时需要经过三步关联查询：Apps → Teams → Users。代码中用 批量查询 + Map 缓存 的方式优化性能：

// 批量查询优化：一次查完，避免 N+1 问题
private BatchQueryMaps buildBatchQueryMaps(List<String> appIds) {
    // 1. 提取所有 teamId
    Set<String> teamIds = apps.stream().map(Apps::getTeamId).collect(...);
    // 2. 一次查询所有团队
    List<Teams> teams = teamsRepository.findBy_idIn(new ArrayList<>(teamIds));
    // 3. 提取所有 ownerId
    Set<String> ownerIds = teams.stream().map(Teams::getOwnerId).collect(...);
    // 4. 一次查询所有用户
    List<Users> users = newUsersRepository.findBy_idIn(new ArrayList<>(ownerIds));
    // 5. 构建 Map 方便后续快速查找
    return new BatchQueryMaps(usersMap, teamsMap);
}

🏷️ 3. 标签分类系统

系统支持对会话（Chat）进行一级分类和二级分类的标签管理，用于满意度分析和质量评估。

3.1 分类变量机制

分类信息存储在 MongoDB 的 chats 集合中的 variables 字段里：

// MongoDB chats 集合中的文档结构
{
  "_id": ObjectId("..."),
  "appId": ObjectId("..."),
  "chatId": "chat_abc123",
  "title": "用户关于XX的咨询",
  "variables": {
    "wBf9rrpa": "售前咨询",    // 一级分类变量（key 由系统生成）
    "gzcXRBWd": "产品功能"     // 二级分类变量
  },
  "updateTime": ISODate("2024-01-15T10:30:00Z")
}

3.2 默认分类 Key

系统预定义了两组默认分类 key：

// SharedAppService 中的默认分类 key
private static final List<String> DEFAULT_CATEGORY1_KEYS = Arrays.asList(
    "wBf9rrpa", "oNdgIreo", "iYsqB3zV", "w0GtoKxz", "lgrmlnI6", "kGZKzDZw");
private static final List<String> DEFAULT_CATEGORY2_KEYS = Arrays.asList(
    "gzcXRBWd", "sxnzXgRY", "wWhZGXCo", "duAz9TdU", "rTNy6CFm", "qy1KAChw");

这些 key 是 variables 中存放一、二级分类值的变量名。不同应用可能用不同的 key，所以代码会先尝试自动推断，再 fallback 到默认值。

3.3 分类选项查询

// Controller 层：POST /kuai/shared-apps/categoryOptions
@PostMapping("/categoryOptions")
public JSONObject categoryOptions(@RequestBody Map<String, Object> body) {
    String appId = (String) body.get("appId");
    String category1Key = (String) body.get("category1Key");

🔍 4. MongoDB 聚合查询实战

SharedAppService 大量使用 MongoTemplate 进行查询，是学习 MongoDB 查询的好范例。

4.1 条件查询（Criteria）

// 构建查询条件
Criteria criteria = Criteria.where("appId").is(appObjectId);

// 排除评估对话（正则匹配）
criteria.and("chatId").regex("^(?!EVAL-)");

// 时间范围筛选
if (query.getDateStart() != null && query.getDateEnd() != null) {
    criteria.and("updateTime").gte(query.getDateStart()).lte(query.getDateEnd());
}

// 标题模糊搜索
if (query.getChatSearch() != null) {
    Pattern pattern = Pattern.compile(searchText, Pattern.CASE_INSENSITIVE);
    criteria.and("title").regex(pattern);
}

// Variables 键值对匹配
applyVariablesCriteria(criteria, query.getVariables());

4.2 分页查询

// 带排序、分页、限制的查询
Query mongoQuery = new Query(criteria)
    .with(new Sort(Sort.Direction.DESC, "updateTime"))  // 按更新时间倒序
    .skip((pageNum - 1) * pageSize)                      // 跳过前面的页
    .limit(pageSize);                                    // 每页大小

List<Chats> chatList = mongoTemplate.find(mongoQuery, Chats.class);
long total = mongoTemplate.count(new Query(criteria), Chats.class);

4.3 常用查询模式总结

模式代码说明
精确匹配Criteria.where("field").is(value)字段等于指定值
正则匹配criteria.and("field").regex(pattern)正则表达式匹配
范围查询.gte(min).lte(max)大于等于、小于等于
排序Sort(Direction.DESC, "field")按字段降序
分页.skip(offset).limit(size)跳过 + 限制
计数mongoTemplate.count(query, Class)统计匹配文档数

4.4 Chats 文档模型（MongoDB 集合）

@Document(collection = "chats")
public class Chats {
    @Id
    private String _id;                        // MongoDB ObjectId
    private ObjectId appId;                    // 所属应用ID
    private String chatId;                     // 会话唯一标识
    private String title;                      // 会话标题
    private Map<String, Object> metadata;     // 元数据
    private Map<String, Object> variables;    // 变量（含分类信息）
    private String source;                     // 来源
    private String teamId;                     // 团队ID
    private Date updateTime;                   // 更新时间

    @Transient                                 // 不持久化到 MongoDB
    private EvaluationStats stats;             // 评估统计（从 MySQL 查）
    @Transient
    private LlmEvalLock llmEvalLock;           // LLM 评估锁状态
}
关键设计

@Transient 标记的字段不会存入 MongoDB，而是在查询后由代码手动填充（从 MySQL 的 evaluation_result 表查询后赋值）。这种"MongoDB + MySQL 混合查询"是本系统的典型模式。
