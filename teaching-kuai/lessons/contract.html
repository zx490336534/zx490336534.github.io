跨语言调用：把契约当边界

让任务服务、前端和工具执行器对参数和错误达成一致。

先看场景走一遍读代码复现失败动手练习自测

先看场景

主服务与工具不必用同一种语言，但要对字段、超时与错误结构达成一致。这里用静态 JSON 演示，不依赖任何服务器。

契约：双方约定要传什么、结果长什么样、失败怎么表达。换语言也遵守同一份约定。

走一遍

  1. 先定义最小字段与必填规则；额外字段是否忽略要有明确约定。
  2. 设置调用期限；调用方分别处理输入错误、超时和暂时不可用。
  3. 同一份契约样例同时给消费方与提供方测试，避免两边各自猜测。
合成示例 可折叠
{"version":1,"caseId":"login-sample","outcome":"assertion_failed","elapsedMs":48}

第二遍 · 把代码读懂

代码拆解

执行器把耗时写成字符串，前端按数字计算。你希望错误怎样在进入报表前被挡住？

调用链

  1. 执行器按带版本的契约提交明细。
  2. 接收边界校验对象、版本、字段和枚举。
  3. 将支持版本的对象转换为已知形状。
  4. 提供方与消费方用同一组正例和反例做测试。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

OUTCOMES = {"pass", "assertion_fail", "infra_error"}

def validate(doc):
    if not isinstance(doc, dict):
        raise ValueError("result must be an object")
    version = doc.get("version")
    if type(version) is not int or version != 1:
        raise ValueError("unsupported result version")
    case = doc.get("caseId")
    if not isinstance(case, str) or not case.strip():
        raise ValueError("empty case id")
    outcome = doc.get("outcome")
    if not isinstance(outcome, str) or outcome not in OUTCOMES:
        raise ValueError("unknown outcome")
    elapsed = doc.get("elapsedMs")
    if type(elapsed) is not int or elapsed < 0:
        raise ValueError("invalid elapsed time")
    return {"version": 1, "caseId": case,
            "outcome": outcome, "elapsedMs": elapsed}

good = {"version": 1, "caseId": "repeat",
        "outcome": "pass", "elapsedMs": 20}
assert validate({**good, "artifact": "preview"}) == good
for change in [{"elapsedMs": "20"}, {"elapsedMs": True},
               {"version": 2}, {"outcome": "mystery"}]:
    try:
        validate({**good, **change})
    except ValueError:
        continue
    raise AssertionError(change)

先看版本，再读字段

版本不支持时，不要试图用当前字段语义猜。需迁移必填字段时，可先支持两版，再逐步淘汰旧版。示例只处理版本 1。

不要让类型自动转换掩盖问题

非负耗时必须是整数。这里用 type(x) is int 避免把 Python 的 bool 当成数字。空 ID 和陌生结果同样在接收边界拦住，避免它们污染后续统计。

兼容和错误分类

示例允许额外可选字段，但只返回当前认识的字段。如果接收方严格拒绝未知字段，就不能直接加。坏契约一般不重试，限时等待、暂时不可用则可考虑有界重试；两者在报表与日志中要可区分。

复现失败

类型不一致
怎么触发：分别送入 20、字符串 20、true、-1。
怎么判断：只接受真正的非负整数。
两端发布不同步
怎么触发：先增加可选字段，再改版本号。
怎么判断：扩展字段丢弃；不支持的版本明确拒绝。
进度被当作结果
怎么触发：生产方把 queued 放在 outcome。
怎么判断：校验失败，不计入明细。

写下这些测试断言

  • 空编号、缺少结果和陌生枚举不通过。
  • 有效样例在两端得到相同形状。
  • 可选扩展不会流入本版本持久层。
  • 超时与格式错误在调用边界有不同分类。

这一课带走：掌握了接口契约，再用相同思路检查 Agent 生成的候选用例。

动手练习

故意删掉 outcome，再加入未知字段。写清两种变化是否应该拒绝。
