def classify(attempts):
    valid = [case for case in attempts if case != "infra_error"]
    if not valid:
        return "no_evidence"
    if len(set(valid)) > 1:
        return "flaky"
    if "infra_error" in attempts:
        return "incomplete"
    return "stable_" + valid[0]

def report(attempts):
    return {
        "first": attempts[0] if attempts else "missing",
        "category": classify(attempts),
        "all_attempts": tuple(attempts),
    }

result = report(["fail", "pass", "pass"])
assert result["first"] == "fail" and result["category"] == "flaky"
assert report(["fail", "fail"])["category"] == "stable_fail"
assert report(["infra_error", "pass"])["category"] == "incomplete"
assert report(["infra_error"])["category"] == "no_evidence"

重跑不能覆盖原始事实

保存第一次与后续尝试；同一用例同版本只在指定条件下比较。稳定失败是明确的回归候选，红绿交替才提示时序、共享状态或真实竞争。

环境错误有自己的一类

环境中断可能导致有效样本不足，不能把它混进通过率，也不能计作断言失败。若有效断言相互矛盾但出现环境噪声，可以同时标记 flaky 和环境告警；这里分类为主因。

隔离应短时且有出口

隔离记录负责人、复现步骤、截止日期和解除阈值。真实处理要看失败前的状态快照，优先用条件等待代替固定 sleep，或消除复用数据带来的污染。

复现失败

绿色覆盖首次失败
怎么触发：输入 fail、pass、pass。
怎么判断：保留 first=fail，分类 flaky。
执行器连续故障
怎么触发：没有任何业务断言完成。
怎么判断：标为无有效证据，不算已通过。

写下这些测试断言

  • 首次与每次尝试都可追溯。
  • 单次环境故障不会冒充产品回归。
  • 稳定失败保留阻断策略。
  • 隔离有明确恢复标准。

这一课带走：可疑的通过也要有证据。不要让最后一次跑绿替代对首次失败原因的排查。
