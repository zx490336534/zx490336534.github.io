监控：区分评测退化与平台故障

看三组指标判断先排模型、框架还是执行环境。

先看场景走一遍读代码复现失败动手练习自测

先看场景

一个回归任务变慢，可能是排队，不一定是模型慢。把排队、执行、评测耗时分开记录，同时观察样本消费到哪一步。

排队耗时：从进入队列到开始处理的等待时间。它变长，不等于模型同一次调用变慢。

走一遍

  1. 关联运行、用例和尝试编号，不把完整业务输入写进日志。
  2. 统计断言失败、系统故障、未执行三类，再决定先排哪层。
  3. 对同一数据集比较版本结果；不能把两次不同样本的通过率当作模型涨跌。
合成示例 可折叠
queue_ms | execution_ms | evaluation_ms
assertion_failed | infrastructure_error | skipped

第二遍 · 把代码读懂

代码拆解

一批评测总耗时涨了，模型推理耗时没涨。应该先排哪一层？

调用链

  1. 按运行、用例和尝试三个编号关联单次测量。
  2. 分别捕捉排队、执行和评分的边界时刻。
  3. 区分业务断言失败、基础设施问题、跳过与未知。
  4. 找最先异常的边界，再跑同一批样本做对照。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

def span(start, end):
    if start is None or end is None or end < start:
        return None
    return end - start

def timing(event):
    return {
        "queue": span(event.get("queued"), event.get("started")),
        "execute": span(event.get("started"), event.get("executed")),
        "grade": span(event.get("executed"), event.get("graded")),
    }

def sample(delay):
    # 由同一个受控时钟生成，单位是毫秒
    return {"run": "demo-1", "case": "repeat", "attempt": 1,
            "queued": 0, "started": delay,
            "executed": delay + 20, "graded": delay + 22}

normal = timing(sample(5))
slow = timing(sample(80))
assert normal == {"queue": 5, "execute": 20, "grade": 2}
assert slow == {"queue": 80, "execute": 20, "grade": 2}
assert timing({"queued": 3, "started": 2})["queue"] is None
assert timing({"queued": 0, "started": 2, "executed": 8})["grade"] is None

先拆时钟再找归因

入队到开始是排队，开始到得到执行输出是执行，评分另记。例子简化成执行结束即开始评分；异步评分另需记录等待。分布式实现不要直接减两台未对齐的机器时钟，可由同一组件或统一跨度测量。

缺测不填零

边界丢失或时间倒退返回 None，不能把没有证据变成没有耗时。汇总时保留缺测个数，避免漏报导致延迟看起来反而下降。尝试号用来区分第一次执行环境失败与后来正常执行发现断言失败。

高延迟先找变化的那一段

示例里只把等待拉长，排队以外的两个跨度不变。真实报表按同类样本、同成功条件比较分位数和缺失率。运行、用例等高基数字段放日志或追踪用于关联，不用作指标标签，不把预约原文记录到日志。

复现失败

评分未结束
怎么触发：去掉 graded，但保留 executed。
怎么判断：评分时长未知，执行耗时仍可用。
队列变慢
怎么触发：把从 started 起的时刻整体后移。
怎么判断：仅排队跨度增长，先检查积压和容量。
同用例重跑
怎么触发：尝试 1 与尝试 2 分别报设施错误与通过。
怎么判断：保留两个事实，汇总时使用明确的取值规则。

写下这些测试断言

  • 三段独立记录，不能以总耗时冒充模型耗时。
  • 缺测和时钟倒退得到未知，并专门计数。
  • 日志可按尝试定位，也不记录原始预约内容。
  • 基础设施错误和业务断言失败分别统计。

这一课带走：最后把数据集、归因、版本对照与发布门槛整合成一份能复跑的报告。
