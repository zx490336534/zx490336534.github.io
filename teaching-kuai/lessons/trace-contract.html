  4. 保留首次越界的事件号和前后状态差。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

def check(events, final_rows, expected):
    confirmed, writes = False, 0
    for index, (kind, slot) in enumerate(events):
        if kind == "confirm":
            confirmed = slot == expected
        elif kind == "save":
            writes += 1
            if not confirmed or slot != expected or writes > 1:
                return ("invalid_write", index)
        elif kind != "check":
            return ("unknown_action", index)
    if writes != 1:
        return ("missing_write", None)
    if final_rows != [expected]:
        return ("unexpected_state", None)
    return ("ok", None)

normal = [("check", "A"), ("confirm", "A"), ("save", "A")]
assert check(normal, ["A"], "A") == ("ok", None)
assert check(normal[:2] + [("save", "B")], ["B"], "A") == ("invalid_write", 2)
assert check(normal + [("save", "A")], ["A", "A"], "A") == ("invalid_write", 3)
assert check(normal, [], "A") == ("unexpected_state", None)

事件里记录最小必要字段

对教学预约，记录动作类型与合成槽位就够用。顺序来自同一运行的可信有序记录；真实分布式追踪若顺序不确定，应记录因果关系和缺失状态，不能只按未同步时钟硬排。

正确顺序不等于正确载荷

示例要求确认 A 且接下来写 A，错槽位无法通过。同类型动作重复也会失败。真实系统中相同幂等键的网络重试可能允许，轨迹契约应区分一次业务操作与多次传输。

状态从另一处读

工具说写入成功不等于确实保存，也不保证只保存一次。单独观察持久状态最可靠；例子把最终行列表作为独立输入，要求新出现的预约恰好是预期一条。

复现失败

写错槽位
怎么触发：确认 A 后提交 save B。
怎么判断：报告定位触发点，不把工具名正确算作通过。
虚假成功
怎么触发：工具报告写成功但状态读不到结果。
怎么判断：错误归类为状态不符，不只归给文案。

写下这些测试断言

  • 未确认就写被拦。
  • 确认与写入的槽位相同。
  • 重复写入检测。
  • 工具回显和持久状态分别核对。

这一课带走：给每一段证据一个独立观察点。名字、参数、顺序和结果必须分别检查。
