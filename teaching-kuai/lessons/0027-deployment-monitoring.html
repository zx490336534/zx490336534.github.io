三个仓库的部署流程、CI/CD 配置和运行时监控

前置知识

如果你不熟悉以下概念，建议先阅读对应教程：

  • Spring Boot 基础入门
  • Redis 基础入门

1. kuai-service（Java 后端）部署

1.1 构建

# 编译打包（跳过测试）
mvn clean package -DskipTests

# 产出物
target/kuai-service-*.war

1.2 部署配置

项目使用 _appconfig/ 目录管理部署配置：

文件用途
cicd.ymlCI/CD 环境配置（JVM 参数、环境变量）
postStart.sh容器启动后脚本（健康检查、服务注册）
preStop.sh容器停止前脚本（优雅关闭）

1.3 环境变量

变量用途示例
SPRING_PROFILES_ACTIVE激活的配置文件dev / sit / prod
stage部署阶段dev / sit / prod
service.version.default.global服务版本dev_tingbai

2. kuai-service-front（前端）部署

2.1 构建

# 安装依赖
pnpm install

# 构建生产版本
pnpm build

# 产出物
.next/ 目录

2.2 部署方式

Next.js 支持两种部署模式：

模式命令适用场景
Node.js 服务器pnpm start需要 API Routes、SSR
静态导出next export纯静态页面，CDN 部署

2.3 环境变量

变量用途
NEXT_PUBLIC_API_BASE后端 API 地址
MONGODB_URIMongoDB 连接字符串
OPENAI_API_KEYOpenAI API 密钥
OPENAI_BASE_URLOpenAI API 代理地址

3. kuai-service-py（Python 服务）部署

3.1 构建

# 安装依赖
uv sync

# 启动服务
uv run python main.py

# 或使用 uvicorn
uvicorn main:app --host 0.0.0.0 --port 8000

3.2 Docker 部署

# 构建镜像
docker build -t kuai-mcp-service .

# 运行容器
docker run -d -p 8000:8000 \
  -e MCP_SERVERS_CONFIG=/app/config/servers.json \
  kuai-mcp-service

4. 监控与日志

4.1 健康检查

服务健康检查端点
kuai-service/status/health
kuai-service-front/api/health
kuai-service-py/status/health

4.2 日志规范

# Java 日志
private static final QHLogger LOG = QHLogger.getLogger(MethodHandles.lookup().lookupClass());
LOG.message("操作描述").with("key", value).info();

# Python 日志
import logging
logger = logging.getLogger(__name__)
logger.info("操作描述", extra={"key": value})

# 前端日志
console.log("[AgentName]", "操作描述", data)

4.3 Langfuse 可观测性

AI 调用通过 Langfuse 追踪：

  • Prompt 版本 — 每次调用记录使用的 prompt 版本
  • Token 用量 — 输入/输出 token 数量和成本
  • 延迟 — 首 token 时间、总响应时间
  • 错误 — 异常堆栈和上下文

5. 常见运维问题

问题排查步骤
服务启动失败检查环境变量 → 检查数据库连接 → 查看启动日志
API 超时检查网络 → 检查下游服务 → 检查数据库慢查询
内存溢出检查 JVM 参数 → 检查 MongoDB 连接池 → 检查大对象
Agent 响应慢检查 Langfuse trace → 检查 LLM API 延迟 → 检查工具调用
