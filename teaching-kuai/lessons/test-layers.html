测试分层：用最短的路径发现缺陷

对同一个预约问题，分别设计单元、契约和端到端测试。

先看场景

13:00 的预约接受了长度为零的区间；改完校验后，页面还必须显示可理解的失败原因。

测试分层：把规则本身、跨边界约定和用户可见流程各自验证，不要求每个场景都穿完整链路。

调用链

  1. 调用规则函数验证零长度与相邻区间。
  2. 从入口读标准错误形状，不检查内部类名。
  3. 运行一个从点击到界面反馈的流程。
  4. 为变化最大、最难定位的那层保留证据。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

def valid(start, end):
    return 0 <= start < end <= 24

def route(start, end):
    if not valid(start, end):
        return 422, {"code": "BAD_INTERVAL"}
    return 201, {"id": "demo-booking"}

def click_submit(start, end):
    status, body = route(start, end)
    messages = {"BAD_INTERVAL": "结束时间须晚于开始"}
    return "预约成功" if status == 201 else messages[body["code"]]

# 单元：把相等边界钉住
assert not valid(13, 13)
assert valid(13, 14)
assert not valid(23, 25)

# 契约：不关心页面长什么样
assert route(13, 13) == (422, {"code": "BAD_INTERVAL"})

# 内存 E2E：保留用户可见的成功和失败各一条
assert click_submit(13, 13) == "结束时间须晚于开始"
assert click_submit(13, 14) == "预约成功"

单元测试是用来穷举变化的

时间区间、默认值和布尔条件由纯函数判定，覆盖相等、相邻、跨分界这几种情况。规则模型不应该关心按钮布局或 HTTP 状态，可用直接参数快速定位回归。

契约是跨边界的最小共同语言

入口把拒绝映射为稳定的 code。端到端不适合替代结构校验：界面可能恰好用兜底提示，掩盖协议字段已经漂移。测试不要断言整段错误文案，那属于展示层。

这里的 E2E 是内存全流程

示例点按钮模拟页面消费入口响应，未启动浏览器。真实 E2E 至少增加一个浏览器脚本，验证点击、提交、状态更新和提示展示，避免把代理函数冒充浏览器证据。

复现失败

零长度被接纳
怎么触发：把 start < end 改为 start <= end。
怎么判断：边界单元断言失败，随后入口和展示断言也暴露影响。
契约漂移
怎么触发：把错误字段从 code 改为 reason，保持值不变。
怎么判断：契约先失败，界面也无法映射错误；修边界不是改业务规则。

写下这些测试断言

  • 合法半开区间可提交。
  • 规则相等边界被拒绝。
  • 协议错误有机器可读码。
  • 用户能看见友好提示。

这一课带走：原则不是一味减少端到端，而是在最小可诊断的边界验证规则，再用关键路径保护整合结果。
