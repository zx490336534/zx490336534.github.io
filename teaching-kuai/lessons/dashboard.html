任务看板：更新、恢复和分页

让用户知道运行在等什么，并能在刷新后找到原进度。

先看场景走一遍读代码复现失败动手练习自测

先看场景

CaseLab 的列表用分页接口拿到运行摘要，详情再订阅状态变化。浏览器刷新后以服务端快照为准，过滤条件由 URL 恢复。

快照：刷新后重新拿到的当前状态，不要求浏览器记住所有历史更新。

走一遍

  1. 保留可链接的运行 ID，筛选和分页条件可通过查询参数复现。
  2. 不同筛选条件的旧请求不覆盖新列表，可使用取消信号或请求版本。
  3. 让空数据、加载失败、排队中和已完成有各自的视觉反馈。
合成示例 可折叠
loading → empty | ready | error
ready + selectedRun → fetchSnapshot(selectedRun)

第二遍 · 把代码读懂

代码拆解

先点「进行中」，立刻切到「失败」。第二个请求先回来，旧的晚回来。怎样防止旧结果覆盖新选择？

调用链

  1. 切筛选时重置游标并启动新一代请求。
  2. 取消上代传输，同时保留代数判断。
  3. 只让当前代读回的成功或失败改变页面。
  4. 详情刷新按运行编号读快照；分页只使用当前查询的游标。
TypeScript 示例 可折叠

阅读函数输入、状态变化和末尾的断言。

type Result = { rows: string[]; next?: string };
type Load = (filter: string, signal: AbortSignal) => Promise<Result>;
type State = { kind: "loading" | "ready" | "empty" | "error";
  rows?: string[]; next?: string };

function createList(load: Load, render: (s: State) => void) {
  let generation = 0;
  let request: AbortController | undefined;
  return async (filter: string) => {
    const current = ++generation;
    request?.abort();
    request = new AbortController();
    render({ kind: "loading" });
    try {
      const result = await load(filter, request.signal);
      if (current !== generation) return;
      render({ kind: result.rows.length ? "ready" : "empty",
        rows: result.rows, next: result.next });
    } catch {
      if (current === generation) render({ kind: "error" });
    }
  };
}

const seen: State[] = [];
const resolve: Record<string, (r: Result) => void> = {};
const search = createList(
  filter => new Promise(done => { resolve[filter] = done; }),
  state => seen.push(state),
);
async function exercise() {
  const old = search("running"), current = search("failed");
  resolve.failed({ rows: ["demo-failed"] });
  await current;
  resolve.running({ rows: ["demo-running"] });
  await old;
  if (seen.at(-1)?.rows?.[0] !== "demo-failed") throw Error("stale update");
}
void exercise();

代数是逻辑边界

每发一次列表请求，generation 就递增。回包时只允许当前代数修改界面。这里刻意让加载器忽略取消信号，来证明正确性不靠网络层一定能中止。

成功和失败都要拦旧请求

AbortController 能省资源，不能判断请求是否仍属于当前筛选。示例在响应和异常路径都检查代数。零行是 empty，连接失败是 error；如果保留旧行作为占位，应明确标注新筛选还在加载。

分页与详情分别处理

详情刷新按运行编号读快照，事件更新可与服务端修订号对上。列表游标绑定筛选与排序，切换时丢弃旧游标；排序值相同时追加唯一字段作稳定排序，避免相邻两页重复或缺项。

复现失败

请求乱序
怎么触发：让 failed 先返回，再完成旧的 running。
怎么判断：最后一帧仍是 failed。
旧请求报错
怎么触发：新请求成功后，旧请求再 reject。
怎么判断：不清空新数据、不展示旧错误。
旧游标
怎么触发：使用上一筛选的 next 拉新筛选第二页。
怎么判断：前端切筛选清掉游标，后端拒绝不匹配的游标。

写下这些测试断言

  • 最新请求零行时显示 empty，失败时显示 error。
  • 旧响应和旧异常都不能改变当前值。
  • 详情刷新后仍查相同运行编号。
  • 切换筛选总从第一页开始。

这一课带走：有了编号和状态，下一课让前端、任务服务与执行器用同一份 JSON 契约沟通。

动手练习

快速先筛「进行中」再筛「失败」，让前一个请求晚返回，确认屏幕仍显示当前条件。
