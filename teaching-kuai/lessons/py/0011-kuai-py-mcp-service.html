📡 MCP 协议详解

MCP（Model Context Protocol）是一种标准化协议，让 AI Agent 能够以统一方式调用各种外部工具。kuai-service-py 作为 MCP 客户端管理器，实现了三种传输协议的连接管理。

SSE（Server-Sent Events）

SseTransport — 基于 HTTP 的单向推送
  • 原理：客户端通过 HTTP 连接到 SSE 端点，服务器通过事件流持续推送数据
  • SDK 入口：from mcp.client.sse import sse_client
  • 连接流程：sse_client(url, headers) → __aenter__ 获取 read/write stream → 创建 ClientSession → session.initialize()
  • 特点：需要 keep-alive 维持连接，支持远程服务器
  • 配置字段：url（SSE 端点地址）、headers（自定义 HTTP 头）

Stdio（标准输入输出）

StdioTransport — 本地进程通信
  • 原理：启动一个子进程，通过 stdin/stdout 进行 JSON-RPC 通信
  • SDK 入口：from mcp.client.stdio import stdio_client
  • 连接流程：StdioServerParameters(command, args, env) → stdio_client(params) → 创建 ClientSession → session.initialize()
  • 特点：不经过网络，延迟最低，适合本地工具；不需要 keep-alive
  • 配置字段：command（启动命令）、args（命令参数）、env（环境变量）

StreamableHTTP

StreamableHttpTransport — HTTP 流式双向通信
  • 原理：基于 HTTP 的可流式传输协议，支持 WebSocket 降级，兼顾 HTTP 兼容性和实时性
  • SDK 入口：from mcp.client.streamable_http import streamablehttp_client
  • 连接流程：streamablehttp_client(url, headers) → __aenter__ 获取 read/write stream + connection_info → 创建 ClientSession → session.initialize()
  • 特点：支持动态更新 headers、需要 keep-alive、适合远程服务
  • 配置字段：url（HTTP 端点）、headers（自定义 HTTP 头）

🔄 服务器生命周期管理

ServerManager 是服务器生命周期的核心管理者。所有状态流转都通过它协调。

状态机

ServerStatus 枚举值:
  DISCONNECTED  →  STARTING  →  CONNECTED  →  STOPPING  →  DISCONNECTED
                      ↓                         ↓
                    ERROR  ←──────────────── ERROR

状态说明:
  - disconnected: 未连接（初始状态 / 已停止）
  - starting:     正在启动
  - connecting:   正在建立传输连接
  - connected:    已连接，工具已加载
  - stopping:     正在停止
  - error:        发生错误

启动流程详解（ServerManager.start_server）

start_server(name)
  ├── 1. 检查服务器是否存在且 enabled
  ├── 2. 设置状态为 STARTING
  ├── 3. TransportFactory.create_transport(config)
  │      └── 根据 transport 类型创建 SseTransport / StdioTransport / ...
  ├── 4. 设置回调：on_status_change, on_error
  ├── 5. transport.connect() （带超时）
  │      ├── BaseTransport.connect()
  │      │   ├── 设置状态为 CONNECTING
  │      │   ├── _do_connect()  ← 子类实现具体连接逻辑
  │      │   ├── 设置状态为 CONNECTED
  │      │   ├── _setup_keep_alive()  ← SSE/StreamableHTTP 启动心跳
  │      │   └── _load_tools()  ← session.list_tools() 加载工具列表
  │      └── 连接失败 → handle_error() → 设置状态为 ERROR
  ├── 6. _refresh_server_tools() 刷新工具到 ServerInfo
  ├── 7. 设置状态为 CONNECTED
  └── 完成

自动启动机制

在 initialize() 中，ServerManager 从数据库加载所有配置，标记 auto_start=true 且 enabled=true 的服务器会通过 _start_servers_parallel() 并行启动：

  • 使用 asyncio.gather 并行执行，避免逐个等待
  • 每个服务器有独立的超时控制（默认 120 秒）
  • 失败自动重试（默认 2 次），递增延迟
  • 可通过环境变量 KUAI_SKIP_MCP_AUTOSTART=true 跳过自动启动
  • 可通过 KUAI_MCP_AUTOSTART_TIMEOUT 和 KUAI_MCP_AUTOSTART_RETRIES 调整参数

Keep-alive 机制

只有 SSE 和 StreamableHTTP 需要 keep-alive（因为它们是持久 HTTP 连接，容易断开）：

  • 连接成功后启动异步心跳循环
  • 默认间隔 60 秒（keep_alive_interval 配置，单位毫秒）
  • 通过 session.send_ping() 发送心跳
  • 连续失败 3 次触发 handle_error，设置状态为 ERROR
  • 断开连接时自动取消心跳任务

📂 分组管理

GroupManager 负责将多个 MCP 服务器组织成逻辑分组，支持灵活的工具访问控制。

分组数据模型

GroupConfig:
  id: str                    # 分组 ID（数据库生成）
  name: str                  # 分组名称（唯一）
  description: Optional[str] # 分组描述
  servers: List[GroupServerConfig]  # 包含的服务器列表
  owner: str                 # 所有者
  created_at / updated_at    # 时间戳

GroupServerConfig:
  name: str                              # 服务器名称（必须已存在于 servers 表）
  tools: Union["all", List[str]]         # 工具过滤: "all" 或 ["tool1", "tool2"]
  enabled: bool                          # 是否在分组中启用

工具过滤机制

分组的核心价值在于工具级访问控制。get_group_tools() 的过滤逻辑：

get_group_tools(group_id)
  ├── 遍历分组中的每个 server_config
  ├── 跳过 enabled=false 的服务器
  ├── 如果服务器运行中但工具为空 → 自动 refresh
  ├── 获取服务器的完整工具列表
  ├── 过滤:
  │   ├── tools == "all" 或空列表 → 返回所有 enabled 的工具
  │   └── tools 是具体列表 → 只返回列表中的工具
  └── 返回 {server_name: [ToolInfo]} 映射

分组 MCP 服务器

每个分组可以暴露为一个独立的 MCP Server 端点（通过 GroupMCPServer），让外部 AI Agent 可以通过标准 MCP 协议访问分组中的工具：

  • /groups/{group_id}/mcp — 分组的 MCP SSE 端点
  • 工具名称格式：{server_name}.{tool_name}
  • 调用时自动路由到对应的 MCP 服务器执行

🔧 工具调用流程

直接调用（通过 REST API）

POST /tools/servers/{server_name}/{tool_name}/call
  ↓
servers endpoint
  ↓
MCPService.call_tool(server_name, tool_name, arguments)
  ↓
ServerManager: 获取 transport 实例
  ↓
BaseTransport.call_tool(tool_name, arguments)
  ↓
session.call_tool(tool_name, arguments)  ← MCP SDK ClientSession
  ↓

  ↓
返回结果

分组调用（通过 MCP 协议）

AI Agent → MCP SSE 连接 → GroupMCPServer
  ↓
call_tool(name="server.tool", arguments={...})
  ↓
MCPService.call_group_tool(group_id, tool_name, arguments)
  ↓
GroupManager: 验证工具在分组中是否存在且启用

  ↓
ServerManager → BaseTransport → session.call_tool()
  ↓
格式化结果（TextContent / ImageContent）
  ↓
返回给 AI Agent

智能路由调用

AI Agent → SmartMCPServer
  ↓
1. query_tools(query="读取文件")  ← 自然语言搜索

🏭 传输协议工厂模式

TransportFactory 是连接配置和传输实现的桥梁：

TransportFactory.create_transport(config: ServerConfig) → BaseTransport

支持的传输类型映射:
  TransportType.SSE            → SseTransport
  TransportType.STDIO          → StdioTransport
  TransportType.STREAMABLE_HTTP → StreamableHttpTransport
  TransportType.AGENT          → AgentTransport

执行流程:
  1. 验证 config.transport 是否在支持列表中
  2. 非 AGENT 类型 → 检查 mcp SDK 是否已安装
  3. 从映射表中获取对应类
  4. 创建实例并返回

此外还有 get_or_create_session() 方法，支持会话池模式——对于需要复用连接的场景（如高并发工具调用），可以通过 TransportSessionPool 管理会话生命周期。
