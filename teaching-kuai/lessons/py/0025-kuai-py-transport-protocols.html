🔌 MCP 传输协议深度解析

🗺️ 传输协议总览

架构设计 Kuai MCP 服务支持 4 种传输协议，每种对应不同的通信场景。所有协议都继承自 BaseTransport 基类。

四种传输协议

协议 类型 通信方式 典型场景 实现文件
SSE 远程 HTTP 单向推送 老版本 MCP 服务器 sse_transport.py
Stdio 本地 进程 stdin/stdout 管道 本地 CLI 工具 stdio_transport.py
StreamableHTTP 远程 HTTP 流式双向 推荐的远程协议 streamable_http_transport.py
Agent 自定义 自定义实现 非标准 MCP 服务器 agent_transport.py

传输协议工厂

transport_factory.py 是创建传输实例的统一入口，根据配置自动选择正确的协议：

# src/transports/transport_factory.py

class TransportFactory:
    """传输协议工厂，支持会话池管理"""

    # 传输类型 → 实现类的映射
    transport_classes = {
        TransportType.STDIO: StdioTransport,
        TransportType.STREAMABLE_HTTP: StreamableHttpTransport,
        TransportType.SSE: SseTransport,
        TransportType.AGENT: AgentTransport,
    }

    @classmethod
    def create_transport(cls, config: ServerConfig) -> BaseTransport:
        """根据配置创建对应的传输实例"""
        if config.transport not in cls.transport_classes:
            raise ValueError(f"不支持的传输协议类型: {config.transport}")

        transport_class = cls.transport_classes[config.transport]
        return transport_class(config)

    @classmethod
    async def get_or_create_session(cls, config, session_id=None, group=""):
        """获取或创建会话（使用会话池）"""
        session_pool = get_session_pool()
        return await session_pool.get_or_create_session(
            session_id, config, group
        )
ServerConfig（来自数据库） │ │ config.transport 字段决定协议类型 ▼ ┌──────────────────────┐ │ TransportFactory │ │ │ │ config.transport: │ │ "sse" │──▶ SseTransport │ "stdio" │──▶ StdioTransport │ "streamable_http" │──▶ StreamableHttpTransport │ "agent" │──▶ AgentTransport └──────────────────────┘

📡 SSE 协议详解

远程协议 SSE（Server-Sent Events）是 MCP 协议最早支持的传输方式，基于 HTTP 的单向推送机制。

什么是 SSE？

SSE 是 HTML5 标准的一部分，允许服务器通过 HTTP 连接持续向客户端推送数据。特点：

  • 单向推送：只能服务器→客户端推送，客户端→服务器需要额外的 HTTP POST
  • 基于 HTTP：不需要特殊协议，穿透防火墙和代理
  • 自动重连：浏览器原生支持断线重连
  • 文本格式：数据以文本形式传输（text/event-stream）

SSE 传输实现

# src/transports/sse_transport.py

class SseTransport(BaseTransport):
    """SSE传输协议，用于远程服务器单向推送通信"""

    def __init__(self, config: ServerConfig):
        if config.transport != TransportType.SSE:
            raise ValueError(f"配置的传输类型不是SSE: {config.transport}")
        super().__init__(config)
        self._context_manager = None
        self._streams = None

    async def _do_connect(self) -> bool:
        """执行SSE连接，建立HTTP SSE事件流"""
        if not self.config.url:
            raise Exception("SSE需要指定URL")

        # 验证URL格式
        parsed = urlparse(self.config.url)
        if not parsed.scheme or not parsed.netloc:
            raise ValueError(f"无效的URL: {self.config.url}")

        # 准备headers（支持自定义认证头等）
        headers = dict(self.config.headers) if self.config.headers else {}

        # 使用 MCP SDK 的 sse_client 建立连接
        self._context_manager = sse_client(
            url=self.config.url,
            headers=headers
        )

        # 进入上下文管理器，获取读写流
        read_stream, write_stream = await self._context_manager.__aenter__()
        self._streams = (read_stream, write_stream)

        # 创建 MCP 会话并初始化
        self.session = ClientSession(read_stream, write_stream)
        await self.session.__aenter__()
        await self.session.initialize()

        self.session_id = f"sse-{id(self.session)}"
        return True

SSE 连接流程

客户端（Kuai MCP 服务） │ │ 1. HTTP GET /sse（建立 SSE 事件流） ▼ 远程 MCP 服务器 │ │ 2. 返回 Content-Type: text/event-stream │ 保持长连接，持续推送事件 │ │ 3. 客户端通过 HTTP POST 发送请求 │ │ 4. 服务器通过 SSE 流返回响应 ▼ 双向通信建立完成（读流 + 写流）

⌨️ Stdio 协议详解

本地协议 Stdio 通过标准输入/输出管道与本地子进程通信，是连接本地 MCP 服务器（如 CLI 工具）的标准方式。

什么是 Stdio？

  • 进程管道：父进程启动子进程，通过 stdin（标准输入）写入，stdout（标准输出）读取
  • 零网络开销：不走网络，直接内存管道通信，延迟极低
  • 安全隔离：子进程运行在独立的地址空间中
  • 自动管理：MCP SDK 自动处理进程启动、停止和清理

Stdio 传输实现

# src/transports/stdio_transport.py

class StdioTransport(BaseTransport):
    """Stdio传输协议，用于本地进程通信"""

    async def _do_connect(self) -> bool:
        """执行Stdio连接，启动子进程并建立通信"""
        if not self.config.command:
            raise Exception("Stdio需要指定command")

        # 准备环境变量（继承当前环境 + 配置的环境）
        env = dict(os.environ)
        if self.config.env:
            for key, value in self.config.env.items():
                env[key] = os.path.expandvars(str(value))

        # 构建 Stdio 服务器参数
        server_params = StdioServerParameters(
            command=self.config.command,   # 如 "python"
            args=self.config.args or [],   # 如 ["-m", "my_mcp_server"]
            env=env
        )

        # 使用 MCP SDK 的 stdio_client 建立连接
        self._context_manager = stdio_client(server_params)
        read_stream, write_stream = await self._context_manager.__aenter__()
        self._streams = (read_stream, write_stream)

        # 创建 MCP 会话并初始化
        self.session = ClientSession(read_stream, write_stream)
        await self.session.__aenter__()
        await self.session.initialize()  # SDK 自动处理 MCP 初始化握手

        self.session_id = f"stdio-{id(self.session)}"
        return True

    def get_process_info(self) -> Optional[dict]:
        """获取进程信息"""
        return {
            'command': self.config.command,
            'args': self.config.args,
            'env_count': len(self.config.env) if self.config.env else 0,
            'session_id': self.session_id
        }

Stdio 通信流程

Kuai MCP 服务（父进程） │ │ 1. subprocess.Popen(command, args, stdin=PIPE, stdout=PIPE) ▼ 本地 MCP 服务器（子进程） │ │ 2. 父进程通过 stdin 管道发送 JSON-RPC 请求 │ → {"jsonrpc":"2.0","method":"tools/list","id":1} │ │ 3. 子进程通过 stdout 管道返回 JSON-RPC 响应 │ ← {"jsonrpc":"2.0","result":{"tools":[...]},"id":1} ▼ 通信完成（双向管道）

Stdio 注意事项

  • 命令路径：config.command 必须是可执行文件的路径或在 PATH 中
  • 环境变量：支持 os.path.expandvars 展开（如 $HOME、${API_KEY}）
  • 进程清理：断开时 SDK 自动关闭子进程，但异常退出可能残留僵尸进程
  • 只限本地：Stdio 只能连接本机的进程，不能跨网络

🌊 StreamableHTTP 协议详解

推荐协议 StreamableHTTP 是 MCP 协议推荐的远程传输方式，结合了 HTTP 的通用性和流式传输的实时性。

为什么推荐 StreamableHTTP？

  • 双向通信：通过 HTTP 实现请求-响应的同时支持服务端推送
  • 流式传输：支持分块传输（chunked transfer），数据实时到达
  • 兼容性好：基于标准 HTTP，与 CDN、负载均衡器、反向代理兼容
  • Session 管理：支持会话标识，可以维护有状态的连接
  • 是 SSE 的升级版：MCP 官方推荐的新一代传输协议

StreamableHTTP 传输实现

# src/transports/streamable_http_transport.py

class StreamableHttpTransport(BaseTransport):
    """StreamableHTTP传输协议，用于HTTP流式双向通信"""

    async def _do_connect(self) -> bool:
        """执行StreamableHTTP连接，建立HTTP流式通信"""
        if not self.config.url:
            raise Exception("StreamableHTTP需要指定URL")

        # 验证URL
        parsed = urlparse(self.config.url)
        if not parsed.scheme or not parsed.netloc:
            raise ValueError(f"无效的URL: {self.config.url}")

        # 准备headers
        headers = dict(self.config.headers) if self.config.headers else {}

        # 使用 MCP SDK 的 streamablehttp_client
        self._context_manager = streamablehttp_client(
            url=self.config.url,
            headers=headers
        )

        # 建立连接 — 注意返回值多了 connection_info
        read_stream, write_stream, connection_info = \
            await self._context_manager.__aenter__()
        self._streams = (read_stream, write_stream)
        self._connection_info = connection_info  # 保存连接信息

        # 创建会话并初始化
        self.session = ClientSession(read_stream, write_stream)
        await self.session.__aenter__()
        await self.session.initialize()

        self.session_id = f"http-{id(self.session)}"
        return True

StreamableHTTP vs SSE 的区别

特性 SSE StreamableHTTP
通信方向 单向推送 + 额外 POST 双向流式
连接信息 无 返回 connection_info
会话管理 无原生支持 内置 Session ID
错误处理 基础 详细错误诊断
推荐程度 兼容旧服务器 ⭐ 推荐使用

高级功能：动态更新 Headers

# StreamableHTTP 支持运行时更新 HTTP 头（如刷新 Token）

async def update_headers(self, new_headers: dict) -> bool:
    """更新HTTP头（需要重新连接）"""
    if not self.config.headers:
        self.config.headers = {}
    self.config.headers.update(new_headers)

    # 重新连接以应用新headers
    if self.status.value == "connected":
        await self.disconnect()
        return await self.connect()
    return True

🧭 协议选择指南

选择哪种传输协议取决于你的 MCP 服务器在哪里、怎么运行：

你的 MCP 服务器在哪里？ │ ├── 本地机器上（CLI 工具、本地脚本） │ → 使用 Stdio │ └── 远程服务器上（HTTP 服务） │ ├── 服务器支持 StreamableHTTP？ │ → 使用 StreamableHTTP ⭐ 推荐 │ └── 只支持 SSE（老版本服务器） → 使用 SSE

配置示例

# Stdio 配置（本地 MCP 服务器）
ServerConfig(
    name="local-tool",
    transport=TransportType.STDIO,
    command="python",
    args=["-m", "my_mcp_server"],
    env={"API_KEY": "${MY_API_KEY}"},
)

# StreamableHTTP 配置（远程 MCP 服务器）
ServerConfig(
    name="remote-tool",
    transport=TransportType.STREAMABLE_HTTP,
    url="https://mcp.example.com/mcp",
    headers={"Authorization": "Bearer xxx"},
)

# SSE 配置（老版本远程服务器）
ServerConfig(
    name="legacy-tool",
    transport=TransportType.SSE,
    url="https://legacy-mcp.example.com/sse",
    headers={"X-API-Key": "xxx"},
)

常见误区

  • 不要混淆 SSE 和 StreamableHTTP：虽然都走 HTTP，但协议细节不同，不能混用
  • Stdio 的 command 不是 URL：Stdio 的 command 是可执行文件路径，不是 HTTP 地址
  • Agent 协议不支持会话池：AgentTransport 是自定义协议，只能用 create_transport() 直接创建
  • 所有协议都需要 MCP SDK：除了 Agent 类型，其他三种都依赖官方 mcp Python 包

🧪 知识检验

题目 1：SSE vs StreamableHTTP

StreamableHTTP 相比 SSE 的主要优势是什么？

A. StreamableHTTP 速度更快
B. StreamableHTTP 支持双向流式通信和原生会话管理
C. StreamableHTTP 不需要 HTTP 协议
D. StreamableHTTP 可以连接本地进程
答案 B。StreamableHTTP 返回 3 个值（read_stream, write_stream, connection_info），支持双向流式通信，并且内置 Session ID 管理。SSE 是单向推送（服务器→客户端），客户端发送请求需要额外的 HTTP POST。StreamableHTTP 是 MCP 官方推荐的新一代远程传输协议。

题目 2：Stdio 协议

Stdio 传输协议通过什么方式与 MCP 服务器通信？

A. 通过 HTTP 请求
B. 通过 WebSocket
C. 通过子进程的 stdin/stdout 管道
D. 通过 TCP Socket
答案 C。Stdio 传输通过 StdioServerParameters(command, args, env) 启动一个子进程，然后通过 stdin 管道写入 JSON-RPC 请求，通过 stdout 管道读取 JSON-RPC 响应。这种方式零网络开销、延迟极低，但只能用于本机进程。

题目 3：传输协议工厂

哪种传输协议不支持会话池模式（get_or_create_session）？

A. SSE
B. Stdio
C. StreamableHTTP
D. Agent
答案 D。代码中明确说明 "Agent传输协议不支持会话池模式，请使用create_transport方法"。Agent 传输是自定义协议，不依赖官方 MCP SDK，因此不能使用基于 SDK 的会话池管理。其他三种协议（SSE、Stdio、StreamableHTTP）都支持会话池。
