取消不是关进程：如何表示已经开始的工作

让取消请求停住后续工作，又不误报已经发生的结果。

先看场景走一遍读代码复现失败动手练习自测

先看场景

预约回归已派发一个项目，用户点取消；一个队列项正好同时被执行器领取。

协作取消：系统记录取消意图，执行器在安全检查点读到后停止启动后续工作，并确认已在跑的工作真正收口。

走一遍

  1. 原子记录取消意图。
  2. 执行器每次领取前检查取消状态。
  3. 已开始的项提交结果或确认停止。
合成示例 可折叠
todo = ["a", "b", "c"]

第二遍 · 把代码读懂

代码拆解

页面能在用户点下取消后立刻承诺「所有副作用已撤销」吗？

调用链

  1. 原子记录取消意图。
  2. 执行器每次领取前检查取消状态。
  3. 已开始的项提交结果或确认停止。
  4. 未开始项标为跳过，已经记录的结果保留。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

todo = ["a", "b", "c"]
active = set()
finished = {}
cancelled = False

def claim():
    if cancelled or not todo:
        return None
    item = todo.pop(0)
    active.add(item)
    return item

def done(item, outcome):
    if item not in active:
        raise ValueError("item was not active")
    active.remove(item)
    finished[item] = outcome

def outcomes():
    skipped = {item: "skipped" for item in todo} if cancelled else {}
    return {**finished, **skipped}

def snapshot():
    if cancelled:
        return "cancelling" if active else "cancelled"
    return "running" if active or todo else "finished"

assert claim() == "a"
cancelled = True
assert snapshot() == "cancelling" and claim() is None
done("a", "pass")
assert snapshot() == "cancelled"
assert outcomes() == {"a": "pass", "b": "skipped", "c": "skipped"}

取消的是未来工作

任务没有开始时可直接结束；运行中需要先标请求已接收。这里捕捉任务级状态及项级状态，示例保留已完成项，并给未被启动的项贴 skipped。

检查点与副作用之间有窗口

如果下一项领取和取消发生竞速，要在同一原子边界控制。对已经完成的外部动作，取消只阻止以后发生的动作，不能回滚过去；若需要撤销，用独立补偿操作并记录结果。

停止确认是一个可观测事实

界面区分 cancelling 与 cancelled。队列运行者失联时不能凭空声称已停止；保留未知状态和超时告警。示例把当前正在执行的项目结果视为晚到的真实事实，不试图删除。

复现失败

还有正在执行项
怎么触发：在 a 已领取后取消，再模拟 a 报回成功。
怎么判断：停止领取 b、c；保留 a 的成功。
重复上报已结束项
怎么触发：对 a 调两次 done。
怎么判断：后一次拒绝，不重复计数。

写下这些测试断言

  • 取消后 claim 不再返回任何新项。
  • 执行器确认之前状态是 cancelling。
  • 取消保留已经确认的副作用与结果。
  • 未领取项与断言失败分开显示。

这一课带走：取消是有顺序的状态变化；写对中间状态，报告才不会对正在执行的工作撒谎。

动手练习

运行代码里的断言，然后只改一个输入，复现「还有正在执行项」。先写预期再运行。
