Agent 生成用例：生成、审查、执行分开

把生成的用例看成候选，不把它当成执行证据。

先看场景走一遍读代码复现失败动手练习自测

先看场景

输入是一条虚构预约规则，模型输出供审查的用例草稿。草稿通过结构验证且人工批准之后，才可以送进测试执行器。

候选用例：它是还没执行的草稿。像检查清单上的一行，写得好不等于已经做过。

走一遍

  1. 每条用例都要包含前置条件、动作、预期观察点。
  2. 补用例前先按需求条目和状态区间看覆盖缺口，别用总条数代替覆盖。
  3. 草稿、审批与执行使用不同状态；不能伪造执行记录。
合成示例 可折叠
{"case":"重复提交","given":"预约已确认","when":"重新提交同一请求","then":"仍只有一条有效预约"}

第二遍 · 把代码读懂

代码拆解

Agent 写了八条预约用例，其中两条都只说「检查是否成功」。哪条能运行？编辑后，旧审批还算数吗？

调用链

  1. 把预约规则编号化，候选用例引用已知规则。
  2. 检查结构与可观察期望，再从规则表找覆盖缺口。
  3. 人工审批绑定草稿版本；任何编辑会使旧审批失效。
  4. 执行使用已确认的用例快照，运行结果另存。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

from copy import deepcopy

RULES = {"R1", "R2", "R3"}
draft = {"revision": 0, "approved": None, "cases": []}

def edit(cases):
    for case in cases:
        if case["rule"] not in RULES:
            raise ValueError("unknown rule")
        if any(not case[field].strip()
               for field in ("given", "when", "then")):
            raise ValueError("missing case detail")
    draft["revision"] += 1
    draft["cases"] = deepcopy(cases)
    draft["approved"] = None

def approve(revision):
    if revision != draft["revision"] or not draft["cases"]:
        raise ValueError("stale or empty draft")
    draft["approved"] = revision

def snapshot():
    if draft["approved"] != draft["revision"]:
        raise ValueError("approval required")
    return draft["revision"], deepcopy(draft["cases"])

case = {"rule": "R2", "given": "已有预约", "when": "重交同一请求",
        "then": "仍只有一条有效预约"}
edit([case])
approve(1)
old = snapshot()
edit([{**case, "then": "预约编号也保持不变"}])
assert draft["approved"] is None and old[0] == 1
assert old[1][0]["then"] == "仍只有一条有效预约"

让期望可观察

模型输出先当候选。每条至少写前置、动作、期望；例如重复提交后有效预约仍为一条，可以数。一句「正常处理」不能判断结果。结构校验只是第一层，还要读业务语义，核对几个不同措辞的用例是不是同一个场景。

审批针对一份版本

approve 记录当下 revision，edit 增加版本并清空确认。迟到审批不能盖章给新文本。实际存储应把版本检查和写入合并成原子提交；只禁用页面按钮挡不住延迟请求。

不要让草稿改变历史

启动运行时复制已确认版本，后续改草稿不会影响正在跑和已经完成的记录。结果报告保留用例版本和执行证据，不能用生成输出中的状态字段冒充测试通过。

复现失败

过时审批
怎么触发：第一版审批请求到达时，第二版已保存。
怎么判断：拒绝旧审批；第二版仍待审。
错误制造通过证据
怎么触发：模型输出额外字段 passed: true。
怎么判断：执行结果只来自执行记录；公开记录应在边界白名单转换。
预期模糊
怎么触发：候选缺期望，或写成含义重复的两个句子。
怎么判断：缺字段校验失败；语义重复在审核阶段发现。

写下这些测试断言

  • 未知需求编号拒绝，未覆盖需求不能计入覆盖。
  • 未审批或版本不一致不能启动。
  • 新编辑不改变老执行快照。
  • 草稿生成、通过审批和执行通过是三件事。
