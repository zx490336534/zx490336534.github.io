边界值与不变量：从几个例子扩展到一类输入

用明确的输入边界和业务不变量解释为什么增加某条用例。

先看场景走一遍读代码复现失败动手练习自测

先看场景

CaseLab 要验证每个团队最多能预约几次。两个常规输入跑通不能说明边界正确，也不能说明排序变化时结果一致。

不变量：一类输入变化前后必须保持的行为，例如改变记录顺序不能改变计数。

走一遍

  1. 从规则提取最小值、最大值和两侧一格。
  2. 写出跨多组数据都应该成立的关系，例如调换无关记录顺序不该改变数量。
  3. 用循环枚举小范围输入，失败时报告实际输入而不只告诉你断言失败。
合成示例 可折叠
capacity = 3
assert ok(2) and ok(3) and not ok(4)

第二遍 · 把代码读懂

代码拆解

样例全过了，怎么找到写错一个比较符号或重复计数这类问题？

调用链

  1. 写下预约数量的类型与区间。
  2. 枚举上限附近的合法和非法输入。
  3. 复制并重排记录，核对数量一致性。
  4. 对去重键重复的记录，验证统计幂等并记录反例。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

from itertools import permutations

def accepts(value, limit):
    return type(value) is int and 0 <= value <= limit

def booked_count(rows):
    return len({row['id'] for row in rows if row['status'] == 'confirmed'})

for limit in range(1, 6):
    pairs = [(0, True), (limit - 1, True), (limit, True), (limit + 1, False), (-1, False)]
    for value, expected in pairs:
        assert accepts(value, limit) == expected, (value, limit)
assert not accepts(True, 3)

base = [
    {'id': 'a', 'status': 'confirmed'},
    {'id': 'b', 'status': 'cancelled'},
    {'id': 'c', 'status': 'confirmed'},
]
assert booked_count(base) == 2
for shuffled in permutations(base):
    assert booked_count(shuffled) == booked_count(base)
assert booked_count(base + base) == booked_count(base)
assert booked_count([base[1]]) == 0

用边界对照比较符号

accepts 同时检查类型和开闭区间。Python 中 bool 是 int 子类，这里用 type(value) is int，避免 True 被当成次数。写出输入约束比只给几个测试数字更有意义。

用关系断言扩展用例，而不是复制同一个期望值

换序与重复写入是一类变换。若业务按唯一预约编号计数，打乱顺序不能改变数量，重复发送同一批记录也不能让数量翻倍。

用最小反例定位出错规则

带着输入值写断言信息；当一批断言失败时，先用最小的失败值单跑。真实生成式测试可扩展范围并收缩反例；这里的确定性枚举用于先建立判断。

复现失败

上限错误
怎么触发：将 <= 改成 < 或把边界对比写反。
怎么判断：上限那一个输入失败，明确指出受影响限制值。
真假值混进整数
怎么触发：把 True 作为预约数量传入。
怎么判断：它返回 False，不被解释为 1。
重复记录抬高统计
怎么触发：把同一批、同一预约编号的记录重复输入。
怎么判断：唯一有效预约的总数保持不变。

写下这些测试断言

  • 闭区间端点可用，端点外不可用。
  • 类型错误与数值错误都能触发失败。
  • 换序和同编号重复写入不改变计数。

这一课带走：边界断言找比较符号错误，不变量断言找一整类数据变化下的错误。

动手练习

把示例里的 <= 改成 <，确认哪条断言报错；再补一个独立检查，防止负数被接受。
