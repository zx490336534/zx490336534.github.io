按影响边界构建用例选择器，未知改动默认扩大范围。

调用链

  1. 给每个用例标出保护的业务路径。
  2. 为改动域追查直接及传递依赖。
  3. 合并受影响用例并必跑关键烟测。
  4. 遇到未知边界扩大范围，并定期全跑来校准映射。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

risk = {
    "money": {"confirm"},
    "confirm": {"receipt"},
    "availability": set(),
    "receipt": set(),
}
cases = {
    "money": {"rounding"}, "confirm": {"blocked-price"},
    "availability": {"full-slot"}, "receipt": {"receipt-amount"},
}
smoke = {"create-booking"}
all_cases = set().union(smoke, *cases.values())

def select(changed):
    if not set(changed) <= risk.keys():
        return all_cases.copy()
    pending, seen = list(changed), set()
    while pending:
        name = pending.pop()
        if name in seen:
            continue
        seen.add(name)
        pending.extend(risk[name])
    return set().union(smoke, *(cases[name] for name in seen))

assert select(["money"]) == smoke | {"rounding", "blocked-price", "receipt-amount"}
assert select(["unknown"]) == all_cases
assert select([]) == smoke

选的是风险覆盖，不是方便覆盖

成本大时实际有两套运行策略：拉取请求执行影响集，固定周期运行全量以校准漏选。用例分类可以对应关键路径、触发域和副作用，而非只对应代码目录。

看传递依赖

示例中金额计算被确认流程依赖，改金额会选上确认用例；使用可终止的 visited 集处理循环。必须从会被改动影响的组件向消费方走，不能把边的方向写反。

保守处理不确定性

公共组件新加且还没有映射时，退回全量。代码覆盖率只说明某行执行过，无法证明必需断言被验证。要增加缺陷注入或突变测试找观察点的弱项。

复现失败

漏传递影响
怎么触发：去掉 confirm 到 receipt 这条边。
怎么判断：跨组件回归用例漏选；选择器测试必须对实际错误响铃。
新模块没分类
怎么触发：传入 unknown。
怎么判断：退回全量，不默许只跑烟测。

写下这些测试断言

  • 直接和传递用例都纳入。
  • 相同用例不会重复运行。
  • 空变更仍运行烟测。
  • 未知变化触发预先约定的全量策略。

这一课带走：全量是安全网，选择器是提速工具。映射捕捉的是风险，而不是行数。
