构建稳定的执行系统 · 第 10 课 · 约 39 分钟

租约与围栏号：让接手者成为唯一写者

阻止失效执行器提交迟到的结果。

先看场景走一遍读代码复现失败动手练习自测

先看场景

A 工作器领取回归后断网，租约过期由 B 接手。A 随后恢复网络并提交旧结果。

围栏号：每次重新领取都发更大的编号；写入端拒绝不再拥有当前编号的执行器。

走一遍

  1. 写入任务租约记录和递增编号。
  2. 到期时由新执行器领取新编号。
  3. 期满或编号失效的写入被拒绝。
合成示例 可折叠
job = {"token": 0, "expiry": 0, "result": None}

第二遍 · 把代码读懂

代码拆解

只靠心跳监控，能防止失联执行器写入迟到结果吗？

调用链

  1. 写入任务租约记录和递增编号。
  2. 到期时由新执行器领取新编号。
  3. 期满或编号失效的写入被拒绝。
  4. 所有时间和编号都以持久化边界为准。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

job = {"token": 0, "expiry": 0, "result": None}

def claim(now, ttl):
    if job["result"] is not None or job["expiry"] > now:
        return None
    job["token"] += 1
    job["expiry"] = now + ttl
    return job["token"]

def commit(token, now, result):
    if token != job["token"] or now >= job["expiry"]:
        return False
    if job["result"] is not None:
        return False
    job["result"] = result
    return True

a = claim(0, ttl=5)
assert a == 1 and claim(3, ttl=5) is None
b = claim(5, ttl=5)
assert b == 2
assert not commit(a, 6, "stale")
assert commit(b, 6, "current")
assert not commit(b, 7, "duplicate")
assert job["result"] == "current"

心跳只说明活跃，不能撤销旧进程

旧进程本身可能还在运行。领取时读当前时钟、比较到期时间、递增编号。每次回报都携带这个编号，持久化接受当前且有效的领取。

先检查租约，再修改结果

示例使用独立计时参数，真实写入需要原子检查与更新。数据库可用条件更新并检查影响行数；只在 Worker 内判断当前号，不能防止另一台机器已经接手。

对外部副作用要单独处理

围栏保护的是支持围栏检查的存储。外部服务不接围栏时，还需要单独的幂等、授权状态和补偿策略；本例不保证随意一段脚本的全部副作用都被撤销。

复现失败

僵尸执行器
怎么触发：A 取编号 1，B 接手后 A 仍提交。
怎么判断：拒绝 A，保留 B 写入的值。
租约到期点
怎么触发：在 now == expiry 时提交。
怎么判断：旧执行器落在有效期外，不得更新。

写下这些测试断言

  • 租约未到期时不可重复领取。
  • 每次真正接手续发严格递增的围栏号。
  • 相同围栏号第二次提交不覆盖。
  • 完成任务不再被重新领取。

这一课带走：判断当前谁有权写结果，要靠存储可检查的凭证，不靠执行器自觉。
