构建稳定的执行系统 · 第 08 课 · 约 28 分钟

队列、调度与重复执行

区分按时投递、实际开始、写入结果三件事。

先看场景走一遍读代码复现失败动手练习自测

先看场景

定时回归重复投递很常见，偶尔还会晚到。一次批次标识应该固定，重试也需要定义是补未结束项还是创建新批次。

触发窗口：计划里原定的一轮，比如某天上午九点。消息迟到十分钟，仍是那一轮。

走一遍

  1. 用计划和触发窗口区分不同批次。
  2. 重复消息只允许恢复原来的批次，不产生第二条运行。
  3. 取消不是瞬间完成：已经在跑的项要确认终止，没有开始的项不能再派发。
合成示例 可折叠
batchKey = scheduleId + ":" + scheduledWindow
run = findOrCreate(batchKey)

第二遍 · 把代码读懂

代码拆解

九点的回归任务因为网络抖动，九点十七分又收到触发消息。怎样知道它是补送，不是新的一批？

调用链

  1. 用计划编号和消息携带的原定 UTC 时间拼出键。
  2. 用唯一约束决定新建还是忽略重复投递。
  3. 取消时停止领取新的项目，等正在执行的项目确认。
  4. 历史批次不复活；下一个窗口可以新建。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

import sqlite3

db = sqlite3.connect(":memory:")
db.execute("""CREATE TABLE batches (
  plan TEXT, slot TEXT, state TEXT NOT NULL,
  PRIMARY KEY(plan, slot)
)""")

def create(plan, slot):
    with db:
        db.execute("""INSERT INTO batches VALUES (?, ?, 'queued')
          ON CONFLICT(plan, slot) DO NOTHING""", (plan, slot))

def cancel(plan, slot):
    with db:
        db.execute("""UPDATE batches SET state = CASE
          WHEN state = 'queued' THEN 'cancelled'
          ELSE 'cancelling' END
          WHERE plan = ? AND slot = ?
          AND state IN ('queued', 'running')""", (plan, slot))

slot = "2030-01-01T01:00:00Z"
create("booking", slot)
create("booking", slot)
assert db.execute("SELECT count(*) FROM batches").fetchone() == (1,)
cancel("booking", slot)
create("booking", slot)
assert db.execute("SELECT state FROM batches").fetchone() == ("cancelled",)
create("booking", "2030-01-02T01:00:00Z")
assert db.execute("SELECT count(*) FROM batches").fetchone() == (2,)

原定时间不是收件时间

约定上游已换算好可信的原定 UTC 时间。迟到消息仍使用原窗口。如果接受本地时间，调度层要明确处理夏令时跳过和重复时刻。两个计划触发在同一时刻，也不能混成一批。

把防重放在持久化边界

SQLite 的复合主键配合 ON CONFLICT，使两个写入争同一个键时由存储决定。如果应用先查再插而没有唯一约束，并发进程仍能各自看到不存在。若还需异步通知执行器，考虑同事务发件箱或可靠扫描，否则可能写入了却没有启动。

取消意图与停止确认分开

queued 可以直接取消，running 先变 cancelling。领任务的边界也要验证状态，不要只在 UI 中隐藏按钮。示例演示发出取消意图，未实现执行器的抢占和终止确认。系统故障重试可以留在同一批增加尝试号，一次从头重跑则显式生成新运行编号。

复现失败

迟到重投
怎么触发：调度器两次发送同一计划与窗口。
怎么判断：只创建一批，终态不回退。
运行中取消
怎么触发：将状态推进 running 再取消。
怎么判断：得到 cancelling，实际停止前不显示 cancelled。
跨窗口执行
怎么触发：同一计划换第二天的窗口再发。
怎么判断：创建新批次，不覆盖前一天。

写下这些测试断言

  • 同窗口的不同计划不互相排斥。
  • 未开始的批次可取消；运行中的先进入 cancelling。
  • 重复取消结果相同。
  • 并发集成测试用两个连接争同一个唯一键。
