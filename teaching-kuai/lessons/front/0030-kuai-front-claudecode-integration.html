1. 什么是 Claude Code Agent SDK

Claude Code Agent SDK 是 Anthropic 提供的代码分析工具。在 kuai-service-front 项目中，它被封装为 ask_claudecode 工具，让 Agent 能够执行深度代码分析、代码审查、设计文档生成等任务。

核心文件

src/agents/tools/claudecodeTools.js — 所有 Claude Code 相关逻辑都在这一个文件中实现。

2. claudecodeTools.js 实现解析

2.2 硬编码配置

// LiteLLM 配置（所有模型共用）
const LITELLM_API_KEY = 'sk-yFo...';
const LITELLM_BASE_URL = 'https://oneapi.example.com';
const DEFAULT_TIMEOUT = 1200000; // 20 分钟

这些配置通过 getModelConfig() 函数暴露，支持环境变量覆盖：

function getModelConfig() {
  const envApiKey = process.env.CLAUDECODE_API_KEY;
  const envBaseURL = process.env.CLAUDECODE_BASE_URL;
  return {
    apiKey: envApiKey || LITELLM_API_KEY,
    baseURL: envBaseURL || LITELLM_BASE_URL,
    timeout: DEFAULT_TIMEOUT,
  };
}

3. ask_claudecode 工具参数

createClaudecodeTool() 返回一个 LangChain tool() 实例，接受以下参数：

参数类型必填说明
promptstring是代码分析任务的指令文本
workDirstring否工作目录路径（通常用 git_clone 返回的 clonePath）
sessionIdstring否恢复之前的会话
timeoutnumber否超时时间（毫秒），默认 1200000（20 分钟）
skillsstring[]否要启用的技能名列表（如 ['dev-design', 'test-analysis']）
modelChoicestring否选择模型，默认使用 AVAILABLE_MODELS[0]
注意

workDir 必须是已存在的目录。如果传入不存在的路径，工具会抛出错误并提示使用 git_clone 返回的 clonePath。

4. 支持的模型列表

通过 AVAILABLE_MODELS 常量定义：

const AVAILABLE_MODELS = [
  'deepseek-v4-pro',   // 默认模型（排在第一位）
  'gpt-5.5',
  'gpt-5.4',
  'glm-5.1',
];

模型标准化逻辑（normalizeModelChoice）：

  • 如果用户不传 modelChoice，使用 AVAILABLE_MODELS[0]（即 deepseek-v4-pro）
  • 如果传入的值不在列表中，打印警告并回退到默认模型
  • 如果传入合法值，直接使用

所有模型都通过同一个 LiteLLM 代理（oneapi.example.com）调用，区别只在环境变量 ANTHROPIC_DEFAULT_SONNET_MODEL 等字段的值。

5. 与 Skills 集成

ask_claudecode 可以加载项目内 Skills，让 Claude Code Agent 按技能文档执行任务。

5.1 技能加载流程

  1. 调用 buildProjectSkillsPrompt(requestedSkills) 构建技能提示词
  2. 通过 listAllSkills() 获取所有技能元数据
  3. 过滤出调用方请求的、且确实存在的技能
  4. 生成包含技能路径的提示词，注入到 prompt 前面
// 生成的提示词示例：
## 项目技能（本地目录）
以下技能在当前仓库中可用，请按需读取对应 SKILL.md：
- dev-design - 技术设计文档生成
  路径: src/agents/skills/dev-design/SKILL.md
- test-analysis - 测试分析报告
  路径: src/agents/skills/test-analysis/SKILL.md

使用规则：
1. 优先读取 SKILL.md，先理解流程再执行
2. 若 SKILL.md 引用了 references/ 或 scripts/，按相对路径继续读取
3. 不需要复制技能文件到 ~/.claude/skills，直接在仓库内读取即可

5.2 MCP 服务器集成

工具还会将项目 src/config/mcpServers.js 中定义的 MCP 服务器转为 Claude SDK 格式，让 Claude Code 可以调用这些外部工具：

6. 超时处理机制

超时处理分三层保护：

6.1 参数规范化（normalizeTimeout）

function normalizeTimeout(timeoutMs) {
  if (!Number.isFinite(timeoutMs) || timeoutMs <= 0) {
    return DEFAULT_TIMEOUT; // 20 分钟
  }
  // 限制在 1 秒 ~ 2 小时之间
  return Math.min(Math.max(Math.floor(timeoutMs), 1000), 2 * 60 * 60 * 1000);
}

6.2 流式迭代超时（createTimeoutIterator）

这是一个核心创新——防止"无输出卡死"场景：

  • 包装一个 AsyncIterable，每次 next() 都与超时 Promise 竞争
  • 如果在剩余时间内没有产出新数据，抛出超时错误
  • 每次有数据产出，重置计时（因为剩余时间会重新计算）

6.3 模型降级重试

当调用失败时，shouldFallbackToDefaultModel() 会判断是否应切换到默认模型重试：

  • 匹配关键词：429、quota、rate limit、timeout、网络错误、502/503/504 等
  • 只有当前模型不是默认模型时才触发
  • 鉴权错误（401/403）不触发降级，而是直接报错
设计亮点

环境变量完全隔离——工具使用 buildClaudeEnv() 构建独立的 env 对象，先清除所有 ANTHROPIC_* 变量再注入新值，避免污染全局 process.env。这是参考了 Proma 项目的最佳实践。

7. CLI 路径解析

resolveClaudeCliPath() 按优先级查找 Claude Code CLI：

  1. Node 模块解析（最稳定）— 通过 createRequire() 解析 @anthropic-ai/claude-agent-sdk/cli.js
  2. 常见本地路径 — src/lib/agents/anthropic-sdk/cli.js、node_modules/@anthropic-ai/
  3. pnpm store 路径 — 扫描 .pnpm 目录下匹配的 SDK 目录
  4. 全局安装兜底 — 通过 which claude-code 查找

找到后还会检查并设置执行权限（Unix 系统）。

8. 在 Agent 中使用

import { getClaudecodeTools } from '@/agents/tools';

// 在 createAgent 中并行加载
const [mcpTools, claudecodeTools, skillTools] = await Promise.all([
  getMCPTools(MCP_SERVERS),
  getClaudecodeTools(),
  getSkillTools({ skills: ['dev-design', 'test-analysis'] }),
]);

return createReactAgent({
  llm: model,
  tools: [...mcpTools, ...claudecodeTools, ...skillTools],
});
