🎯 一、项目定位

kuai-service-front 是一个 AI 测试平台前端，核心使命是：

  • Agent 驱动：所有功能通过 LangChain Agent 暴露，用户与 AI 对话完成任务
  • 工具集成：集成 MCP 协议、Claude Code、XMind、DrawIO 等多种工具
  • 后台执行：Agent 任务与浏览器连接解耦，关闭页面后任务继续运行
  • 增量持久化：流式响应实时写入 MongoDB，支持断线恢复
Agent-First 架构意味着：不是"页面调用 API"，而是"用户与 Agent 对话 → Agent 调用工具 → 结果流式返回"。这是与传统前端最大的区别。

🏗️ 四、核心架构：Agent-First

1. Agent 系统

使用 LangChain + LangGraph 构建 AI Agent，通过 MCP 协议集成外部工具。核心流程：

  1. 定义 Agent：在 src/agents/ 使用 defineAgent() 创建
  2. 注册 Agent：在 src/lib/agents/scanner.js 手动注册
  3. 自动发现：AgentScanner 启动时加载，通过 /api/agents 暴露元数据
  4. 用户对话：前端调用 /api/agents/[id]/chat，流式返回结果
  5. 后台执行：Agent 任务与 HTTP 连接解耦，浏览器关闭后继续运行

2. 后台执行架构

这是项目最核心的设计之一：

  • AsyncQueue 广播：一个 Agent 事件流可同时推送给多个消费者
  • 增量 DB 持久化：流式响应每 500ms 节流写入 MongoDB
  • 断线恢复：用户重新进入聊天页面可查看已完成或进行中的任务
  • 任务管理：abortTask() / getRunningTasks() 管理后台任务

3. API 代理配置

使用 Next.js rewrites 实现 API 代理，优先级从高到低：

  1. 本地 API Routes（排除代理）：/api/agents/*, /api/proxy/* 等
  2. 特殊后端：/ai/* → qaigc, /api/moon/* → Moon
  3. 默认后端：/api/* → 后端服务器
易错点：新增 API Route 时必须在 next.config.js 的 rewrites 数组前面添加排除规则，否则会被通用规则代理到后端。

5. 技能系统（Skills）

基于 LangChain Skills 的渐进式披露架构：

  • 渐进式披露：系统提示中只包含技能名称和描述
  • 按需加载：Agent 先调用 list_skills 查看列表，再用 get_skill_content 读取详情
  • 技能目录：src/agents/skills/ 下每个子目录为一个技能
  • 技能文件：每个技能必须包含 SKILL.md（带 YAML frontmatter）

6. 导航与页面

  • 导航配置：集中在 src/config/navigation.js 的 navbarMenu 数组
  • 页面路由：基于 src/app/ 文件系统自动生成
  • 组件组织：components/features/ 按业务模块，components/common/ 通用组件

📝 Quiz

Q1：kuai-service-front 的核心架构设计理念是什么？

  • A. MVC 架构
  • B. Agent-First 架构 — 所有功能通过 LangChain Agent 暴露
  • C. 微前端架构
  • D. 纯 REST API 驱动

✅ 答案：B — Agent-First 是该项目最核心的设计，用户通过与 AI Agent 对话来完成任务。

Q2：Agent 任务在浏览器关闭后会怎样？

  • A. 任务立即终止
  • B. 任务继续在后台运行，支持断线恢复
  • C. 任务暂停，需要手动恢复
  • D. 任务丢失，需要重新开始

✅ 答案：B — Agent 任务与 HTTP 连接完全解耦，通过 AsyncQueue 广播和 MongoDB 增量持久化实现后台执行。

Q3：新增 API Route 时为什么需要在 rewrites 数组前面添加排除规则？

  • A. 这是可选步骤，不加也行
  • B. Next.js rewrites 按顺序匹配，不排除会被通用规则代理到后端
  • C. 为了提高性能
  • D. 为了安全认证

✅ 答案：B — Next.js rewrites 按数组顺序匹配，/api/:path* 通用规则会拦截所有请求，必须在它前面排除本地 Route。
