🧭 导航与路由系统详解

理解 navbarMenu 配置、文件系统路由、动态路由和路由守卫

本课程聚焦 Kuai 前端的导航和路由系统。导航菜单在 src/config/navigation.js 中集中配置，页面路由基于 Next.js App Router 的文件系统约定自动生成。两者配合构成了用户在应用中的导航体验。

📋 navbarMenu 导航配置

核心配置 src/config/navigation.js 是整个应用导航菜单的单一数据源。侧边栏（Sider）组件读取这个配置来渲染菜单。

配置结构

// src/config/navigation.js
export const navbarMenu = [
  // 一级菜单项（无子菜单）
  {
    label: '工作台',
    key: 'dashboard',
    icon: <HomeOutlined />,
    path: '/dashboard',
  },

  // 一级菜单项（有子菜单）
  {
    label: 'Agent管理',
    key: 'application',
    icon: <AppstoreOutlined />,
    children: [
      {
        label: 'FastQA应用列表',
        key: 'app-list',
        icon: <UnorderedListOutlined />,
        path: '/application/list',
      },
      {
        label: 'Agent评分',
        key: 'app-rating',
        icon: <StarOutlined />,
        path: '/application/rating',
      },
      // ... 更多子菜单
    ],
  },

  // 外部链接（不走前端路由）
  {
    label: 'AI语料库管理',
    key: 'knowledge-librify',
    icon: <DatabaseOutlined />,
    path: 'https://librify.example.com/',
    external: true,  // 标记为外部链接
  },
];

菜单项属性说明

属性类型必填说明
labelstring是菜单项显示文本
keystring是唯一标识，用于 Ant Design Menu 的选中状态
iconReactNode否菜单项图标（Ant Design 图标组件）
pathstring否路由路径（内部链接）或 URL（外部链接）
childrenArray否子菜单项数组（形成折叠子菜单）
externalboolean否是否为外部链接（新窗口打开）

📂 文件系统路由

Next.js App Router 使用 文件系统作为路由。你在 src/app/ 下创建的文件夹和文件结构，直接决定了 URL 路径。

基本规则

src/app/
├── page.js              →  / (首页)
├── dashboard/
│   └── page.js          →  /dashboard
├── application/
│   ├── list/
│   │   └── page.js      →  /application/list
│   └── rating/
│       └── page.js      →  /application/rating
├── agents/
│   └── page.js          →  /agents
└── mcp/
    ├── servers/
    │   └── page.js      →  /mcp/servers
    ├── groups/
    │   └── page.js      →  /mcp/groups
    └── test/
        └── page.js      →  /mcp/test

💡 导航配置与路由的对应关系

导航菜单中的 path 值必须与 src/app/ 下的文件结构一一对应。例如：

  • 菜单 path: '/mcp/servers' 对应 src/app/mcp/servers/page.js
  • 菜单 path: '/agents' 对应 src/app/agents/page.js

如果菜单配置了路径但没有对应的 page.js 文件，点击菜单会显示 404 页面。

特殊文件

文件名作用示例
page.js页面组件（必须）定义页面内容
layout.js布局组件（可选）子页面共享的布局
loading.js加载状态（可选）页面加载时的骨架屏
error.js错误处理（可选）页面出错时的错误界面
not-found.js404 页面（可选）路由未找到时显示
// src/app/agents/page.js — 典型的页面组件
'use client';  // 标记为客户端组件

import { useState, useEffect } from 'react';
import AgentChat from '@/components/common/AgentChat';

export default function AgentsPage() {
  const [agents, setAgents] = useState([]);

  useEffect(() => {
    // 加载 Agent 列表
    fetch('/api/agents')
      .then(res => res.json())
      .then(data => setAgents(data));
  }, []);

  return (
    <div>
      <h1>LangChain Agent</h1>
      {agents.map(agent => (
        <AgentCard key={agent.id} agent={agent} />
      ))}
    </div>
  );
}

🔀 动态路由

当页面需要根据 URL 参数显示不同内容时，使用 动态路由（文件夹名用方括号包裹）。

动态路由示例

# 文件结构
src/app/
└── agents/
    └── [agentId]/
        └── page.js      →  /agents/chart-agent
                            →  /agents/code-assistant
                            →  /agents/:agentId（任意 ID）
// src/app/agents/[agentId]/page.js
'use client';

import { useParams } from 'next/navigation';

export default function AgentDetailPage() {
  const { agentId } = useParams();  // 获取动态路由参数

  return (
    <div>
      <h1>Agent 详情: {agentId}</h1>
      <AgentChat agentId={agentId} />
    </div>
  );
}

嵌套动态路由

# 多级动态参数
src/app/
└── prompt-system/
    └── [promptId]/
        └── page.js      →  /prompt-system/abc123（查看提示词详情）
                            →  /prompt-system/xyz789（查看另一个提示词）

📌 实际使用：Agent 对话页面

Kuai 前端的 Agent 对话页面就是动态路由的典型应用：

  • /agents — Agent 列表页（src/app/agents/page.js）
  • /agents/[agentId] — Agent 对话页（src/app/agents/[agentId]/page.js）

用户点击列表中的某个 Agent 时，URL 变为 /agents/chart-agent，页面根据 agentId 加载对应的 Agent 配置和对话历史。

🛡️ 路由守卫与权限控制

Kuai 前端的路由守卫主要通过 布局组件 和 request 封装 来实现，而不是传统的路由中间件。

认证守卫：401 自动跳转

// 认证守卫在 request 层统一处理
// src/services/request/index.js
function checkStatus(response) {
  if (response.status === 401) {
    if (isGuestMode()) {
      return response;  // 访客模式放行
    }
    redirectToLogin();  // 未登录 → 跳转 SSO
    throw new Error('Unauthorized');
  }
  return response;
}

// 每个页面加载时都会调用 API（如获取用户信息）
// 如果未登录，第一个 API 调用就会触发 401 → 自动跳转

💡 认证守卫的工作原理

与传统前端路由守卫不同，Kuai 采用"懒认证"策略：

  • 不在路由切换时检查登录状态（避免每次导航都发请求）
  • 而是在页面发起第一个 API 请求时，由 request 函数统一检查 401
  • 如果未登录，自动跳转 SSO；登录成功后跳回原页面

这种方式的好处是：认证检查与业务逻辑解耦，所有页面自动获得认证保护。

布局层守卫：页面类型判断

// src/components/AppLayout.jsx — 根据页面类型选择布局
function AppLayoutContent({ children }) {
  const pathname = usePathname();

  // 分享页面和嵌入页面：不需要导航栏
  const isSharePage = pathname.startsWith('/share');
  const isEmbedPage = pathname.startsWith('/embed');

  if (isSharePage || isEmbedPage) {
    return <div style={{ minHeight: '100dvh' }}>{children}</div>;
  }

  // 正常页面：完整布局（Header + Sider + Content）
  return (
    <Layout>
      <Header />
      <Layout>
        <Sider>
          <SideNav menu={navbarMenu} />
        </Sider>
        <Content>{children}</Content>
      </Layout>
    </Layout>
  );
}

访客模式守卫

// 访客模式的判断逻辑
function isGuestMode() {
  const urlParams = new URLSearchParams(window.location.search);
  const isGuestMode = urlParams.get('mode') === 'guest';
  const isSharePage = window.location.pathname.startsWith('/share');

  // 必须同时满足：是分享页面 + URL 有 ?mode=guest 参数
  return isSharePage && isGuestMode;
}

📐 侧边栏菜单渲染

侧边栏组件 SideNav 读取 navbarMenu 配置，使用 Ant Design 的 Menu 组件渲染：

// src/components/layout/sider/SideNav.jsx（简化）
'use client';
import { Menu } from 'antd';
import { usePathname, useRouter } from 'next/navigation';

function SideNav({ menu }) {
  const pathname = usePathname();
  const router = useRouter();

  // 根据当前路径自动选中对应菜单项
  const selectedKey = findSelectedKey(menu, pathname);

  // 点击菜单项时的处理
  const handleClick = ({ key, keyPath }) => {
    const menuItem = findMenuItem(menu, key);

    if (menuItem.external) {
      // 外部链接：新窗口打开
      window.open(menuItem.path, '_blank');
    } else if (menuItem.path) {
      // 内部链接：使用 Next.js 路由跳转
      router.push(menuItem.path);
    }
  };

  return (
    <Menu
      mode="inline"
      selectedKeys={[selectedKey]}
      items={convertToMenuItems(menu)}
      onClick={handleClick}
    />
  );
}

⚠️ 添加新导航项的步骤

新增页面时，需要同时完成两步：

  1. 在 src/app/ 下创建对应的 page.js 文件（路由）
  2. 在 src/config/navigation.js 的 navbarMenu 数组中添加菜单配置

如果只做了其中一步，要么菜单点不开（没有页面），要么页面存在但找不到入口（没有菜单）。

🧪 知识检验

题目 1：导航配置

如果要添加一个新的子菜单项"定时任务管理"到"Agent管理"下，应该修改哪个文件？

A. src/app/application/page.js
B. src/components/layout/sider/SideNav.jsx
C. src/config/navigation.js
D. next.config.js
答案 C。所有导航菜单配置集中在 src/config/navigation.js 的 navbarMenu 数组中。要添加子菜单，需要在"Agent管理"对象的 children 数组中添加新的菜单项。同时还需要在 src/app/ 下创建对应的 page.js 文件。

题目 2：路由守卫

用户未登录时访问 /agents 页面，系统如何处理？

A. 显示一个登录弹窗
B. 直接显示 403 无权限页面
C. 页面加载后第一个 API 请求返回 401，request 函数自动跳转到 SSO 登录页
D. Next.js 中间件在路由层面拦截，直接重定向
答案 C。Kuai 前端采用"懒认证"策略：页面可以正常加载和渲染，但当组件发起第一个 API 请求（如获取 Agent 列表）时，后端返回 401。request 函数的 checkStatus 检测到 401 后自动调用 redirectToLogin() 跳转到 SSO 登录页。登录成功后会跳回原页面。

题目 3：外部链接

导航菜单中 external: true 的菜单项与普通菜单项有什么区别？

A. 外部链接会显示不同的图标
B. 外部链接不能有子菜单
C. 外部链接点击后在新窗口打开，不走 Next.js 客户端路由
D. 外部链接不需要配置 key 属性
答案 C。标记了 external: true 的菜单项，点击时会调用 window.open(menuItem.path, '_blank') 在新标签页打开。普通菜单项则使用 router.push(menuItem.path) 进行客户端路由跳转。外部链接的 path 是完整的 URL（如 https://librify.example.com/），而不是相对路径。
