⚙️ Next.js API Routes 机制

基本概念

在 Next.js App Router 中，src/app/api/ 目录下的 route.js 文件自动成为 API 端点。文件路径就是 URL 路径：

文件路径 API 端点 HTTP 方法
src/app/api/agents/route.js GET /api/agents GET
src/app/api/agents/[id]/chat/route.js POST /api/agents/:id/chat POST
src/app/api/share/[shareId]/chat/route.js POST /api/share/:shareId/chat POST
src/app/api/session-data/[sessionId]/route.js GET /api/session-data/:sessionId GET

Route Handler 语法

// src/app/api/agents/route.js

// 运行时配置
export const runtime = 'nodejs';     // 使用 Node.js runtime（非 Edge）

// 导出 HTTP 方法处理函数
export async function GET(request) {
  // request: NextRequest 对象
  const { searchParams } = new URL(request.url);
  const agentId = searchParams.get('id');

  // 业务逻辑...
  const agents = await agentRegistry.getAll();

  // 返回 JSON 响应
  return NextResponse.json(agents, {
    status: 200,
    headers: { 'Access-Control-Allow-Origin': '*' },
  });
}

动态路由参数

// src/app/api/agents/[id]/chat/route.js

// params 是动态路由参数
export async function POST(request, { params }) {
  const { id: agentId } = await params;  // 注意：需要 await
  // ...
}

注意：Next.js 16 的 params 是 Promise

在 Next.js 16 中，params 是一个 Promise，需要使用 await 解构。这是从 Next.js 15 开始的变化。

// Next.js 16 正确写法
const { id } = await params;

// 旧写法（Next.js 14 及之前）
const { id } = params;  // 不需要 await

🔀 rewrites 代理配置

架构设计 前端 API 层并不是所有请求都自己处理，很多请求通过 next.config.js 的 rewrites 配置代理到 Java 后端。

为什么需要代理？

  • 解决跨域：前端域名和 Java 后端域名不同，直接调用会有 CORS 问题
  • 统一入口：前端只需要调用自己的 /api/xxx，不需要关心后端地址
  • 安全：后端 API 地址不暴露给浏览器
  • 灵活性：可以先在 Next.js API Route 中做预处理，再代理到后端

代理流程

// next.config.js (简化)
module.exports = {
  async rewrites() {
    return [
      // 排除规则：这些路径由 Next.js 自己处理，不代理
      // （必须放在 rewrites 数组前面）

      // 代理规则：其他 /api/xxx 请求转发到 Java 后端
      {
        source: '/api/:path*',
        destination: 'http://kuai-backend:8080/api/:path*',
      },
    ];
  },
};

关键规则：排除在前，代理在后

如果新增一个 Next.js API Route（如 /api/my-feature），必须在 rewrites 中添加排除规则，否则请求会被代理到 Java 后端：

// next.config.js
async rewrites() {
  return [
    // 1. 先排除 Next.js 自己处理的路径
    { source: '/api/my-feature/:path*', destination: '/api/my-feature/:path*' },
    { source: '/api/agents/:path*', destination: '/api/agents/:path*' },
    // ...其他排除规则

    // 2. 最后是通用代理规则
    { source: '/api/:path*', destination: 'http://kuai-backend:8080/api/:path*' },
  ];
}

🤖 Agent API

GET /api/agents — Agent 列表

src/app/api/agents/route.js 提供已注册 Agent 的元数据查询。

// 查询参数
// ?public=true   → 只返回公开 Agent（默认）
// ?public=false  → 返回所有 Agent
// ?id=xxx        → 返回特定 Agent

export async function GET(request) {
  const { searchParams } = new URL(request.url);
  const agentId = searchParams.get('id');
  const showPublic = searchParams.get('public') !== 'false';

  if (agentId) {
    // 查询单个 Agent
    const definition = await agentRegistry.getDefinition(agentId);
    if (!definition) {
      return NextResponse.json(
        { error: { code: 'AGENT_NOT_FOUND' } },
        { status: 404 }
      );
    }
    return NextResponse.json(definition);
  }

  // 查询 Agent 列表
  const agents = await agentRegistry.getAll();
  const filtered = showPublic
    ? agents.filter(a => a.isPublic)
    : agents;

  return NextResponse.json(filtered);
}

POST /api/agents/[id]/chat — Agent 对话

src/app/api/agents/[id]/chat/route.js 是最核心的 API，处理 Agent 对话请求。

// 请求体结构
{
  "message": "帮我分析这个代码",       // 用户消息
  "sessionId": "abc123",               // 可选，续接已有会话
  "userId": "user1",                   // 用户 ID
  "userName": "张三",                  // 用户名
  "initialFormData": {},               // 表单数据（Agent 初始化参数）
  "runtimeSkills": [],                 // 运行时技能
  "modelKey": "gpt-4",                // 模型选择
  "xmindData": {}                      // XMind 数据（测试用例 Agent）
}

Chat API 的完整流程

  1. 解析请求，提取 agentId、message、sessionId
  2. 从 agentRegistry 获取 Agent 定义
  3. 如果没有 sessionId，创建新会话（写入 MongoDB）
  4. 加载历史消息，转换为 LangChain 格式
  5. 创建 Langfuse 追踪配置（可观测性）
  6. 调用 createAgentStreamResponse() 启动流式响应
  7. 返回 SSE 流给前端

运行时配置

// Agent 对话 API 的特殊配置
export const runtime = 'nodejs';      // 必须用 Node.js（不能用 Edge）
export const maxDuration = 1800;      // 最大执行时间 30 分钟

// 为什么是 30 分钟？
// Agent 可能执行复杂的多步骤任务（代码分析、文件操作等）
// 普通 API 通常 10 秒就够了，但 Agent 对话需要长时间运行

🔧 MCP API

API MCP 相关的 API 通过代理方式实现。

MCPHub 代理

src/app/api/proxy/mcphub/[...path]/route.js 是一个全能代理，支持所有 HTTP 方法：

// 支持的 HTTP 方法
export async function GET(request, { params }) { ... }
export async function POST(request, { params }) { ... }
export async function PUT(request, { params }) { ... }
export async function DELETE(request, { params }) { ... }
export async function PATCH(request, { params }) { ... }
export async function OPTIONS(request, { params }) { ... }

// 使用示例
// GET  /api/proxy/mcphub/servers        → MCPHub 的服务器列表
// POST /api/proxy/mcphub/servers        → 创建 MCP Server
// GET  /api/proxy/mcphub/servers/:id    → 获取 Server 详情
// PUT  /api/proxy/mcphub/servers/:id    → 更新 Server

MCP 工具在 Agent 中的实际加载通过 src/agents/tools/mcpLoader.js 完成，它使用 @langchain/mcp-adapters 库直接连接 MCP Server，不经过这个代理。代理主要用于 MCP 管理页面的 CRUD 操作。

📝 Prompt API

Prompt 管理的 API 全部在 Java 后端，前端通过服务层 src/services/modules/prompt.js 调用。由于 rewrites 配置，前端调用 /api/prompts/xxx 会被自动代理到 Java 后端。

前端服务层封装

// src/services/modules/prompt.js (示意)
import { get, post, put, del } from '@/services/request';

// 获取 Prompt 列表
export const getPrompts = (params) => get('/api/prompts', params);

// 获取 Prompt 详情
export const getPromptById = (id) => get(`/api/prompts/${id}`);

// 创建 Prompt
export const createPrompt = (data) => post('/api/prompts', data);

// 更新 Prompt
export const updatePrompt = (id, data) => put(`/api/prompts/${id}`, data);

// 获取版本列表
export const getPromptVersions = (id) => get(`/api/prompts/${id}/versions`);

Agent 内部的 Prompt 管理

除了前端页面的 CRUD，Agent 运行时也有 Prompt 管理逻辑（src/lib/agents/prompt.js）：

  • 从数据库加载 Prompt 模板
  • 变量替换（{{variable}}）
  • 版本选择和缓存
  • 与 LangChain SystemMessage 集成

🧪 知识检验

题目 1：rewrites 代理

当你在 src/app/api/ 下新增一个 /api/my-feature/route.js，但没有在 next.config.js 中添加排除规则，会发生什么？

A. 正常工作，Next.js 优先匹配自己的 API Route
B. 编译报错
C. 请求被代理到 Java 后端，你的 Route Handler 不会被执行
D. 请求返回 404
答案 C。由于 next.config.js 中有通用代理规则 { source: '/api/:path*', destination: 'http://kuai-backend:8080/api/:path*' }，所有 /api/ 开头的请求都会被代理到 Java 后端。Next.js API Route 不会自动"优先匹配"，必须在 rewrites 中添加排除规则才能让 Next.js 自己处理。这是项目中最容易踩的坑之一。

题目 2：Agent Chat API

Agent Chat API 的 maxDuration 设置为 1800 秒（30 分钟），为什么要这么长？

A. 为了防止网络超时
B. Agent 可能执行多步骤复杂任务（代码分析、文件操作、多轮工具调用），需要较长时间
C. 这是 Vercel 平台的默认值
D. 为了兼容所有浏览器的 SSE 超时设置
答案 B。Agent 在执行复杂任务时可能需要：克隆 Git 仓库、读取多个文件、调用 Claude Code 分析代码、生成 XMind 文件等。这些操作可能需要数分钟甚至更久。普通 API 通常 10 秒内完成，但 Agent 对话是一个长时间运行的任务，所以 maxDuration 设置为 1800 秒（30 分钟）。同时 runtime = 'nodejs' 确保不使用 Edge Runtime（Edge 有执行时间限制）。

题目 3：API 分层

以下哪种说法正确描述了项目的 API 架构？

A. 所有 API 都由 Next.js API Routes 处理
B. 所有 API 都代理到 Java 后端
C. 部分 API 由 Next.js 处理（如 Agent 对话），其他通过 rewrites 代理到 Java 后端
D. 前端直接调用 Java 后端，不需要 API Routes
答案 C。项目的 API 分为两层：Next.js 层处理需要 Node.js 运行时的请求（Agent 对话、流式响应、会话管理、知识库等），Java 后端层处理业务 CRUD（Prompt 管理、MCP 管理、用户管理等）。通过 rewrites 配置，前端统一调用 /api/xxx，不需要知道实际处理请求的是哪个服务。Next.js API Route 优先级需要通过排除规则来控制。
