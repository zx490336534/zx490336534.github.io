🔧 MCP 工具集成

深度 理解 MCP 协议、mcpLoader 加载器、工具缓存与各类工具实现

📖 1. MCP 协议基础

MCP (Model Context Protocol) 是 Anthropic 提出的开放协议，用于标准化 AI Agent 与外部工具/数据源之间的通信。在 kuai-service-front 中，MCP 是 Agent 获取外部能力的核心通道。

1.1 什么是 MCP？

MCP 定义了一套标准化的工具描述和调用协议，让 AI 模型能够：

  • 发现工具 — 自动获取服务器提供的工具列表及其参数描述
  • 调用工具 — 通过统一接口调用远程工具，获取结构化结果
  • 多服务器支持 — 同时连接多个 MCP 服务器，工具自动聚合

1.2 项目中的 MCP 角色

┌─────────────┐ MCP 协议 ┌──────────────────┐ │ LangChain │ ◄──────────► │ MCP Server(s) │ │ Agent │ │ (HTTP/Stdio/SSE) │ │ │ └──────────────────┘ │ ┌─────────┐ │ │ │ Tools │ │ ← mcpLoader.js 负责将 MCP 工具转换为 │ └─────────┘ │ LangChain 兼容的 Tool 对象 └─────────────┘

1.3 传输方式

传输方式配置 key说明

Stdiotransport: 'stdio'本地进程通信，适合 CLI 工具

⚙️ 2. mcpLoader 工具加载器

src/agents/tools/mcpLoader.js 是项目中最核心的工具加载模块，它将 MCP 协议的工具转换为 LangChain 兼容的 Tool 对象，并提供缓存、过滤、转换等高级能力。

2.1 核心函数：getMCPTools()

import { getMCPTools } from '@/agents/tools';

// 基本用法
const tools = await getMCPTools(MCP_SERVERS, {
  agentName: 'MyAgent',          // 日志标识
  useCache: true,                 // 使用缓存（默认 true）
  includeTools: ['create_page'],  // 仅暴露指定工具
  excludeTools: ['dangerous_*'],  // 排除指定工具
  descriptionOverrides: {         // 覆盖冗长描述，减少 token
    some_tool: '更简洁的描述',
  },
  resultTransformers: {           // 转换工具返回结果
    some_tool: (result) => result.slice(0, 500),
  },
  handleRuntimeErrors: true,      // 将异常转为可恢复结果（默认 true）
});

2.2 后处理管道

mcpLoader 在获取原始工具后，会依次执行 5 步后处理：

原始 MCP 工具 │ ▼ ① applyToolFilters — includeTools / excludeTools 过滤 │ ▼ ② applyDescriptionOverrides — 覆盖冗长描述，减少 token │ ▼ ③ applyResultTransformers — 转换工具返回结果 │ ▼ ④ applyInvokeWrappings — 入参转换 + 串行排队（合并为单层包装） │ ▼ ⑤ applyRuntimeErrorHandling — MCP 异常转为 ToolMessage(status: 'error') │ ▼ 最终可用工具列表

2.3 工具名规范化

OpenAI 兼容 API 要求工具名仅允许 [a-zA-Z0-9_-]。mcpLoader 通过 sanitizeToolName() 自动将不合规的工具名转换为安全格式，并保证唯一性。

// 原始工具名 "confluence/get-page" → 规范化为 "confluence_get-page"
// 冲突时自动追加后缀：tool, tool_1, tool_2 ...

💾 3. 工具缓存机制

mcpLoader 使用 永久缓存 策略（当前版本已从 2 分钟改为不过期），避免重复创建 MCP 客户端连接。

3.1 缓存结构

// 内部缓存 Map
const cache = new Map();
// key: JSON.stringify(排序后的 { mcpServers, loadOptions })
// value: { tools: Array, client: MultiServerMCPClient, timestamp: number }

// 并发去重
const loadingPromises = new Map();
// 同时发起相同配置的加载请求，只会实际创建一次 MCP 客户端

3.2 缓存 Key 生成

缓存 key 基于 mcpServers 配置和 loadOptions 的 JSON 序列化（对象 key 排序），确保语义相同的配置命中同一缓存。

设计要点：缓存是永久的，不过期。如果 MCP 服务端更新了工具列表，需要调用 clearMCPCache() 手动清除缓存。

3.3 Stdio 重试机制

对于 Stdio 类型的 MCP 服务，mcpLoader 内置了重试机制：

  • 重试次数：STDIO_RETRY_COUNT = 2
  • 重试间隔：STDIO_RETRY_DELAY_MS = 800ms
  • 可重试错误：connection closed、ECONNRESET、socket hang up、timed out

🧰 4. 各工具类型详解

项目在 src/agents/tools/ 目录下提供了丰富的工具集，统一从 index.js 导出。以下是核心工具类型的详细说明：

4.1 GitClone 工具

gitClone.js — 将 Git 克隆操作封装为 LangChain Tool。

import { getGitCloneTools } from '@/agents/tools';

const gitTools = await getGitCloneTools();
// 提供 git_clone 工具，Agent 可自动克隆仓库
特性说明
认证方式HTTPS 认证（默认 username: qacenter）
克隆目录自动选择 $GIT_CLONE_BASE_DIR 或 ~/repos
超时时间5 分钟（300000ms）
权限处理克隆后自动 chmod -R 777

4.2 ClaudeCode 工具

claudecodeTools.js — 基于 Claude Agent SDK 的深度代码分析工具。

import { getClaudecodeTools } from '@/agents/tools';

const claudecodeTools = await getClaudecodeTools();
// 提供 ask_claudecode 工具

支持模型deepseek-v4-pro, gpt-5.5, gpt-5.4, glm-5.1
超时时间20 分钟（1200000ms）

技能集成自动加载 ~/.claude/skills/ 目录下的技能文件

4.3 XMind 工具

xmindTools.js — 服务端 XMind 脑图编辑工具集，提供完整的脑图 CRUD 操作。

import { getXmindTools } from '@/agents/tools';

const xmindTools = await getXmindTools();

4.4 DrawIO 工具

drawioTools.js — DrawIO 图表编辑工具，支持加载、编辑、导出和验证图表。

import { getDrawioTools } from '@/agents/tools';

const drawioTools = await getDrawioTools();
// 提供：load_diagram, get_current_diagram, clear_diagram,
//        export_diagram, validate_diagram, suggest_optimization
DrawIO vs XMind：DrawIO 工具用于流程图/架构图等图表编辑，需配合 requiresDrawio: true 配置启用分屏布局；XMind 工具用于思维导图编辑，需配合 requiresXmind: true。

4.6 在 Agent 中组合使用

// 推荐：使用 Promise.all 并行加载所有工具
const [mcpTools, gitTools, claudecodeTools, xmindTools] = await Promise.all([
  getMCPTools(MCP_SERVERS, {
    agentName: 'CodeAssistant',
    useCache: true,
    descriptionOverrides: { 'confluence_get_page': '获取 Confluence 页面内容' },
  }),
  getGitCloneTools(),
  getClaudecodeTools(),
  getXmindTools(),
]);

return createReactAgent({
  llm: model,
  tools: [...mcpTools, ...gitTools, ...claudecodeTools, ...xmindTools],
});

🛡️ 5. 错误处理与容错

mcpLoader 内置了完善的错误处理机制，确保单个工具失败不会中断整个 Agent 流程：

  • 加载失败容错：MCP 工具加载失败时返回空数组，不阻塞 Agent 启动
  • 运行期错误降级：工具执行异常时，自动转换为 ToolMessage(status: 'error')，让模型决定下一步
  • AbortError 不拦截：用户主动取消时直接抛出，不做降级处理
  • 串行排队：对需要串行执行的工具（如 Confluence 页面创建），通过 serializeTools 配置避免并发冲突
// 错误降级示例
// MCP 工具执行失败后，模型收到的不是异常，而是：
// "MCP 工具 xxx 执行失败，但这不是 Agent 流程终止条件。
//  请把这次工具失败当作可恢复的工具结果处理：可以调整参数后重试、
//  改用其他工具/资料继续，或在缺少关键信息时向用户简短说明需要补充什么。"

📝 Quiz — 测测你理解了多少

Q1：mcpLoader 的缓存策略是什么？
✅ 正确答案：B
mcpLoader 使用永久缓存策略。缓存 key 基于 mcpServers 配置的 JSON 序列化，相同配置会命中缓存。如果 MCP 服务端更新了工具列表，需要调用 clearMCPCache() 手动清除。
Q2：MCP 工具加载失败时，Agent 会怎样？
✅ 正确答案：B
mcpLoader 的设计原则是"不阻塞 Agent 启动"。加载失败时返回空数组，Agent 仍可提供基础问答能力。运行期工具异常也会被转换为可恢复的 ToolMessage，不会中断 Agent 流程。
Q3：以下哪个工具用于深度代码分析？
✅ 正确答案：C
getClaudecodeTools() 基于 Claude Agent SDK 提供 ask_claudecode 工具，支持深度代码分析、技术设计文档生成等。GitClone 用于克隆仓库，XMind 用于脑图编辑，DrawIO 用于图表编辑。
