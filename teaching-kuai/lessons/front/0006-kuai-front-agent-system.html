📐 一、LangChain Agent 定义流程

每个 Agent 的生命周期分为 3 个阶段：定义 → 注册 → 运行。

1

↓
2

↓
3

↓

🔧 二、defineAgent 辅助函数

源码位置：src/lib/agents/define.js

defineAgent() 是所有 Agent 定义的入口，它做的事情很简单 — 给定义对象设置默认值：

// src/lib/agents/define.js
export function defineAgent(definition) {
  return {
    isPublic: true,           // 默认公开
    enableSuggestions: true,   // 默认启用建议
    enableModelSwitch: false,  // 默认不启用模型切换
    ...definition,             // 用户定义覆盖默认值
  };
}

extractMetadata — 元数据提取

define.js 还导出了 extractMetadata() 函数，用于从 Agent 定义中提取轻量级元数据（不含 createAgent 函数），供 /api/agents 返回给前端：

export function extractMetadata(definition, fallbackId) {
  return {
    id: definition.id || fallbackId,
    name: definition.name,
    description: definition.description,
    isPublic: definition.isPublic ?? true,
    enableSuggestions: definition.enableSuggestions ?? true,
    examples: [...(definition.examples || [])],
    requiresDrawio: definition.requiresDrawio ?? false,
    requiresXmind: definition.requiresXmind ?? false,
    allowAddKnowledge: definition.allowAddKnowledge ?? false,
    initialForm: definition.initialForm ?? null,
    mountedSkills: inferMountedSkills(definition),  // 自动推断挂载的技能
    enableModelSwitch: ...,
    modelOptions: ...,
  };
}
inferMountedSkills 会自动扫描 createAgent 函数源码中的 getSkillTools() 调用，提取挂载的技能名称。这是一种巧妙的静态分析技巧。

🔍 三、AgentScanner 自动注册

源码位置：src/lib/agents/scanner.js

由于 Next.js 打包限制无法使用真正的动态导入，所有 Agent 必须手动静态导入后注册到 AGENT_MODULES 数组。

注册步骤

// src/lib/agents/scanner.js

// 1. 导入 Agent 定义
import myAgent from '@/agents/my-agent';

// 2. 添加到 AGENT_MODULES 数组
const AGENT_MODULES = [
  { filename: 'chart-agent.js', module: chartAgent },
  { filename: 'code-assistant-agent.js', module: codeAssistantAgent },
  // ... 更多 Agent
  { filename: 'my-agent.js', module: myAgent },  // ⬅️ 新增
];

AgentScanner 类

class AgentScanner {
  constructor() {
    this.agentModules = AGENT_MODULES;
  }

  // 从文件名推导 Agent ID
  getAgentIdFromFilename(filename) {
    return filename.replace(/\.(ts|js)$/, '');
  }

  // 加载并验证单个 Agent 模块
  loadAgentModule(agentEntry) {
    const { filename, module: definition } = agentEntry;
    const fallbackId = this.getAgentIdFromFilename(filename);

    // 验证必填字段
    if (!isValidAgentDefinition(definition)) {
      return { success: false, error: '缺少 name, description, createAgent' };
    }

    // 提取元数据
    const metadata = extractMetadata(definition, fallbackId);
    return { success: true, definition, metadata };
  }

  // 扫描所有 Agent
  async scanAgents() {
    const agents = new Map();
    for (const entry of this.agentModules) {
      const result = this.loadAgentModule(entry);
      if (result.success) {
        agents.set(result.definition.id, result.definition);
      }
    }
    return agents;
  }
}

// 单例导出
export const agentScanner = new AgentScanner();

扫描流程

  1. 遍历 AGENT_MODULES 数组
  2. 对每个模块调用 isValidAgentDefinition() 验证（必须有 name, description, createAgent）
  3. 调用 extractMetadata() 提取元数据
  4. 去重检查（相同 ID 的 Agent 跳过后者）
  5. 返回 Map<id, definition>
常见错误：忘记在 scanner.js 注册是最常见的遗漏。Agent 文件写好了但不出现在列表中，第一步就检查这里。

🤖 四、createReactAgent

createReactAgent 来自 @langchain/langgraph/prebuilt，是 LangGraph 提供的预构建 ReAct Agent。

ReAct 模式

ReAct = Reasoning + Acting。Agent 的思考-行动循环：

  1. 思考（Thought）：分析用户问题，决定需要什么工具
  2. 行动（Action）：调用工具获取信息
  3. 观察（Observation）：获取工具返回结果
  4. 循环：重复直到得出最终答案

在 Agent 中使用

// src/agents/my-agent.js
import { defineAgent } from "@/lib/agents/define";
import { createReactAgent } from "@langchain/langgraph/prebuilt";
import { ChatOpenAI } from "@langchain/openai";
import { MODEL_CONFIG } from "@/config/modelConfig";

export default defineAgent({
  name: '我的助手',
  description: '示例 Agent',

  createAgent: async (options = {}) => {
    const { formData = {} } = options;

    // 1. 创建 LLM 模型
    const model = new ChatOpenAI({
      model: MODEL_CONFIG.defaultModel,
      temperature: 0.3,
      apiKey: MODEL_CONFIG.defaultApiKey,
      configuration: { baseURL: MODEL_CONFIG.defaultBaseHost },
    });

    // 2. 并行加载工具（推荐）
    const [mcpTools, gitTools, claudecodeTools] = await Promise.all([
      getMCPTools(MCP_SERVERS, { useCache: true }),
      getGitCloneTools(),
      getClaudecodeTools(),
    ]);

    // 3. 创建 ReAct Agent
    return createReactAgent({
      llm: model,
      tools: [...mcpTools, ...gitTools, ...claudecodeTools],
    });
  },
});
最佳实践：使用 Promise.all() 并行加载工具，避免串行等待。MCP 工具有 2 分钟缓存，重复调用不会重新创建客户端。

工具并行加载模式

// 推荐：并行加载
const [mcpTools, gitTools, skillTools] = await Promise.all([
  getMCPTools(MCP_SERVERS, { useCache: true }),
  getGitCloneTools(),
  getSkillTools({ skills: ['git-clone', 'dev-design'] }),

// 不推荐：串行加载
const mcpTools = await getMCPTools(...);      // 等待...
const gitTools = await getGitCloneTools();    // 再等待...
const skillTools = await getSkillTools(...);  // 再等待...

🌊 五、流式对话处理

源码位置：src/lib/agents/chatStreamHandler.js

这是整个 Agent 系统最复杂的部分 — 统一的对话流处理器，同时服务于普通对话和分享对话。

核心架构

agent.streamEvents()           ← LangGraph 生成事件流
        │
        ▼
   AsyncQueue 广播              ← 一个流分发给多个消费者
        │
   ┌────┴────┐
   ▼         ▼
AI SDK 流   后台 DB 持久化       ← 两条独立管道
(前端 SSE)  (MongoDB 增量写入)

AsyncQueue — 解耦生产者和消费者

核心设计：当浏览器关闭时，AI SDK 流消费者断开，但后台 DB 持久化消费者不受影响。

class AsyncQueue {
  constructor() {
    this._queue = [];
    this._resolve = null;
    this._done = false;
  }

  // 生产者推送事件
  push(value) {
    if (this._resolve) {
      this._resolve({ value, done: false });
      this._resolve = null;
    } else {
      this._queue.push(value);
    }
  }

  // 标记结束
  end() { this._done = true; }

  // 消费者通过 async iteration 消费
  [Symbol.asyncIterator]() {
    return {
      next: () => {
        if (this._queue.length > 0)
          return Promise.resolve({ value: this._queue.shift(), done: false });
        if (this._done)
          return Promise.resolve({ value: undefined, done: true });
        return new Promise((resolve, reject) => { this._resolve = resolve; });
      }
    };
  }
}

后台 DB 持久化

persistInBackground() 函数消费事件流并增量写入 MongoDB：

  • 节流写入：每 500ms 最多写一次 DB，避免频繁 IO
  • 累积状态：content（文本）、toolCalls（工具调用）、parts（有序消息部件）
  • 最终写入：流结束时强制写入 streaming: false
  • 中断支持：收到 abort 信号时保存当前进度

任务管理

// 全局任务注册表
const runningTasks = new Map();

// 终止任务
export function abortTask(taskId) {
  const task = runningTasks.get(taskId);
  if (task) {
    task.abortController.abort();
    runningTasks.delete(taskId);
    return true;
  }
  return false;
}

// 查询运行中的任务
export function getRunningTasks() {
  return Array.from(runningTasks.values());
}

📝 Quiz

Q1：defineAgent() 函数的核心作用是什么？

  • A. 创建 LangGraph Agent 实例
  • B. 给 Agent 定义对象设置默认值（isPublic=true, enableSuggestions=true 等）
  • C. 注册 Agent 到全局注册中心
  • D. 启动流式对话

✅ 答案：B — defineAgent() 本身非常简单，就是用展开运算符合并默认值和用户定义。真正的 Agent 创建在 createAgent 工厂函数中。

Q2：为什么 Agent 必须在 scanner.js 中手动注册，而不能自动扫描 src/agents/ 目录？

  • A. 为了代码审查方便
  • B. Next.js 打包限制，无法使用真正的动态导入
  • C. 为了安全性
  • D. 这是 LangChain 的要求

✅ 答案：B — Next.js 的 Turbopack/Webpack 打包器需要在编译时知道所有依赖，不支持运行时动态扫描目录，所以必须静态导入。

Q3：在 chatStreamHandler 的后台持久化中，DB 写入的节流间隔是多少？为什么需要节流？

  • A. 100ms，为了实时性
  • B. 500ms，避免频繁 IO 操作影响性能
  • C. 5s，节省存储空间
  • D. 不节流，每次事件都写入

✅ 答案：B — DB_UPDATE_INTERVAL_MS = 500。流式输出每秒可能产生几十个 token 事件，每次都写 DB 会造成巨大 IO 压力，500ms 节流是性能和实时性的平衡点。
