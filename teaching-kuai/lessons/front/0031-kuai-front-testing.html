2. ESLint 代码检查

ESLint 是项目中最常用的代码质量工具，每次提交前都应该运行。

2.1 配置文件

配置位于项目根目录 .eslintrc.js：

// .eslintrc.js 核心配置
module.exports = {
  root: true,
  env: {
    browser: true,
    es2021: true,
    node: true,
  },
  extends: ['eslint:recommended', 'plugin:react/recommended'],
  plugins: ['react'],
  rules: {
    'no-var': 'error',           // 禁止 var，必须用 let/const
    eqeqeq: 'error',             // 必须用 === 而非 ==
    'no-unused-vars': 'warn',   // 未使用的变量给警告
    'no-undef': 'error',         // 未定义的变量报错
    'no-console': 'off',         // 允许 console.log（项目需要调试）
    'react/prop-types': 'off',  // 不使用 PropTypes
  },
};

2.2 关键规则解读

规则级别含义
no-varerror禁止使用 var，防止变量提升带来的 bug
eqeqeqerror强制使用 ===，避免隐式类型转换
no-unused-varswarn未使用的变量给警告（_ 开头的变量豁免）
no-redeclareerror禁止重复声明变量
default-caseerrorswitch 语句必须有 default 分支
max-paramserror函数最多 10 个参数（超过说明函数太复杂）
no-consoleoff允许 console.log（项目调试需要）

2.3 忽略文件

.eslintignore 配置了忽略目录：

node_modules/
build/
.next/
craco.config.js

2.4 使用方法

# 检查所有文件
pnpm lint

# 检查特定文件（VS Code 自动集成）
# 保存时自动检查，无需手动运行
最佳实践

建议在 VS Code 中安装 ESLint 扩展，实现保存时自动检查。这样在写代码时就能实时发现错误，而不是等到提交时才看到一堆警告。

3. 单元测试（Vitest）

Vitest 是一个基于 Vite 的极速测试框架，兼容 Jest API。适合测试纯函数、工具类、Hooks 等。

3.1 为什么选择 Vitest

特性VitestJest
速度极快（基于 Vite）较快
配置零配置（与 Vite 共享）需要额外配置
ESM 支持原生支持需要额外配置
API 兼容兼容 Jest标准
与 Next.js 16推荐（Turbopack 兼容）需要额外适配

3.2 测试文件规范

测试文件命名约定：

  • 文件名：*.test.js 或 *.spec.js
  • 位置：与被测文件同目录，或在 __tests__/ 子目录
// 示例：测试工具函数
// src/lib/utils.test.js
import { describe, it, expect } from 'vitest';
import { maskSecret } from './utils';

describe('maskSecret', () => {
  it('应该脱敏长字符串', () => {
    expect(maskSecret('sk-1234567890abcdef'))
      .toBe('sk-1***cdef');
  });

  it('短字符串返回 ***', () => {
    expect(maskSecret('short')).toBe('***');
  });

  it('空值返回 (empty)', () => {
    expect(maskSecret(undefined)).toBe('(empty)');
  });
});

Agent 核心逻辑（如 createReactAgent、MCP 工具加载）依赖外部服务，不适合纯单元测试，应该用集成测试或 E2E 测试覆盖。

4. E2E 测试（Playwright）

Playwright 是 Microsoft 出品的端到端测试工具，支持 Chromium、Firefox、WebKit 三大浏览器引擎。

4.1 为什么选择 Playwright

  • 自动等待 — 不需要手动 sleep，自动等元素出现
  • 多浏览器 — 一套代码测试 Chromium/Firefox/WebKit
  • API 测试 — 可以同时测试前端页面和后端 API
  • 调试友好 — 自带 Trace Viewer 录制测试过程

4.2 测试场景示例

// 示例：测试 Agent 对话页面
import { test, expect } from '@playwright/test';

test('Agent 列表页应该显示所有 Agent', async ({ page }) => {
  await page.goto('/application/list');

  // 等待 Agent 卡片加载
  const cards = page.locator('.agent-card');
  await expect(cards.first()).toBeVisible();

  // 至少应该有一个 Agent
  const count = await cards.count();
  expect(count).toBeGreaterThan(0);
});

test('应该能发送消息并收到回复', async ({ page }) => {
  await page.goto('/agents?agent=code-assistant');

  // 输入消息
  await page.fill('textarea', '你好');
  await page.click('button[type="submit"]');

  // 等待 AI 回复出现
  const reply = page.locator('.message-assistant');
  await expect(reply.first()).toBeVisible({ timeout: 30000 });
});

4.3 适合 E2E 测试的场景

场景测试内容
Agent 列表页面加载、Agent 卡片渲染、点击跳转
对话页面消息发送、流式回复、历史加载
MCP 管理工具列表展示、配置编辑
分享页面访客模式访问、内容渲染
导航侧边栏展开收起、路由跳转
注意

E2E 测试涉及真实 AI 调用时，建议使用 Mock 服务或录制回放，避免测试依赖外部 API 的可用性和费用。Playwright 的 page.route() 可以拦截网络请求。

5. 测试策略

5.1 测试金字塔

          /\
         /  \        E2E 测试（少量，覆盖核心流程）
        /    \
       /------\      集成测试（中量，覆盖模块交互）
      /        \
     /----------\    单元测试（大量，覆盖工具函数和逻辑）
    /            \

5.2 项目测试优先级

优先级测试类型覆盖范围
P0（必须）ESLint所有代码提交前检查
P1（重要）单元测试工具函数、配置解析、错误处理
P2（补充）E2E 测试核心用户流程（登录→选 Agent→对话）
P3（可选）视觉回归关键页面截图对比

5.3 AI 项目的特殊挑战

难点
  • LLM 输出不确定 — 同样的输入可能得到不同的输出，不能用精确匹配
  • 外部依赖多 — MCP 服务、LLM API、Git 服务都可能不可用
  • 流式响应 — 需要测试流式事件的完整性和顺序
  • 长时间任务 — Agent 任务可能运行数分钟，E2E 测试需要设置足够超时

5.4 推荐做法

  1. ESLint 优先 — 配合 VS Code 扩展，保存时自动检查
  2. 工具函数写单元测试 — 纯函数最容易测试，回报最高
  3. 关键路径写 E2E — 登录、Agent 列表、对话发送
  4. Mock 外部服务 — 用 page.route() 拦截 API 请求
  5. 集成到 CI — 提交时自动运行 ESLint 和单元测试
