🤖 1. 如何新增 Agent（3 步）

新增 Agent 是最常见的开发任务，必须完成以下 3 个步骤（第 2 步最容易忘记！）：

步骤 1：创建 Agent 定义文件

在 src/agents/ 目录下创建 Agent 文件，使用 defineAgent 辅助函数：

// src/agents/my-new-agent.js
import { defineAgent } from '@/lib/agents/define';
import { createReactAgent } from '@langchain/langgraph/prebuilt';
import { ChatOpenAI } from '@langchain/openai';
import { MODEL_CONFIG } from '@/config/modelConfig';
import { getMCPTools, getGitCloneTools } from '@/agents/tools';

export default defineAgent({
  // === 元数据 ===
  id: 'my-new-agent',           // 可选，默认从文件名推断
  name: '我的新助手',
  description: '这个 Agent 做什么...',
  isPublic: true,                // 是否在前端列表中显示

  // === UI 布局 ===
  requiresDrawio: false,         // 需要 DrawIO 编辑器分屏？
  requiresXmind: false,          // 需要 XMind 脑图分屏？
  allowAddKnowledge: false,      // 允许添加知识库？

  // === 示例问题 ===
  examples: [
    { key: 'ex1', icon: 'BulbOutlined', label: '示例问题 1' },
    { key: 'ex2', icon: 'CodeOutlined', label: '示例问题 2' },
  ],

  // === Agent 创建函数 ===
  createAgent: async (options = {}) => {
    const { formData = {} } = options;

    const model = new ChatOpenAI({
      model: MODEL_CONFIG.defaultModel,
      temperature: 0.3,
      apiKey: MODEL_CONFIG.defaultApiKey,
      configuration: { baseURL: MODEL_CONFIG.defaultBaseHost },
    });

    // 并行加载工具
    const [mcpTools, gitTools] = await Promise.all([
      getMCPTools({
        my_server: {
          transport: 'http',
          url: 'https://kuai-mcp.example.com/groups/xxx/mcp',
        },
      }, { agentName: 'MyNewAgent' }),
      getGitCloneTools(),
    ]);

    return createReactAgent({
      llm: model,
      tools: [...mcpTools, ...gitTools],
    });
  },
});

步骤 2：在 scanner.js 中注册 ⚠️ 必须！

由于 Next.js 的动态导入限制，所有 Agent 必须手动在 scanner.js 中注册：

// src/lib/agents/scanner.js
// 1. 添加 import
import myNewAgent from '@/agents/my-new-agent';

// 2. 在 AGENT_MODULES 数组中添加
const AGENT_MODULES = [
  // ... 现有 agents
  { filename: 'my-new-agent.js', module: myNewAgent },  // ← 新增这一行
];
最常见的错误：忘记在 scanner.js 中注册！Agent 文件写好了但不出现在列表中，99% 是因为漏了这一步。

步骤 3：验证

# 1. 启动开发服务器
pnpm dev

# 2. 检查控制台日志，应看到：
# [AgentScanner] Registered agent: my-new-agent (我的新助手)

# 3. 验证 API 返回
curl http://localhost:3000/api/agents | grep "my-new-agent"

# 4. 在浏览器中访问测试
# http://localhost:3000/agents?agent=my-new-agent

📄 2. 如何新增页面

项目使用 Next.js 16 App Router 的文件系统路由，新增页面只需在 src/app/ 下创建对应文件。

2.1 创建页面文件

src/app/
├── my-feature/
│   ├── page.js           # 页面组件（必需）
│   ├── layout.js         # 可选：页面布局
│   ├── loading.js        # 可选：加载状态
│   └── error.js          # 可选：错误处理

2.2 页面组件模板

// src/app/my-feature/page.js

🔧 3. 如何新增 MCP 工具

如果需要让 Agent 使用新的 MCP 工具，有两种方式：

3.1 使用已有 MCP 服务器的工具

只需在 Agent 的 createAgent 中配置 MCP 服务器 URL，工具会自动加载：

const tools = await getMCPTools({
  my_server: {
    transport: 'http',
    url: 'https://kuai-mcp.example.com/groups/my-group/mcp',
  },
}, {
  agentName: 'MyAgent',
  // 可选：只暴露部分工具
  includeTools: ['tool_a', 'tool_b'],
  // 可选：排除某些工具
  excludeTools: ['dangerous_tool'],
  // 可选：覆盖冗长描述
  descriptionOverrides: {
    tool_a: '更简洁的描述',
  },
});

3.2 使用自定义工具（非 MCP）

如果需要添加非 MCP 的自定义工具，使用 LangChain 的 tool() 函数：

import { tool } from '@langchain/core/tools';
import { z } from 'zod';

const myCustomTool = tool(
  async (input) => {
    // 工具逻辑
    const { param1, param2 } = input;
    const result = await doSomething(param1, param2);
    return JSON.stringify(result);
  },
  {
    name: 'my_custom_tool',
    description: '工具描述，告诉 Agent 什么时候使用这个工具',
    schema: z.object({
      param1: z.string().describe('参数1的描述'),
      param2: z.number().optional().describe('参数2的描述（可选）'),
    }),
  }
);

// 在 createAgent 中使用
return createReactAgent({
  llm: model,
  tools: [...mcpTools, myCustomTool],
});

3.3 注册为可复用工具

如果工具需要在多个 Agent 中复用，在 src/agents/tools/ 创建独立文件并从 index.js 导出：

// src/agents/tools/myTools.js
import { tool } from '@langchain/core/tools';
import { z } from 'zod';

export function createMyTool(options = {}) {
  return tool(async (input) => { /* ... */ }, {
    name: 'my_tool',
    description: '...',
    schema: z.object({ /* ... */ }),
  });
}

export function getMyTools() {
  return [createMyTool()];
}

// src/agents/tools/index.js — 添加导出
export { createMyTool, getMyTools } from './myTools';

🔌 5. API Route 开发

项目使用 Next.js API Routes 实现服务端逻辑，并通过 rewrites 代理后端请求。新增 API Route 有两个必须步骤。

5.1 创建 API Route

// src/app/api/my-feature/route.js
import { NextResponse } from 'next/server';

export async function GET(request) {
  // 处理 GET 请求
  const { searchParams } = new URL(request.url);
  const id = searchParams.get('id');

  return NextResponse.json({ data: { id, name: 'test' } });
}

export async function POST(request) {
  // 处理 POST 请求
  const body = await request.json();
  // ... 业务逻辑
  return NextResponse.json({ success: true });
}

5.2 添加 rewrites 排除规则 ⚠️ 必须！

在 next.config.js 的 rewrites 数组前面添加排除规则：

// next.config.js
async rewrites() {
  return [
    // ✅ 新增：排除新的 API Route（放在最前面！）
    {
      source: '/api/my-feature/:path*',
      destination: '/api/my-feature/:path*',
    },

    // 现有排除规则
    { source: '/api/agents/:path*', destination: '/api/agents/:path*' },
    { source: '/api/health/:path*', destination: '/api/health/:path*' },
    // ...

    // ⚠️ 通用代理规则（必须放在最后！）
    {
      source: '/api/:path*',
      destination: 'http://backend.com/api/:path*',
    },
  ];
}
为什么需要排除规则？Next.js 的 rewrites 按顺序匹配。如果没有排除规则，/api/my-feature/* 会被最后的通用规则 /api/:path* 代理到后端，导致本地 API Route 不生效。

5.3 API Route 开发检查清单

  • 在 src/app/api/[feature]/route.js 创建文件
  • 在 next.config.js 的 rewrites 数组前面添加排除规则
  • 使用 NextResponse 返回响应（不是 res.json()）
  • 测试 API 是否被错误代理到后端

📋 6. 开发流程总结

6.1 新功能开发流程

  1. 创建页面：在 src/app/ 创建路由文件
  2. 添加导航：在 src/config/navigation.js 添加配置
  3. 创建组件：在 src/components/features/ 组织组件
  4. API 集成：在 src/services/modules/ 添加 API 服务
  5. 状态管理：复杂状态用 Redux，简单状态用 React hooks

6.2 Agent 开发流程

  1. 定义 Agent：在 src/agents/ 创建 Agent 文件
  2. 注册 Agent：在 src/lib/agents/scanner.js 中添加
  3. 测试 Agent：访问 /agents?agent=my-agent 测试
  4. 集成工具：MCP / ClaudeCode / Git Clone / XMind / DrawIO
  5. 优化提示词：调整系统提示词和技能描述

6.3 技能开发流程

  1. 创建技能目录：在 src/agents/skills/ 创建目录（kebab-case）
  2. 编写 SKILL.md：包含 YAML frontmatter（name + description）
  3. 添加参考资料：在 references/ 添加最佳实践和示例
  4. 测试技能：在 Agent 中使用 getSkillTools({ skills: ['my-skill'] })

📝 Quiz — 测测你理解了多少

Q1：新增 Agent 必须完成的 3 个步骤中，最容易忘记的是哪个？
✅ 正确答案：B
在 scanner.js 中注册是最容易忘记的步骤。由于 Next.js 的动态导入限制，Agent 必须手动在 AGENT_MODULES 数组中注册，否则不会出现在 Agent 列表中。
Q2：新增 API Route 时，为什么要在 rewrites 数组前面添加排除规则？
✅ 正确答案：B
Next.js 的 rewrites 按顺序匹配。如果排除规则放在通用规则 /api/:path* 后面，新 Route 会被通用规则代理到后端，导致本地 API Route 不生效。必须放在前面。
Q3：以下哪个不是 defineAgent 的有效配置项？
✅ 正确答案：C
requiresRedux 不是 defineAgent 的有效配置项。有效的配置包括 requiresDrawio（DrawIO 分屏）、requiresXmind（XMind 分屏）、allowAddKnowledge（知识库导入）等。Redux 是全局状态管理，与 Agent 定义无关。
