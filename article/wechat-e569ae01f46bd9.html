创建自定义模板标签

  • simple_tag 处理数据并返回一个字符串

  • inclusion_tag 处理数据并返回所显示的模版

每个模板标签模块都需要定义一个register变量作为有效的标签库。

在blog/templatetags/blog_tags.py

from django import template
from ..models import Post
from django.db.models import Count
from django.utils.safestring import mark_safe
import markdown

register = template.Library()


@register.simple_tag #注册为简单的标签
def total_posts():
    return Post.published.count()


@register.inclusion_tag('blog/post/latest_posts.html')
def show_latest_posts(count=5):
    latest_posts = Post.published.order_by('-publish')[:count]
    return {'latest_posts': latest_posts}


@register.simple_tag
def get_most_commented_posts(count=5):
    return Post.published.annotate(
        total_comments=Count('comments')
    ).order_by('-total_comments')[:count]


@register.filter(name='markdown')
def markdown_format(text):
    return mark_safe(markdown.markdown(text))

blog/post/latest_posts.html

<ul>
    {% for post in latest_posts %}
        <li>
            <a href="{{ post.get_absolute_url }}">{{ post.title }}</a>
        </li>
    {% endfor %}
</ul>

使用标签

  • 在html文件上使用total_posts

{% load blog_tags %}
<p>This is my blog. I`ve written {% total_posts %} posts so far.</p>

  • 在html文件上使用show_latest_posts

<h3>Latest posts</h3>
{% show_latest_posts 3 %}

  • 在html文件上使用get_most_commented_posts

<h3>Most commented posts</h3>
{% get_most_commented_posts as most_commented_posts %}
<ul>
    {% for post in most_commented_posts %}
        <li>
            <a href="{{ post.get_absolute_url }}">{{ post.title }}</a>
        </li>
    {% endfor %}
</ul>

纸舟的原文章卡包含完整说明，摘要页只想显示较短的片段。

原文介绍自定义模板标签和过滤器。

本片不运行引擎，而用蓝帆文章说明两类工具。

一个场景是变换某个给定值，另一个是组织一段展示结构。

先决定实际想做什么，再考虑用哪一种。

不要让模板的便利掩盖规则，也不要为缩短展示误把原始内容改掉。

把蓝帆的全文放进一个展示镜片，读者看到缩短的版本，原始卡仍保留完整内容。

过滤器的职责可描述为拿到值、按约定转换并给出结果。

还需给空值或本来很短的内容一条可核对的规则，否则简单的展示改动会导致一些读者看不到合理结果。

不因为一个工具处理了显示，就让它替应用判断谁有权看到原始资料。

原文提到一种标签返回简单输出，另一种可以配合一段模板。

比如页上想重复展示虚构文章卡，可以让对应片段接到标题和摘要，而不是读取一个无边界的全站资料库。

简单的变换仍可交给过滤器。

版本相关名称要按项目核对。

课堂重点是能解释输入、责任和输出，不是让每种模板功能都走同一个入口。

例如纸舟某张文章卡尚未公开，不靠模板把标题剪短就变成可见。

业务先决定这批内容有哪些，模板再选择怎样排列。

空列表应该有清楚的展示，不为凑一个非空结果偷拿其它草稿。

旧文具体语法依时代而定。

我们不执行输入和模板，只在手画片段中验证一条简单边界：可见什么与怎样显示，是两份不同规则。

最后让同伴拿短摘要和重复展品卡各讲一遍。

不执行框架也应该能指出某个值怎么转换，某个片段为什么出现。

再用一张没有内容的纸卡验空态。

把数据是否可见、值怎样展示、片段如何组织区分开后，对框架各种标签不必死记也能看懂；遇到新需求，先选最小的展示办法，再检查是否改变了原来负责的事情。
