主题：UI 自动化框架

执行测试的时候使用的语句是

stage('执行测试'){
   steps{
       dir("${env.WORKSPACE}/src/cases/") {
       sh ""
              sh '''
              python3 allure_debug.py
              exit 0
              '''
                  }
          }
}

所以还需要一个src/cases/allure_debug.py文件来执行整个测试套件

编写allure_debug.py

第三方模块路径添加到环境变量

在项目中导包使用的语句为from src.xxx import xxx

这种导入方式在Pycharm中可以正常执行，但是在命令行执行的时候会报错，因为对于命令行的环境来说，它不知道你的src所在的路径，所以需要把它加到环境变量中

import os
import sys

BASE_PATH = os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__)))) 
sys.path.append(BASE_PATH)
sys.path.append(os.path.join(BASE_PATH, 'src'))

通过os和sys模块找到文件路径并添加到环境变量中

获取需要执行的用例

有两种方式获取要执行的用例

  1. 根据jenkinsfile中的case的内容

  2. 当前文件夹下全部符合pytest执行条件的测试文件

from src.utils.constant import CASES

if CASES:
    test_cases = CASES.split('\n')

通过切割\n就可以拿到jenkinsfile中填写的测试用例了

使用pytest.main执行

https://docs.pytest.org/en/7.0.x/reference/reference.html?highlight=main#pytest.main

pytest有很多的命令可以使用，可以使用pytest -h查看

这次用到

-s ：shortcut for --capture=no.

-v：increase verbosity.

--durations=0：show N slowest setup/test durations (N=0 for all)

--alluredir：Generate Allure report in the specified directory (may not exist)

拼接一个pytest执行命令来执行

if CASES:
    test_cases = CASES.split('\n')
    main_list = [
        '-s',
        '-v',
        *test_cases,
        '--durations=0', '--clean-alluredir',
        '--alluredir', f'{REPORT_PATH}/allure_results'
    ]
else:
    main_list = [
        '-s',
        '-v',
        '--durations=0', '--clean-alluredir',
        '--alluredir', f'{REPORT_PATH}/allure_results'
    ]

判断是否需要并发

if CONCURRENT != '否':  # 是否并发执行
    main_list.append('-n')
    main_list.append(CONCURRENT)
    main_list.append('--dist')
    main_list.append('loadfile')

运行

pytest.main(main_list)

阅读视频文字稿

纸舟的离线展品示意有三个检查：打开预览、缺少标题和保留原样。

原文讲写一个 pytest 执行入口，用来选择、跑并发并生成报告。

本片用长条纸卡画清三个问题，先选择要验证什么，再说明怎么组织运行，最后把结果交给报告。

不因为设置了三个用例就假定三个都执行完，也不通过打开报告界面推断上一次没有失败。

想选择预览这一组静态样本，可以按事先定义的标签缩小范围。

下一步不是直接假定已经选对，而是先核对实际能够收集到哪些项目。

可能拼错标签，一条也没选到。

只有在清单满足意图的时候才继续讨论计划。

用三张纸卡比较只选一组、选多个合成样本和未收集到样本，各自应该是不同的记录，不让空清单变成绿色。

两条路同时检查时，不能共用一张会被修改的纸舟卡。

否则一条已经选了新封面，另一条看到旧封面失败的原因就不清楚。

并发在不同工具和插件里要按受控项目核对。

更重要的是先确认数据、资源与结果归属是否独立，仍能知道哪个回执属于哪条用例。

没有可信串行基准或者隔离证据，不应为了看起来快就强行一起跑。

画两个虚构运行批次，每个结果有自己的回执。

报告只根据本轮回执汇总；如果本轮缺少某条，就说没有证据。

别用上次成功那张卡补位。

即使有失败，仍可以整理出已得到的结果。

一份报告打不开，不代表测试没有运行。

旧文里不同参数和工具属于历史选择，本片只留下职责和可追溯的关系，不使用真实报告路径。

最后让没参与的人从入口说明看到这一轮选了哪些内容，是否真正运行，报告用了哪张资料。

再用一份空选的纸卡检查，没有用例时不能说本轮完成验证。

把边界留在可读的地方，方便以后排查执行入口、测试本身或报告哪边出了问题。

它的价值不在于把多条命令藏起来，而在于每一步都有能解释的结果。
