用 AI 补上 UI 自动化里的视觉断言

听白2026-11-25 约 2 分钟 近 30 天阅读 评论

有些页面看起来出错了，UI 自动化还会通过。脚本确认了画布存在，按钮也能点，截图里却出现一块不该出现的黑区。原来的元素断言仍然有用，只是它回答不了画面是否异常。

我在尝试补这类断言时，把截图和要问的问题一起交给模型，要求它返回结构化结果。这里用合成截图解释怎样提问和处理结果，图中的页面与数据都为演示构造。

把要判断的现象说窄一点

直接问“这个页面有没有问题”，每次检查的范围都可能变。模型可能评价配色，也可能把正常的暗色背景当成错误。这个例子里，我只问它一件事，画布内容区是否被一块非预期的连续黑色区域盖住。顶部导航、侧栏和正常的暗色背景都不计入判断。

先指定截图范围，脚本也更容易复查。比如固定在页面进入可截图状态之后截取画布区域，报告里保留实际传给模型的那张图。用户从失败记录点进去，能看到模型判断的是哪一块。

让脚本读到判断，还能查它的依据

返回结构只留三项。状态用 pass、fail 或 uncertain，再给一条可见依据和画面位置。下面是合成图片对应的示例返回，供说明格式。

{
  "verdict": "fail",
  "evidence": "A solid black block covers part of the content",
  "region": "upper-right area of the canvas"
}

脚本先校验 JSON 和状态枚举。模型输出不合法、图片读取失败，或者无法确定黑区是不是设计的一部分，就进入人工复核。测试报告保留截图、原判断和可见依据，方便人对照画面核对。

我会保留原来的确定性断言。元素存在、文字内容、颜色值和尺寸这类可以直接读出来的条件，继续用脚本检查。等到需要判断截图里的组合现象，再用视觉模型补一项单独结果。是否能把这项结果升级成发布条件，要用标好的正常和异常样本核对误报与漏报。当前材料能说明这种接法，暂时不足以给出准确率。
