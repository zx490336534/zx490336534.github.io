用 AI 补上 UI 自动化里的视觉断言

脚本确认画布存在，按钮也能点，截图里却有一块不该出现的黑区。遇到这种问题，我会保留原来的元素和状态断言，再补一项画面检查。模型要看的范围和现象，尽量提前写清楚。

把要判断的现象说窄一点

直接问“页面有没有问题”，模型可能去评配色，也可能把正常的暗色背景当成异常。在下面的合成示例里，问题缩到一个动作。检查画布内的连续黑区有没有盖住应当可见的内容。顶部导航、侧栏和正常的暗色背景都排除在判断范围外。

脚本等画布进入可截图状态，再截取内容区。报告里保留实际送给模型的那张图。 回看失败时，读者需要知道模型看到了什么，还要能在图上找到它说的那个位置。

让脚本读到判断，还能查它的依据

我会让模型只返回三个字段。verdict 是判断，evidence 写图里实际可见的内容，region 说明画面位置。下面是合成图对应的示例，展示输出格式。

{
  "verdict": "fail",
  "evidence": "黑色矩形盖住了原本应该可见的图形",
  "region": "画布右侧"
}

脚本先解析 JSON，确认状态在 pass、fail、uncertain 里，并检查依据和位置两个字段是字符串。对于 fail，还要能定位到具体画面。示例中的黑块有明确位置，复核者能回到截图上检查。

视觉断言的处理方式
模型或调用的结果 脚本怎么记
返回 pass 记录本项视觉检查通过
返回 fail，有依据和位置 保留截图和判断，把该用例标为视觉失败
返回 uncertain 交给人看图
超时、读图失败或返回格式不对 单独记录执行异常，等重跑或复核

如果画面还在加载，就先查截图时机。此时模型可能看到占位区域，格式再规整的回答也不能用于判断最终画面。

先把正常图和异常图一起跑一遍

元素是否出现、文字、可读取的颜色值和尺寸，能从页面直接判断的部分继续交给原来的自动化脚本。视觉断言集中在脚本难以表达的画面组合，比如一块遮挡盖住了该显示的组件。

接入后先拿人工标过的正常暗色图和遮挡图做对照，分别看误报、漏报和无法判断的情况。当前示例能说明检查方式和结果怎么回到报告里。实际项目要不要把这项结果用于发布判定，先看这批真实样本的复核结果。
