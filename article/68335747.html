阅读视频文字稿

假设你有一个 Python 测试结果服务，先只让它输出一条演示报告。

它在你电脑上能跑，到了别人电脑上，却可能因为 Python 版本或当前目录不同而失败。

文章先从一个小脚本入手，展示怎么借用现成的 Python 镜像运行。

理解这种做法以前，先把镜像、容器、脚本本身分成三种东西。

镜像里可以已有 Python 解释器和基础运行文件，但不一定带你的脚本。

创建容器时，可以说明进程从哪个目录开始，传哪些输入。

这个容器是一份具体运行实例：有开始和停止时间，也可能有临时文件。

换一份输入，可以从同一镜像再建另一个实例。

镜像不会因为前一个实例退出就消失。

原文通过挂载把当前的脚本交给容器。

开发时改动马上可见，适合做小试验。

但如果交给别人，依赖某个主机目录就不容易复现。

这时可以考虑把代码和依赖一起打包。

无论哪种方法，脚本看到的是容器内的工作目录，不是操作者电脑原来的位置。

不要图省事把整个家目录交进去，给演示任务一小份输入就够。

如果第一次运行输出了演示报告，而第二次启动另一个实例，第二次并不会自动读到第一份的临时文件。

这是因为容器的临时改动没有更新源镜像。

也不要仅凭容器已经启动就判断程序成功；还得看它是在提供服务、正常按计划退出，还是启动后马上报错。

镜像版本和实例记录分开留，更容易定位。

最后给一个正例、一个缺脚本负例、一个重建例。

正例能产出已知演示结果，负例明确报告是环境、目录还是脚本的问题，重建不应该偷偷依赖上一轮留下的文件。

这个习惯比记命令更有用。

下一篇再看，当这个服务要和别的组件互通，或者要保留报告时，哪些东西不该放在容器的一次性层里。
