主题：职业与实践

Algorithm。主要是为了编程训练和学习。每周至少做一个 leetcode 的算法题（先从Easy开始，然后再Medium，最后才Hard）。进行编程训练，如果不训练你看再多的算法书，你依然不会做算法题，看完书后，你需要训练。关于做Leetcode的的优势，你可以看一下我在coolshell上的文章 Leetcode 编程训练 - 酷 壳 - CoolShell。

Review：主要是为了学习英文，如果你的英文不行，你基本上无缘技术高手。所以，需要你阅读并点评至少一篇英文技术文章，我个人最喜欢去的地方是http://Medium.com（需要梯子）以及各个公司的技术blog，如Netflix的。

Tip：主要是为了总结和归纳你在是常工作中所遇到的知识点。学习至少一个技术技巧。你在工作中遇到的问题，踩过的坑，学习的点滴知识。

Share：主要是为了建立你的影响力，能够输出价值观。分享一篇有观点和思考的技术文章。

Algorithm

罗马数字包含以下七种字符: I， V， X， L，C，D 和 M。

字符          数值
I             1
V             5
X             10
L             50
C             100
D             500
M             1000
 

例如， 罗马数字 2 写做 II ，即为两个并列的 1。12 写做 XII ，即为 X + II 。27 写做  XXVII, 即为 XX + V + II 。

通常情况下，罗马数字中小的数字在大的数字的右边。但也存在特例，例如 4 不写做 IIII，而是 IV。数字 1 在数字 5 的左边，所表示的数等于大数 5 减小数 1 得到的数值 4 。同样地，数字 9 表示为 IX。这个特殊的规则只适用于以下六种情况：

  • I 可以放在 V (5) 和 X (10) 的左边，来表示 4 和 9。

  • X 可以放在 L (50) 和 C (100) 的左边，来表示 40 和 90。

  • C 可以放在 D (500) 和 M (1000) 的左边，来表示 400 和 900。

给定一个罗马数字，将其转换成整数。输入确保在 1 到 3999 的范围内。

示例 1:

输入: "III"
输出: 3
 

示例 2:

输入: "IV"
输出: 4
 

示例 3:

输入: "IX"
输出: 9
 

示例 4:

输入: "LVIII"
输出: 58
解释: L = 50, V= 5, III = 3.
 

示例 5:

输入: "MCMXCIV"
输出: 1994
解释: M = 1000, CM = 900, XC = 90, IV = 4.
class Solution:
    def romanToInt(self, s: str) -> int:
        data = {"I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000}
        num = 0
        for i in range(len(s)):
            if i < len(s) - 1 and data[s[i]] < data[s[i + 1]]:
                num -= data[s[i]]
            else:
                num += data[s[i]]
        return num

  1. 首先使用字典来列出字符串对应的数字大小

  2. 假设每一位都代表一个数字，那么肯定是按照映射关系从大到小排列。

  3. 实际上存在两个字母组成的内容，且两者的差值为较小值

所以只要遍历输入的字符串，当它不是最后一位的时候判断一下它是否小于它的后一位。

  • 如果小于，则总数减去它；

  • 如果大于，则总数加上它；

原文第四篇周记的算法练习是将罗马数字转换成整数。

这一集不做第三篇的镜像判断。

我们只拿几个符号的虚构课堂纸牌，说明转换分两层：先知道每个符号通常代表多少，再知道哪些相邻组合不能直接照加。

查表回答单个符号的值，计算规则负责一张纸条里的相邻关系。

单看一个字符不能知道它是否属于合法的减法组合。

桌上先放一张代表十的卡，再放一张代表一的卡。

按普通示例相加得到十一。

如果换成一在十之前，这个具体、允许的组合读作九。

同样两张纸，顺序改了就不能用原来的解释。

这里不是说所有较小的符号只要放前边就能减。

展板另列课堂接受的组合，解析时既要看值，也要看具体的邻接规则。

把一张不在对应表里的符号放进去，就应明说未识别，不可以叫它零。

就算每张符号都认识，也还可能出现不允许的组合。

题目如果保证输入是合法罗马数字，可以据此省掉某些输入检查；若外面的人可能给任意字符，就得另订验证规则。

这类条件决定哪些输入能计算，所以不能把一道在受限样本下的技巧当作通用解析器。

举一个课堂组合十四：先有十，再用已经约定的一在五之前来表达四。

十和四相加后就足够，不能把组成四的两个符号又各加一次。

如果阅读者没弄清这一小段被当成一个组合，报告可能会记双份。

让对方在纸上圈组合，另写每段对总值的贡献，就能知道是哪一步出现偏差。

这里不运行文章代码。

最后摆三张纸条：一张普通相加，一张含允许的减法，一张含未知符号。

请同伴依次声明它能不能解释，并指出哪一段怎样进入结果。

这比一眼发一个答案更可靠。

原文另有阅读笔记，本片只想留下算法上的一个边界：既要看到单项意义，也要看到相邻结构，遇到不在约定内的输入，不将格式漂亮或数字说得流畅当成正确。
