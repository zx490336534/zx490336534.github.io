else块

else子句不仅能在if语句中使用，还能在for、while和try语句中使用。

for

仅当for循环运行完毕（没有被break语句终止）才运行else块

while

仅当while循环因条件为假值而退出（没有被break语句终止）才运行else块

try

仅当try块中没有异常抛出时才运行else块

with块

with不仅能管理资源，还能用于去掉常规的设置和清理代码，或者在另一个过程前后只想的操作。

with语句的目的是简化try/finally模式

这种模式用于保证一段代码运行完毕后执行某项操作，即使那段代码由于异常、return或sys.exit()调试而中止，也会执行指定的操作

  • with语句开始的时候会在上下文管理对象上调用__enter__方法

  • with语句结束的时候会在上下文管理对象上调用__exit__方法

exit的三个参数

def __exit__(self, exc_type, exc_value, traceback)

exc_type：异常类

exc_value：异常实例

有时会有参数传给异常构造方法，例如错误消息，这些参数可以使用exc_value.args获取

traceback：异常的堆栈信息

使用@contextmanager

不用编写完整的__enter__与__exit__函数，只需要实现有一个yield语句的生成器

yield把函数分为了两部分，

  • 上半部分相当于enter中的内容

  • 下半部分相当于__exit__中的内容

class A(object):
    def __enter__(self):
        print("进入")

    def __exit__(self, exc_type, exc_val, exc_tb):
        print("退出")


if __name__ == '__main__':
    with A():
        print('test')
        assert 0
import contextlib


@contextlib.contextmanager
def B():
    print("进入")
    try:
        yield
    finally:
        print("退出")


if __name__ == '__main__':
    with B() as b:
        print('test1')
        assert 0

上述两段代码的实现效果是一样的

假设程序需要扫描几份合成报告，找到指定条目就停，再在一个演示会话里处理它。

这里同时有三种不同的事：遍历完没找到怎么办，处理成功后怎样继续，以及中途失败了怎么关闭会话。

它们都会出现在代码末尾，但触发条件不同。

先认清你想表达哪一种，再选循环的 else、异常的 else、还是清理机制。

找到了演示条目就跳出循环。

假如所有条目看完都没触发跳出，才进入循环的 else。

因此空列表也会走这条路径。

与其理解为条件是假，不如读成整个循环没有被 break 提前停止。

错误或函数提前返回不会被当成自然结束。

对 while 来说，也可以用这个思路区分条件自然结束和显式跳出。

要处理这条报告时，可以让 try 只负责把演示数据解析出来，捕获明知道如何处置的解析错误。

正常解析后进入 else，再把已验证结果写到展示模型。

这样写能避免把展示错误误当成解析错误。

同一组前面的捕获不会接住新在 else 里抛出的异常。

它不是永远会跑的收尾，更不是可以随意扩大捕获范围的理由。

如果演示会话开始成功，离开 with 块时就会交给退出方法收尾，不管块正常结束还是中途抛异常。

退出方法可看到异常信息，只有明确返回真值才会压制块内的异常。

进入阶段自身失败时，不能靠该次退出方法补救。

手写 finally 也能做清理；当这套设置和清理反复出现，用上下文管理器可以把意图和责任放到一起。

最后用空报告、有效报告、已知坏格式和意外异常各测一遍。

空报告应走未匹配；有效数据应走成功分支；坏格式给明确提示；意外问题应继续传播。

凡是已经成功进入的会话都要收尾。

能同时检查业务结果和清理执行与否，就不会把不同控制流混成一个普遍含义的否则。
