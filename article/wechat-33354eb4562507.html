FLAG_SECURE

APP出于安全考虑，不希望被用户截屏或者录屏，所以使用FLAG_SECURE来进行处理

禁止截屏的实现方式并不是很难，在需要设置禁止截屏的 Activity 的生命周期 onCreate() 方法中添加一行代码即可

void onCreate() {
  //禁止截屏
  // 方法 1
  getWindow().addFlags(WindowManager.LayoutParams.FLAG_SECURE);
  // 方法 2
  getWindow().setFlags(WindowManager.LayoutParams.FLAG_SECURE, WindowManager.LayoutParams.FLAG_SECURE);
}

设置了这个flag后, 系统会把当前窗口的内容视为安全隐私内容, 系统会阻止这些内容被截屏或者在不安全可靠的场景显示出来.

在Google的过程中, 发现这个flag可以实现以下功能:

  • 阻止屏幕截图

  • 在Recent apps(任务切换界面)中只显示应用名字和图标, 不显示内容

  • Google App的Now on tap功能不会去分析你的页面的内容

代码里面可以通过去除来去除这个防录屏

Window window = getActivity().getWindow();
window.clearFlags(WindowManager.LayoutParams.FLAG_SECURE);

不过在进行自动化测试的时候就不能这样操作了，但其实这个只会影响录屏，而不影响操作，所以我们直接拿到页面元素，就可以通过元素标签，来编写定位信息来操作元素了。

driver = app_webdriver.Remote("http://127.0.0.1:4723/wd/hub", desired_caps)
driver.page_source

原文讨论 Android 页面截屏保护。

这集不调用设备，不展示解除保护的方法，只画一个完全虚构的展签：现场阅读者可以看见虚构内容，而录制产物用黑色块示意有意不留页面内容。

黑块可能正是产品预期的一部分，不能因为证据不符合平常截图格式，就要求把保护关掉。

测试问题先问这个行为原本应该怎样。

同伴拿到一张黑框和一张画有标题的假界面。

能说的是这两份纸上表示了什么，不能从黑框判断界面没有显示，更不能推导出真实平台必然出现黑屏。

若需求纸明确规定受保护内容不进入录制，本轮假输出可与策略相符。

若还没有相应约定，只能报告观察到黑框，原因待确认。

证据应该和需求一起读。

在纸面报告中记下选择了哪个合成场景、当时界面处于什么阶段和录制产物有无内容，再用自制非敏感示意图表达期待。

这些都不是把原画抓出来。

需要额外证据时，应由负责人在明确允许范围内给合适材料，或者如实留缺。

不要为了让一张报告看着完整，收集不应该出现的内容，也不把没得到图视为收集失败。

如果课堂另外拿来一张没有保护约定的黑框，不能复用第一张的通过结论。

可能是什么原因，这一集都不猜。

应该先知道本轮环境和要验证的规则，然后记下证据只支持什么。

如果现场读不到必要内容，可以标待查，把与本次验证无关的信息继续留在原处。

没有必要为了制造一个能截到的样本改变假设中的保护。

最后请同伴重新解释两个画面，一份是用户可读，一份是录制产物无内容。

若问题是保护是否符合约定，就对照需求卡，用允许的方式留一句证据说明。

若问题是页面真正内容是什么，而没有可以合法获取的资料，就应当留空。

原文的技术设置不在这里，主要习惯是知道该验证什么，保护仍在，证据照样可以诚实。
