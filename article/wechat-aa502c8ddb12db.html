 0、背景

随着测试自动化需求的增长，Python脚本作为重要的测试工具，在项目中得到了广泛应用。然而，由于缺乏统一的管理平台，测试脚本分散存储、执行记录难以追踪等问题日益突出，严重影响了测试效率和结果分析能力。

本文介绍了一个Python脚本运行管理平台的设计与实现过程，重点解决以下问题：

  1. 脚本分散管理导致维护困难
  2. 执行记录难以追踪影响问题定位
  3. 测试报告缺乏结构化分析
  4. 管理界面不友好限制用户体验

1、主要步骤

1、调用jenkins执行python任务

2、默认使用allure展示报告

3、定制化展示：脚本中将数据写入数据库，然后在页面上展示

2、整体设计

平台利用Jenkins构建了一个动态任务调度系统，允许用户无需人工干预即可根据需求调整待执行的Python脚本。这种机制提升了响应速度，并减少了人为失误。

  1. 调用Jenkins
    ：平台通过REST API调用Jenkins以启动Python任务。
  2. 参数处理
    ：系统接收输入参数（如Git仓库、分支等），并进行解析，为后续操作做好准备。
  3. 代码拉取
    ：从指定Git仓库拉取最新代码，以确保每次运行都使用最新版本。
  4. 依赖安装
    ：检查是否存在Python环境，如无则自动安装所需依赖，提高构建灵活性。
  5. 脚本执行
    ：在隔离环境中运行测试脚本，并跟踪其执行状态。
  6. 生成报告
    ：根据测试结果生成Allure报告或自定义页面展示结果，供用户查看。

3、后端部分

3.1、Python项目管理表

该模块负责管理代码仓库的信息，包括：

  • 项目名称
    ：标识不同的Python项目。
  • Git仓库地址
    ：方便快速拉取代码，确保执行的是最新版本。
  • 管理人员列表
    ：记录相关人员，便于责任分配和沟通。
  • 创建和更新时间
    ：追踪项目的更新历史。

通过集中管理这些信息，团队可以更高效地维护多个项目，并确保所有成员能够轻松访问到所需资源。

3.2、Python任务表

该模块用于定义和跟踪每个可执行脚本（任务）：

  • 任务名称
    ：简洁明了地描述任务功能。
  • 关联项目ID
    ：与相应Python项目关联，实现数据整合。
  • 执行分支和参数
    ：灵活配置不同分支或脚本参数，以满足多样化需求。
  • 报告类型选择
    ：用户可根据需要选择生成Allure报告或自定义页面展示结果。

这一设计使得用户能够根据实际需求灵活地配置测试任务，提高了执行效率。

3.3、Python任务执行记录表

为确保每次测试运行都可被追踪，该模块会记录执行过程中的关键信息：

  • 状态监控
    ：实时更新当前任务状态（如等待、执行中、成功、失败），使得团队能迅速响应问题。
  • 结果链接
    ：提供直接访问结果报告的链接，便于快速查看测试结果并进行分析。
  • 错误信息记录
    ：详细记录执行过程中遇到的问题，有助于后续排查与修复。

通过这种方式，我们可以清晰了解每次测试的表现，并在必要时进行深度分析。

3.4、自定义展示数据存储

为了满足特定业务需求，我们设计了一些额外的数据存储方案，用于保存与特定场景相关的重要信息，例如：

3.4.1、计量订单数据

此模块专注于存储测量相关的数据，如订单ID、场景描述等，为业务决策提供依据。

3.4.2、接口比对数据

该模块记录接口请求的信息，包括请求体及其差异，对比不同接口调用情况，为差异对比，性能优化，问题发现等提供参考。

4、Jenkins执行python任务

为保证后续变更的灵活性，将流水线流程写入在python代码中，这样每次执行的时候通过拉取对应的代码就可以完成类似Pipeline的流程

4.1、参数

使用文本参数，并且传入一个json字符串

在python代码中处理参数

def get_kwargs(name, default=None):
    """
    获取kwargs中的值
    """
    try:
        return json.loads(os.getenv("kwargs"))[name]
    except Exception as e:
        print(f"获取kwargs中的值失败: {e}")
        return default
repo = get_kwargs("repo")
branch = get_kwargs("branch")
case = get_kwargs("case")

通过上述方式 实现了 动态参数传递机制

创新点：采用JSON参数化配置取代传统键值对参数

  • 通过单文本参数接收结构化JSON数据，突破Jenkins原生参数类型限制

  • 在Python层面对kwargs进行智能解析，实现动态参数扩展

  • 支持嵌套参数传递，满足复杂测试场景需求

在本项目中，我们建立了一个Python脚本运行管理平台，以解决现有测试脚本分散管理所带来的效率低下和结果追踪难题。通过集成Jenkins、Allure报告以及自定义数据展示，我们实现了对Python项目及其任务的有效管理，提升了整体测试流程的规范性和可视化。

  1. 统一管理：我们设计并实施了一个后端数据库，包含项目、任务及执行记录等多个表格，确保所有相关信息都可以集中存储和查询。这为后续的维护与扩展提供了良好的基础。

  2. 灵活执行：借助Jenkins流水线，我们将Python任务的执行逻辑封装在代码中，使得每次执行都能动态拉取最新代码，并支持参数化配置，提高了测试的灵活性。

  3. 丰富报告：集成Allure报告功能，自动生成详尽的测试报告，并提供自定义展示页面，让用户能够快速获取关键信息，提高了结果分析的便利性。

  4. 可视化界面：前端部分设计友好，实现了项目管理、任务执行、执行记录查看及自定义数据展示等功能，使得用户可以直观地进行操作和数据分析。

  5. 定制化需求：考虑到不同团队可能有特定需求，我们特别设计了一些数据表用于存储测量订单和接口比对日志，为未来的业务扩展留出了空间。

通过这些措施，平台不仅提高了测试效率，也增强了团队之间的信息共享与协作能力。
