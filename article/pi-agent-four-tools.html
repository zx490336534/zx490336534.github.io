Pi Agent 为什么默认只给四个工具？

听白2026-11-25 约 2 分钟 近 30 天阅读 评论

读 Pi coding agent 的公开文档时，我先看了它默认暴露给模型的工具。read 读取文件，bash 执行命令，edit 修改现有内容，write 新建或重写文件。搜索、测试和 Git 都可以通过命令完成。要看这四件事够不够用，可以拿一次修复失败测试的任务来走一遍。

修一个失败测试，四个动作就能串起来

模型先用 bash 跑单测，从错误输出判断需要看哪些文件。用 read 读实现和测试，用 edit 改掉有问题的分支，再回到 bash 跑相同的测试。如果需要新建测试文件，用 write 保存。这个例子只有少数几次文件操作，测试命令本身就能给出下一步所需的信息。

四个是默认配置。Pi 的文档还列了 grep、find、ls 等可选工具，也允许调整模型能看到的工具集合。每个项目所需的外围能力也不同。命令能找到测试，不代表它能生成代码审查证据，或者为多人协作记录同一份验收决定。

要扩展时，先看缺的是哪一种能力

如果团队总要先检查工作目录，再允许执行高影响命令，可以用扩展接住工具调用。Pi 提供了在调用前拦截的扩展事件。这个入口也可以补一些重复出现的项目规则。文件访问和进程隔离仍依赖运行环境。给 Agent 一个工作目录，只确定了它从哪里开始，并不会自动限制外部访问。

另一项值得看的功能是会话树。走到一半发现假设错了，可以回到前面一个节点，沿着新的方向继续对话，旧分支仍能查看。会话树记录对话的路径。工作目录里已经改过的代码，要用 Git 或自己的检查点处理。准备从旧节点尝试另一条路线时，我会先看工作区有没有未提交改动。

如果任务是围绕一个仓库反复读代码、改文件、跑验证，默认工具足以用来试做一次完整修复。我会从这个任务开始，看结果里具体缺了什么。团队要把发布审批、隔离环境或交付证据放进去时，再决定哪些由扩展处理，哪些该保留在外部流程。
