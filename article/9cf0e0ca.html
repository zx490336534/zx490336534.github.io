POJO

POJO:Plain Ordinary Java Object 简单普通的java对象

没有从任何类继承、也没有实现任何接口，更没有被其它框架侵入的java对象。

JavaBean

JavaBean 是一种JAVA语言写成的可重用组件。

JavaBean符合一定规范编写的Java类，不是一种技术，而是一种规范。

大家针对这种规范，总结了很多开发技巧、工具函数。

符合这种规范的类，可以被其它的程序员或者框架使用。

它的方法命名，构造及行为必须符合特定的约定：所有属性为private。

成员变量和局部变量的区别

局部变量的特点

  • 定义在函数体内
  • 定义在函数参数列表里
  • 代码块{}中

全局变量的特点

  • 定义在类体内
  • 在函数外
  • 在代码块外

生命周期（作用域）

  • 局部变量：出了包含他的{}就死亡
  • 全局变量：对象不消亡就一直存在

想象一只模具可以制作蓝色和橙色两艘纸舟。

它规定这类物件有什么字段、能执行哪些行为；做出的每一艘可以有不同名字和状态。

原文介绍 Java 的类、对象与方法。

我们在模型里不背术语，先做一件事：只送其中一艘去展示，再看看另一艘为什么不会因为同一种类而自动改变它的状态。

创建蓝船时给它一个演示名，初始状态是待展示。

橙船可以用不同的名字，初始状态也由这一次创建决定。

只要状态是分别保存的实例状态，蓝船展示以后，橙船仍是待展示。

类型相同不等于数据共享。

某些成员可以属于整个类，但那是另一个设计选择。

想做可分别控制的测试样本，就先问这条数据究竟放在哪里。

比如有一个行为叫安排展示。

它可以接收展示位作为输入，按条件判断，成功后让当前纸舟进入已展示状态。

另一个行为只读取状态，不应该顺手改变它。

类只是把某些职责放到一起，不代表方法可以替其他对象做决定。

把输入、输出和可能发生的状态变化说清，测试时就不用看到一个返回值便猜背后已经执行了哪些事。

在蓝船的卡片上放入合成展示位，再核对它的状态。

桌上的橙船没有被调用，应该保持待展示。

最后为蓝船换一个情形，假设缺展示位。

这次应先说明预期，是拒绝更新还是记录需要补充，不能既说没有位置，又在状态里写成功。

这就是面向对象测试里一个非常实用的习惯：明确受影响的是哪个对象、状态为什么变化。

最后看两艘船、一只模具和一张操作回执。

解释模具规定什么，两艘船各自记什么，调用一次应该改变哪一个对象。

原文的入门示例来自其时代，编辑器和环境不必沿用。

把类、对象、方法视作结构、实例、行为，不只方便阅读，也让测试员能看出状态是否串到了别的案例里，判断结果究竟错在哪。
