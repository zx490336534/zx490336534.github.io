实现TabBar页面

AppDelegate.m文件：

- (BOOL)application:(UIApplication *)application didFinishLaunchingWithOptions:(NSDictionary *)launchOptions {
    // Override point for customization after application launch.
    self.window = [[UIWindow alloc] initWithFrame:[[UIScreen mainScreen] bounds]];
    UITabBarController *tabbarController = [[UITabBarController alloc] init];
    UIViewController *controller1 =[[UIViewController alloc]init];
    controller1.view.backgroundColor = [UIColor redColor];
    UIViewController *controller2 =[[UIViewController alloc]init];
    controller2.view.backgroundColor = [UIColor yellowColor];
    UIViewController *controller3 =[[UIViewController alloc]init];
    controller3.view.backgroundColor = [UIColor greenColor];
    UIViewController *controller4 =[[UIViewController alloc]init];
    controller4.view.backgroundColor = [UIColor lightGrayColor];
    [tabbarController setViewControllers:@[controller1,controller2,controller3,controller4]];
    self.window.rootViewController = tabbarController;
    [self.window makeKeyAndVisible];
    return YES;
}

阅读视频文字稿

原文是从零开发 iOS 应用的第一天，包含第一个工程，以及在视图中放一个文字标签。

本片不执行原文程序，用纸面画一个虚构纸舟口袋工具。

第一次成功不需要很多功能，先让画板里出现一句纸舟准备就绪。

了解这句文字属于哪个视觉元素、容器在哪里、最终要观察什么，比一开始做复杂菜单更容易确认进度。

想象一张纸面手机，先摆出屏幕轮廓，再放一个写欢迎的标签。

标签文字属于控件内容，它在画面哪里则是布局决定。

若标签画在手机外面，仅看文字正确并不能说界面已经成功。

若框架依然存在，但文字放到了另一个虚构页面上，也不符合预期。

原文有具体入门方式，这里不照搬旧代码，只保留看得见的结果及必要条件。

将同一张纸签移到较窄的合成画框，原本居中很好看的文字可能太长。

把需要完整显示、可以换行还是应该另作短文案，写在课堂验收约定里。

这个练习是设计思路，不暗示原来代码一定会如何布局。

如果需要处理真实系统样式或辅助功能，应另外确认。

本文不给具体历史平台要求，只用对照图说明设置文字并不自动得到可阅读的画面。

如果合成设计图只画了一张待放的标签，不能宣称页面上已经看见它。

即使放入屏幕，也需要看是否正被其他图遮住，是否与预期一致。

写假报告时至少指明出现在哪一张画框，内容是什么，以及这只说明初始界面而非整个应用都可用。

第一天只验一个小目标，可以更快区分是资料没准备，还是布局和显示的问题。

收尾给同伴两张小手机插画，一张标题可读，另一张末尾看不到。

请他复述具体差异，不要只说一个能用一个不能用。

正文的初学案例提醒我们，短小的第一屏也有清晰可查的新成果。

接着添加后续功能之前，先为这个成果写出明确验收边界；旧文章的工程与语言写法，只作历史背景，不作为今天设备操作指令。
