用 URL 文本片段把测试报告定位到具体一行

本文速读

结论：用 URL 文本片段把读者带到报告里的一段文字。重复内容要缩小匹配范围，不能只给一个到处出现的函数名。

适用范围：用于能公开分享的网页内容；要保留普通锚点或其他可手工找到的位置，避免某些客户端不跳转。

测试结果列出一个未覆盖的函数。点开覆盖率报告后，还得用搜索在页面里找函数名。如果报告已经给这一行分配了稳定的 id，直接用普通的章节锚点即可。只有可见文字时，可以用 URL 文本片段补上定位。

先从一段能唯一匹配的文字开始

用户点击链接后，在支持文本片段的浏览器里，地址末尾的 #:~:text= 会告诉浏览器要查找哪段文字。找到后，页面会滚动过去并高亮。以下地址是格式示例，域名和报告路径都是构造的。MDN 文本片段说明

https://example.com/report.html#:~:text=calculateTotal

生成链接时，拿报告上确实显示的文字当输入。先只编码文字部分，再拼浏览器要识别的分隔符。空格转成 %20。词里出现的短横线转成 %2D，语法里用来连接前文和目标文字的短横线照原样写。

同一个函数名出现两次怎么办

假如报告把两个模块的函数列表写在同一页，两个模块都可能出现 calculateTotal。单独搜索函数名，浏览器会命中第一个符合条件的地方。可以先给浏览器一小段相邻的前文，缩小范围。

https://example.com/report.html#:~:text=module%20B-,calculateTotal

在这个链接里，浏览器要找的是紧邻 module B 之后的函数名，两段之间允许有空白。如果模块名放在另外的标题里，中间还隔着几个字段，就要换一段真正相邻的文字，或者直接改用模块的章节锚点。

在这篇里试一下

这两行是构造的报告内容。只给函数名，正文里其他地方也可能匹配。加上前文条件，下面的链接就会找第二行里的函数名。

module A calculateTotal

module B calculateTotal

链接仍然要让人手动找得到

报告重新生成以后，展示文字可能变化。文本片段没有匹配，或者浏览器不支持时，读者仍然能打开报告。链接旁留着模块名和函数名，方便手动搜索。生成链接后，至少点一次正常样本和一次重复函数名，看看落点是否符合预期，再把链接放进测试结果里。

测试结果已经知道哪个函数没被测到，打开覆盖率报告，却从第一页开始，还得手动搜索。

能控制报告页面时，先看目标那一行有没有稳定的标记。

有了稳定标记，普通锚点是优先选项。

只有页面上可见的文字，而没有稳定标记时，才需要文本片段来补定位。

文本片段把要查的文字放在链接末尾。

支持它的浏览器会滚动到匹配位置，并可能高亮这段文字。

生成链接时，先对文字部分做百分号编码，再拼语法。

比如把空格编码，而不要把浏览器用来识别条件的标记和分隔符也当作文本编码。

两个模块都出现同名函数，只给函数名，容易停在第一个符合条件的位置。

可以增加紧邻目标文字的前文，比如同一行上的模块名。

注意，这个前文要在正确位置。

假如模块名只是很远的标题，中间隔了几个字段，就换一段真的相邻的文字，或者回到普通章节锚点。

再做一次编码检查。

空格会变成百分号二零，文字自身包含的短横线可以编码为百分号二 D。

但语法里连接上下文与目标的分隔符要保留。

一个很实用的做法，是把目标和前文当作两个独立的文本输入，然后由链接生成器负责拼接。

报告重新生成以后，函数名、空格或者周围的文字可能变动。

也有浏览器不能按文本片段定位。

链接应该仍然能打开对应报告，同时旁边显示模块名和函数名，方便手动查找。

自动定位是节省时间的增强能力，内容可找才是底线。

最后至少点一次目标唯一的链接，再点一次名称重复的链接。

亲眼确认页面不是只滚动了，而是停在正确的函数和模块。

如果还能在禁用高亮或者文字改变时打开原报告并手动找到，就可以把这个链接带进测试结果。
