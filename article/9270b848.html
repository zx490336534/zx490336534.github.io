关键字

  • 使用FROM来指定base image镜像(在base image的基础上来操作)，放在首行

  • LABEL指明作者，不执行的指令

  • WORKDIR相当于cd命令，如果进入的目录不存在，会创建

  • COPY相当于cp命令，宿主机中的内容「前」 复制到 容器中「后」

  • ./为当前目录WORKDIR

  • ADD和COPY命令类似，他会将一个压缩文件解压后，复制到容器中

  • RUN在容器中执行linux命令需要使用RUN

  • 可以执行多个RUN

  • COPY . .把相对于Dockerfile文件所在路径的所有文件拷贝到容器的当前目录

  • CMD当镜像运行的时候会默认执行的命令

RUN

在已存在的image顶层执行命令，创建一个新的layer层

往往将需要安装的依赖，使用一个RUN来创建。多个命令可以用&&来拼接

ENV

在容器内创建环境变量

VOLUME

VOLUME命令指定的目录「容器中」才能被映射

EXPOSE

将容器中的端口暴露出来

ENTRYPOINT 和 CMD

不同点

CMD

  • 运行容器时，不加任何参数，会自动执行CMD，如果添加参数会忽略CMD
  • 有多个CMD，则只有最后一个会执行，其他都被忽略
  • 可以给ENTRYPOINT传参

CMD[“p1”,”p2”]

如果ENTRYPOINT使用shell格式，CMD 会被忽略

如果ENTRYPOINT使用exec格式，CMD 会和它进行组合

ENTRYPOINT

  • 运行容器时，如果添加参数不会忽略ENTRYPOINT

相同点

  • 只有1个CMD或者ENTRYPOINT时，没有区别
  • shell格式和exec格式

shell格式:ls /

exec格式:[“ls”,”/“]

一定要「双引号」

CMD和ENTRYPOINT一起使用的时候，

  • 不入参为ENTRYPOINT+CMD
  • 传参时为 ENTRYPOINT + 参数

上一支里，一个容器从镜像启动，能运行 Python 程序。

现在想把它接给一个演示查询页，还希望替换容器后能保留报告。

此时不能把连接、数据和构建混成一份配置。

Docker 网络负责几个运行实例怎样互通，卷负责让有价值的数据独立于一次实例，Dockerfile 则说明如何做出可使用的镜像。

想象查询页与演示服务在专门的应用网络上，页面只需要按事先规定的名字找到服务，不必记录经常变化的内部地址。

把端口发布到主机，是让网络外的访问方通过另一个入口进来，这不等于内部互通。

也不应该因为测试时能打开页面，就把其他组件一同发布出去。

用拓扑图先写清楚真正需要哪两段连接。

当报告写到数据卷里的约定目录，替换服务容器后，可以再将同一份卷连回去读取。

如果程序实际写在另一个目录，图上有卷也没用。

开发用的主机目录挂载是另一种办法，方便观察文件，但依赖主机路径和权限。

无论用哪个都要验真实写入目标，还要知道备份和清理由谁负责。

不要把卷当成不会丢的数据保险箱。

构建文件就像镜像的配方：选基础环境、把项目放到明确位置、安装已知依赖。

网络和数据卷常在运行时再附上。

这样同一份镜像能在几种环境复用，只需按环境指定必要输入。

别把真实口令、外部地址或机器绝对路径写进构建层。

遇到问题，先问是配方做错，还是这次实例启动时连错了东西。

可以设计三个失败注入：让页面不在相同的演示网络，让程序把报告写到临时目录，再让构建漏一项依赖。

观察三种错误是否能各自定位。

网络解决的是连接，卷解决的是持久，构建配方解决的是环境能否按版本重新做出来。

后面把几个服务写成一组，仍然是这三件事，只是开始把它们统一管理。
