主题：Skills 与提示词

MCP和Skills的区别

MCP（Model Context Protocol）和 Skills（技能）解决的是不同层面的问题，它们不是替代关系，而是互补关系，共同扩展 Claude 的能力

  • MCP 就像是 Claude 的"手和感官"
    。它让 Claude 能够连接到外部世界，执行动作（如读写数据库、调用 API、操作文件系统）和获取实时数据（如天气、股票、公司内部数据）。
  • Skills 就像是 Claude 的"专业知识和做事方法论"
    。它教导 Claude 在特定领域内如何思考、规划和执行复杂任务，包括何时以及如何有效地使用那些"手和感官"（MCP 服务）。

为什么有了"手"（MCP），还需要"大脑"（Skills）？

假设你想让 Claude 帮你创建一份符合公司品牌规范的季度报告。这个过程需要：

  1. 从数据库获取数据
     -> 需要 MCP 数据库工具。
  2. 分析数据并生成图表
     -> 需要 MCP 文件读写和计算工具。
  3. 将图表和分析写入一个格式规范的 Word 文档
     -> 需要复杂的文档处理逻辑。

如果只有 MCP，会发生什么？你只能对 Claude 说："我有这些工具：query_database, create_chart, write_docx。" 但 Claude 可能不知道：

  • 公司报告的标准结构是什么？（先执行摘要，再市场分析…）
  • 品牌规范中标题用什么字体、颜色和字号？
  • 图表应该放在哪个位置？大小如何？
  • 如何处理数据异常？

你需要不断地在对话中给出详细的、一步步的指令，整个过程会非常繁琐且容易出错。而有了 Skills，情况就完全不同了。 你可以创建一个名为 company-report-generator的 Skill。在这个 SKILL.md文件中，你会详细写明：

  • 报告的标准结构和章节。
  • 品牌指南的具体要求
    （如："主标题使用 'Brand Font' 字体，24pt，颜色为 #2A5BDC"）。
  • 数据分析和图表嵌入的最佳实践。
  • 一个完整的工作流程示例。

当这个 Skill 被激活时，Claude 就"化身"为一名深谙你公司报告规范的专家。它知道整个任务的蓝图，并会智能地调用你通过 MCP 提供的工具来高效、高质量地完成报告。

举例：文档处理技能（Document Skills）

以document-skills为例。这些技能内部很可能使用了 MCP 工具 来读写 .docx, .pdf等文件。

  • MCP 的角色
     提供一个基础的 read_file和 write_file工具，用于处理二进制文件。
  • Skill 的角色
     教导 Claude .docx文件的内部 XML 结构、如何维护格式、如何处理 tracked changes、如何合并文档等高度复杂的领域知识。

如果没有 docx这个 Skill，仅凭基础的 MCP 文件工具，让 Claude 可靠地编辑一个复杂的 Word 文档几乎是不可能的。

小结

一个强大的 Claude 应用往往是 MCP 和 Skills 的协同：

  1. MCP 搭建基础能力
    你通过 MCP 服务器为 Claude 接入所需的外部系统和工具（如 GitHub、Jira、内部数据库、设计软件）。
  2. Skills 定义专业工作流
    你创建 Skills 来指导 Claude 如何利用这些工具完成具体的业务任务（如："自动化发布流程"、"生成客户分析报告"）。
  3. 用户获得专家级助手
    用户只需下达高级指令（如："帮我准备本周的产品发布说明"），Claude 会结合激活的 Skill 中的专业知识，自动规划并调用 MCP 工具来完成任务。

结论就是：MCP 赋予了 Claude 行动的能力，而 Skills 则赋予了 Claude 专业思考的能力。 两者结合，才能让 Claude 从一个通用的对话AI，转变为你业务中各个领域的专家助手。这就是为什么两者都不可或缺。

Skills和在提示词中编写sop有什么不同

在提示词中编写 SOP（标准作业程序）和创建一个 Skill，在"内容"上可能非常相似。但关键的差异在于执行层面、系统性、可复用性和性能 。

可以把 Skills 理解为 "系统化、可持久化、高性能的超级提示词"。以下是具体区别：

1. 激活方式：一次性指令 vs. 持久化能力

  • 提示词中的 SOP
     每次都需要在对话中重新编写或粘贴。这是一个一次性的请求。如果你想让 Claude 在另一个对话中遵循同样的 SOP，你必须重新输入一遍。这容易出错、不一致，且效率低下。
  • Skill
     一旦安装或激活，它就变成了 Claude 持续拥有 的能力。你不需要在每次对话中重复指令。只需说"请使用 [某某] Skill 来完成这个任务"，Claude 就会自动调用那套完整的知识体系。这是一种 "一键激活专家模式" 的能力。

类比：

  • 提示词SOP
    像每次开车前都手动输入一遍GPS导航的完整指令。
  • Skill
    像在车里预设了"回家"和"公司"的快捷按钮，一键即可调用完整的导航路线。

2. 上下文占用与性能

  • 提示词中的 SOP
    SOP 的每一个字都会占用宝贵的上下文窗口（Token）。如果 SOP 非常详细（比如一个复杂的报告生成指南），它可能会挤占本应用于处理实际任务内容（如你的数据、你的草稿）的空间。
  • Skill
     Skill 的指令是按需加载的。启动时只加载技能名称和描述；相关的 Skill 正文被读取后仍会占用上下文。这意味着你可以处理更复杂的任务，而不会因为提示词过长而丢失中间步骤或历史信息。

这是技术上最关键的差异之一，它使得 Skills 能够处理远比单次提示词所能容纳的更复杂的流程。

3. 维护性与版本控制

  • 提示词中的 SOP
    你的 SOP 可能分散在各个聊天记录、文档或笔记中。如果你想改进 SOP，你需要在所有地方进行更新，很难保证一致性。
  • Skill
     Skill 是一个独立的、版本控制的文件（如仓库中的 SKILL.md）。你可以像管理代码一样管理它：进行版本迭代、回滚、协作开发。一次更新，所有调用该 Skill 的地方都会自动受益。这对于企业级应用至关重要。

4. 系统集成度

  • 提示词中的 SOP
    SOP 主要包含自然语言指令。它很难与 MCP 工具进行深度、结构化的集成。
  • Skill
     Skill 是与 Claude 系统深度集成的。它不仅是文本指令，更是一种"模式"或"角色"的切换。当 Skill 激活时，Claude 会进入该 Skill 所定义的"思维框架"，更智能地决定何时以及如何调用可用的 MCP 工具。Skills 是为杠杆化使用工具而设计的。

举例：创建品牌化PPT

假设任务是为一个新项目创建一份符合公司品牌指南的PPT。

  • 方式一：提示词中的 SOP
     你：请按以下SOP创建PPT：1. 第一页用主Logo，标题用"品牌蓝#0055A4"，36号字。2. 第二页项目背景，用"深灰#333333"… （此处省略200字）。这是项目资料：[资料内容]。请开始。
  • 问题
    SOP本身占了大量字数。如果PPT结构复杂，你可能需要分多次对话发送SOP，Claude可能会忘记前面的步骤。
  • 方式二：使用 Skill
     你：请激活 company-brand-pptSkill，并基于以下项目资料创建一份项目启动会PPT。[资料内容]。
  • 优势
    1. 简洁
      无需重复指令。
    2. 可靠
      Claude 严格按照经过测试和优化的 Skill 逻辑执行。
    3. 高效
      不必在每次对话开头粘贴完整 SOP，可以给项目资料留出更多上下文空间。
    4. 智能
       `company-brand-ppt`Skill 内部可能已经集成了对 MCP 工具（如从设计系统获取最新Logo）的调用逻辑，Claude 会自动执行。

小结

在提示词中写 SOP 是一个快速上手的好方法，适合轻量级、探索性的任务。但当某个工作流被证明是高频、关键且复杂时，将其固化为一个 Skill 是必然选择。

Skills 将你的专业知识从"单次对话的消耗品"提升为"Claude 生态系统中可复用的核心资产"。

这类似于为什么我们有了记事本（可写简单脚本），但还是需要专业的IDE和代码库来开发软件项目。Skills 就是为 Claude 构建复杂应用的"专业框架"。
