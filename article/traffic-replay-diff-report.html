流量回放出了差异，报告该怎么做

拿一条构造的库存查询来说，两个版本都返回 HTTP 200，回放报告却标了一条失败。开发点开后，先要知道是哪次请求，再看哪个字段变了。报告只留一个失败状态，人就得回日志把这两件事重新查一遍。

我会先把一条差异写完整，再决定用 Allure、Flask 还是单独做查询页面。下文沿用这条库存查询，请求、响应和结果都用于演示。

先让一条差异能看懂

同一条库存查询发给基线版本和待测版本。两边状态码都是 200，只有 inStock 从 true 变成 false。排查先看字段值是否符合接口约定，再决定要不要追到库存计算。

报告按请求记录批次、方法和路径，再存差异字段在响应里的位置和两个值。记住一个容易漏掉的情况。字段缺失和值为 null 要分别记。 下面的 Python 示例用一个标记区分这两种情况，再输出库存差异。

import json

def field(payload, name):
    return {
        "present": name in payload,
        "value": payload.get(name),
    }

assert field({}, "inStock") != field({"inStock": None}, "inStock")

baseline = field({"inStock": True}, "inStock")
candidate = field({"inStock": False}, "inStock")

print(json.dumps({
    "path": "$.inStock",
    "baseline": baseline,
    "candidate": candidate,
}, indent=2))

运行后，两边的 present 都是 true，区别只在 value。实际报告还要带上请求标识和原响应的入口，有疑问时可以按同一次请求查回去。这个例子只比较一个顶层字段，数组顺序和嵌套字段需要另定规则。

时间戳这样的动态字段也别一上来整组排除。先问验收是否关心它的值，再记录忽略的字段和理由。以后同一条回放通过了，读者还知道哪些内容实际比过。

三种报告各自适合什么情况

流量回放报告展示方式
打开报告后要做的事 适合的做法
跟着失败用例逐条查 Allure 附上两份响应和差异字段
在一页浏览这次回放的差异 Flask 读取结构化日志并渲染列表
按接口或字段筛选多次回放 SQLite 存明细，Next.js 做汇总和详情

如果手上已经用 pytest 跑回放，我会先在失败用例里附上标明基线和待测的两份响应。报告摘要直接写 inStock 的变化，点开附件再查看上下文。Allure Pytest 附件文档

要跨用例浏览整批结果，可以让脚本输出一行一个 JSON 对象的日志，Flask 读取字段后交给 Jinja 模板展示。查历史批次的需求稳定下来，再把差异存到 SQLite，页面按批次、接口和字段筛选。同一次请求有三处字段变化时，按请求统计是一条，按字段统计是三条，汇总页要写清用哪个口径。Flask 模板文档

第一版跑通一条差异就可以停。先请开发只看报告，试着找出变化字段和对应的请求。哪个信息还得回日志里找，就先补哪个。
