流量回放出了差异，报告该怎么做

分类 / 测试与质量 / 测试平台与工具

流量回放跑完，开发还得知道哪次请求出了差异，以及新旧响应差在哪个字段。报告里只有“比对失败”四个字，排查就得回到日志里再找一遍。

我比较过三种展示方式。Allure 可以把两份响应附到失败用例上。Flask 可以把已有日志排成一张差异页。需要跨批次筛选和查详情时，可以把差异存到 SQLite，再用 Next.js 提供查询页面。要选哪一种，先看读报告的人接下来要做什么。

先让一条差异能看懂

下面用一条构造的库存查询举例。同一份请求交给基线版本和待测版本，两边都返回 HTTP 200。基线的 inStock 是 true，待测版本返回 false。HTTP 状态码没有告诉我们这次变化，报告需要把字段路径和两个值摆出来。

一条差异至少要让人找到请求和对应的两份响应。我会保存批次、请求标识、方法与路径、两边的 HTTP 状态码，以及差异字段的路径和类型。空值、缺字段和布尔值改变要分开记。这样点开详情就能区分是字段被删了，还是字段还在、值变了。

有些响应会带时间戳等动态字段。先问清这个字段的语义和验收要求，再决定是否排除。忽略规则也要入报告，让读者能看出这次检查覆盖了什么。直接把整个字段组排掉，后续可能很难发现业务值跟着变了。

三种报告各自适合什么情况

做法 适用情况 要维护的东西
Allure 附件 已经用 pytest 跑回放，主要按失败用例逐条看 给失败记录附基线与待测响应，并注明变化字段
Flask 日志页 回放脚本已经产出日志，读者希望在一页看到差异 定义稳定的日志字段，解析后交给 Jinja 模板展示
SQLite 与 Next.js 差异多，读者需要按批次、接口或字段筛选 保存可查询的差异记录，维护汇总和详情两种视图

从 Allure 起步时，一次失败只附必要的样本，两个响应要有清楚的名称。附件之外再留一句发现，例如 inStock 的值变了。开发扫一眼报告就能决定是否打开完整响应。 Allure Pytest 附件文档

做 Flask 页面时，我会让回放程序输出一行一个 JSON 对象的日志。页面只读取结构化记录，不靠拆日志里的中文提示来找字段。最小的页面可以只显示请求、差异路径、基线值和待测值。 Flask 模板文档

需要查历史批次时，再把记录写进 SQLite。列表页按接口查看差异数量，详情页并排展示同一个请求的两个响应。汇总数字按什么聚合也要说明清楚。例如按请求计数时，同一请求里的三个字段差异仍算一条请求。

我会先拿一条真的能解释清楚的差异跑通。失败少、每次都按用例看，Allure 就够了。到了同一类差异在几批任务里反复出现，才值得为按接口和字段查询加一张页面。
