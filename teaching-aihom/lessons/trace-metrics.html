把一次失败变成可汇总的运行指标

用低基数维度统计失败，明白日志与指标各该记录什么。

先看场景走一遍读代码复现失败动手练习自测

先看场景

偶发生成失败每天几十条。团队既想知道失败都发生在哪一层，又想点开一次具体运行复盘。

基数：同一标签能出现多少不同取值。

走一遍

  1. 先定义允许的阶段和结果。
  2. 每次尝试保留关联标识。
  3. 汇总时只按阶段和结果聚合。
合成示例 可折叠
from collections import Counter

第二遍 · 把代码读懂

代码拆解

怎样让看板稳定，具体错误又可追溯？

调用链

  1. 写结构化阶段事件。
  2. 按尝试身份消除重复。
  3. 只用有限标签创建指标。
  4. 具体运行用追踪记录查询。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

from collections import Counter
ALLOWED_PHASES = {"generate", "validate", "publish"}
ALLOWED_OUTCOMES = {"ok", "timeout", "invalid"}

def summarize(events):
    totals, seen = Counter(), set()
    for run, attempt, phase, outcome in events:
        if phase not in ALLOWED_PHASES or outcome not in ALLOWED_OUTCOMES:
            continue
        identity = (run, attempt, phase)
        if identity in seen:
            continue
        seen.add(identity)
        totals[(phase, outcome)] += 1
    return totals

slow = ("run-1", 1, "generate", "timeout")
done = ("run-1", 2, "generate", "ok")
wrong = ("run-2", 1, "user-chosen-label", "ok")
totals = summarize([slow, slow, done, wrong])
assert totals[("generate", "timeout")] == 1
assert totals[("generate", "ok")] == 1
assert len(totals) == 2

日志与指标的查询目标不同

排查一次运行需要关联编号；找全体趋势需要阶段、结果和固定时间范围。把两种目标塞一个维度，既难查又昂贵。

先确定统计单位

示例统计一次尝试的一条完成事件，不以每次重传为新执行。同一任务重跑第二次会增加尝试计数。若产品关注用户最终体验，可以另做按运行计数。

未识别分类不任其增长

未知阶段或结果枚举拒收；维护监控时应记录单独的事件格式错误指标。避免动态错误文本变成标签。

复现失败

重复投递
怎么触发：同一次尝试上报两遍。
怎么判断：超时计数仍是一。
动态错误标签
怎么触发：阶段字段给自由文本。
怎么判断：不创建新指标序列。

写下这些测试断言

  • 每个指标键只含有限枚举。
  • 同次尝试重复上报不增加计数。
  • 重跑成功与初次超时都可识别。

这一课带走：用指标找整体问题，再用关联信息查个案，不让一个维度承担两种目标。

动手练习

把同一条终态重复上报，再将两次不同 attempt 送入指标。
