工作进程重启后如何接回任务

用领取、租约和完成条件模拟安全接手。

先看场景走一遍读代码复现失败动手练习自测

先看场景

一个进程拿到布局任务后停止响应。另一个进程接手时，旧进程可能稍后重新活过来，带着旧结果回来。

租约：工作者在一定期限内拥有处理权，过期后允许接手。

走一遍

  1. 每次领取都有唯一代号。
  2. 过期任务能被新工作者接手。
  3. 提交结果时仍核对领取身份。

第二遍 · 把代码读懂

代码拆解

为什么新工作者接手后，还要拦旧工作者的完成？

调用链

  1. 领取获得递增代次。
  2. 读取必要的中间状态。
  3. 过期后由下一代接手。
  4. 提交时比较自己的代次和当前代次。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

class QueueRow:
    def __init__(self):
        self.epoch, self.until, self.result = 0, 0, None

    def claim(self, now, ttl):
        if self.result is not None or now < self.until:
            return None
        self.epoch += 1
        self.until = now + ttl
        return self.epoch

    def finish(self, epoch, now, result):
        if epoch != self.epoch or now >= self.until or self.result is not None:
            return False
        self.result = result
        return True

row = QueueRow()
first = row.claim(now=0, ttl=5)
assert row.claim(now=4, ttl=5) is None
second = row.claim(now=5, ttl=5)
assert second != first
assert not row.finish(first, now=6, result="old")
assert row.finish(second, now=6, result="new")
assert row.result == "new" and row.claim(now=11, ttl=5) is None

接手不等于安全终止旧进程

进程停顿后可能恢复。不能仅靠内存中的定时器或网络连接识别当前唯一工作者。

代次用于持久化屏障

这个单进程模型每次领取递增代次。真实系统必须在数据库原子领取与写入时比较，不允许旧代夺回任务。

外部副作用也要防重复

旧进程已经向外部工具发请求的情况，仅阻止其向任务表回写并不够。工具写操作仍需要幂等键或等价防重策略。

复现失败

处理超时
怎么触发：A 未在期限内完成，B 在到期时领取。
怎么判断：B 能拿到新代次。
旧进程回归
怎么触发：B 领取后 A 尝试提交。
怎么判断：拒绝 A，最终只保留 B 的结果。

写下这些测试断言

  • 租期未到不会重复领取。
  • 旧代即使先返回也不能写。
  • 有终态后不再领取。

这一课带走：持久任务恢复必须保护交接窗口，而不只是能把任务重新拿起来。

动手练习

让 A 过期后由 B 接手，再让 A 的完成事件先回来。
