拆开接口、业务规则和外部模型

先跑通一个可测的后端切片，再接入真实模型。

先看场景走一遍读代码复现失败动手练习自测

先看场景

把生成请求拆成参数校验、任务编排和模型适配。下一步只用一个假模型，就能复现超时并观察任务状态。

适配器：业务说「给我一个草案」，适配器负责翻译成某个模型听得懂的请求。换模型时，不用重写业务规则。

走一遍

  1. 接口负责输入合法性和可读的错误结构。
  2. 应用服务定义状态流转；不依赖浏览器事件名。
  3. 模型是可替换的端口。测试可以返回固定结果或故意抛出超时。
合成示例 可折叠
interface LayoutModel {
  propose(input: RoomInput): Promise<LayoutDraft>;
}

第二遍 · 把代码读懂

代码拆解

把模型从成功换成超时，能不能只改一行测试输入就验证整个后端分支？

调用链

  1. 接口先校验房间尺寸，把请求转成明确输入。
  2. 应用函数向一个可替换的生成器请求草案。
  3. 规则函数检查草案坐标，决定能否接纳。
  4. 只有通过检查的结果才获得新版本。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

def propose_revision(room_width, old, generate):
    if type(room_width) is not int or room_width <= 0:
        return ("invalid-input", old)
    try:
        draft = generate(room_width)
    except TimeoutError:
        return ("retryable-timeout", old)

    if not isinstance(draft, dict):
        return ("invalid-draft", old)
    left, width = draft.get("left"), draft.get("width")
    valid = (
        type(left) is int and type(width) is int
        and left >= 0 and width > 0 and left + width <= room_width
    )
    if not valid:
        return ("invalid-draft", old)
    return ("accepted", {
        "revision": old["revision"] + 1,
        "shape": {"left": left, "width": width},
    })

base = {"revision": 2, "shape": {"left": 0, "width": 1}}

def timeout(_):
    raise TimeoutError()

assert propose_revision(5, base, timeout) == ("retryable-timeout", base)
assert propose_revision(5, base, lambda _: {"left": 4, "width": 2})[1] is base
assert propose_revision(5, base, lambda _: {"left": 4, "width": 1})[1]["revision"] == 3
assert propose_revision(0, base, lambda _: 1 / 0)[0] == "invalid-input"

三层职责对应三种错误

输入不合法应在模型调用前结束；模型超时说明生成尚无结果，不表示房间本身不合法；草案越界说明模型返回了结果但结果不可采纳。把三个类别都叫「生成失败」会让 UI 和测试没法判断如何恢复。

用函数参数接住变化

generate 可以是模型适配器，也可以是返回固定结果的测试函数。规则层不依赖它内部使用哪种技术，适配层应把上游异常翻译成应用已知的错误。这个例子只捕获 TimeoutError；未预期的程序错误不伪装成超时。

定一个很小的可验证契约

示例把房间当作一条长度线，只检查一件家具的左边与右边是否在界内，以便单独验证单位和边界。多件家具的重叠、碰撞与旋转应有单独的规则和用例，不宜在这里假定已验证。

复现失败

非法输入
怎么触发：把房间宽度设为 0，生成器故意一调用就报错。
怎么判断：不会调用生成器，返回可识别的输入错误。
超时
怎么触发：注入主动抛出 TimeoutError 的生成器。
怎么判断：能区分超时和草案非法，两者都不发布新版本。
越一格
怎么触发：宽 5，左坐标 4，分别用宽 1 与宽 2。
怎么判断：恰好贴边通过，越过一格失败。

写下这些测试断言

  • 同一份旧布局在失败路径不被修改。
  • 非法请求不调用模型适配器。
  • 只有合法草案出现在下一版本，且边界值等于房间宽度可接受。

这一课带走：应用定义错误和发布规则，适配器只负责把模型输入输出接进来。
