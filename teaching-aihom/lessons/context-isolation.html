拆分服务与模型 · 第 08 课 · 约 36 分钟

给每个任务一份独立而可重现的上下文

防止并行任务把不同房间的规则拼到同一次模型调用。

先看场景走一遍读代码复现失败动手练习自测

先看场景

旧任务的模型请求被延迟，用户已经切到另一个房间。若生成时去读界面当前选项，可能组合出错误的输入。

快照：将容易随页面操作变化的生成输入固定在本次操作中。

走一遍

  1. 生成时冻结输入快照。
  2. 将房间身份放入缓存键。
  3. 只选择本房间的资料。
合成示例 可折叠
from dataclasses import dataclass

第二遍 · 把代码读懂

代码拆解

同时生成两个房间时，如何防止模型读到串线的规则？

调用链

  1. 从当前选择构建不可变请求。
  2. 读对应版本规则与允许的资料。
  3. 用快照计算稳定标识。
  4. 把标识用于调试、恢复和缓存。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

from dataclasses import dataclass

@dataclass(frozen=True)
class Context:
    room: str
    rules_rev: int
    width: int
    docs: tuple[str, ...]

def freeze(selected, notes):
    permitted = tuple(sorted({
        n["id"] for n in notes if n["room"] == selected["room"]
    })[:2])
    return Context(selected["room"], selected["rules_rev"], selected["width"], permitted)

a = {"room": "A", "rules_rev": 1, "width": 4}
notes = [{"room": "A", "id": "furniture"}, {"room": "B", "id": "desk"}]
snapshot = freeze(a, notes)
a["width"] = 6
assert snapshot.width == 4
assert snapshot.docs == ("furniture",)
assert freeze(a, notes) != snapshot
assert freeze({**a, "room": "B"}, notes).docs == ("desk",)

延迟读取是隐藏变量

工作者不能在看来应该读取输入时去访问可变的当前房间。冻结规则数值、约束版本与文档 ID，可以让重试的语义不变。

限制资料进入模型上下文

在拼接前过滤所属房间，按确定顺序排序并限制数量。示例仅保留标识；检索后还需要重新校验权限与事实。

缓存身份与执行身份不同

执行 ID 用来追踪一次调用，缓存键代表什么输入可以共享结果。生产应纳入模型、提示版本和访问作用域等影响结果的维度。

复现失败

旧请求晚执行
怎么触发：冻结后修改宽度。
怎么判断：旧请求输入仍是原尺寸。
同用户跨房间并行
怎么触发：A 和 B 的资料均存在。
怎么判断：A 只引用 A 的资料。

写下这些测试断言

  • 输入切换不修改已排队上下文。
  • 快照标识区分不同规则和房间。
  • 跨房间资料在拼装前被排除。

这一课带走：把上下文当作正式输入固定下来，而不是运行中随手读取的页面状态。

动手练习
