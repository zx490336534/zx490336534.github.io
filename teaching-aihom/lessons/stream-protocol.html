区分流字节、消息帧与业务事件

看清为什么数据一次读到了也不等于事件完整。

先看场景走一遍读代码复现失败动手练习自测

先看场景

RoomLab 的流在本地总是一次读完整行，稍慢的网络上却会在两个字符之间切分消息。

分帧：从连续字节中识别出每条完整消息的边界。

走一遍

  1. 用增量解码得到字符。
  2. 按协议边界拼完整帧。
  3. 只交付已经解析并校验的业务事件。
合成示例 可折叠
import codecs, json

第二遍 · 把代码读懂

代码拆解

一个汉字分在两个传输块里时，为什么不能把每块直接转 JSON？

调用链

  1. 收到字节片段。
  2. UTF-8 增量解码。
  3. 按换行找完整记录。
  4. 解析后把事件交给状态更新。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

import codecs, json

def frames(chunks, limit=120):
    decoder = codecs.getincrementaldecoder("utf-8")()
    pending = ""
    for chunk in chunks:
        pending += decoder.decode(chunk)
        while "\n" in pending:
            line, pending = pending.split("\n", 1)
            if len(line) > limit:
                raise ValueError("frame too long")
            if line.strip():
                yield json.loads(line)
        if len(pending) > limit:
            raise ValueError("frame too long")
    pending += decoder.decode(b"", final=True)
    if pending:
        raise ValueError("stream ended mid-frame")

data = '{"seq":1,"phase":"准备"}\n{"seq":2,"phase":"完成"}\n'.encode()
assert [x["seq"] for x in frames([data])] == [1, 2]
assert list(frames([data[i:i+1] for i in range(len(data))])) == list(frames([data]))
try:
    list(frames([b'{"seq":3}']))
    raise AssertionError("expected truncation")
except ValueError as exc:
    assert "mid-frame" in str(exc)

这里只讲 NDJSON

每条 JSON 一行并以换行结束；这不是 SSE 解析器。SSE 按空行结束事件，还支持多行 data 与重连标识。

字节和字符是不同层

增量解码器保存未完成的多字节字符；缓冲区保存未完成的消息。超长帧需要限制，免得坏流占满内存。

断开时不要推测

尾部无分隔符就不是完整帧。按上一课的状态快照恢复，而不是拿残句猜完成。

复现失败

UTF-8 拆开
怎么触发：把字节逐个喂入。
怎么判断：获得跟完整输入相同的两个事件。
流无分隔符断开
怎么触发：移除最后的换行。
怎么判断：报告半帧，不能制造完成事件。

写下这些测试断言

  • 任意切片不改变解码结果。
  • 连续两帧不会合并成一条记录。
  • 截断需走恢复，不将半帧当终态。

这一课带走：先把传输数据恢复成合法消息，再用业务状态规则消费它。
