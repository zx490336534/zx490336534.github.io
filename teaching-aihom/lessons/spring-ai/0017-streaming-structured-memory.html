017 流式响应 + 结构化输出 + 会话记忆

本节目标：搞懂 Spring AI 里"让 AI 像打字机一样一字一字蹦"的流式调用、让 AI 返回能直接映射成 Java 对象的结构化输出、以及让 AI 记住多轮对话上下文的会话记忆。这三个能力组合在一起，撑起了 AIHom 聊天页面的核心体验。

为什么这三个一起讲

上一课我们学会了 ChatClient 的基础调用：.prompt().user(q).call().content()，一次问、一次答、拿到一坨字符串。这个模式能跑，但离真正的产品体验还差三块：

痛点解决它对应能力
AI 回答很长，用户盯着转圈圈等几秒才出结果，体验差 边生成边返回，让前端做"打字机"效果 流式响应
AI 返回的是一段自然语言文本，但我想要 {"title":"...","summary":"..."} 这种结构化数据 让 AI 按指定结构返回，自动映射成 Java 对象 结构化输出
第二轮提问，AI 把第一轮说过的事全忘了 把历史消息存起来，每次提问带上 会话记忆
AIHom 里的真实场景

AIHom 的聊天页就是这三件套合体：WebSocket 把流式 token 推到前端（你看到的字一个一个蹦出来），结构化输出用来让 AI 返回"要不要触发工具、参数是什么"这类机器要读的数据，会话记忆让你这分钟问的"它刚才说的那个词啥意思"能被听懂。本课讲的，就是这三块的 API 长什么样。

1. 流式响应：让 AI 逐字返回

大模型生成文字是一个 token 一个 token 往外吐的（一个 token 大概是半个到一个汉字）。传统调用 .call().content() 会等模型把整段话全生成完，再一次性返回给你——用户要干等几秒。流式调用则每生成出一个 token 就立刻发给你一次，前端可以马上显示出来。

一字之差：.call() → .stream()

Spring AI 里切到流式，就是把 .call() 换成 .stream()。返回类型从 String（一整段）变成 Flux<String>（一堆小片段）。

Flux<String> 里的 Flux 来自一个叫 Reactor 的响应式库。现在不用深究，记住一句话就够：Flux<String> 是一条"会陆续发出多个字符串"的流水线。前端订阅这条流水线，每来一个片段就追加显示，就形成了打字机效果。

@RestController
public class StreamController {

    private final ChatClient chatClient;   // Spring AI 注入的聊天客户端

    public StreamController(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    // 流式接口：访问 /chat/stream?q=你好，会不断返回片段
    @GetMapping(value = "/chat/stream", produces = "text/event-stream")
    public Flux<String> stream(@RequestParam String q) {
        return chatClient.prompt()        // 组装提问
                           .user(q)             // 用户的问题
                           .stream()            // ★ 关键：流式调用，不是 .call()
                           .content();          // 取出每个片段的文字
    }
}

逐行拆这段：

代码归谁管大白话
produces = "text/event-stream" Spring HTTP 协议里的 SSE（Server-Sent Events），告诉浏览器"这是一条会不断有数据的流"。Spring 帮你处理协议头。
Flux<String> Spring Reactor 的响应式类型，表示"陆续发出的多个字符串"。Spring Boot 3 原生支持把它转成 SSE 流推给前端。
.stream().content() Spring AI Spring AI 的流式调用入口。模型每生成一个片段，Flux 就发一个。
流式 vs 一次性，一张图记住

一次性 .call()：模型 ━━━━━━━生成完━━━━━━━▶ 你（用户干等 3 秒，然后一下全出来）
流式 .stream()：模型 ─▶你 ─▶你 ─▶你 ─▶你（第 0.1 秒就开始显示，边生成边显示）

小白避坑：不是更快，是更早

流式不会让模型整体生成得更快——总时间差不多。它只是让第一个字出现得早，用户体感上"快得多"。这就是为什么 ChatGPT、AIHom 都用流式：人对"立刻有反馈"的感知，远比对"总时长短"敏感。

2. 结构化输出：让 AI 返回 JSON 并自动变成 Java 对象

大模型默认返回的是自然语言文本。但很多时候你想要的不是一段话，而是一份机器能读的数据：比如让 AI 总结一篇文章，你想要的是 {"title": "...", "summary": "..."} 这种结构，而不是一坨散文。

Spring AI 的结构化输出干的就是这件事：你先用 Java 定义一个结构（用一个 record），然后让 AI 按这个结构返回，Spring AI 会自动把 JSON 映射成你的 Java 对象。

第一步：用 record 定义"我想要什么结构"

record 是 Java 16+ 引入的"不可变数据类"——你就当成"一个只有字段的数据盒子"。下面定义一个盒子，装两个字段：

// 我希望 AI 返回这种结构：一个标题 + 一段摘要
public record ArticleSummary(
    String title,      // 文章标题
    String summary     // 三句话摘要
) {}

这段等于告诉 AI："请返回类似 {"title":"...","summary":"..."} 的 JSON"。Spring AI 会自动把这个结构塞进提示词，约束模型的输出格式。

第二步：用 .entity() 声明"我要映射成哪个类"

@GetMapping("/summarize")
public ArticleSummary summarize(@RequestParam String article) {
    return chatClient.prompt()
                       .user(u -> u.text("请总结这篇文章：\n\n{article}")
                                   .param("article", article))
                       .call()
                       .entity(ArticleSummary.class);   // ★ 关键：告诉它映射成哪个类
}

注意最后那行 .entity(ArticleSummary.class)——这就是结构化输出的入口。它做了三件事：

  1. 读 ArticleSummary 的字段，自动生成一段"请按 {"title":..., "summary":...} 这个 JSON schema 返回"的指令，塞进给模型的提示词；
  2. 拿到模型的 JSON 文本后，自动用 BeanOutputConverter 反序列化成 ArticleSummary 对象；
  3. 如果格式不对，会自动重试修正（很贴心）。
BeanOutputConverter 是什么

.entity(Xxx.class) 内部用的就是这个转换器。它的活儿就一句：把 JSON 字符串 → Java 对象（字段名对得上就填，对不上就报错）。你不用手写解析代码，Spring AI 全包了。

测试工程师视角

以后你在 AIHom 看到 .entity(SomeRecord.class)，就知道：这不是什么神秘魔法，是"让 AI 按 record 定义的结构吐 JSON，再自动变回 Java 对象"。这个能力在工具调用（下一课）和 Agent 编排里大量使用——AI 要返回"该调哪个工具、参数是什么"，这种必须用结构化输出。

3. 会话记忆 ChatMemory：让 AI 记住上文

大模型本身是无状态的——你这次问"它刚才说的那个词啥意思"，它根本不知道"刚才"是什么。所谓"多轮对话"，其实是每次提问时把历史消息一起打包带过去。Spring AI 把这件事抽象成了 ChatMemory。

ChatMemory 的核心思路

按一个 conversationId（会话 ID）把历史消息存起来。下次同一个会话再提问时，Spring AI 会自动把这条会话之前的消息取出来，拼到新提问前面，一起发给模型。模型就"显得"记住了上下文。

Spring AI 1.1.x 里，ChatMemory 有两种典型实现（你只需要知道区别，不用现在背 API）：

实现存在哪什么时候用
MessageWindowChatMemory（内存） 程序内存里 开发联调、demo、单机小流量。重启就没了
持久化实现（如 Redis / JDBC） 数据库 / 缓存 生产环境，多实例、要长期保存。AIHom 走这条

概念性的用法长这样（先看懂结构，不用记 API）：

// 给 ChatClient 装上"记忆"，绑定一个 conversationId
String conversationId = "user-42-session-1";   // 哪个用户的哪次会话

String reply = chatClient.prompt()
        .messages(memory.get(conversationId))   // 取出这个会话的历史消息，带上
        .user("它刚才说的那个词啥意思？")       // 新问题
        .call()
        .content();

memory.add(conversationId, new UserMessage("它刚才说的那个词啥意思？"));
memory.add(conversationId, new AssistantMessage(reply));  // 把这轮对话存回去
小白的常见误解

"记忆"不是模型自己学进去了什么——模型每次还是从零开始读你发来的全部消息。记东西的是你的程序（存在 ChatMemory 里），每次提问把它原样转发给模型。所以历史越长，每次发的 token 越多、越贵、越慢——这是后面要权衡的事，现在先知道原理。
