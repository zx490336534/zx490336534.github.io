001 Spring AI 是什么 + AIHom 技术地图

本节目标：用一句话讲清 Spring AI 解决什么问题，第一次看 Spring AI 代码时能分清"哪部分是 Java、哪部分是 Spring、哪部分才是 Spring AI"，并看清接下来要走的路。

先讲一个你会感同身受的痛点

作为测试工程师，你大概率见过这样的后端代码：业务要调大模型，于是开发同事去对接 OpenAI 的接口。过几天又要接国产的通义千问，再过几天接 智谱、DeepSeek……每家模型的请求格式、返回结构、鉴权方式都不一样。

结果就是：代码里塞满了 if (provider.equals("openai")) {...} else if (...)，换一个模型要改一堆地方，测试用例也得重写一遍。这就是"没有统一抽象"带来的混乱。

Spring AI 一句话定位

Spring AI 是一个 Java 框架，把"调用各种大模型"这件事统一成一套相同的写法。你换模型，基本只改一行配置；业务代码不动。就像 JDBC 统一了各种数据库、Spring Data 统一了各种数据访问一样——Spring AI 统一了各种大模型。

它在技术栈里的位置

从底到顶是层层依赖的关系。你写的业务代码站在最顶层，脚下踩着的就是这一串：

# 从底层到顶层（标注 AIHom 真实版本）
JDK                     # Java 21
  └── Spring Boot            # 3.x（用 Jetty，不是 Tomcat）
        └── Spring AI        # 1.1.2 — 统一的大模型调用抽象
              └── Spring AI Alibaba # 1.1.2.0.5-qh ★ AIHom 真正的核心
                    └── AIHom 业务代码 # 你最终要读写的地方
关键认知：AIHom 真正用的是 Spring AI Alibaba

注意多出来的那一层 Spring AI Alibaba。它是阿里巴巴在 Spring AI 之上做的扩展，专干两件事：① 国产模型接入——你的项目用的是通义千问 / DashScope，不是 OpenAI；② Agent 编排——AIHom 里大量出现的 StateGraph / Graph、Agent、Tool / MCP 都来自这一层。所以严格说，你要学的是 "Spring AI + Spring AI Alibaba"，后者更是重点。

这就是为什么要先补地基

看清楚了吗？Spring AI 上面叠着 Spring Boot，Spring Boot 上面叠着 Java。三层你都不熟，直接冲最顶层的 AIHom 代码，当然看不懂。我们要做的，就是从下面一层层往上补——但每层只补够用的最小子集，不贪多。

第一次看 Spring AI 代码：分清三层

下面是一段真正能跑的 Spring AI 代码——一个 HTTP 接口，你访问 /ask?q=你好，它就把问题丢给大模型，返回回答。现在看不懂很正常，重点不是记住，而是感受它的结构。

@RestController                          // 告诉 Spring：这是一个 HTTP 接口类
public class ChatController {

    private final ChatClient.Builder builder;  // Spring AI 提供的"聊天客户端"

    public ChatController(ChatClient.Builder builder) {
        this.builder = builder;            // Spring 自动把 builder 传进来（依赖注入）
    }

    @GetMapping("/ask")                    // 把方法映射成 GET /ask
    public String ask(@RequestParam String q) {
        return builder.build()            // ① 造一个聊天客户端
                       .prompt()            // ② 开始组装一次提问
                       .user(q)             // ③ 把用户的问题塞进去
                       .call()              // ④ 真正去调大模型
                       .content();          // ⑤ 取出回答的文字
    }
}

关键来了——这段代码里的东西，分属三个不同的"主人"。认清这一点，你以后看任何 Spring AI 代码都不会慌：

代码归谁管大白话
public class ChatController、构造方法、this.builder = ... Java 这是 Java 的"类"和"构造方法"——面向对象的基本功。阶段 0 补。
@RestController、@GetMapping、@RequestParam、builder 自动被传进来 Spring 带 @ 的叫"注解"，是 Spring 的魔法；对象不用自己 new、自动传进来叫"依赖注入"。阶段 1 补。
ChatClient.Builder、.prompt().user().call().content() Spring AI 这才是 Spring AI 本体——怎么提问、怎么调模型、怎么取结果。015-020 重点学。
测试工程师视角的提醒

注意第 ④ 步 .call()——这是真正发起网络请求、去调大模型的地方。以后你做接口测试、看耗时、排查"为什么回答很慢"，盯的就是这一步。先记住它。

你的学习地图

我们会按下面的顺序走。每一站都只为下一站服务，绝不跑偏：

  • 阶段0Java 够用就好 — 类 / 接口 / 注解 / 泛型 / lambda。只学读懂 AIHom 代码必需的最小 Java。
  • 阶段1Spring Boot 够用就好 — 依赖注入、自动配置、starter、三层注解（@Controller/@Service/...）、application.yml。
  • 阶段2Spring AI + Alibaba 核心 ★ — 先学 ChatClient / Prompt / 流式 / 结构化输出，再进 AIHom 真正的核心：Spring AI Alibaba 的 Agent 框架、StateGraph/Graph 编排、Tool/MCP、DashScope 接入、Nacos 配置。
  • 阶段3回到 AIHom 实战 — 用学到的知识重新读 ai-native-service，这次能看懂、能改、能加新功能。

你现在站在阶段 0 的起点。下一课我们就从"Java 里什么是类、什么是注解"开始，但会全程用"这段代码在 AIHom 里长这样"来锚定，绝不讲成枯燥的 Java 课本。
