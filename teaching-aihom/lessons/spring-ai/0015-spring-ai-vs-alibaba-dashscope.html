一句话先压住全场

Spring AI 是底层统一抽象（造标准），Spring AI Alibaba 是阿里在它上面做的扩展层（加国产模型 + Agent + Graph + Nacos）。AIHom 站在扩展层之上，所以你以后查资料、写代码，盯的都是 Alibaba 这一层的 API。

先看清：谁包含谁、谁依赖谁

把三者画成一张图就一目了然。下面的每一层都"不知道"上面有什么，而上面的层"依赖"下面的层——这正是分层架构的本质：

┌─────────────────────────────────────────────┐
│  AIHom 业务代码（你最终要写的地方）         │   ← 最顶层
└───────────────────────┬─────────────────────┘
                        依赖
┌───────────────────────▼─────────────────────┐
│  Spring AI Alibaba 1.1.2.0.5-qh        ★ 核心
│  ├─ DashScope 适配（通义千问接入）        │
│  ├─ Agent 框架（多步推理 + 工具调用）   │
│  ├─ StateGraph / Graph（流程编排）        │
│  └─ Nacos 集成（配置中心 / 注册中心）     │
└───────────────────────┬─────────────────────┘
                        扩展 / 依赖
┌───────────────────────▼─────────────────────┐
│  Spring AI 1.1.2                          ← 底层标准
│  统一抽象：ChatClient / Prompt / Memory …   │
└───────────────────────┬─────────────────────┘
                        跑在
┌───────────────────────▼─────────────────────┐
│  Spring Boot 3（Jetty）+ Java 21         ← 地基
└─────────────────────────────────────────────┘
关键认知：Alibaba "包含于" Spring AI 体系，又"多包了"一层

准确说：Spring AI Alibaba 是 Spring AI 生态里的一个扩展项目，它必须依赖 Spring AI 才能跑（所以是"包含于"生态、站在 Spring AI 肩上）；同时它又额外包了一层国产模型适配和 Agent 编排能力，AIHom 直接调的就是这一层的 API。换句话说——Spring AI 给了"统一接口"，Alibaba 给了"通义千问的实现 + Agent 编排工具"。

Alibaba 在 Spring AI 之上，多做了这四件事

你可能会问：既然 Spring AI 已经统一了大模型调用，为什么还要 Alibaba？因为 Spring AI 原生只"懂"OpenAI 那一套协议，国产模型、Agent 编排、配置中心这些它不管。Alibaba 专门补上：

能力Spring AI 有吗Alibaba 额外做了什么（AIHom 直接用）
DashScope / 通义千问接入 没有原生支持 把通义千问的 DashScope API 适配成 Spring AI 的统一接口，让你用 ChatClient 就能调国产模型
Agent 框架 只有基础工具调用 提供 Agent 抽象，支持多步推理、自动决定调用哪个工具，是 AIHom 智能体的骨架
StateGraph / Graph 编排 没有 用"节点 + 连线"的方式编排复杂 AI 流程（先检索→再判断→再生成），AIHom 大量靠它
Nacos 集成 没有 把模型配置、Prompt 模板等放到 Nacos 配置中心，动态刷新不用重启
这就是 AIHom 选 Alibaba 而非纯 Spring AI 的根本原因

纯 Spring AI 接不了通义千问，也没有 Agent/Graph 编排能力。AIHom 是群核的国产化项目，必须用通义千问 + 需要复杂流程编排，所以只能选 Alibaba 这一层。这也是为什么 0011 课（Agent/StateGraph）和 0009 课（Tool/MCP）会大量出现 Alibaba 特有的 API。

DashScope 是什么：AIHom 的模型入口

这里有个最容易混淆的点，先帮你掰开：

  • 通义千问（Qwen）——阿里训练出来的大语言模型本身，是一堆神经网络权重。
  • DashScope——阿里提供的模型服务 API 网关。你不可能直接"调用模型权重"，而是通过 DashScope 这个 HTTP 接口去调它。通义千问、通义万相（图像）等模型都挂在 DashScope 后面。
打个比方，立刻懂

通义千问 = 后厨的厨师（真正做饭的人）；DashScope = 餐厅的菜单 + 服务台（你点单、传菜、结账都走这里）。你作为顾客（AIHom 代码）永远不会直接冲进后厨，而是通过服务台下单。AIHom 的模型入口就是 DashScope，不是 OpenAI，也不是直连模型。

为什么反复强调"不是 OpenAI"

网上 90% 的 Spring AI 教程默认接 OpenAI，配置项是 spring.ai.openai.api-key。但你的 AIHom 是国内项目，接的是 DashScope，配置项是 spring.ai.dashscope.*。照搬 OpenAI 教程会直接跑不起来——这就是为什么要专门讲这一课。

怎么把通义千问接进项目：依赖 + yml 配置

核心就两步：① 引入 Alibaba 的 DashScope starter 依赖；② 在 yml 里填 api-key。记牢一个铁律——密钥永远写在配置里，绝不写死在 Java 代码中（这既是安全要求，也是"换环境只改配置"的基础）。

第 ① 步：pom.xml 加依赖

<!-- Spring AI Alibaba 的 DashScope 自动配置 starter -->
<dependency>
    <groupId>com.alibaba.cloud.ai</groupId>
    <artifactId>spring-ai-alibaba-autoconfigure-dashscope</artifactId>
    <version>1.1.2.0.5-qh</version>   <!-- 群核定制版，对齐 AIHom -->
</dependency>

<!-- 通常还需要 Spring AI 的 BOM 统一版本 -->
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.ai</groupId>
            <artifactId>spring-ai-bom</artifactId>
            <version>1.1.2</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
starter 名字要记牢

关键 artifactId 是 spring-ai-alibaba-autoconfigure-dashscope。看到 -autoconfigure- 后缀，就回忆 0005 课讲的：它会自动往 Spring 容器里塞好 DashScope 的客户端 Bean，你直接用 ChatClient 就行，不用手动 new。这是 Spring Boot 自动配置的又一次实战。

第 ② 步：application.yml 配 api-key

spring:
  ai:
    dashscope:
      # 通义千问的 API Key，从阿里云 DashScope 控制台申请
      # 绝不写死在 Java 代码里！用环境变量注入更安全
      api-key: ${DASHSCOPE_API_KEY}
      # 指定用哪个模型，换模型只改这里
      model: qwen-plus
      # 可选：其他参数
      temperature: 0.7
"换模型只改配置"在这里就落地了

想从 qwen-plus 换成 qwen-max（更强的模型）？只改 yml 里的 model: qwen-max，Java 业务代码一行都不用动。想从通义千问换到另一个 DashScope 上的模型？同样只改配置。这就是 0001 课说的"统一抽象"带来的实际红利——你第一次摸到了它。

安全提醒（测试工程师尤其要记住）

${DASHSCOPE_API_KEY} 这种写法表示从环境变量读，yml 里不出现明文 key。这是公司安全规范，也是你做测试时检查代码的安全红线——看到代码里硬编码 api-key 字符串，要立刻报问题。密钥泄漏 = 别人拿你的钱调模型。

对比一下：如果接 OpenAI 会怎样

为了让你彻底分清，把两套配置摆在一起比：

# 接通义千问（AIHom 真实方案）          # 接 OpenAI（网上教程常见，AIHom 不用）
spring:                                  spring:
  ai:                                     ai:
    dashscope:                              openai:
      api-key: ${DASHSCOPE_API_KEY}          api-key: ${OPENAI_API_KEY}
      model: qwen-plus                     model: gpt-4o

看，结构几乎一样，只是配置前缀从 dashscope 换成 openai、模型名换成对应的。而上层调用的 Java 代码完全相同（都是 ChatClient.prompt().user(q).call()）。这就是 Spring AI 抽象层的威力——Alibaba 只是把"通义千问这一侧"补齐了。

版本对齐（重要，已从 AIHom 代码核实）

AIHom 真实栈：Spring AI 1.1.2 + Spring AI Alibaba 1.1.2.0.5-qh（群核定制版）+ 通义千问 DashScope。⚠️ 社区 Spring AI 已发到 2.0.0（2026-06-12，Boot 4.x），但和你的项目无关——查文档务必对齐 1.1.x + Alibaba，别被网上 2.x 教程带偏。本课讲的分层关系在 1.x / 2.x 都通用，但具体 starter 名字、配置项以 java2ai.com 为准。
