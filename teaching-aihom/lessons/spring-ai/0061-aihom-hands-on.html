怎么用所学重读 ai-native-service

第一次打开 ai-native-service/ 时，它是一团迷雾。现在不是了。给你一条固定的阅读路径，从外到内，每一层都映射回你已经学过的课：

阅读层看到什么对应哪节课
第 1 层 · HTTP 入口 @RestController + @PostMapping/@GetMapping，定义对外的接口路径 0004 Spring 注解
第 2 层 · 业务编排 @Service 类，接收请求、组装参数、调用下层、返回结果 0004 + 0002
第 3 层 · 调通义千问 ChatClient / ChatModel / Agent，把问题发给模型服务，拿回回答 016 ChatClient + 017 流式/结构化
第 4 层 · Agent 编排 StateGraph / Graph（Alibaba 核心），把多个节点串成一条流程 020 StateGraph
第 5 层 · 配置与 Tool yml / Nacos 动态配置；Tool 通过 MCP 委托给前端执行 005 + 018 Tool/MCP
阅读姿势

找一个最简单的接口（比如一个"问问答答"的 /chat），从 Controller 开始，顺着调用一层层点进去。每点开一个类，先问自己："这是第几层？对应哪一课？"——你会发现，很多层都已经在前面的课程里见过。

第一次重读，别贪多

不要试图一次读懂整个 StateGraph 流程图。先把第 1、2、3 层彻底吃透（这三层占了日常 80% 的改动），StateGraph 留到你想加"多步推理"功能时再深挖。地基扎实，上面怎么盖都不慌。

新增一个 AI 小功能：五步方法论

下面这套流程，是你在 AIHom 里加任何 AI 功能的通用套路。记住顺序，按部就班：

  1. 定需求（一句话能说清）
    先想清楚：这个功能解决谁的什么问题？输入是什么、输出是什么。写不出一句话，说明需求还没想清，别动手。
  2. 加配置（yml / Nacos）
    模型选哪个（通义千问哪个型号）、Agent 用哪个、温度参数……这些都在 application.yml 或 Nacos 里配。对应 005、008、037。
  3. 写 @Service 业务层
    简单实验可以用 ChatClient；对齐 AIHom 真实链路时，常见的是 ChatModelFactory 创建 ChatModel，再交给 Agent / StateGraph。对应 016 / 020。
  4. 写 @RestController 接口
    把 Service 暴露成 HTTP 接口，让前端能调。对应 004、007。
  5. 自己测（你的主场）
    这一步是你的强项，详见下面。
什么时候用 ChatClient，什么时候用 Agent/StateGraph

简单的一问一答或学习实验 → ChatClient（016）最容易上手。AIHom 真实业务里，若涉及"先查资料再回答""多轮推理""调用工具""Supervisor 路由" → 通常看 ChatModelFactory、Agent / StateGraph（020、050）。别为了用而用——先按需求复杂度选层级。

测试工程师的独特优势：别丢

这一点我必须单独拎出来讲，因为很多转开发的测试工程师会忘掉自己最大的优势。

你的超能力

写代码时，你会天然地考虑：这个输入是空怎么办？模型超时怎么办？返回结构不对怎么办？这些边界和异常，很多纯开发事后才想起来，而你会事前就想到。

在第 ⑤ 步"自己测"时，把这个优势用满：

  • 先想验证，再写代码：动手前先问自己——这个功能做完，我用什么证明它对了？正常 case、空输入、超长输入、模型报错……列出来。
  • 异常路径当一等公民：大模型会超时、会返回脏数据、会拒绝回答。你的 Service 里有没有 try/catch？有没有给前端一个友好的错误？
  • 可验证性写进设计：如果一个功能你自己都说不清"怎么算成功"，那它就是不可测的——不可测的功能，上线就是定时炸弹。
很多开发写完代码才问"怎么测"。你会先问"怎么测"再写代码——这一个顺序的差别，就是工程质量的天壤之别。

下一步：往哪深入

前面的课是地基，不是终点。下面三个方向，按兴趣和项目需要挑：

  1. 读 StateGraph 源码（StateGraphFactory）
    搞懂一个 Graph 是怎么从配置"被造出来"的。这是理解 Alibaba Agent 框架内部机理的钥匙。
  2. 学 Graph 高级编排
    条件分支（根据模型回答走不同路）、人机交互（中间停下来等人工确认）、多 Agent 协作（多个 Agent 分工）。这些是 AIHom 未来会越用越多的模式。
  3. 前后端联调 MCP Tool
    AIHom 的特色是 Tool 委托前端执行。搞懂一个 Tool 调用怎么从后端发起、前端怎么接住、结果怎么回传——你能打通整条链路，价值就翻倍。
选方向的建议

别三个一起冲。先看手头项目最需要哪个——如果你最近要改的就是某个 Agent 的流程，就先啃 StateGraph；如果要加新接口，就先练五步方法论。需求驱动学习，永远比"系统性学完"高效。
