002 Java 的类、对象、构造方法

本节目标：拿到一段 AIHom 风格的 Java 代码，能准确指出哪些是字段、哪些是构造方法、哪些是普通方法——并理解"类是图纸、对象是按图纸造出来的实物"这层关系。

从一个 AIHom 里真实存在的类说起

上一课结尾那段 ChatController，你大概扫了一眼就发现：它不是流水账式的脚本，而是被装进了一个名叫 ChatController 的"盒子"里。这个盒子，在 Java 里就叫类（class）。

一句话定义"类"

类 = 把"数据"和"行为"打包在一起的一个黑盒。"数据"是这个类记住的东西（字段），"行为"是这个类能做的事（方法）。就像一个员工：他脑子里记住的客户名单是数据，他接电话、发邮件这些动作是行为——两者合起来就是一个完整的"人"。

我们再把那段代码拿出来，这次只看它的骨架，先不管那些 @ 符号（下节课讲）：

public class ChatController {          // ← 类的开始，名字叫 ChatController

    private final ChatClient.Builder builder;  // ← 数据（字段）：记住一个 builder

    public ChatController(ChatClient.Builder builder) {  // ← 构造方法
        this.builder = builder;
    }

    public String ask(String q) {              // ← 行为（方法）：能回答问题
        return builder.build().prompt().user(q).call().content();
    }
}                                                 // ← 类的结束

整个类被一对大括号 { } 包起来，名字写在 class 后面。里面只住了三样东西：一个字段、一个构造方法、一个普通方法。这就是 Java 世界的最小完整单元。

字段（成员变量）= 对象记住的状态

看这一行：

private final ChatClient.Builder builder;

它声明了一个名叫 builder 的字段（field），也叫成员变量。逐个词翻译：

写法读法大白话
private 私有的 这个字段是这个类自己的私事，外面的人不能直接伸手进来拿。
final 最终的 赋值之后不能再改。AIHom 大量用 final，是一种好习惯。
ChatClient.Builder 类型 这个字段是什么种类的东西。就像"这是个苹果"里的"苹果"。
builder 变量名 给它起个小名，方便后面叫它。就像"这个苹果叫小明"。
关于"类型"这个词

你可能听过"类型（type）"和"类（class）"被混着用。类是定义、类型是身份。你写 class ChatController 是在定义一个类；当 builder 被标注为 ChatClient.Builder 时，ChatClient.Builder 就是 builder 这个变量的"类型"。先有这么个感觉就行。

字段的作用是让对象"记住"东西。一个 ChatController 对象只要活着，就一直记着那个 builder，下次 ask() 时还能用。这跟测试里你熟悉的"局部变量用完就丢"完全不同——字段跟着对象走，不跟着方法走。

方法 = 对象能做的事

再看这段：

public String ask(String q) {
    return builder.build().prompt().user(q).call().content();
}

这叫方法（method），就是这个类能做的一件事。同样逐个翻译：

写法读法大白话
public 公开的 外面的人可以叫它做这件事。和 private 字段正好相反。
String（方法名前面那个） 返回类型 做完这件事会给你一个字符串当结果。
ask 方法名 这件事叫"问问题"。
String q 参数 做这件事需要你先告诉我一个问题。q 是这个参数的小名。
return ... 返回 把算出来的结果交回去给调用它的人。
小白最常踩的坑：分不清"字段"和"参数"

上面同时出现了 builder（字段，写在类里）和 q（参数，写在方法括号里）。区别：字段是"对象长期记住的东西"，参数是"这次方法调用临时收到的输入"。q 用完这次 ask() 就没了；builder 会跟着对象一直活到对象被销毁。

类是图纸，对象是按图纸造的实物

这是 Java 面向对象里最最核心的一对概念，新手一定要分清：

概念比喻在 AIHom 里
类（class） 手机的设计图纸 ChatController 这段代码本身
对象（object / instance） 按图纸造出来的一台真手机 程序运行时，按 ChatController 造出来的一个个具体实例

图纸只能有一张，但按图纸能造很多台手机。同样，一个类只定义一次，但运行时可以造出任意多个对象——每个对象都各自记着自己的字段，互不干扰。

怎么造对象？用 new

造对象的动作叫实例化，关键字是 new：

// 假装我们手动造一个（AIHom 里实际由 Spring 自动造，下几节课讲）
ChatController ctrl1 = new ChatController(某个Builder);
ChatController ctrl2 = new ChatController(另一个Builder);

ctrl1.ask("你好");   // 用第一个对象问问题
ctrl2.ask("在吗");   // 用第二个对象问问题，互不影响

这里 ctrl1 和 ctrl2 是两个独立的对象，各自记着自己的 builder。这就是"一个类可以 new 出很多对象"。

AIHom 里的真相

真实 AIHom 项目里，你几乎不会自己写 new ChatController(...)。这件事由 Spring 帮你做了（叫"依赖注入"，第 4 课讲）。但理解 new 的存在是理解 Spring 的前提——Spring 只是把"你手动 new"这件事自动化了而已。

构造方法：new 的时候自动跑一次

回到这段代码，注意它很特殊：

public ChatController(ChatClient.Builder builder) {
    this.builder = builder;
}

它叫构造方法（constructor），有三条识别特征：

特征说明
① 名字和类同名 类叫 ChatController，它就叫 ChatController。普通方法不会有这种名字。
② 没有返回类型 注意连 void 都没有。普通方法 ask 前面有 String，构造方法前面什么都没有。
③ new 的时候自动跑 你写 new ChatController(xxx) 时，它会自动被调用一次，你不用手动调。

构造方法干什么用？初始化字段

构造方法的唯一使命就是：在对象刚出生的瞬间，把它的字段填上初值。

看这行：

this.builder = builder;

右边那个 builder 是构造方法收到的参数（括号里那个），左边那个 builder 是类的字段（开头声明那个）。这句话的意思是："把外面传进来的 builder，存到我自己（this）的 builder 字段里。"

为什么需要构造方法？

想象你新招一个员工（造一个新对象），第一天上班就得告诉他："你的工位是 3 号、你的直属领导是老王、你的客户名单是这个"。这些信息不能等他自己猜，得入职当天就交代清楚。构造方法就是"入职当天交代清楚"的那一步。AIHom 里 ChatController 一出生就被告知"你的 builder 是这个"，之后每次 ask() 都能用上。

this = "当前对象自己"

上面那行 this.builder = builder; 里的 this，是 Java 里一个特别的小词，意思是"当前正在被创建的这个对象自己"。

为什么要写 this？因为参数和字段都叫 builder，名字撞了。Java 默认认为"没加前缀的名字 = 最近的那一层"，也就是参数。所以：

写法指的是谁
builder（裸写） 参数 builder（离它最近的那层）
this.builder 当前对象的字段 builder

所以 this.builder = builder; 的完整人话翻译是："把外面传给我的 builder 参数，赋值给我自己内部的 builder 字段。"

this 的更直观理解

想象 this 是一根手指，指着自己。在任何一个对象的方法里，this 都代表"我这个对象"。AIHom 里你会看到大量 this.xxx = xxx;，几乎全是"把参数存进自己的字段"这个套路。

不是必须写 this

如果参数名和字段名不撞，比如参数叫 b，那写 builder = b; 就够了，Java 自己能认出 builder 是字段。AIHom 习惯让参数名和字段名一样（更清晰），所以 this 就成了必备。看到 this. 开头的赋值，十有八九就是这个意思。

综合起来：给段代码你能指认吗

下面是一个 AIHom 风格的简化类（虚构的，但写法和真实代码一致）。试着不往下看答案，先自己分一分：哪些是字段、哪个是构造方法、哪些是普通方法？

public class MessageService {

    private final String defaultName;
    private int count;

    public MessageService(String defaultName) {
        this.defaultName = defaultName;
        this.count = 0;
    }

    public String greet() {
        count = count + 1;
        return "你好，" + defaultName;
    }

    public int getCount() {
        return count;
    }
}

答案拆解：

分类对应代码识别依据
字段 private final String defaultName;
private int count;		 写在类里、方法外，声明"这个对象记住的东西"。
构造方法 public MessageService(String defaultName) {...} 名字和类同名，没有返回类型，负责初始化 defaultName 和 count。
普通方法 public String greet() {...}
public int getCount() {...}		 有返回类型（String、int），名字随便起，是对象"能做的事"。
一个细节

greet() 里写了 count = count + 1;，这里没加 this——因为这一层没有叫 count 的参数，Java 直接认出 count 是字段。这也反过来说明：this 只在"名字撞车"时才必须写。
