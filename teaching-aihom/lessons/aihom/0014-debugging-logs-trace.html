014 日志、Trace、断点与 WebSocket 排查

从浏览器里一条 SendMessage，一路追到后端 handler、StateGraph、Agent 和 tool

1. 排查时只抓三样东西

AIHom 链路长，前端、WebSocket、后端、Agent、tool 都可能出问题。不要一上来全看。先抓三样：

东西在哪里找能回答什么
request idWebSocket 业务消息 RawSocketMessage.id前端这次 SendMessage 和后端响应是不是同一轮。
traceId请求头、后端日志、SpanContextHolder.getTraceId()这次请求在多个服务之间怎么串起来。
conversationUuidSendMessage data、后端 MessageContext这次对话的历史、锁、流式输出归属哪条会话。
核心习惯

先从浏览器 Network 复制 WebSocket 帧，再用其中的 id、key、conversationUuid 去搜后端日志。不要只看 UI 表现。

2. 浏览器里怎么确认消息发出去了

  1. 打开 DevTools 的 Network。
  2. 过滤 WS，找到连接到 /ws 的 WebSocket。
  3. 切到 Messages/Frames，找 key: "SendMessage"。
  4. 展开 data，确认 content、graphId、graphVersion、conversationUuid 是否符合预期。
{
  "id": "req-xxx",
  "key": "SendMessage",
  "type": "request",
  "data": {
    "content": "帮我设计一个客厅",
    "graphId": "graph_ai_home",
    "graphVersion": "...",
    "conversationUuid": "..."
  }
}

前端真实入口在 ai-home 的 ConversationManager.sendMessage()：它先乐观更新临时消息，再调用 this.conversationRef.send(userMsg)。WebSocket 配置来自 getAgentConfig()，默认 graphId 是 graph_ai_home，也允许 URL query 覆盖 graphId 和 graphVersion。

3. 后端第一站：WsMessageListener

后端收到消息后，第一站不是 Agent，而是 WebSocket listener：

WsMessageListener.onMessage
  │  解析 StompSendCommand
  │  HeaderUtils.getTraceId(headers)
  │  JSON 解析成 RawSocketMessage
  ▼
SocketHandlerFactory.getRequestHandler(rawSocketMessage.getKey())
  ▼
SendMessageHandlerImpl.handleMessage

WsMessageListener 使用 QHLogger 打 Received message，并用 LocalTracer.startServerSpan("<ws>", HeaderUtils.getTraceId(headers), null) 建立 WebSocket 侧 trace。

4. 第二站：SendMessageHandlerImpl

SendMessageHandlerImpl 做的是“把前端消息变成可执行的 Agent 上下文”：

  1. 把 rawSocketMessage.data 转成 ClientSendMessageDto。
  2. 读取 graphId、graphVersion，必要时生成 conversationUuid。
  3. 调用 StateGraphFactory.getStateGraphCacheDto(graphId, graphVersion) 拿图配置。
  4. 构造 MessageContext 和 RunnableConfig。
  5. 调用 messageProcessService.handleMessage(messageContext)。
断点建议

第一次排查不要把断点打到很深。先打在 WsMessageListener.onMessage()、SendMessageHandlerImpl.handleMessage()、MessageProcessService.handleMessage()。能走到哪一步，就说明前面的链路基本通了。

5. 第三站：StateGraph、Agent、tool

MessageProcessService.handleMessage() 会编译图并开始流式执行：

MessageProcessService.handleMessage
  │  StateGraphFactory.buildCompiledGraph(stateGraph)
  │  compiledGraph.stream(...)
  ▼
processNewMessage / processStreamingOutput
  │  处理 nodeOutput.agent()
  ▼
前端收到 assistant/tool 消息

Agent 节点由 AgentNodeAdapterImpl 添加：它解析 AgentConfigDto，再通过 AgentNodeFactory.getReactAgent(agentConfig) 构建 ReactAgent。tool 侧可以从 AgentNodeFactory 里看到 MCP tool callback 的组装，也可以从 ToolCallBackFactory 查已经注册的 tool 名。

6. QHLogger 和 traceId 怎么配合看

两个后端都使用 QHLogger，并在配置里打开 qunhe.hunter.enable-mdc: true。普通 HTTP 接口会在各自的 BaseController.initContext() 里写入 SpanContextHolder.getTraceId()。

服务日志/trace 线索用法
ai-native-serviceWsMessageListener、SendMessageHandlerImpl、MessageProcessService用 request id、conversationUuid、agent 过滤。
auto-layout-serviceBaseProcessor.doAfter()、BaseAsyncV2Processor.onSuccess()用 traceId 找接口入参、耗时、任务状态。
ai-homeTracer.error、业务埋点、浏览器 Console确认 SDK 是否连接、消息是否调用 send()。

7. 如果调用到了 auto-layout-service

自动布局服务里很多接口是 Processor 模式。排查路径是：

Controller / ProcessorFactory
  ▼
BaseProcessor.doProcess(req)
  ▼
BaseProcessor.doAfter(req, result)
  │  打印 methodUri / totalTime / traceId / request / result
  ▼
异步任务还会进 BaseAsyncV2Processor.onSuccess/onError

比如 AutoLayoutWithImageProcessor、SubmitAutoDesignV2AsyncProcessor、GenerateLayoutImageProcessor 等类都显式使用 SpanContextHolder.getTraceId() 打日志或传 header。

8. 一次完整 SendMessage 排查清单

  1. 浏览器 Network/WS：确认 SendMessage 发出，复制 id 和 conversationUuid。
  2. ai-home：确认 ConversationManager.sendMessage() 真的调用 conversationRef.send()。
  3. ai-native-service：断点进 WsMessageListener.onMessage()，看 RawSocketMessage.key。
  4. ai-native-service：断点进 SendMessageHandlerImpl.handleMessage()，看 graphId 和 graphVersion。
  5. ai-native-service：断点进 MessageProcessService.handleMessage()，看 compiledGraph.stream() 是否产生 nodeOutput.agent()。
  6. tool/auto-layout：如果 Agent 调 tool，用 traceId 搜 auto-layout-service 的 Processor 日志。
  7. 回浏览器：看 WebSocket 是否收到 AddMessages、流式响应或错误 response。
问 agent：“我这里有一个 WebSocket frame 和 traceId，帮我判断应该断在哪个类”，把 frame 的 key/data 和后端错误日志贴过去。
