037 AIHom 前端入口 06：iframe/postMessage 与 viewer 边界

目标：遇到 2D/3D viewer 问题时，先知道边界在哪里，再决定看 ai-home、viewer-2d 还是 render-3d。

先分清角色

ai-home 是宿主页面，负责对话、状态和整体布局。viewer-2d 负责 2D 户型展示。render-3d 负责 3D 场景和截图/离线渲染。它们不是一个页面里的普通 div，而是通过 iframe 和消息协作。

1. 最小结构

ai-home 主页面
  ├─ 嵌入 viewer-2d iframe
  ├─ 嵌入 render-3d iframe
  └─ 通过 postMessage / SDK / 状态管理传递指令和结果

2. iframe 是边界

iframe 可以先理解成“页面里嵌了另一个小浏览器”。所以宿主和 viewer 之间不是直接互相改变量，而是发消息。

如果问题是优先看哪里
ai-home 没有把参数传进去ai-home 的 viewer 组件和 iframe URL
viewer 收到消息但没处理viewer-2d 或 render-3d 的消息监听
viewer 处理完没有回传回传的 message type 和 payload
页面状态没更新ViewerStateManager 或对应 connect 组件

3. viewer-2d 先理解成“数据变图形”

2D 里看到的户型不是 DOM 一行行画出来的。更合理的读法是：

designDoc 数据
  ↓
EntityDocument / Entity
  ↓
Drawable
  ↓
PixiJS 画到 2D 画布

所以 2D 显示不对，先问：数据有没有进来？Entity 有没有创建？Drawable 有没有画？

4. render-3d 先理解成“场景 + 任务状态”

3D 不只是显示模型，还会做刷新、截图、离线渲染。读它时先看状态名：WAITING、IN_PROCESS、COMPLETED、FAILED、CANCELLED。

如果截图失败，不要先看 CSS。先看任务是否创建、是否轮询、是否进入终态、是否把结果回传给宿主。

5. 排查决策卡

现象第一反应
iframe 空白看 URL、加载报错、资源构建
2D 数据不对看 designDoc、Entity、Drawable
3D 不刷新看消息有没有发到 render-3d
截图没回来看离线渲染任务状态和回传消息
Q1：iframe 最接近什么？
  • A. 嵌入页面
  • B. 后端接口
  • C. 数据库表
  • D. Git 分支
Q2：2D 显示不对，优先确认什么？
  • A. 字体大小
  • B. 发布日期
  • C. 数据实体
  • D. 分支名称
Q3：截图失败先看什么？
  • A. 卡片圆角
  • B. 任务状态
  • C. 标题字号
  • D. 注释数量
复习时可以问 agent：给我一个 3D 截图失败的排查路线，从 ai-home iframe 到 render-3d 任务状态一路追。
