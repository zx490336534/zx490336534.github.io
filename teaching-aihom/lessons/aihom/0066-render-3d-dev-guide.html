066 render-3d 开发实战

掌握 render-3d 渲染引擎的参数扩展、iframe 通信协议以及常见问题排查

1. 如何新增渲染参数

render-3d 是一个独立的 3D 渲染服务，通过 iframe 嵌入到 ai-home 主应用中。渲染参数定义了场景的材质、光照、视角等视觉效果。

参数架构

render-3d 参数体系
├── 场景参数 (Scene)
│   ├── backgroundColor    # 背景色
│   ├── environmentMap     # 环境贴图
│   └── fog                # 雾效配置
├── 相机参数 (Camera)
│   ├── position           # 相机位置 [x, y, z]
│   ├── target             # 观察目标点
│   └── fov                # 视场角
├── 光照参数 (Lighting)
│   ├── ambientIntensity   # 环境光强度
│   ├── directionalLight   # 方向光
│   └── shadowQuality      # 阴影质量
└── 材质参数 (Material)
    ├── roughness           # 粗糙度
    ├── metalness           # 金属度
    └── textureScale        # 贴图缩放

参数命名规范

参数 key 使用 点分层级 命名（如 lighting.colorTemperature），与 JSON 嵌套结构一致，方便后端 Agent 直接引用。

2. iframe 通信协议

render-3d 以 iframe 方式嵌入 ai-home，两者通过 postMessage 进行双向通信。所有消息遵循统一协议格式。

消息格式

// 通用消息结构
interface RenderMessage {
  type: string;        // 消息类型
  payload: unknown;   // 消息载荷
  requestId: string;  // 请求 ID，用于匹配响应
  source: 'ai-home' | 'render-3d';  // 消息来源
}

消息类型一览

type方向说明
RENDER_INITai-home → render-3d初始化渲染场景
RENDER_UPDATE_PARAMSai-home → render-3d更新渲染参数
RENDER_LOAD_MODELai-home → render-3d加载 3D 模型
RENDER_SET_CAMERAai-home → render-3d设置相机视角
RENDER_CAPTUREai-home → render-3d截图并返回 base64
RENDER_READYrender-3d → ai-home渲染器初始化完成
RENDER_PROGRESSrender-3d → ai-home加载/渲染进度
RENDER_RESULTrender-3d → ai-home操作结果（含截图数据）
RENDER_ERRORrender-3d → ai-home错误信息

通信流程示例

ai-home: RENDER_INIT → render-3d 初始化 → render-3d: RENDER_READY → ai-home: RENDER_UPDATE_PARAMS → render-3d: RENDER_RESULT

ai-home 侧的消息发送

// src/services/renderBridge.ts
class RenderBridge {
  private iframe: HTMLIFrameElement;
  private pendingRequests = new Map<string, PromiseResolve>();

  send<T>(type: string, payload: unknown): Promise<T> {
    const requestId = crypto.randomUUID();

    this.iframe.contentWindow?.postMessage({
      type,
      payload,
      requestId,
      source: 'ai-home',
    }, '*');

    return new Promise((resolve) => {
      this.pendingRequests.set(requestId, resolve);
    });
  }
}

// 使用示例
const result = await renderBridge.send<CaptureResult>(
  'RENDER_CAPTURE',
  { width: 1920, height: 1080, format: 'png' }
);

render-3d 侧的消息接收

// render-3d/src/bridge/messageHandler.ts
window.addEventListener('message', (event) => {
  const msg = event.data as RenderMessage;

  if (msg.source !== 'ai-home') return;

  switch (msg.type) {
    case 'RENDER_INIT':
      initScene(msg.payload);
      reply(msg.requestId, 'RENDER_READY', {});
      break;
    case 'RENDER_UPDATE_PARAMS':
      updateParams(msg.payload);
      reply(msg.requestId, 'RENDER_RESULT', { success: true });
      break;
    // ...其他消息类型
  }
});
安全须知

生产环境中 postMessage 的 targetOrigin 必须指定为具体域名（不能用 '*'），防止跨域消息泄露。开发环境可放宽限制。

3. 常见排查路径

问题 1：iframe 加载白屏

排查步骤：
1. 检查 iframe src 是否正确
   → 浏览器 DevTools → Elements → 检查 iframe 标签的 src 属性
2. 检查跨域
   → Console 中是否出现 "Blocked a frame with origin" 错误
3. 检查 render-3d 服务状态
   → 直接在新标签页打开 iframe 的 URL，确认是否可访问
4. 检查网络
   → DevTools → Network，查看是否有资源加载失败（404/500）

问题 2：渲染参数不生效

排查步骤：
1. 确认消息已发送
   → Console 中打印发送的 postMessage 数据
2. 确认消息已接收
   → render-3d 侧的 message 事件是否触发
3. 检查参数 key 拼写
   → 参数 key 必须与 render-3d 侧 schema 完全一致（区分大小写）
4. 检查参数值范围
   → 数值参数是否在 min/max 范围内，超范围可能被忽略

问题 3：截图返回空白或黑屏

排查步骤：
1. 确认 RENDER_READY 已收到
   → 在发送 RENDER_CAPTURE 前必须等待 READY 响应
2. 检查 WebGL 上下文
   → canvas.getContext('webgl2') 是否返回 null
3. 检查 preserveDrawingBuffer
   → WebGL 创建时必须设置 preserveDrawingBuffer: true
4. 检查时序
   → capture 请求是否在模型加载完成之后发出

快速调试技巧

Debug Mode

在 URL 后加 ?renderDebug=true 可开启 render-3d 的调试模式，会在控制台打印所有收发消息和渲染状态变更，极大加速排查。
