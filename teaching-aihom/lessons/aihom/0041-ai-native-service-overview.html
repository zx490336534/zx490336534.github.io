041 ai-native-service 项目全景

理解后端核心仓库的结构、架构和关键入口 — 为后续功能开发打下基础

1. 这个项目是什么

ai-native-service 是 AI Home 产品的后端大脑。它接收用户在前端对话框中发送的消息，通过 AI Agent 决策路由，调用各种工具（户型识别、自动布局、图像生成等），最终把结果返回给前端。

一句话定位

Spring Boot 3 + Spring AI 驱动的 Multi-Agent 对话服务，负责"用户说了什么 → AI 怎么理解 → 调用什么工具 → 返回什么结果"这条完整链路。

2. 三模块结构

项目是一个 Maven 多模块工程，共三个子模块：

模块JDK职责
ai-native-service-commonJava 8公共常量、枚举、VO — 跨模块共享的数据结构
ai-native-service-clientJava 8SOA 客户端接口定义 — 让其他服务能调用 ai-native
ai-native-service-webJava 21核心业务 — Controller、Agent、Service、Tool 全在这里
开发重点

你 90% 的开发工作都在 ai-native-service-web 模块里。common 和 client 只在需要新增跨服务接口或共享类型时才动。

4. 一条消息的完整旅程

当用户在 AI Home 前端输入 "帮我设计一个现代风格的客厅"，这条消息经历了什么？

用户发消息 → WebSocket → SendMessageHandler → MessageProcessService → StateGraph 执行 → Supervisor 路由 → 子 Agent → Tool 调用 → 流式返回

关键步骤拆解：

  1. WebSocket 接收 — WebSocketController 收到消息，转给 SocketService
  2. 消息处理 — SendMessageHandlerImpl 加并发锁（同一用户同时只能有一个对话），调用 MessageProcessService
  3. StateGraph 执行 — 从数据库加载图配置，构建状态图，执行 Agent 节点
  4. Supervisor 路由 — CustomSupervisorAgent 根据用户意图，决定路由到哪个子 Agent（如 Floorplan_to_Design、Image_Editor）
  5. Tool 调用 — 子 Agent 调用具体工具（如 FloorplanToStructureTool 识别户型图）
  6. 流式返回 — 结果通过 WebSocket 流式推送给前端
不理解某个步骤？随时问我。比如 "StateGraph 是什么" 或 "Supervisor 怎么决定路由到哪个子 Agent"。

6. 核心概念速查

StateGraph（状态图）

不是简单的 if-else 流程，而是一个可配置的工作流图。每个节点是一个 Agent 或 Tool，边定义了节点间的流转逻辑。配置存在数据库里，支持动态更新、版本控制。

Supervisor Agent（监督代理）

整个系统的"调度员"。收到用户消息后，Supervisor 根据意图决定路由到哪个子 Agent。比如"设计户型图"路由到 Floorplan_to_Design，"编辑图片"路由到 Image_Editor。

MCP 工具桥接

后端需要动前端资源时（如 3D 渲染），不走 HTTP 轮询，而是通过 WebSocket 发 Tool Call 让前端执行再回传。这就是"前端 MCP 工具"。

Nacos 配置驱动

Agent 的 prompt、模型参数、工具列表等都存在 Nacos 配置中心，支持热更新，不需要重启服务。
