035 AIHom 前端入口 04：接口请求与数据契约

目标：理解前端和后端怎么“说同一种话”：字段名、类型、枚举、状态码必须对齐。

先记住一句话

接口不是“前端随便传、后端随便收”。接口是一份约定：前端按约定传参数，后端按约定返回数据。约定对不上，就会出现页面空白、字段 undefined、状态判断失效。

1. 一个接口请求由四部分组成

部分新手理解例子
URL请求发到哪里/api/xxx
Method这次动作类型GET / POST
Request前端传给后端的数据designId、message
Response后端返回给前端的数据code、data、msg

2. TypeScript 类型和 Java DTO 要对齐

前端常用 TypeScript 描述数据长什么样；后端常用 Java DTO / VO 描述请求和响应。它们名字可以不完全一样，但字段含义必须一致。

// 前端 TypeScript
interface SendMessageRequest {
  sessionId: string;
  message: string;
}

// 后端 Java
class SendMessageRequestDTO {
  private String sessionId;
  private String message;
}

读接口问题时，先把前端类型和后端 DTO 摆在一起看：字段名是否一致、是否必填、类型是否一致、枚举值是否一致。

3. 最常见的四类对不齐

问题表现排查
字段名不一致后端收到 null，前端读到 undefined对比 TS interface 和 Java DTO
类型不一致数字当字符串、字符串当对象看 Network 真实 payload
枚举不一致状态分支走错找 enum / constant 定义
包装层不一致前端读错 data 层级确认响应是 data.xxx 还是 xxx

4. WebSocket 也是数据契约

AIHom 里不只有 HTTP。WebSocket 消息同样有契约：type 表示消息大类，key 表示具体动作，data 是业务数据。下一课会专门看 WebSocket。

5. 全栈开发时的最小检查顺序

  1. 浏览器 Network / WS 里看真实请求和真实响应。
  2. 前端找到对应 TypeScript 类型或调用方法。
  3. 后端找到 Controller / Handler / DTO / VO。
  4. 确认字段名、类型、枚举、包装层是否一致。
  5. 再看业务逻辑，不要一开始就猜。
Q1：接口契约首先约定什么？
  • A. 数据格式
  • B. 字体大小
  • C. 页面颜色
  • D. 文件图标
Q2：字段对不齐时优先看哪里？
  • A. README 标题
  • B. CSS 圆角
  • C. 真实请求
  • D. 终端主题
Q3：WebSocket 消息是否也有契约？
  • A. 没有
  • B. 有的
  • C. 随机
  • D. 不看
