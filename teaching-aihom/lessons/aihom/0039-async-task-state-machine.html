039 AIHom 前端入口 08：异步任务与状态机基础

目标：理解为什么很多 AIHom 功能不是点一下马上返回结果，而是先创建任务、再查状态、最后拿结果。

先用外卖类比

同步接口像“问前台库存，马上回答”。异步任务像“下单做饭”：先给你订单号，然后你不断查“已接单、制作中、已完成、失败/取消”。AI 布局、截图、渲染都更像后者。

1. 异步任务的四步

提交任务
  ↓
拿到 taskId
  ↓
轮询 task status
  ↓
成功拿结果 / 失败看原因 / 取消停止

2. auto-layout-service 的 Processor 先这么看

在 auto-layout-service 里，Processor 可以先理解成“处理某类请求的工人”。同步任务直接处理完返回；异步任务会创建任务状态，然后后台继续跑。

类名先理解成
BaseAsyncProcessor异步任务的通用流程
BaseDbTaskAsyncProcessor任务状态存在 DB
BaseRedisTaskAsyncProcessor任务状态存在 Redis
AutoLayoutAsyncProcessor自动布局任务的真实处理器之一

3. 状态机是什么

状态机不是神秘东西。它就是规定：任务现在处于哪个状态，下一步允许变成哪个状态。

INIT
  ↓
PROCESSING
  ├─ FINISHED
  ├─ FAILED
  └─ CANCELLED

读任务代码时，先找状态枚举和终态集合。终态就是“不会继续往下跑”的状态。

4. render-3d 的例子

render-3d 的 OfflineRenderStateManager 会维护截图任务状态，并启动轮询。状态里能看到 WAITING、IN_PROCESS、COMPLETED、FAILED、CANCELLED。

所以排查 3D 截图问题时，先问：任务有没有创建？轮询有没有启动？状态有没有进入 COMPLETED 或 FAILED？

5. 新手排查清单

  1. 提交接口是否成功返回 taskId？
  2. 状态接口是否能查到这个任务？
  3. 状态是否一直卡在处理中？
  4. 失败时有没有错误原因？
  5. 前端是否把终态结果显示出来？
Q1：异步任务第一次通常返回什么？
  • A. 最终图片
  • B. 任务 id
  • C. CSS 类名
  • D. Git 分支
Q2：状态机主要规定什么？
  • A. 页面颜色
  • B. 文件目录
  • C. 状态流转
  • D. 注释格式
Q3：任务卡住优先看什么？
  • A. 当前状态
  • B. 标题字号
  • C. 卡片圆角
  • D. 空格数量
