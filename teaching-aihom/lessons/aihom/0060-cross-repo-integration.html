3. 接口契约

3.1 ai-home ↔ ai-native-service

协议用途关键接口
WebSocket/STOMP 帧 + RawSocketMessage实时对话SendMessage, CancelMessage, AddMessages
HTTP REST非实时操作/conversation, /image, /credit

3.2 ai-home ↔ viewer-2d / render-3d

协议用途关键消息
iframe postMessage数据同步roomInfo, previewImage, showRule
iframe postMessageMCP 工具调用capture3DScreenshot, generateVideo

3.3 ai-native-service → auto-layout-service

协议用途关键接口
HTTP REST自动布局/auto-layout, /match-furniture
HTTP REST户型识别/floorplan-to-structure

4. 版本兼容性注意事项

高风险
  • WebSocket 消息格式 — 前后端必须同步更新，否则消息解析失败
  • iframe postMessage 协议 — ai-home 和 viewer 的消息类型必须一致
  • MCP 工具签名 — 工具名、参数格式变更需要前后端同步
  • auto-layout-service 接口 — 请求/响应结构变更需要 ai-native-service 同步
安全
  • Nacos 配置变更 — 只影响 ai-native-service，无需协调
  • CSS/样式变更 — 各仓库独立，互不影响
  • 工具内部逻辑 — 只要接口不变，内部实现可独立修改

5. 联调指南

  1. 本地联调 — ai-home 本地启动，连接 dev 环境的 ai-native-service
  2. 前端联调 — viewer-2d / render-3d 本地启动，通过 iframe 嵌入 ai-home
  3. 后端联调 — ai-native-service 本地启动，连接 dev 环境的 auto-layout-service
  4. 全链路 — 所有服务本地启动，修改 ai-home 的 WebSocket endpoint 指向本地
