011 Coops Agent 配置与 MCP 注入

目标：搞清 AIHom 的 Agent、Prompt、Model、MCP Server、Skill 是从哪里配置、如何加载、最终怎样变成大模型可调用的工具。

1. 先统一名字

这块的准确入口是 Coops Agent 管理中心、MCP 中心、Skill 中心，准确代码链路是 Nacos 配置加载 + Agent 构建 + ToolCallback 注入。

AIHom 这条链路要同时看两类信息：Coops/Nacos 里的 Agent、Prompt、Model、MCP Server、Skill 配置，以及 StateGraph 里的 Supervisor、SubAgent、工具挂载关系。只看 Agent 详情页容易误判“没有工具”。

2. Coops 页面实际读取什么

打开 Coops 的 Agent 详情页时，页面会从 Nacos 配置读取当前 Agent 的四类核心配置。

配置文件Nacos group作用AIHom 现场
agent-base.jsonai-agent-{agentName}Agent 描述、promptKey、最大迭代次数。Ai_Home_Agent 的 promptKey 是 Ai_Home_Agent，最大迭代 100。
model.jsonai-agent-{agentName}模型名、baseUrl、API key、temperature、maxTokens。页面直接展示当前模型配置。
mcp-servers.jsonai-agent-{agentName}该 Agent 直接挂载哪些 MCP Server，以及白名单 tools、headers、queryParams。当前 Supervisor 页面显示直接 MCP Server 数量为 0。
agent-skill.jsonai-agent-{agentName}该 Agent 直接挂载哪些 Skill。当前 Supervisor 页面显示直接 Skill 数量为 0。
prompt-{promptKey}.jsonnacos-ai-metaAgent 实际使用的 System Prompt 模板。Supervisor 的路由规则就在 Prompt 里。

“直接挂载为 0”不等于整个 AIHom 没有工具。AIHom 还通过 StateGraph 的 Supervisor 配置挂 SubAgent，每个 SubAgent 可以有自己的 local tools 或 MCP tools。

3. StateGraph 补充哪块视角

Coops Agent 详情页看单个 Agent 的 Nacos 配置。AIHom 还要结合 Graph 数据库配置，才能回答“当前 AI Home 实际跑的是哪个 Supervisor 图”。

来源读取内容能判断什么
DB API /api/dbv/sql/exec查询 state_graph，限定 graph_id='graph_ai_home'、deleted=0、is_active=1。当前激活 Graph 的 id、版本、名称。
graph_nodes按 state_graph_id 查询节点，找到 node_type='supervisor'。当前 Supervisor 节点配置。
node_config解析 agentName、subAgents、subAgentList、localTools。Supervisor 下有哪些 SubAgent，每个 SubAgent 挂了哪些本地工具。
Nacos按每个 Agent 的 agent-base.json 和 prompt-{promptKey}.json 拉描述与 Prompt。看见每个 Agent 的真实提示词和配置。

4. 后端代码如何注入 MCP 和 Agent

读代码时抓住两条路径即可。

路径关键类真实含义
Nacos Agent 路径CustomNacosReactAgentBuilder加载 AgentVO、PromptVO、ModelVO、McpServersVO，把 local tools 和 MCP tools 合并成 allTools。
MCP Server 解析CustomNacosMcpGatewayToolsInitializer用 NacosMcpOperationService.getServerDetail() 读取 MCP Server 详情，按协议、白名单、enabled 开关过滤工具。
Tool 变成模型可见AgentLlmNode / AgentToolNode同一批 ToolCallback 同时给 LLM 节点和 Tool 节点：前者让模型看见工具定义，后者负责真正执行。
postmessage 工具FrontendNacosMcpGatewayToolCallback协议是 postmessage 时，工具调用不是后端 HTTP，而是转给浏览器前端执行。
StateGraph 配置路径AgentNodeFactory从 AgentConfigDto 创建 ReactAgent/SupervisorAgent，支持 localTools 和 mcpServers。
Coops / Nacos 配置
  ↓
agent-base.json / prompt-*.json / model.json / mcp-servers.json / agent-skill.json
  ↓
CustomNacosReactAgentBuilder.build()
  ↓
localTools + buildMcpTools(...)
  ↓

  ↓

5. MCP 注入排查顺序

  1. 先看 Coops Agent 页：当前 region、namespace、Agent 名称是否正确。
  2. 看 mcp-servers.json：有没有挂 MCP Server，whiteTools 是否过滤掉了目标工具。
  3. 看 MCP Server 详情：协议是否在支持列表内，tool 是否 enabled，schema 是否正确。
  4. 看后端构建日志：CustomNacosMcpGatewayToolsInitializer 有没有加载到工具。
  5. 看模型请求：大模型看到的工具名是 {mcpServerName}_tools_{toolName}，不是裸 toolName。
  6. 看执行端：普通 MCP 走后端 callback；postmessage 走前端页面。

对 AIHom 来说，先分清“Supervisor 直接挂的工具”和“SubAgent 挂的工具”。当前 Coops 的 Ai_Home_Agent 详情页显示 Supervisor 直接 MCP/Skill 为 0；StateGraph 配置里还能看到 SubAgent 与本地工具挂载。
