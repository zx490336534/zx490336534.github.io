034 AIHom 前端入口 03：一次页面动作的数据流

目标：用“用户点了一下发送”这件小事，看懂 AIHom 前端里数据怎么从页面流向状态、服务、后端，再回到页面。

先不要急着看框架

新手读前端最容易被文件名和类名吓住。先把每次交互都看成一条线：用户做动作 → 组件收到动作 → 调用服务 → 改状态 → 页面重新显示。

1. 一次发送消息，大概经过谁

用户在输入框里点“发送”
  ↓
InputArea / Chat 相关组件收到 onClick
  ↓
ConversationManager 记录“正在发送、当前消息”
  ↓
AgentSDKService 或对话 SDK 把消息送出去
  ↓
WebSocket 连接到 ai-native-service
  ↓
后端持续返回消息片段、排队信息、工具调用
  ↓
ConversationManager 更新消息列表
  ↓
AIChatDrawer / 消息组件重新渲染

2. 每一层只先记一个职责

层新手先理解成排查时看什么
组件负责显示和接收点击onClick、onChange、props
Manager负责保存页面状态消息列表、loading、当前选中项
Service / SDK负责和外部通信初始化、发送方法、回调注册
WebSocket负责持续传消息Frames 里的 type、key、data
后端负责 Agent、工具、模型和任务handler、traceId、日志

3. 读代码时从“动作词”开始

不要一上来全文搜索某个类。先找动作词：

  1. 用户点按钮，就搜 onClick 或按钮文案附近的组件。
  2. 输入框变化，就搜 onChange、value、placeholder。
  3. 发送消息，就搜 send、message、conversation。
  4. 画布变化，就搜 viewer、designDoc、postMessage。

4. “状态变了”不等于“页面立刻变了”

前端页面通常不是手动刷新出来的。组件会读取状态；状态变化后，React 和状态框架让组件重新渲染。你排查时要分开问：

  • 数据有没有回来？看 Network / WebSocket。
  • 状态有没有改？看 Manager 里的字段。
  • 组件有没有读这个状态？看 props、connect、observer。
  • 页面有没有被 CSS 遮住？看 Elements 和样式。

5. 新手练习：只追一条线

打开 ai-home 时，给自己一个很小的问题：“点击发送后，第一处改变 loading 的代码在哪里？”你只需要找到第一处，不需要一次追完所有异步回调。

Q1：一次页面动作的第一步通常看什么？
  • A. 发布分支
  • B. 事件入口
  • C. 字体配置
  • D. 数据库表
Q2：Manager 最常见的职责是什么？
  • A. 保存状态
  • B. 编译代码
  • C. 购买域名
  • D. 生成字体
Q3：页面没变时，不应该只看哪一层？
  • A. 网络消息
  • B. 状态字段
  • C. 单一层级
  • D. 组件读取
复习时可以问 agent：带我用“点击发送”这条线，在 ai-home 里从 onClick 追到 ConversationManager，再追到 WebSocket。
