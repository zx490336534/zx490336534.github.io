050 render-3d 深度追踪

拆解 3D 渲染容器的核心状态机 — 模板缓存、父页面同步、渲染轮询与房间自动出图

1. render-3d 是什么

render-3d 是 AI Home 的 3D 渲染与离线出图容器。它不是一个独立页面，而是一个嵌在 iframe 里的 3D 工作台，负责加载设计方案、维护实时模板与相机状态、同步父页面显示规则、提交离线渲染任务，并驱动图册和房间自动出图。

一句话定位

React 16 + TypeScript 前端容器，核心状态挂在 KAF 状态树和多个 StateManager 里，其中 OfflineRenderStateManager 是整个渲染业务的中枢。

关键特征

页面不是普通 React 预览页。入口启动后会先初始化 3D 场景、相机视角、可见楼层和离线渲染配置，再把 UI 和场景状态联动起来。很多看起来像按钮的小组件，实际上直接挂着渲染任务、相机切换和跨 iframe 协议。

2. 状态总线：RootStateManager

RootStateManager 是根状态中心，负责把场景与实时层串起来。它从 URL 读取 designId、levelId，初始化所有子状态：

RootStateManager
├── room              # 房间状态
├── cameraView        # 相机视角
├── scene3D           # 3D 场景实体
├── visibilityResources # 可见模块/楼层
├── realtime          # 实时模板 & 渲染状态
├── offlineRender     # 离线渲染状态机 ★
├── outside           # 外部状态
└── selectControl     # 选中控制

它还维护 __onSceneUpdatingStart 回调，通过 debounce / cooldown 控制 realtime.syncSceneData() 的兜底同步，避免"替换布局先删后加"时在错误时机触发同步。

3. 核心：OfflineRenderStateManager 状态机

OfflineRenderStateManager 看起来是一个普通状态类，实际上是离线渲染、模板缓存、自动出图和轮询的业务中枢。

3.1 初始化流程

init() → 拉 snapshotList → 取当前模板 obsId → 初始化灯光/背景配置

3.2 关键状态字段

字段类型含义
snapshotListArray历史快照列表
lightStyleIdstring当前灯光样式 ID
hdriBackgroundIdstring当前 HDRI 背景 ID
backgroundConfigobject背景配置
objectShowRuleMapMap对象显示规则（来自父页面同步）
renderTasksArray当前渲染任务列表
hasNewRenderboolean图册红点 & 新结果提示
isSubmittingboolean是否正在提交渲染
hdPermissionobject高清渲染权限

容易踩的坑

hasNewRender 不是展示层临时状态，而是图册红点和新结果提示的共享业务状态。改渲染结果展示时必须连着它一起看。

4. 模板缓存机制

fetchAndCacheObsConfig(obsId) 是模板配置的核心方法。它会把灯光样式映射与背景配置缓存到 obsConfigCache，同一模板重复切换时优先走缓存。

切换模板 obsId → 检查 obsConfigCache → 命中? 直接用 : 发请求 → 写入缓存 → 更新灯光/背景
静默回退

初始化失败时会回退到 DEFAULT_TEMPLATE_CONFIG.backgroundConfigData。所以有些错误不会直接炸页面，而是表现成渲染风格悄悄回到默认值。

改模板切换逻辑时，必须同时检查 currentObsId、obsConfigCache、实时模板来源和默认背景回退这四条路径。

5. 父页面同步协议

render-3d 嵌在 iframe 里，很多关键数据不是自己算的，而是通过 postMessage 从父页面同步过来。

5.1 对象显示规则

objectShowRuleMap 来自父层同步。离线渲染会基于这些外部显示规则决定最终提交参数。如果规则没同步到位，渲染结果会出现"多余物体"或"缺少家具"。

5.2 协议注意事项

改协议时必须同步核对
  • 显示规则（objectShowRuleMap）
  • 渲染任务回写
  • 图册入口状态
  • 父页面接收端

最常见的症状是：页面还能渲染，但离线参数或图册结果已经和父层脱节。

5.3 iframe 协议代码位置

utils/iframeHelper/*
├── postMessage 消息定义
├── 父页面 → 子页面: 显示规则同步
├── 子页面 → 父页面: 渲染结果回写
└── 双向: 图册状态同步

6. 渲染任务轮询

渲染任务提交后，系统会自动轮询任务状态，直到完成或超时。

轮询策略

6 秒一次，最长 10 分钟。轮询目标是 SnapshotTaskStatus 接口。

提交渲染任务 → 任务加入 renderTasks → 每 6s 轮询状态 → 完成/超时 → 更新 hasNewRender → 图册红点
改渲染权限时

不要只看按钮可点性。hdPermission、轮询状态和父层同步结果都会影响最终行为。

7. 房间自动出图

自动出图不是简单的按钮行为，它依赖房间类型、智能视角结果和当前场景相机状态三条链路。

7.1 核心函数

generateGellarys() 按指定 RoomType 过滤房间，然后为每个房间生成渲染图。

7.2 视角选择策略

按 RoomType 过滤房间 → 查 smartCameraViewMap → 有智能视角? 用它 : renderRoomCenterView() → 生成渲染图
两条分支
  • 优先：使用 smartCameraViewMap 的智能视角（服务端返回的最佳视角）
  • 兜底：退回 renderRoomCenterView()，用房间中心和当前相机方向计算新相机属性

改自动出图逻辑时，必须确认两条分支都还成立。
