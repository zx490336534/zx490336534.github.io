012 端到端环境排查清单

目标：前后端都跑起来后，用固定顺序排查“页面能开但 AIHom 功能不通”的问题。

1. 先确认你在测哪种组合

组合典型用途风险
本地前端 + 环境后端改 UI、SDK、前端 Tool，后端不动。前端资源本地，后端配置在环境里，问题容易跨层。
环境前端 + 本地后端改 ai-native-service / auto-layout-service，验证接口和 WebSocket。需要服务版本路由、toad stage、Nacos 配置都对。
本地前端 + 本地后端完整联调新协议、新 Tool、新状态。最灵活，也最容易出现配置不一致。
环境前端 + 环境后端回归、验收、发布前验证。不要把本地修复误判为环境已修复。

排查第一句话应该是：“我现在测的是哪几个仓库、哪个分支、哪个环境、哪个服务版本”。这句话说不清，后面所有判断都会漂。

2. 15 分钟排查顺序

  1. 前端入口：Console 第一条红错是什么？入口 JS/CSS 是否 404？
  2. 目标环境：kjl dev -T 指向哪里？页面实际接口域名是什么？
  3. 登录态/权限：接口 401/403 先处理账号、cookie、权限，不要先看业务代码。
  4. WebSocket：destination 接口是否成功？WS 是否 connected？是否有 inbound/outbound frame？
  5. 后端路由：请求是否打到你的 dev_{花名} 服务版本？
  6. 配置：spring.profiles.active、qunhe.toad.stage、Nacos graph/prompt/tool 是否一致？
  7. Agent 执行：Langfuse/trace 里是否进入预期 Agent、节点、Tool？
  8. 中间件：Redis 锁、队列、TDDL 数据、RocketMQ 消费、OSS 资源是否正常？
  9. 前端展示：消息到了但没展示，再看 React state、reactive-framework、iframe/postMessage。

3. 常见症状对照

症状优先怀疑第一证据
页面白屏前端资源、运行时 JS 错误。Console 第一条 error；Network 404/500。
能打开但发不了消息登录态、WebSocket destination、SDK 初始化。接口状态码；WS 是否 connected。
消息发出但没回复后端 handler、Graph、模型调用、Redis 锁。traceId；后端日志；Langfuse trace。
模型说完成但画面没变MCP Tool、前端工具回调、viewer 通信。tool_call/tool_response；Console；postMessage。
生成/渲染一直排队Redis 队列、异步任务、worker 并发。queuePos/queueSize；Redis key；任务状态。
只在某环境失败toad、Nacos、OSS bucket、服务版本。环境变量；配置中心；实际请求域名。
