026 前端基础 06：JavaScript 异步运行模型

目标：看到 ai-home 里的函数、对象、Promise、async/await、事件回调时，知道代码为什么不是从上到下一次跑完。

为什么先学它

React、SDK、WebSocket、postMessage 都跑在浏览器里的 JavaScript 运行时上。你读前端代码时最常见的困惑，不是语法本身，而是“这个回调什么时候执行”。

1. JS 代码的三种常见形态

形态读法AIHom 场景
对象一包相关数据message、toolCall、viewer 配置
函数一段可重复执行的动作sendMessage()、handleMessage()
回调先登记，等事件发生再执行WebSocket 消息、按钮点击、postMessage
const message = { key: 'SendMessage', data: { text: '设计客厅' } };

function sendMessage(msg) {
  return conversation.send(msg); // 返回 Promise，不是立刻拿到最终回答
}

2. Promise：未来才会有结果

前端调用接口、等 SDK 初始化、等 viewer 截图，很多都不会立刻完成。Promise 就是“这个结果以后会回来”。

async function openConversation() {
  const conversation = await sdk.openConversation(id);
  return conversation.messages;
}

await 的读法是：先暂停当前函数，等 Promise 完成，再继续往下读。它不会卡死整个浏览器页面。

3. 事件循环：为什么回调会“晚点执行”

浏览器先执行当前同步代码；网络、定时器、WebSocket、用户点击这类事件完成后，再把对应回调排队执行。

同步代码先跑
  -> WebSocket 收到消息
  -> 回调进入队列
  -> 当前代码结束
  -> 执行消息回调，更新状态，触发 UI

4. 读 AIHom 前端代码的口诀

  1. 看到 async / await：问“它在等谁”。
  2. 看到 .then()：问“成功后接着做什么”。
  3. 看到 addEventListener / onXxx：问“谁触发这个回调”。
  4. 看到状态赋值：问“哪个组件会因此重渲染”。
