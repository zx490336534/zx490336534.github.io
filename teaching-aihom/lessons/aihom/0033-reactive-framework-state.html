033 AIHom 前端入口 02：状态管理基础

目标：不用先懂框架实现，先学会顺着一个页面变化，找到“数据在哪里、谁改了它、哪个组件读了它”。

先记这三句话

状态就是页面需要记住的数据。比如“对话是否正在生成”“连接是否成功”“某个 viewer 是否正在刷新”。

Manager就是专门管理一类状态的对象。比如 ConversationManager 管聊天状态，ViewerStateManager 管 viewer 状态。

组件负责把状态显示出来。状态变了，组件重新渲染，用户就看到页面变了。

1. 先看一个最小现象：聊天区显示“连接中”

在 AIHom 里，如果后端对话 SDK 还没连上，聊天抽屉会显示连接状态。读代码不要从术语开始，先从这个现象倒推。

用户看到
聊天抽屉上出现“连接中 / 重连中”。
组件读取
AIChatDrawer.tsx 在 render() 里读取 conversationManager.connectionStatus。
状态存放
ConversationManager.ts 里有 @observable connectionStatus。
状态更新
SDK 连接状态变化后，调用 conversationManager.handleConnectionStatusChange(...) 修改它。
AIChatDrawer render()
  ↓ 读取
conversationManager.connectionStatus
  ↓ 来自
ConversationManager.ts
  ↓ 被 SDK 回调更新
页面显示连接中 / 已连接 / 重连中

这就是状态管理最核心的事：把页面变化，翻译成一条数据流。

2. 第一条状态线：ConversationManager 管聊天

ConversationManager 是一个单例。你可以先把它理解成“聊天状态仓库”。它里面有这些真实字段：

class ConversationManager {
  @observable messages = [];
  @observable streamMessage = undefined;
  @observable status = ConversationStatus.done;
  @observable connectionStatus = ConnectionStatus.disconnected;
  @observable taskQueueInfo = null;
}
字段页面含义你读代码时怎么用
messages已经显示出来的聊天消息消息列表为什么多了一条，先查它
streamMessage正在流式生成的消息AI 边生成边显示，先查它
status发送中、处理中、完成按钮 loading、输入框禁用，先查它
connectionStatus连接、断开、重连聊天区连接提示，先查它
taskQueueInfo排队位置、队列长度输入框上方排队提示，先查它

@observable 是什么？

你先不用理解内部实现。第一次读代码时，只要把 @observable 当作一个标记：这个字段变了，相关页面可能跟着变。

@observer 是什么？

@observer 标在组件上，意思是：这个组件会观察自己读过的 @observable 字段。字段变了，它有机会重新渲染。

@observer
class AIChatDrawer extends React.Component {
  render() {
    const status = conversationManager.status;
    const connectionStatus = conversationManager.connectionStatus;
    const isLoading = status === ConversationStatus.processing;
    return ...;
  }
}
读法

看到 @observer 组件，不要先慌。你只做一件事：看它的 render() 里读了哪些 conversationManager.xxx。这些 xxx 就是会影响页面的状态。

3. 第二条状态线：RootStateManager 管画布和 viewer

聊天状态主要在 ConversationManager。但画布、2D/3D viewer、用户信息这些状态更多，所以 AIHom 又有一个根状态：RootStateManager。

export class RootStateManager extends combine({
  scene2D: AIHomeScene2DStateManager,
  viewerState: ViewerStateManager,
  userInfo: UserInfoStateManager,
}) {
  @observable
  declare designDoc: DesignDocument;
}

你可以把 RootStateManager 想成一个总目录：

入口负责什么例子
rootState.scene2D2D 画布状态缩放、拖动画布、选中对象
rootState.viewerStateviewer 同步状态刷新 loading、同步状态、布局进度
rootState.userInfo用户信息租户、会员、订阅状态
rootState.designDoc当前设计文档户型、容器、图片、视频来源

4. ViewerStateManager：一个真实的“改状态”例子

ViewerStateManager 里面有几个 Map，用来记录不同 viewer 的状态：

interface State {
  syncStatusMap: Map<string, SyncStatus>;
  connectorLineLoadingMap: Map<string, boolean>;
  layoutProgressMap: Map<string, { current: number; total: number }>;
  refreshLoadingMap: Map<string, boolean>;
}

比如刷新某个 viewer 时，会调用 setRefreshLoading：

setRefreshLoading(viewContainerId: string, isLoading: boolean) {
  const newMap = new Map(this.state.refreshLoadingMap);
  if (isLoading) {
    newMap.set(viewContainerId, true);
  } else {
    newMap.delete(viewContainerId);
  }

  this.mergeState({
    refreshLoadingMap: newMap,
  });
}

这里有两个小细节：

  1. new Map(...)：先复制一份新的 Map，再改它。
  2. mergeState(...)：告诉状态系统“这部分状态变了”。
为什么不直接改原来的 Map？

直接改原对象，状态系统不一定知道你改了。复制一份新对象再 mergeState，是更明确的“通知更新”写法。

5. connect：把 RootStateManager 接进组件

connect 做的事很朴素：从 rootState 里挑一些数据，塞给 React 组件当 props。

export const Viewer2D = connect(
  (rootState) => ({
    viewerState: rootState.viewerState,
  }),
  (subs) => ({
    syncStatusMap: subs.viewerState.syncStatusMap,
    refreshLoadingMap: subs.viewerState.refreshLoadingMap,
    layoutProgressMap: subs.viewerState.layoutProgressMap,
  }),
  Viewer2DImpl
);
代码位置你怎么读
第一个函数从根状态里拿哪几个 manager
第二个函数从 manager 里拿哪些字段给组件
第三个参数真正要渲染的组件

所以上面这段的意思就是：Viewer2DImpl 关心 viewerState 里的同步状态、刷新 loading、布局进度。

6. 五个词，一次只理解到这个程度

词小白版解释AIHom 里怎么看
@observable被追踪的数据字段变了，页面可能变
@observer会响应数据变化的组件看 render() 读了什么
Manager管理一组状态的对象ConversationManager、ViewerStateManager
combine把多个 manager 组合起来组成 RootStateManager
connect把状态接到组件 props看组件订阅了哪些字段

7. 以后读状态代码，就按这四步

  1. 先说页面现象：比如“排队提示为什么出现？”
  2. 找组件：搜索页面文字、样式名、组件名，找到负责渲染的 TSX。
  3. 找读取字段：看它读了 conversationManager.xxx 还是 props.xxx。
  4. 找更新方法：回到 manager 里搜索这个字段，看哪个方法 mergeState 或直接赋值。

练习一个真实例子：排队提示来自 InputArea 读取 conversationManager.taskQueueInfo。所以如果排队文案不对，第一反应不是翻 CSS，而是追 taskQueueInfo 在哪里被设置。

8. 本节你不需要先掌握的东西

  • 不需要先搞懂 @qunhe/reactive-framework 的内部实现。
  • 不需要先搞懂 @qunhe/kaf 的所有能力。
  • 不需要背 computed。当前主线先抓 @observable、@observer、mergeState、connect。
