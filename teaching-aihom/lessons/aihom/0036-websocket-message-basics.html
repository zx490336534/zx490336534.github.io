036 AIHom 前端入口 05：WebSocket 消息入门

目标：先能在浏览器 Network 里看懂一条消息：它是谁发的、属于哪类、要交给哪个处理器。

先把 WebSocket 当电话线

普通 HTTP 像“问一次答一次”。WebSocket 像“一直开着的电话线”。AI 对话要持续收消息、流式输出、排队通知和工具调用，所以需要 WebSocket。

1. 一条消息最重要的三个字段

{
  "id": "本次消息 id",
  "type": "request / response / notification / tool_call / tool_response",
  "key": "SendMessage / TaskQueueInfo / ...",
  "data": { "真正的数据在这里" }
}
字段先理解成
id用来配对请求和响应
type这条消息属于哪一大类
key具体要做什么事
data业务参数

2. 五类消息不用一次全背

type人话解释例子
request前端请求后端做事SendMessage
response后端回答某个请求发送成功/失败
notification后端主动通知前端TaskQueueInfo
tool_call后端要求前端执行工具前端工具调用
tool_response前端把工具结果回给后端工具执行结果

3. 后端入口怎么看

后端收到消息后，入口是 WsMessageListener。第一次读只看分流逻辑：

if type == request:
  交给请求处理器
else if type == notification:
  交给通知处理器
else if type == tool_response:
  交给前端工具结果处理器

真正发聊天消息的处理器是 SendMessageHandlerImpl，它处理 ProcessorMessageType.SendMessage。

4. 排队提示怎么看

排队提示不是前端自己猜的。后端工具执行过程中会发 TaskQueueInfo，里面有队列位置和队列大小。前端收到后更新 conversationManager.taskQueueInfo，输入区就能显示排队状态。

5. 浏览器排查顺序

  1. 打开 DevTools → Network → WS。
  2. 点开 WebSocket 连接，看 Frames。
  3. 先看 type，判断消息大类。
  4. 再看 key，判断业务动作。
  5. 最后看 data，确认参数是否符合预期。
