009 后端本地运行与部署基础

目标：第一次介入 ai-native-service / auto-layout-service 时，知道服务怎么启动、构建产物是什么、发布入口在哪里。

1. 先分清三个动作

动作你在做什么真实证据
本地运行在 IDE 或命令行启动 web 模块，连接 dev/sit 配置和中间件。两个后端 README 都给了 -Dqunhe.toad.stage=sit、-Dstage=dev、-Dqunhe.service.version=dev_{花名}。
构建/发布包用 Maven 编译、测试、打包，把产物发布到远程制品仓库。两个后端 README 都写了 mvn clean deploy -U -DskipTests。
部署到环境Pilot 根据环境和 _appconfig/cicd.yml 启动服务。README 指向 Pilot 文档，并说明启动参数在 /_appConfig/cicd.yml。

小白版理解：Maven 负责“把代码做成能运行的包”；Pilot 负责“在公司环境里把包跑起来”；toad/Nacos 负责“服务启动后该读哪些配置”。

2. ai-native-service 本地启动最小参数

ai-native-service 是 Java 21 + Spring Boot 3 的主服务。本地启动时最容易混淆的是：本地 profile 是 dev，但远程配置 stage 常用 sit。

--add-opens java.base/java.lang=ALL-UNNAMED
-Dqunhe.toad.host=http://toad.example.com
-Dqunhe.toad.stage=sit
-Dstage=dev
-Dservice.version.default.global=sit
-Dspring.profiles.active=dev
-Dqunhe.service.version=dev_{花名}
参数判断标准
-Dspring.profiles.active=devSpring 加载 application-dev.yml。
-Dqunhe.toad.stage=sittoad 从 sit 环境拉远程配置。
-Dstage=dev告诉公司中间件当前应用阶段是本地开发。
-Dqunhe.service.version=dev_{花名}联调时用服务版本标识把调用路由到你的本地服务。

3. auto-layout-service 本地启动差异

auto-layout-service README 里的参数少了 --add-opens 和 -Dspring.profiles.active=dev，但环境变量里仍给了 SPRING_PROFILES_ACTIVE=dev。

-Dqunhe.toad.host=http://toad.example.com
-Dqunhe.toad.stage=sit
-Dstage=dev
-Dservice.version.default.global=sit
-Dqunhe.service.version=dev_{花名}

APP_STAGE=dev
SPRING_PROFILES_ACTIVE=dev
APP_ENV_NAME=sit
qunhe.has.stage=sit

不要只复制一段 JVM 参数就结束。IDE 里还要看 Environment variables。很多“本地跑起来但配置不对”的问题，本质是 VM options 和环境变量缺一块。

4. 部署前你真正要确认什么

  1. 代码分支对不对：需求分支、发布分支、hotfix 分支不要混用。
  2. 构建命令是否通过：至少能执行 mvn clean install -DskipTests 或团队要求的测试集。
  3. 发布配置是否在正确环境：看 _appconfig/cicd.yml 里的 stage、内存、profile、toad stage。
  4. 中间件依赖是否存在：TDDL/MySQL、Spore Redis、RocketMQ、OSS、Nacos、toad。
  5. 上线后怎么观测：QHLogger、traceId、Hunter/OpenTelemetry、Langfuse。

5. 最小命令速查

# 构建并安装到本地 Maven 仓库
mvn clean install -DskipTests

# 发布到远程制品仓库，两个后端 README 均记录了这个命令
mvn clean deploy -U -DskipTests

# 查 Java 版本，ai-native-service web 侧需要 Java 21
java -version

# 查当前分支和未提交改动
git status
git branch --show-current
问 agent：“帮我检查这个后端仓库本地运行参数是否完整”，并贴 Run Configuration 里的 VM options 和 Environment variables。
