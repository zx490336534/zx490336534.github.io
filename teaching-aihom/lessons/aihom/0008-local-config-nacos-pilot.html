008 本地启动与配置体系

用 ai-native-service 和 auto-layout-service 学会判断：一个配置到底从哪里来，谁覆盖了谁

1. 先记住一张地图

本地启动后端服务时，不要先猜配置。先按这条线索找：

JVM 参数 / 环境变量
  │  决定当前 profile 和远程配置环境
  ▼
application.yml / bootstrap.yml
  │  基础配置，写通用默认值
  ▼
application-dev.yml / bootstrap-sit.yml
  │  profile 专属配置，覆盖基础配置
  ▼
toad / Nacos
     运行期从远程配置中心取环境差异和 Agent 配置
小白友好版

application.yml 像默认说明书，application-dev.yml 像本地便签，-Dspring.profiles.active=dev 像告诉 Spring 先读哪张便签。toad/Nacos 则是公司统一放配置的地方。

2. 本地启动最少要看这几项

两个后端仓库的 README 都给了本地启动参数。第一次启动时，先确认这些值一致：

配置项作用真实线索
-Dspring.profiles.active=dev
SPRING_PROFILES_ACTIVE=dev		让 Spring 加载 application-dev.yml 这一组 profile 配置。两个仓库的 _appconfig/cicd.yml 都按 dev/stable/prod_test/sit/prod 设置这个参数。
-Dqunhe.toad.stage=sit
APP_ENV_NAME=sit		告诉 toad 拉哪个环境的远程配置。README 的本地启动参数建议本地 profile 用 dev，远程配置 stage 用 sit。
-Dstage=dev
APP_STAGE=dev		给公司中间件和业务代码识别当前应用阶段。auto-layout-service 的 Redis namespace 写了 als:${APP_STAGE}:。
-Dqunhe.service.version=dev_{花名}本地联调时标记服务版本，方便 SOA/网关路由到自己的服务。两个仓库 README 都给了这个占位写法。

3. 两个仓库的配置入口不同

3.1 ai-native-service

ai-native-service-web/src/main/resources/application.yml 里直接能看到服务名、Hunter trace、toad、Nacos Agent 代理：

spring.application.name: ai-native-service
qunhe.hunter.enable-mdc: true   # 日志打印 TraceId / SpanId
qunhe.toad.app-id: khrd.i18n.ai-native-service
spring.ai.alibaba.agent.proxy.nacos.enabled: true

这说明它不只是普通 Spring Boot 服务，还会从 Nacos 读取 Agent/model/prompt/tool 相关配置。

3.2 auto-layout-service

auto-layout-service 多了 bootstrap.yml 系列，里面声明 toad：

# bootstrap.yml
qunhe.toad.app-id: khrd.i18n.auto-layout-service
qunhe.toad.stage: stable

# bootstrap-sit.yml
qunhe.toad.stage: sit

它的 application-dev.yml 里还能看到更业务化的开关，例如 layout.debug.enable、layout.frameless.config、layout.framed.config 和 openai.api.host。

4. 配置覆盖顺序怎么判断

遇到“我明明改了配置，为什么没生效”，按四步查，不要跳：

  1. 先看启动参数：IDE Run Configuration 里有没有 -Dspring.profiles.active，环境变量里有没有 SPRING_PROFILES_ACTIVE。
  2. 再看本地文件：同一个 key 是否同时出现在 application.yml 和 application-dev.yml。
  3. 再看远程中心：toad stage 是否是你以为的环境，Nacos Agent 配置是否被远程配置覆盖。
  4. 最后看运行时日志：启动日志、接口日志和 traceId 能告诉你实际连到了哪个环境。
最常见坑

spring.profiles.active=dev 和 qunhe.toad.stage=sit 可以同时出现。前者控制本地 Spring profile，后者控制 toad 远程配置环境。它们不是同一个开关。

5. Nacos、Pilot、toad 各管什么

名字你该怎么理解AIHom 里的证据
Pilot公司应用运行框架，README 指向 Pilot 文档，并要求改 _appconfig/cicd.yml 设置启动参数。两个后端根 pom.xml 使用 pilot-boot-dependencies。
toad区分环境的远程配置中心，README 明确说 Pilot 推荐把环境差异配置托管到 toad。两个服务都有 qunhe.toad.app-id。
Nacosai-native-service 的 Agent 配置入口，主要影响 Agent、model、prompt、tool 这类 AI 编排配置。AgentNodeFactory 引入 NacosAgentInjector，ChatModelFactory 使用 Nacos model/prompt 相关类。

6. 30 秒排查模板

# 1. 我现在跑哪个 profile？
SPRING_PROFILES_ACTIVE=dev
-Dspring.profiles.active=dev

# 2. 我现在拉哪个远程配置环境？
APP_ENV_NAME=sit
-Dqunhe.toad.stage=sit

# 3. 这个 key 在哪里出现？
rg -n "layout.debug.enable|qunhe.toad.stage|spring.ai.alibaba.agent.proxy.nacos" .

# 4. 如果是 Agent/prompt/tool，不只看 yml，还要去 Nacos 查。
问 agent：“帮我按当前 Run Configuration 判断 ai-native-service 会读哪些配置源”，把启动参数和你怀疑的 key 贴过去。
