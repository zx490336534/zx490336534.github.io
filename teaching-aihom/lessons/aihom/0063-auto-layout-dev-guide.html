063 auto-layout-service 开发实战

手把手教你新增 Processor、Manager，接入 AI 服务，以及本地调试与排查技巧

1. 如何新增 Processor

新增一个 Processor 是 auto-layout-service 中最常见的开发任务。以新增一个 MyNewProcessor 为例：

1选择基类

根据任务类型选择继承的基类：

场景继承说明
需要 DB 持久化任务状态BaseDbTaskAsyncProcessor任务记录写 MySQL
需要 Redis 管理任务状态BaseRedisTaskAsyncProcessor任务记录写 Redis，高并发友好
简单同步任务BaseProcessor不需要异步，直接执行

2创建 Processor 类

@Component
public class MyNewProcessor extends BaseRedisTaskAsyncProcessor {

    @Autowired
    private SomeManager someManager;

    @Override
    protected String getTaskType() {
        return "MY_NEW_TASK";
    }

    @Override
    protected void doProcessInner(YourRequestVO request) {
        // 1. 参数校验
        // 2. 调用 Manager 做业务
        someManager.doSomething(request);
        // 3. 构建返回结果
    }
}

3注册到路由

确保新 Processor 能被请求路由到。通常在 Service 层或配置中添加路由映射。

注意

不要在 Processor 里直接调用外部 HTTP/RPC 接口。把外部调用封装到 Manager 中，Processor 只负责编排流程。

2. 如何新增 Manager

Manager 是外部服务的封装层。当你需要接入一个新的外部服务（AI 服务、第三方 API 等），新建一个 Manager。

1在 manager/ 目录下创建类

@Component
@Slf4j
public class MyServiceManager {

    @Autowired
    private SomeFeignClient feignClient;

    public ResultVO callExternalService(ParamVO param) {
        log.info("调用外部服务, param={}", param);
        try {
            ResultVO result = feignClient.call(param);
            log.info("调用成功, result={}", result);
            return result;
        } catch (Exception e) {
            log.error("调用失败", e);
            throw e;
        }
    }
}

2创建 Feign Client（如果需要）

如果外部服务有 HTTP 接口，在 auto-layout-service-client 模块中定义 Feign Client：

@FeignClient(name = "my-external-service", url = "${my.service.url}")
public interface MyExternalServiceClient {

    @PostMapping("/api/endpoint")
    ResultVO call(@RequestBody ParamVO param);
}
命名规范

Manager 类名以 Manager 结尾，放在 manager/ 目录下。Feign Client 以 Client 结尾，放在 client 模块中。

3. 如何接入新的 AI 服务

项目当前集成了两类 AI 服务：

AI 服务ManagerSDK能力
OpenAIOpenaiManagercom.openaiChat、Embedding、Vision
AI NativeAiNativeManagerai-native-service-client图像生成

接入新 AI 服务的步骤：

  1. 引入 SDK — 在 pom.xml 中添加 AI 服务的客户端依赖
  2. 新建 Manager — 在 manager/ 下创建 XxxAiManager，封装所有 AI 调用
  3. 配置化 — API Key、endpoint 等放到 Nacos 或 application.yml，不要硬编码
  4. 在 Processor 中调用 — 在 Processor 的 doProcessInner() 中注入并调用 Manager
最佳实践

AI 调用通常有超时、限流、重试等需求。在 Manager 层统一处理这些逻辑，Processor 层只关注业务编排。

4. 本地运行命令

在本地启动 auto-layout-service 需要配置以下 JVM 参数：

mvn spring-boot:run \
  -pl auto-layout-service-web \
  -Dqunhe.toad.host=http://toad.example.com \
  -Dqunhe.toad.stage=sit \
  -Dstage=dev \
  -Dservice.version.default.global=sit \
  -Dqunhe.service.version=dev_{花名}
替换花名

{花名} 替换为你自己的花名拼音（如 dev_zhangsan），用于区分不同开发者的实例。

常用构建命令

# 完整构建（跳过测试）
mvn clean deploy -U -DskipTests

# 运行所有测试
mvn test

# 运行单个测试类
mvn test -pl auto-layout-service-web -am -Dtest=TestClassName

5. 常见排查路径

任务卡住不返回

  1. 检查 Redis 中任务状态：AutoLayoutContext.get().getTaskId() 拿到 taskId
  2. 查看线程池是否满：doAsyncProcess() 提交到线程池时可能排队
  3. 检查 Manager 层的外部调用是否超时

AI 返回结果异常

  1. 检查 prompt 是否正确 — 看 Manager 层日志中发送给 AI 的完整 prompt
  2. 检查图片 URL 是否可访问 — AI Vision 需要能下载图片
  3. 检查模型参数 — temperature、max_tokens 等是否合理

任务重复执行

  1. 检查 getExistTask() 逻辑 — 是否正确判断了已有任务
  2. 检查 Redis key 是否过期 — 任务还没完成但 key 已经过期了
  3. 检查是否有并发请求 — 同一个用户短时间内重复提交
日志技巧

项目使用自定义 QHLogger，通过 QHLogger.getLogger(getClass()) 获取 logger。排查时重点关注 Processor 和 Manager 的 INFO/ERROR 日志。

6. 目录结构速查

auto-layout-service/
├── auto-layout-service-common/     # 共享 DTO、VO、枚举
├── auto-layout-service-client/     # Feign Client 定义
└── auto-layout-service-web/        # 核心业务
    └── .../web/
        ├── processor/
        │   ├── base/           # 基类：BaseProcessor、BaseAsyncProcessor...
        │   └── layoutv2/       # 具体 Processor 实现
        ├── manager/            # 业务 + 外部调用封装
        ├── service/            # Service 层
        ├── mapper/             # MyBatis Mapper
        ├── context/            # ThreadLocal 上下文
        ├── config/             # 配置类
        └── bean/               # PO / VO / DTO
