010 前端本地运行与部署基础

目标：知道 ai-home、viewer-2d、render-3d 该怎么本地启动、构建，以及为什么它们不是同一个部署边界。

1. 三个前端仓库的角色不同

仓库本地运行命令你在验证什么
ai-homeyarn dev → kjl dev
yarn beta → kjl dev -T https://prod-test-seoul.example.com		主页面、AI 对话、SDK、前端 Tool、嵌入 viewer 的链路。
viewer-2dyarn dev → kjl pub:dev2D 户型画布、PixiJS、Entity/Drawable、和父页面通信。
render-3dyarn dev → kjl pub:dev3D 场景、截图、离线渲染、iframe 通信。

ai-home 更像主应用；viewer-2d 和 render-3d 更像被主应用嵌入的能力容器。联调时不要只问“前端跑了吗”，要问“跑的是主应用，还是被嵌入的 viewer”。

2. ai-home：主前端怎么跑

ai-home/package.json 里真实脚本如下：

"dev": "kjl dev"
"beta": "kjl dev -T https://prod-test-seoul.example.com"
"build": "kjl build"
命令用途小白判断
yarn dev启动本地 dev-server。你主要看页面能不能加载、bundle 有没有报错。
yarn beta本地前端资源对接 beta 目标站点。适合验证“本地代码 + 线上/测试环境后端”的组合。
yarn build生产构建。合并前至少确认构建不炸，尤其是类型/资源路径问题。

3. viewer-2d / render-3d：pub 应用怎么跑

两个 viewer 仓库的脚本很像：

"postinstall": "yarn dupe"
"dev": "npx cross-env NODE_OPTIONS=--max-old-space-size=8192 kjl pub:dev"
"pub-script": "npx cross-env NODE_OPTIONS=--max-old-space-size=8192 kjl pub:build"

这里的重点不是背命令，而是理解 pub:dev / pub:build：它们按公司 pub 体系启动和构建前端资源。def.config.js 里三个前端仓库都声明了 pub:deploy 任务。

viewer-2d / render-3d 的 NODE_OPTIONS=--max-old-space-size=8192 是为了给构建更多内存。不要随手删除；构建很大的前端项目时内存不足会导致莫名其妙的失败。

4. 联调时先画清楚资源从哪里来

浏览器打开 AIHom 页面
  ↓
加载 ai-home 本地或环境资源
  ↓
ai-home 通过 iframe / SDK 嵌入 viewer-2d、render-3d
  ↓
ai-home 通过 agent-conversation-sdk 连 ai-native-service
  ↓
后端通过 WebSocket 让前端执行 MCP Tool

所以一个前端问题可能来自四种地方：主应用资源、viewer 资源、后端接口/WebSocket、环境配置。不要只盯着 React 组件。

5. 部署前最小检查

  1. yarn install 后没有依赖冲突；viewer 仓库会执行 yarn dupe。
  2. 本地 dev-server 能打开，Console 没有启动级红错。
  3. Network 里入口 JS、CSS、iframe 资源不是 404。
  4. 涉及 WebSocket/MCP 的改动，要确认 tool_call 和 tool_response 成对出现。
  5. 涉及 viewer 的改动，要分别验证主应用嵌入场景和 viewer 自身场景。
问 agent：“帮我判断这个 ai-home 问题属于主应用、viewer、WebSocket 还是环境配置”，并贴 Console + Network 里第一条红错。
