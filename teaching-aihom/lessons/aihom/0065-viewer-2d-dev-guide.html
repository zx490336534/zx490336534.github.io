065 viewer-2d 开发实战

掌握 viewer-2d 的日常开发技能 — 新增实体、修改交互、自动化测试、问题排查

1. 如何新增实体类型

当需要在 2D 场景中新增一种可渲染、可交互的元素（如新的标注类型、新的家具图例），需要完成以下步骤：

1.1 定义实体类

在 src/app/Entities/ 下新建实体类文件。参考已有的实体（如 Room、Door、Window），确保：

  • 实体类继承合适的基类
  • 定义业务数据属性（位置、尺寸、类型等）
  • 定义交互状态属性（选中、拖拽中等）
  • 绑定对应的 Drawable

1.2 实现 Drawable

Drawable 负责实体的 2D 可视化表现。需要：

  • 实现 PixiJS 图形绘制逻辑（参考 src/drawSVG/ 中的 SVG 到 Pixi 图形转换）
  • 响应实体状态变化触发重绘
  • 处理选中态的视觉反馈（高亮、边框等）

1.3 注册到场景

在 DfScene2d.tsx 的 onInit 中注册新的实体类型，让场景知道如何创建和管理它。

创建实体类 → 实现 Drawable → 注册到 onInit → 连接数据源 → 手动验证
注意

新增实体类型前，先全局搜索确认没有已存在的类似实体可以复用或扩展。实体与 Drawable 的绑定关系属于高风险改动区域，修改后必须手动验证渲染和交互。

2. 如何修改交互逻辑

viewer-2d 的交互逻辑分布在多个模块中，修改前需要先定位到正确的模块。

交互类型涉及模块关键文件
拖拽移动transformsrc/modules/transform/
吸附对齐inference + inferenceBoxAlignsrc/modules/inference/、src/modules/inferenceBoxAlign/
缩放/旋转transformsrc/modules/transform/
选中/取消选中SelectedControlssrc/modules/SelectedControls/
左侧面板交互LeftPanel + viewssrc/app/views/、src/StateManager/LeftPanelStateManager.ts
工具切换Toolssrc/app/Tools/

修改交互的标准流程

  1. 定位：根据上表确定交互逻辑所在的模块
  2. 搜索：全局搜索相关的事件处理函数、状态字段
  3. 理解：阅读现有代码，理解交互的状态流转
  4. 修改：做最小范围修改，不做无关重构
  5. 验证：运行 yarn dev，在页面中手动验证交互行为
提示

修改拖拽、吸附、推理、缩放逻辑中的数学计算或坐标系转换属于高风险改动。务必充分测试边界情况（极端位置、重叠、边界碰撞等）。

3. Playwright 测试

viewer-2d 项目已补充 Playwright E2E 能力，用于自动化验证关键链路。

3.1 运行测试

# 标准执行
yarn test:e2e

# PowerShell 执行策略受限时
yarn.cmd test:e2e

3.2 配置与结构

  • 配置文件：playwright.config.js
  • 测试目录：playwright/tests/，匹配 *.e2e.ts
  • 基准域名：https://localhost:7000（需先启动 yarn dev）
  • 用例配置：playwright/support/cases.ts 或环境变量
  • 分类：smoke、integration、contract、ui

3.3 现有用例

用例文件验证内容
viewer-bootstrap.e2e.ts基础挂载验证
door-window-save.e2e.ts门窗保存验证
ksg-furniture-legend.e2e.tsKSG 图例验证
room-fill-geometry.e2e.ts房间铺贴边界回归
ai-home-push-session.e2e.ts多 iframe 推送订阅竞态

3.4 编写新用例的原则

  • 优先验证"真实页面挂载 + rootState/请求级断言"的稳定链路
  • 只有在需求涉及复杂交互时，才补充拖拽、缩放、旋转等重交互自动化
  • 需要登录态时，通过 PLAYWRIGHT_QUNHE_JWT 环境变量提供 cookie
验证责任

需求实现后，如果影响已有自动验证覆盖范围，必须同步修改现有用例；如果没有对应覆盖，则必须新增用例。不允许只停留在"已写代码但未验证"的状态。

4. 常见排查路径

遇到问题时，先确定问题属于哪条链路，然后按路径定位：

问题类型排查起点
页面不挂载 / 容器尺寸异常plugin.ts → App.tsx → state.ts
Scene2D 初始化失败DfScene2d.tsx onInit → Scene2D/state.ts → state.ts
选中/拖拽/缩放/旋转异常modules/SelectedControls/ → modules/transform/
左侧面板不联动views/ → LeftPanelStateManager.ts → OutsideStateManager.ts
房间/门窗/标注渲染异常Entities/ → SelectedControls/ → drawSVG/
拖拽/吸附/推理逻辑异常modules/layout/ → modules/inference/ → modules/transform/
外部数据不同步documentSource/ → helpers/ → OutsideStateManager.ts

排查步骤

  1. 确认现象：页面是否挂载？Scene2D 是否初始化？交互是否响应？
  2. 定位链路：根据现象确定入口链路
  3. 全局搜索：搜索相关符号，确认影响范围
  4. 阅读代码：理解现有逻辑后再动手修改
  5. 最小修改：做最小闭环修改，不做无关重构
  6. 验证：改完后至少做一次与改动链路对应的人工验证
调试提示

本项目没有 Jest / Vitest 等单元测试框架，改动验证主要依赖 yarn dev + 手动验证 + kjl ci:lint / kjl pub:lint。每次改动代码后，必须额外检查是否引入了新的 TypeScript 报错。

5. 编码规范速查

  • 禁止使用 any 绕过类型检查，优先补全类型
  • 禁止在 finally 中 return（会覆盖返回值）
  • 删除变量/函数/类型前必须全局搜索引用
  • 优先定义 enum，不用联合类型字面量
  • 类型导入优先使用 import type
  • 路径别名：@/*、@cloudapi/*、@pcIndex/*
  • 样式沿用模块内已有写法（SCSS / CSS Modules / styled-components）
  • 不要为了"现代化"把类组件批量改为 Hooks
