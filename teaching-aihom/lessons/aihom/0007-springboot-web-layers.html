007 Spring Boot Web 三层最小闭环

从 Controller 追到 Service / Factory / Manager，再追到 Client / Mapper，读懂 AIHom 后端一次请求怎么跑完

1. 最小闭环不是死板三层

教科书常说 Controller、Service、DAO 三层。AIHom 的真实后端更像这个闭环：

Controller → Processor / Service → Factory / Manager → Client / Mapper → Result / VO

前端同学看接口时关心 URL、入参、返回值；后端同学还要继续往后追：这个 Controller 把请求交给了谁，谁又访问了数据库或外部服务。

2. ai-native-service：从 Controller 追会话链路

ConversationController 很薄，接到请求后直接交给 ProcessorFactory.exec(reqVo)。这说明项目里有一套“按请求对象选择 Processor”的分发机制。

@RestController
public class ConversationController {
  @GetMapping(UriConstants.CONVERSATION)
  public Result<GetConversationResVo> getConversation(GetConversationReqVo reqVo) {
    return ProcessorFactory.exec(reqVo);
  }
}

如果你是在排查“为什么会话标题没更新”，就不能停在 Controller。真实调用会进入 ConversationServiceImpl，它注入了多个 Bean：

ConversationServiceImpl
├── ConversationDao        会话表读写
├── MessageDao             消息表读写
├── StateGraphFactory      按 graphId/version 找状态图
├── NotificationServiceImpl通知前端更新标题
└── ISummaryService        总结消息、生成标题

再往下，ConversationDao 注入 ConversationMapper，而 ConversationMapper 继承 BaseMapper<ConversationPo>。这就是“业务对象落库”的常见末端。

读链路口诀

Controller 看入口，Service 看业务，Dao/Mapper 看数据库，Factory 看“选哪个实现”。每次只追一条线，不要一上来全局搜索所有类。

3. auto-layout-service：从自动布局接口追异步任务

AutoLayoutV2Controller 也是薄 Controller。比如 AUTO_LAYOUT_WITH_IMAGE 的 POST 接口，接收 AutoLayoutWithImageReqVo 和 CurrentUser，然后交给 ProcessorFactory.exec(reqVo, user)。

@PostMapping(UriConstants.AUTO_LAYOUT_WITH_IMAGE)
@PreAuthorize("hasAuthority('ROLE_USER')")
public Result<LayoutTaskStatusVo> autoLayoutWithImage(
    @RequestBody AutoLayoutWithImageReqVo reqVo,
    CurrentUser user) {
  return ProcessorFactory.exec(reqVo, user);
}

后面会进入 AutoLayoutWithImageProcessor。它继承 BaseDbTaskAsyncProcessor<AutoLayoutWithImageReqVo, LayoutTaskStatusVo>，说明这是一个“创建任务，然后异步处理，再查询状态”的接口。

AutoLayoutWithImageProcessor
├── verify(reqVo)                       校验权限、加锁，避免并发提交
├── initTask(reqVo)                     初始化 LayoutTaskStatusVo
├── AutoDesignInfoManager               更新自动设计状态
├── KWorkbenchManager / LOD300Manager   查设计、查户型模型
├── OpenaiManager / OpenAIClient        调用大模型能力
└── IProductConfigService               读取选品配置

这个服务里还有一个很典型的 Factory：AutoLayoutFactory。它启动后收集所有 IAutoLayoutService 实现，用 LayoutChannel 做 key。后来只要知道通道，就能拿到对应布局实现。

AutoLayoutFactory
└── Map<LayoutChannel, IAutoLayoutService>
    ├── GeminiLayoutServiceImpl
    ├── MaasLayoutServiceImpl
    └── 其他 IAutoLayoutService 实现

排查建议

接口返回失败时，先看 Controller 返回的 Result 类型，再搜 BizzException 抛出的 message。很多失败不是框架异常，而是业务校验主动抛出的。

5. Bean 注入：代码怎么连起来

这两个服务里常见 @Resource 和 @Autowired。它们的作用都是让 Spring 把容器里的对象塞进来。你看到这些字段，就知道“当前类依赖谁”。

@Service
public class ConversationServiceImpl {
  @Resource
  private ConversationDao conversationDao;

  @Resource
  private StateGraphFactory stateGraphFactory;
}

Factory 类通常用列表注入：例如 StateGraphBuildFactory 注入 List<IStateGraphBuildService>，启动后塞进 Map。新增一种图构建方式时，你通常要实现接口，并让它成为 Spring Bean。

6. 三步追代码练习

  1. 从 URL 找 Controller：搜 UriConstants.AUTO_LAYOUT_WITH_IMAGE 或接口路径常量。
  2. 从 Controller 找下一跳：看它直接调用 Service，还是走 ProcessorFactory.exec。
  3. 从 Service / Processor 看依赖字段：@Resource、@Autowired 后面的类，就是下一批要追的对象。
