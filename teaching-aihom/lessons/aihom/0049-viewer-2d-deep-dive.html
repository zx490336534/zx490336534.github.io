049 viewer-2d 深度追踪

深入 viewer-2d 核心链路 — 从 DfScene2d 初始化到外部同步机制的完整追踪

1. DfScene2d.tsx onInit 初始化流程

DfScene2d.tsx 是 Scene2D 的 React 组件入口，onInit 是排查场景初始化问题的第一入口。它负责在组件挂载后完成整个 2D 场景的搭建。

关键路径

src/app/Scene2D/DfScene2d.tsx 的 onInit 方法按顺序完成：创建 Scene2D 实例 → 注册视图 → 注册系统 → 注册推理能力 → 激活场景。

初始化流程概览：

App.tsx 挂载 Scene2D 容器 → DfScene2d 组件渲染 → onInit 触发 → 创建 Scene2D 实例 → 注册视图/系统 → 场景激活

在 onInit 中依次完成的核心注册：

  • 视图注册：将 UI 视图（房间信息、尺寸标注、加载态等）挂载到 Scene2D 的视图层
  • 系统注册：注册布局系统、推理系统、变换系统、选中控制系统等横切模块
  • 推理能力注册：注册门窗推理、对齐推理等能力
  • 实体初始化：根据文档数据创建房间、门窗、标注等实体及其 Drawable 绑定
高风险注意

修改系统注册、视图注册、场景激活顺序属于高风险改动，可能导致场景渲染失败或交互异常。改动后必须手动验证：场景是否正常挂载、选中/拖拽/缩放/旋转是否正常。

2. RootStateManager 子状态组合

RootStateManager（位于 src/app/state.ts）是整个 viewer-2d 的状态中枢，它组合了多个子状态管理器，各司其职。

子状态管理器职责
scene2DScene2D stateScene2D 自身状态，管理场景实例与渲染状态
selectedControlSelectedControls选中态管理，控制实体的选中/取消选中状态
layoutLayoutManager布局状态，管理自动布局与手动调整
outsideOutsideStateManager外部通讯，与父页面或外部容器双向通信
leftPanelLeftPanelStateManager左侧面板状态，管理菜单、悬浮信息等

React 组件通过 connect() 函数（来自 src/StateManager/index.ts）连接到根状态。连接层导出三个核心 API：

  • connect — 组件订阅状态变化
  • dispatch — 发起状态变更动作
  • setRootState — 在插件入口注入根状态（由 plugin.ts 调用）
设计要点

RootStateManager 采用组合模式，每个子状态管理器独立维护自己的状态和方法，通过根管理器统一暴露。这种设计让各模块可以独立演化，但改动根状态字段结构或初始化顺序属于高风险操作。

3. 实体与 Drawable 绑定

viewer-2d 的实体系统位于 src/app/Entities/，每个领域实体（房间、门窗、标注等）都绑定一个 Drawable，负责 2D 可视化表现。

实体与 Drawable 的绑定关系：

Entity（领域实体）
  ├── 持有业务数据（位置、尺寸、类型、属性）
  ├── 持有交互状态（选中、拖拽中、吸附中）
  └── 绑定 Drawable
        ├── 负责 PixiJS 图形绘制
        ├── 响应实体状态变化重绘
        └── 通过 src/drawSVG/ 完成 SVG 到 Pixi 图形转换

常见的实体类型：

  • 房间（Room）：矩形或多边形区域，支持铺贴边界渲染
  • 门（Door）：墙体上的开口，支持拖拽定位和尺寸调整
  • 窗（Window）：类似门但有不同的渲染逻辑和交互规则
  • 标注（Dimension）：尺寸标注线，自动跟随实体变化
  • 家具图例（FurnitureLegend）：KSG 家具的 2D 表现
高风险注意

修改实体类与 Drawable 的绑定关系属于高风险改动。删除实体类型前必须全局搜索引用，确保没有其他模块依赖该实体的 Drawable。

4. Scene2D 系统注册

Scene2D 的"系统"是横切关注点的实现，每个系统负责一类通用能力。在 DfScene2d.tsx 的 onInit 中统一注册。

系统源码位置职责
布局系统src/modules/layout/管理房间和家具的自动/手动布局
推理系统src/modules/inference/门窗位置推理、对齐推理
变换系统src/modules/transform/拖拽、缩放、旋转的数学计算和坐标系转换
选中控制src/modules/SelectedControls/管理实体的选中态和交互反馈
撤销重做（undo/redo 模块）操作历史记录与回退

系统的注册顺序很重要：依赖关系决定了注册的先后。例如变换系统依赖选中控制的状态，推理系统依赖布局系统的上下文。

5. 外部同步机制

viewer-2d 不是一个孤立的渲染器，它需要与外部世界保持数据同步。主要的外部同步通道包括：

5.1 文档数据源

src/documentSource/createDocumentSource.ts 是文档数据源的接入点，负责从外部获取房间、门窗、标注等初始数据，并在数据变化时触发场景更新。

5.2 父页面通信

OutsideStateManager（src/StateManager/OutsideStateManager.ts）负责与父页面或外部容器的双向通信。典型场景：

  • 通过 window.parent 向父页面发送状态更新
  • 通过 createPortal 将 UI 视图渲染到父页面 DOM
  • 通过 iframe 通信接收外部指令

5.3 推送服务

src/helpers/pushService.ts 实现外部推送与同步服务，支持多 viewer-2d iframe 之间的推送订阅（参见 ai-home-push-session.e2e.ts）。

5.4 预览图同步

src/app/setup/previewImageSetup.ts 负责预览图的生成与更新，当场景内容变化时自动刷新预览图。

高风险注意

修改外部同步逻辑属于高风险改动，尤其是房间信息、预览图、父页面消息相关。改动后必须验证：左侧面板与场景联动是否正常、父页面通信是否异常、预览图更新是否正确。

6. 完整调用链路图

入口层
  plugin.ts → 初始化 RootStateManager → setRootState()
  entry.tsx → 挂载页面到运行环境
  App.tsx  → 容器尺寸监听 + Scene2D 容器挂载

场景层
  DfScene2d.tsx onInit → 创建实例 → 注册视图/系统 → 激活
  Scene2D/state.ts → 场景自身状态管理

实体层
  Entities/ → Room, Door, Window, Dimension, ...
  drawSVG/ → SVG → PixiJS 图形转换

模块层
  modules/layout/      → 布局计算
  modules/inference/   → 推理能力
  modules/transform/   → 拖拽/缩放/旋转
  modules/SelectedControls/ → 选中态

同步层
  documentSource/ → 文档数据接入
  helpers/pushService.ts → 推送服务
  OutsideStateManager.ts → 父页面通信
  previewImageSetup.ts → 预览图同步
