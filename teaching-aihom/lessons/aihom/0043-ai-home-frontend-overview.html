043 ai-home 前端项目全景

理解前端核心仓库的结构、架构和关键入口 — 从 App.tsx 到画布+对话+Viewer 的完整链路

1. 这个项目是什么

ai-home 是 AI Home 产品的前端界面。它是一个基于 React 的单页应用，核心交互模式是"左侧画布 + 右侧 AI 对话"——用户通过自然语言对话驱动 AI 完成家装设计，设计结果实时呈现在 2D/3D 画布上。

一句话定位

React 17 + TypeScript 构建的 AI 对话驱动家装设计工具，通过 WebSocket 与后端 ai-native-service 通信，前端同时承载 2D/3D 画布渲染和 AI 对话交互。

5. 入口文件与路由

App.tsx — 应用入口

src/app/App.tsx 是整个前端的入口，极其简洁：

// App.tsx — 核心路由逻辑
class App extends React.Component {
    render() {
        const page = new URLSearchParams(location.search).get('page');
        const isMain = page === 'mainPage';

        return (
            <>
                <GlobalShortcuts />
                {isMain ? <MainPage /> : <HomePage />}
                <Toaster />
            </>
        );
    }
}

只有两个主页面：HomePage（首页/项目列表）和 MainPage（设计工作台）。通过 URL 参数 ?page=mainPage 切换，没有使用 React Router。

state.ts — 全局状态

src/app/state.ts 使用 @qunhe/kaf 的 combine() 将多个 StateManager 组合成一个根状态对象，包括：

  • AIHomeScene2DStateManager — 2D 场景状态（缩放、平移、选中）
  • ViewerStateManager — Viewer 同步状态、加载进度
  • UserInfoStateManager — 用户信息
  • Document 相关状态 — 设计文档的加载、保存、备份
不理解 StateManager 模式？可以问："KafBaseStateManager 和 Redux 有什么区别？" 或 "combine() 是怎么把多个 StateManager 组合的？"

6. AI 对话：前端 Agent 通信

前端通过 @qunhe/agent-conversation-sdk 与后端 ai-native-service 的 WebSocket 通信。核心链路：

InputArea 发送消息 → ConversationManager → AgentSDKService (WebSocket) → 后端 Agent → 流式响应 → MessageHandler 分发

8. 数据流

状态管理模式

项目使用 @qunhe/reactive-framework 的 observable + observer 模式，类似 MobX 但更轻量：

// 1. 定义 StateManager（继承 KafBaseStateManager）
class ViewerStateManager extends KafBaseStateManager<State> {
    initState() { this.updateState({...}); }
    setSyncStatus(id, level, status) { this.mergeState({...}); }
}

// 2. 在 state.ts 中 combine 组合
const rootState = combine({
    scene2d: AIHomeScene2DStateManager,
    viewer: ViewerStateManager,
    userInfo: UserInfoStateManager,
});

// 3. 组件中通过 connect() 注入
const MainPage = connect(rootState)(
    (props) => <div>{props.rootState.viewer.state.syncStatus}</div>
);

// 4. 或使用 @observer 装饰器（Class Component）
@observer
class AIChatDrawer extends React.Component { ... }

数据流路径

用户操作 / AI 消息 → StateManager.mergeState() → observable 响应式更新 → observer 组件重渲染

设计文档数据流

后端下发设计数据 → MessageHandler 解析 → storage/model 更新 → Entities 渲染到画布
注意

修改 storage/model/、storage/interface/、Entities/ 下的数据结构属于高风险操作，必须先输出方案说明并确认后再动手。参见 AGENTS.md 第七节。

9. 核心概念速查

ViewContainer（视图容器）

画布上每个设计元素（户型图、效果图、3D 场景）都是一个 ViewContainer。它有 2D 和 3D 两种渲染模式，通过 Viewer2D（iframe）和 Viewer3D（Canvas）分别承载。

MCP 工具桥接

后端通过 WebSocket 下发 Tool Call，前端执行后回传结果。例如后端需要 3D 渲染截图时，会调用 capture_3d_screenshot，前端在浏览器中完成截图后把图片数据返回给后端。

Tools（画布工具）

类似 CAD 软件的工具栏。每个 Tool 定义了一组交互行为（鼠标事件、键盘事件），如 IdleTool（选择/框选）、DragScene2dTool（拖拽画布）、ContainerControlsTool（容器控件）。

Entities（实体）

src/Entities/ 下的实体类是对 storage/model/ 数据模型的渲染层封装。例如 EntityDocument 包含所有 ViewContainer 的 2D 绘制逻辑，Drawable2D 负责将模型数据转化为 Canvas 绘制指令。
