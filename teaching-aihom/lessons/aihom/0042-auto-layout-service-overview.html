042 auto-layout-service 项目全景

理解 AI 自动布局引擎的结构、Processor 模式和核心数据流 — 为后续布局功能开发打下基础

1. 这个项目是什么

auto-layout-service 是 AI Home 产品的自动布局引擎。当用户请求"帮我自动布置这个户型"时，ai-native-service 会调用本服务，由它完成户型分析、AI 布局、商品匹配等核心工作，最终返回一份完整的软装方案。

一句话定位

Java 8 + Spring Boot 驱动的 AI 自动布局服务，负责"户型图进来 → AI 分析 → 自动摆放家具 → 匹配真实商品 → 方案出去"这条完整链路。

与 ai-native-service 的关系

ai-native-service 是总调度中心（Multi-Agent），auto-layout-service 是它的一个下游工具服务。ai-native-service 通过 Feign/HTTP 调用本服务的接口，获取布局结果后返回给前端。

4. 核心架构：Processor 模式

本项目最核心的设计模式是 Processor 模式 — 一种异步任务处理框架。不同于 ai-native-service 的 Agent/StateGraph 架构，这里用的是更传统的"任务处理器"模式。

5. Processor 生命周期

所有异步任务都遵循统一的生命周期，由基类 BaseAsyncProcessor 管理：

1. getExistTask() → 2. executeNewTask() → 3. initTask() → 4. doAsyncProcess() → 5. onSuccess() / onError()
  1. getExistTask() — 检查是否已有相同任务在执行（防重复提交）
  2. executeNewTask() — 判断是否应该创建新任务
  3. initTask() — 初始化任务记录（写入 DB 或 Redis）
  4. doAsyncProcess() — 提交到线程池，执行真正的业务逻辑
  5. onSuccess() / onError() — 任务完成后的回调（更新状态、通知等）

三层继承

基类存储方式适用场景
BaseAsyncProcessor内存简单异步任务
BaseDbTaskAsyncProcessorMySQL需要持久化的任务（如自动设计）
BaseRedisTaskAsyncProcessorRedis高频、短生命周期的任务状态

7. 核心数据流：AutoLayoutWithImage

当 ai-native-service 请求"根据户型图自动布局"时，数据经过这条链路：

请求进入 → SubmitAutoDesignV2AsyncProcessor → AutoLayoutWithImageProcessor → 结果返回

在 AutoLayoutWithImageProcessor.doProcessInner() 中，核心三步：

  1. coloringLayoutImage() — 调用 AI Native 服务，给户型图上色（区分卧室、客厅、厨房等区域）
  2. getLayoutWithImage() — 调用 OpenAI GPT，分析上色后的图像，生成结构化的布局方案
  3. buildAutoLayoutDesign() — 将 AI 输出构建成最终的布局设计结果，匹配真实商品
AI 双引擎

本服务同时使用两个 AI 引擎：OpenAI（GPT 做分析推理）和 AI Native Service（做图像处理）。理解这一点对后续开发很重要。

8. 关键设计模式

ThreadLocal 上下文：AutoLayoutContext

请求级别的上下文数据通过 AutoLayoutContext.get() 获取。在一个请求的整个生命周期内，任何 Processor、Manager 都可以通过它共享数据，而不需要层层传参。

// 使用方式
AutoLayoutContext ctx = AutoLayoutContext.get();
ctx.setSomeParam(value);
// ... 在另一个 Processor 中
String val = AutoLayoutContext.get().getSomeParam();

Manager 层封装外部依赖

所有外部服务调用（OpenAI、Milvus、KAM 等）都通过 Manager 层封装。Processor 只调用 Manager，不直接写 HTTP 请求。这保证了外部依赖的集中管理和测试便利。

自定义日志：QHLogger

不使用 slf4j 的 LoggerFactory，而是用公司自定义的 QHLogger.getLogger(getClass())。
