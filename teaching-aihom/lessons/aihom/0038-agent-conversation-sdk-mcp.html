038 AIHom 前端入口 07：SDK + MCP 工具桥

目标：先理解一句话：有些工具不是后端自己执行，而是后端让前端页面帮它执行，再把结果送回去。

先建立画面

大模型说“我要调用一个工具”。如果这个工具需要操作浏览器里的画布、viewer 或页面状态，后端就不能自己完成。它会发一个 tool_call 给前端。前端执行完，再发 tool_response 回后端。

1. 最小链路

模型决定调用工具
  ↓
ai-native-service 生成 tool_call
  ↓
WebSocket 发给 ai-home
  ↓
ai-home 前端执行工具
  ↓
tool_response 回到后端
  ↓
模型继续回答

2. 前端先做了什么

在 ai-home 里，AgentSDKService 负责初始化对话 SDK。你第一次读这块时，只要记住它做两件事：

  1. 建立和后端的对话连接。
  2. 把前端可执行的工具注册给 SDK。

所以排查“前端工具为什么没执行”，先看 SDK 是否初始化成功，再看工具是否注册进去。

3. 后端为什么知道要找前端

后端构建 Agent 时，会把工具变成 ToolCallback。其中一类工具走前端执行路径，关键类名是 FrontendNacosMcpGatewayToolCallback 和 PostMessageToolInterceptor。

代码先理解成
CustomNacosReactAgentBuilder把 Agent、模型、Prompt、Tools 装起来
CustomNacosMcpGatewayToolsInitializer从 MCP Server 配置里解析工具
FrontendNacosMcpGatewayToolCallback这类工具要交给前端执行
FrontendToolCallHandlerImpl把前端工具调用发成 tool_call
FrontendToolResponseHandlerImpl接收前端回来的 tool_response

4. 读问题时只问四件事

  1. 工具有没有被模型看到？没有的话查 Nacos/MCP 工具配置和后端构建日志。
  2. 后端有没有发 tool_call？没有的话查 FrontendToolCallHandlerImpl。
  3. 前端有没有收到并执行？没有的话查 WebSocket 和 SDK 注册。
  4. 前端有没有回 tool_response？没有的话查工具执行结果和 response id。

5. 这节不要先钻的细节

  • 不要一开始就研究 MCP 协议全文。
  • 不要一开始就追所有 ToolCallback 实现。
  • 先把 tool_call → 前端执行 → tool_response 这条主线看顺。
Q1：前端工具调用的核心消息是什么？
  • A. normal_log
  • B. page_render
  • C. tool_call
  • D. style_sync
Q2：前端执行完工具后回什么？
  • A. tool_open
  • B. tool_response
  • C. tool_schema
  • D. tool_config
Q3：工具没执行，第一步先确认什么？
  • A. 是否发出调用
  • B. 字体是否正确
  • C. 页面是否好看
  • D. 注释是否足够
复习时可以问 agent：用一条具体工具调用，带我从 FrontendToolCallHandlerImpl 追到 ai-home 前端执行，再追回 FrontendToolResponseHandlerImpl。
