流式事件：断线、乱序与旧响应

给每个事件一个版本，用断线与乱序测试验证恢复。

先看场景走一遍动手练习自测

先看场景

同一个页面可能有两次生成请求，第一条比第二条更晚完成。只看消息到达时间，会出现旧布局覆盖新布局。

快照：此刻的完整状态。错过了中间几条消息时，重读一次当前状态比猜测之前发生了什么更稳妥。

走一遍

  1. 用任务 ID 判断结果属于哪次运行，事件序号只在同一次运行里比较。
  2. 事件出现缺口时，向服务端重新读快照，而不是猜漏过了什么。
  3. 开始新任务后忽略旧任务消息；终态事件重复到达不得重复执行副作用。
合成示例 可折叠
if (e.taskId !== current.taskId || e.seq <= current.seq) return;
if (e.seq > current.seq + 1) return reloadSnapshot();
applyEvent(e);

动手练习

造出序号 1、3、2、3，验证重新读取快照后没有倒退；再让旧任务晚到一次。

自测
