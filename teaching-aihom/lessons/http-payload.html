读懂一次生成请求的 HTTP 与 JSON

从请求方法、响应码、响应体三个位置判断下一步。

先看场景走一遍读代码复现失败动手练习自测

先看场景

RoomLab 提交布局生成。你在浏览器的网络面板看到 202，但返回体可能因为中间层故障而不完整。

响应契约：除了状态码，还规定必要的字段和字段类型。

走一遍

  1. 先辨认发出的是创建任务，不是读布局。
  2. 分开读 HTTP 状态和 JSON 字段。
  3. 接受以后用任务编号追踪进展。

第二遍 · 把代码读懂

代码拆解

怎样从网络面板判断服务器真的受理了本次操作？

调用链

  1. 找创建任务的请求。
  2. 核对状态码。
  3. 读取媒介类型、JSON 与任务身份。
  4. 把可追踪回执交给 UI。
Python 示例 可折叠

可复制到 lesson.py，再运行 python3 lesson.py。

import json

def receipt(status, media_type, body):
    if status == 422:
        return ("fix-input", None)
    if status != 202:
        return ("unexpected-status", None)
    if media_type.split(";")[0].strip().lower() != "application/json":
        return ("bad-media-type", None)
    try:
        payload = json.loads(body)
    except json.JSONDecodeError:
        return ("bad-json", None)
    if not isinstance(payload, dict):
        return ("bad-receipt", None)
    task = payload.get("task")
    if not isinstance(task, str) or not task.strip():
        return ("bad-receipt", None)
    return ("wait", task)

assert receipt(202, "application/json; charset=utf-8", '{"task":"R2"}') == ("wait", "R2")
assert receipt(202, "application/json", '{}') == ("bad-receipt", None)
assert receipt(202, "text/html", '<p>Oops</p>')[0] == "bad-media-type"
assert receipt(422, "application/json", '{}')[0] == "fix-input"

202 表示接受而非完成

创建任务受到接受后通常还有排队、执行与校验。浏览器保留上一个布局，不把 202 当成可渲染结果。

格式正确也可能不符合契约

从 body 解出对象仍要检查任务编号是否为非空文本。一个成功码配上代理返回的 HTML 不能拿去订阅任务。

拒绝输入和协议故障分开

422 指向输入，格式错误指向响应链路；它们需要不同的提示。时间敏感的服务规范应另行注明。

复现失败

状态码看着正常
怎么触发：202 但缺失 task。
怎么判断：不订阅、不显示已排队。
返回 HTML
怎么触发：媒体类型为 text/html。
怎么判断：提示回执异常，别重误判成输入错。

写下这些测试断言

  • 202 有效回执进入等待，不进入完成。
  • 缺身份和媒体类型异常能区分。
  • 422 显示修正输入的提示。

这一课带走：请求状态回答是否受理；回执身份让你知道在等哪一次。
